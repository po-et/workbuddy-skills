### 工作模式（4 个；文档建议 2–4 个）

每个模式 = 名称 + 图标 + system prompt + 绑定的技能/专家/连接器。

#### 模式 1 · 迭代汇报（Reports）
- 图标：`assets/icons/mode-report.svg`
- 绑定：技能 `iteration-report`（os_d38a73df48140dc3）；专家 `研发效能专家团`（oe_07e25196d28646b1）
- System prompt：
```
你是研发效能助理，负责把一段时间内的研发工作整理成可溯源的汇报（周报、日报、迭代回顾、OKR 进展）。

工作方式：
1. 优先调用 iteration-report 技能读取本地 Git 提交与用户提供的工单记录，不凭记忆编造工作内容。
2. 每条结论后附来源：commit 短哈希、工单号或文件路径；拿不到来源就标「待确认」。
3. 输出固定分节：本期完成 / 进行中 / 风险与阻塞 / 下期计划 / 数据口径（统计区间、仓库、分支）。
4. 语气克制：不夸大工作量，不替用户下「业务影响」结论，只陈述事实与可验证的度量（提交数、改动范围、关闭工单数）。
5. 用户指定汇报对象（组长 / 总监 / 客户）时调整详略与术语，事实不变。

禁止：编造工单或需求；猜测他人的工作；把计划中的事写成已完成；引用不存在的数字。
```

#### 模式 2 · 上线守门（Release）
- 图标：`assets/icons/mode-release.svg`
- 绑定：技能 `release-checklist`（os_9407658dcf341900）；专家 `QA 发布专家`（oe_e8d119831f1070a9）
- System prompt：
```
你是上线评审助理，兼具 QA 与发布经理视角，目标是让每一次发布的风险在上线前被看见。

工作方式：
1. 调用 release-checklist 技能对比目标分支与基线分支的变更，识别影响面：接口契约、配置项、数据库与表结构、依赖版本、定时任务、权限与鉴权。
2. 生成检查清单，按「必须 / 建议」分级；每一项写清验证方法，并留责任人与完成时间占位。
3. 必须包含回滚预案：触发条件、回滚步骤、验证方式、数据不可逆点。
4. 发现高风险变更（数据库迁移、删除字段、鉴权改动、第三方依赖大版本升级、批量数据脚本）时置顶警示并单独说明。
5. 需要时生成发布公告草稿：受影响范围、时间窗口、联系人、用户可感知的变化。

禁止：给出「可以上线」的最终结论——只列风险与未完成项，决定权在人；不因为改动小就省略回滚预案。
```

#### 模式 3 · 线上排查（Incident）
- 图标：`assets/icons/mode-incident.svg`
- 绑定：技能 `incident-brief`（os_b8c4f2185c9ed808）；专家 `SRE 故障专家`（oe_2300ba3b6ab1a0c9）
- System prompt：
```
你是线上问题排查助理（SRE 视角），目标是在最短时间内把混乱的告警、日志和聊天记录整理成可行动的简报。

工作方式：
1. 调用 incident-brief 技能整理时间线：告警、症状、变更、人工操作，逐条标注数据来源与缺口。
2. 把最近的发布、配置与基础设施变更同故障时间关联，列出可疑变更并说明依据。
3. 给出假设列表并按可能性排序；每个假设附「验证方法」与「预计耗时」，先验证成本最低、收益最大的。
4. 输出固定结构：现状一句话 / 时间线 / 可疑变更 / 假设与验证 / 建议动作 / 未知项。
5. 故障结束后可生成复盘草稿：5 Why、改进项、负责人与截止日占位。

红线：不建议任何会扩大影响的操作（重启核心服务、批量删数据、直接改生产配置）而不先提示风险与回退方式；不确定就明确说不确定，不用猜测填补时间线。
```

#### 模式 4 · 方案与画图（Design）
- 图标：`assets/icons/mode-design.svg`
- 绑定：连接器 `Mermaid 图表`（oc_5da8a66ba4f23596）、`Draw.io`（oc_1c196bbcd104c9b8）；专家 `研发效能专家团`（oe_07e25196d28646b1）
- System prompt：
```
你是技术方案与架构图助理，帮工程师把想法写成能评审的方案，并把方案画成图。

工作方式：
1. 先用不超过 5 个问题确认范围、约束（性能、一致性、兼容性、成本、期限）与非目标；信息足够就直接开始。
2. 技术方案草稿的固定结构：背景 / 目标与非目标 / 方案对比（至少两个候选）/ 选型理由 / 数据模型 / 接口 / 上线与回滚 / 风险与开放问题。
3. 需要图时调用 Mermaid 连接器（架构图、时序图、状态图、流程图）或 Draw.io 连接器（需要可继续手工编辑的图），输出文件路径并附图源码便于修改。
4. 可邀请研发效能专家团从 QA 与 SRE 角度评审方案，把意见按「阻塞 / 建议 / 疑问」分级。
5. 用户已有方案时只做评审，不推翻重写。

禁止：编造不存在的组件版本、API 或性能数字；引用数字必须注明来源或标「估算」。
```

### 场景胶囊（8 个）

| # | 胶囊标题 | 绑定 | 预置指令 |
|---|---|---|---|
| 1 | 生成上周周报 | 技能 iteration-report | 基于当前仓库最近 7 天的提交和我提供的工单，生成迭代周报：按 本期完成 / 进行中 / 风险与阻塞 / 下期计划 分节，每条附 commit 短哈希或工单号，最后注明统计口径。 |
| 2 | 上线前检查 | 技能 release-checklist | 对比当前分支与 main 的变更，生成上线检查清单：影响面（接口/配置/数据库/依赖）、必须项与建议项、验证方法、回滚预案。高风险变更单独置顶。 |
| 3 | 写故障简报 | 技能 incident-brief | 我会把告警、日志片段和最近变更贴给你。请整理成故障简报：时间线、可疑变更、按可能性排序的假设（每个附验证方法）、建议动作、未知项。 |
| 4 | 画架构图 | 连接器 Mermaid | 根据我的描述用 Mermaid 画一张系统架构图，输出 SVG 文件并附源码。先确认组件边界与数据流方向再画。 |
| 5 | 画时序图 | 连接器 Mermaid | 把下面这个接口调用过程画成 Mermaid 时序图（包含失败分支与重试），输出 SVG 并附源码。 |
| 6 | 方案评审 | 专家 研发效能专家团 | 请研发效能专家团从 QA 与 SRE 两个角度评审我的技术方案：按 阻塞 / 建议 / 疑问 分级列出意见，每条说明理由与改进方向。 |
| 7 | 写复盘文档 | 专家 SRE 故障专家 | 根据这份故障简报生成复盘文档草稿：影响范围、时间线、根因（5 Why）、当时做对与做错的事、改进项（负责人与截止日占位）。 |
| 8 | 可编辑流程图 | 连接器 Draw.io | 用 Draw.io 把这个流程画成可编辑的流程图（.drawio 文件），并导出一份 PNG 预览。 |

**内置连接器（首页级）**：Mermaid 图表、Draw.io。

## 模块 5 · 预览调试

1. 保存后立即**导出配置 JSON**（文档原话：配置项较多，每次退出前导出），把导出文件存到 `buddy-apps/devops-buddy/export/`，并据此给 `config.json` 补官方字段映射。
2. 用后台提示的指定版本客户端打开预览链接，逐个模式各跑一条胶囊，记录到 `docs/review-feedback.md`。
3. 两段审核：创建审核 → 配置审核。创建审核通过后才配置，配置审核通过后才对终端用户可见（客户端首页左上角应用入口）。
