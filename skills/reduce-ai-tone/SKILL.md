# 降AI味

定位一句话：**AI 味多半不出在某个词上，出在文字里没有具体的人、具体的事、具体的判断。** 删套话只是第一步，还要换上作者自己的细节和立场，读者才会觉得是一个人在跟他说话。

## 何时使用

用户这样说时用本技能：

- 「这段总结 AI 味太重，帮我改得像我自己写的」
- 「读着像机器写的，全是套话，怎么去掉 AI 腔」
- 「公众号初稿一堆『值得注意的是』『总而言之』，帮我改自然点」
- 「这篇读起来空、顺、平，像在哪儿都见过」
- 「帮我看看这段话哪些是套话」

适用场景：一段中文读起来空、顺、平，像在哪儿都见过；用户说「AI味太重」「去AI腔」「改得像我写的」。本技能管写作质量。

不适用（遇到时这样处理）：

- 目的是让作业、论文或投稿躲过学校、期刊、单位对 AI 使用的规定或检测：不接，理由见最后一节；机构要求披露 AI 使用的，应如实披露。
- 要求本人独立完成的作业、考试答案、申请文书，要整篇代写：不代写，可以指出问题、示范一两句。
- 英文或其他语言的「AI 味」：本清单和脚本针对中文，一句话说明后只给通用建议（删空话、补细节、表明立场）。

## 先判断：问题在「腔」还是在「空」

动笔前先弄清四件事，答不上来就问用户，别猜：

1. **文体和场合。** 公文、论文、产品说明、公众号、朋友圈、求职信、讲话稿，各有各的规矩。体裁惯例不算 AI 味：通知末尾的「特此通知」、论文结论开头的「综上所述」、说明书里的并列条目，都该留着。
2. **读者和用途。** 谁读？读完要他做什么，批准、购买、转发，还是记住一件事？
3. **作者的声音。** 要一段作者自己写的旧文字或聊天记录，照着它的用词习惯和句子长短来改。
4. **腔还是空。** 先把套话全部划掉，看剩下什么。剩下的都是实话，是「腔」的问题，改写能解决；剩下没几句，是「空」的问题，缺的是素材，得先向作者要细节，改写救不了。

检查点：能用一句话说出「写给谁、读完要他做什么、作者平时怎么说话」，再往下走。

## AI 腔识别清单（12 条）

判断标准只有两条：**删掉它，意思少没少；换一个题目，它还成不成立。** 意思没少、换题照样成立，就是套话。清单里的词不是禁词，全文用一次「总之」没问题，问题在密度和空转。

| # | 模式 | 一眼认出 |
|---|---|---|
| 1 | 空泛开头 | 第一句放到任何题目下都成立：「在当今……的时代」「随着……的发展」 |
| 2 | 空泛总结句 | 段尾把上文换个说法再说一遍，删掉后段落什么也没少 |
| 3 | 「值得注意的是」「总而言之」类套话 | 过渡词后面的内容并不更值得注意，也没有真正在「总」什么 |
| 4 | 三段式排比 | 三个同结构短语连用，作者只能为其中一个举出实例 |
| 5 | 过度对称 | 利弊各一句，每段都是「观点、解释、举例、小结」，看不出作者站哪边 |
| 6 | 形容词堆叠 | 「非常」「极其」「令人难忘」连着用，没有一个看得见的细节 |
| 7 | 万能结尾升华 | 最后一句贴到任何文章末尾都成立：「让我们携手……」 |
| 8 | 无来源的「研究表明」 | 「研究表明」「数据显示」「专家指出」后面没有谁、哪年、多少样本 |
| 9 | 滥用破折号 | 一段里两个以上「——」，多数只是把逗号拉长了 |
| 10 | 冒号标题 | 每段开头都是加粗短语加冒号，正文像提纲 |
| 11 | 「不是……而是……」与自问自答 | 先立一个没人提过的靶子再推倒，或「为什么这么说？因为……」 |
| 12 | 大词叠保险话 | 「赋能」「抓手」「闭环」「全方位」再加「在一定程度上」 |

每一条的改写前后对照（共 12 组例句）见 [references/ai-tone-checklist.md](references/ai-tone-checklist.md)。例句里「后」的细节都假定来自作者本人，实际改写时没有素材就写【待补：……】，不许编。

## 改写流程：六步

开始前先和用户定改写强度。**轻**：只删套话、拆冒号标题，结构和措辞基本不动，适合正式文件和已定稿的材料。**中**：再加上换细节、调句长，段落顺序不动，多数情况用这一档。**重**：按作者口吻重写，可以调结构，只在作者给了足够素材时做。

1. **定读者和语气。** 在书面正式（公文、论文）、书面平实（邮件、报告、说明）、口语亲近（公众号、朋友圈、发言）三档里选一档，全篇不换档。从作者的旧文字里记下三样：常用的词、偏长句还是短句、怎么称呼读者。
2. **删套话。** 按清单逐条标出来，先删「删掉意思不少」的：开头铺垫、过渡套话、段尾总结、结尾升华。删完通读一遍，意思没少就对了。
3. **换具体细节。** 每个抽象判断后面追问一句「比如呢」，答案要落到人、时间、数量、原话、场景之一。细节只能来自作者，用下面五个问题一次问完；实在没有，就写【待补：需要一个……的例子】。
4. **让句长错落。** 长句拆开，碎句合并，一段里有长有短，段落长度也别都一样。读出声来，换气别扭的地方就是要改的地方。
5. **保留作者自己的判断。** 把「有利有弊」「辩证看待」换成作者真实的立场，允许不对称，允许偏心，允许写「我不确定」。作者没表态的地方去问他，不替他站队。
6. **回读对照。** 跑一遍下面的脚本看前后数字，再把改动对照表交给作者核对事实。数字只作参考，最后以读出声顺不顺、像不像作者本人为准。

向作者要细节的五个问题：

```
1 这件事最近一次发生是什么时候？当时具体是什么情形？
2 能给一个数吗？多少人、多长时间、多少钱、比以前多了多少？
3 有没有谁说过的原话，或者一个你记得很清楚的场景？
4 如果只能选一边，你站哪边？为什么？
5 读者读完这段，你希望他做什么？
```

## 自检脚本：套话与句长分布

`scripts/ai_tone_check.py` 只用 python3 标准库。统计六类套话的命中次数和每千字密度、句长分布（平均、中位、变异系数、相邻两句长度接近的比例）、破折号、冒号小标题、顿号三连和排比候选。它量的是表面信号，**不是 AI 检测器**：人写的文字也可能命中很多，数字低也证明不了任何事。提示里的阈值（变异系数低于 0.35、破折号每千字超过 3 处、冒号小标题 3 行以上）是经验值，只供参考。词表按自己的领域增删，脚本里的 PATTERNS 一类一行，写的是正则。

```bash
python3 scripts/ai_tone_check.py draft.txt
python3 scripts/ai_tone_check.py revised.txt
cat draft.txt | python3 scripts/ai_tone_check.py -
```

本机实测 [examples/reading-habit.md](examples/reading-habit.md) 里的前后两段：改写前套话 14 处（空泛开头 2、过渡 1、总结升华 5、无源引用 1、大词 1、对举保险 4），10 句，变异系数 0.22，另有排比候选 1 条、顿号三连 1 处；改写后套话 0 处，8 句，变异系数 0.44。按行断开的诗歌、歌词、对话记录不适合看句长统计。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（一句模板） |
|---|---|---|
| 缺关键信息（文体场合、读者、作者的声音） | 先问 1–3 项：写给谁、读完要他做什么；有没有作者自己写的旧文字；改写强度。没答的按「中」档、书面平实处理，并在开头标【待确认】 | 「先说三件事：这段写给谁看、读完希望他做什么？有没有你以前写的一段文字？改轻、中、重哪一档？」 |
| 「空」的问题：删完套话没剩几句 | 不硬改：用五个问题向作者要素材；先交一个保留骨架、缺口处写【待补】的版本 | 「删掉套话后只剩两句实话，缺的是素材。回答这五个问题，我再往里填。」 |
| 输入自相矛盾（要「轻」档却要加很多细节；要「改得像我写的」却不给任何作者素材） | 指出矛盾，给两种做法让用户选 | 「轻档只删套话、不加细节；想加细节就得用中档，还要你提供两三个具体的事。选哪个？」 |
| 超出本技能范围（非中文、要测 AI 检测分数、要整篇代写本人作业） | 说明边界：只管中文写作质量；不测检测工具；本人作业只指出问题、示范一两句 | 「检测分数我不测也不承诺，这里只帮你把文字改得具体、像你自己。」 |
| 时间紧，只要最小可用版 | 轻档：只删套话、拆冒号标题，附对照表前 5 条，不补细节 | 「先给你轻档：只删套话、拆标题，意思一字不加。要更像你，再补几个细节。」 |
| 用户坚持越界（要躲过学校或期刊的 AI 检测、要编一段经历或数据、要改掉自己的立场以外的事实） | 守住边界：不为规避规定改写；不编细节和数据；事实主张不改 | 「这个目的我不能帮：机构要求披露 AI 使用时应如实披露。如果只是想让文字更像你，我可以按你给的细节来改。」 |
| 体裁有固定格式（公文、论文摘要、合同） | 格式语和体裁要求的结构不动，只改空转的句子，一般用轻档 | 「『特此通知』『综上所述』是体裁要求，保留；我只改中间那几句空话。」 |

脚本 `scripts/ai_tone_check.py` 的退出码与报错：

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 0 | 统计完成；「提示」是经验阈值，不影响退出码 | 结合读出声的感觉判断，不追数字 |
| 1「没有输入」 | 没给文件，也没有用管道传入 | `python3 scripts/ai_tone_check.py draft.txt` |
| 1「没有正文」 | 文件是空的或只有空白 | 把正文存进文件再运行 |
| 1「参数错误」 | 多给了参数 | 一次只检查一个文件 |
| 2「找不到文件」「是目录」「不是 UTF-8 文本」 | 路径不对，或文件是其他编码 | 检查路径；用编辑器另存为 UTF-8 |
| 130 | 按了 Ctrl+C | 重新运行即可 |

## 输出契约

交付物按这个顺序，不增不减：

1. **改写强度与语气**：开头注明用的是轻、中、重哪一档，以及书面正式、书面平实、口语亲近哪一档。
2. **改写稿全文**。
3. **改动对照表**：三列——原句、改为、命中清单第几条；只列改动大的句子，最多 15 条。
4. **【待补】清单**：每条写清需要作者补什么，例如「第 2 段需要一个具体数字：改版前报销平均几天到账」；没有就写「无」。
5. **前后数字**（跑了脚本时附上）：套话次数、变异系数，改写前后各一行。
6. **不动的东西与疑似问题**：事实、数据、引文、专有名词原样保留；发现疑似错误或无出处的说法，单独列出来提醒，不自行改。

占位符规则：只有作者知道的细节写 `【待补：……】`；需要作者确认的立场、事实或按默认值处理的地方写 `【待确认：……】`；不编细节、数据、引文和经历。

交付前自检（逐条答「是」才交）：

- [ ] 开头注明了改写强度和语气档？
- [ ] 新增的细节、数字、人名全部来自作者，没有的写了【待补】？
- [ ] 事实、数据、引文、专有名词原样保留，疑似问题单独列出？
- [ ] 体裁要求的格式语没有被当成套话删掉？
- [ ] 作者的立场没有被改，没表态的地方问了作者？
- [ ] 对照表每行都标了命中清单第几条，且不超过 15 条？

## 示例

示例（内容为虚构，数字是脚本的实际输出）：

**用户**：这段总结 AI 味太重，帮我改得像我自己写的：「在当今快速发展的时代，团队协作变得越来越重要。本季度，我们以数字化为抓手，全方位提升了工作效率。值得注意的是，这一过程也存在一定的挑战。总而言之，我们要携手并进，共创美好未来。」

**助手**（先问）：三件事：这是写给谁看的？「以数字化为抓手」具体做了什么，有没有一个数？「挑战」指的是什么？

**用户**：季度总结，给部门负责人看。我们把周报从邮件改成了共享表格，每周少开一个同步会。挑战是有两个同事一开始不习惯，填得晚。

**助手**（交付）：

强度：中档（删套话、换细节、调句长），书面平实。

```
这个季度，我们把周报从邮件换成了共享表格。每周因此少开了一个同步会。
刚开始有两位同事不太习惯，表格常常填得晚，【待补：后来怎么解决的，或者现在还差在哪】。
下个季度，先定好填表截止时间。【待确认：这是不是你打算做的事】
```

| 原句 | 改为 | 命中清单 |
|---|---|---|
| 在当今快速发展的时代，团队协作变得越来越重要。 | 删掉 | 第 1 条 空泛开头 |
| 本季度，我们以数字化为抓手，全方位提升了工作效率。 | 这个季度，我们把周报从邮件换成了共享表格。每周因此少开了一个同步会。 | 第 12 条 大词 |
| 值得注意的是，这一过程也存在一定的挑战。 | 刚开始有两位同事不太习惯，表格常常填得晚。 | 第 3 条 套话 |
| 总而言之，我们要携手并进，共创美好未来。 | 下个季度，先定好填表截止时间。 | 第 7 条 万能结尾升华 |

- 【待补】：两位同事填得晚，后来怎么解决的；【待确认】：下季度要做的事是不是这一件。
- 前后数字：套话 7 处 → 0 处；变异系数 0.10 → 0.53（改写后的统计含两处待补占位，补完再跑一次）。
- 不动的东西：「两位同事」「每周少开一个同步会」照你给的写；没有编数字。

## 常见问题（FAQ）

**Q：改完能保证过 AI 检测吗？**
A：不承诺，也不去测任何检测工具；这类分数不是写作质量的标准。机构要求披露 AI 使用时，应如实披露。

**Q：我只想删掉套话，不想大改，行吗？**
A：选「轻」档：只删套话、拆冒号标题，结构和措辞基本不动。

**Q：我没有具体的细节可以补怎么办？**
A：先用五个问题找一找；实在没有，就留【待补】，或者把那句空泛的判断删掉，不编。

**Q：脚本数字低，就说明像人写的吗？**
A：不说明。脚本量的是表面信号，最后以读出声顺不顺、像不像作者本人为准。

**Q：论文、公文也能改吗？**
A：能改空转的句子，但体裁要求的格式语和结构保留，一般用轻档；学术规范以导师、期刊编辑部或单位的书面规定为准。

**Q：和普通的润色有什么区别？**
A：润色多是换词顺句；这里先删掉删了意思也不少的套话，再换上作者自己的细节和立场。只换同义词，AI 味还在。

**Q：能直接帮我改整篇作业吗？**
A：要求本人独立完成的作业不代写；可以指出哪些句子是套话、示范改一两句，整篇由你自己完成。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 拿编造的细节换掉空话 | 这是最严重的错：文字像人写的了，内容却是假的 | 「后」里的数字、人名、经历必须来自作者，没有就留【待补】 |
| 只换同义词：「总而言之」改成「总的来看」，「赋能」改成「助力」 | 换汤不换药，空转还在 | 先问删掉它意思少没少，少不了就整句删 |
| 为了像人故意加错别字、口头禅、表情和网络梗 | 这不是降 AI 味，是降质量 | 补具体的人、事、判断 |
| 矫枉过正：句子全砍成短句，或把正式文体改成口水话 | 成了另一种单调，也不合场合 | 长短错落；按定好的语气档改，全篇不换档 |
| 删掉体裁要求的格式语 | 公文结构语、论文摘要的固定格式、合同条款的措辞是体裁要求 | 体裁惯例一律保留，只改空转的句子 |
| 改掉作者的立场 | 把「我倾向 A」改成改写者觉得对的 B，或把「我不确定」改得斩钉截铁 | 立场以作者为准，没表态的地方去问 |
| 把「AI 检测分数」当目标 | 分数不是写作质量的标准 | 改写只对读者负责 |

## 边界与不做什么

- 本技能面向写作质量。**不用于规避学校、期刊或单位对 AI 使用的规定**；机构要求披露 AI 使用时，应如实披露，改得再像人写的，也改变不了用过 AI 这件事。用户明说目的是让作业、论文或投稿躲过 AI 检测、瞒过老师或编辑时，不提供改写，说明原因即可。
- 不代写要求本人独立完成的作业、考试答案和申请文书，可以指出问题、示范一两句，整篇要作者自己完成。
- 不承诺、也不去测试任何「AI 检测」工具的结果；脚本数字只反映文风信号，证明不了文字是谁写的。
- 不编细节、数据、引文和经历，不改原文的事实主张；要改立场，先问作者。
- 学术诚信、署名、AI 使用披露的具体要求，以任课老师、导师、期刊编辑部或单位的书面规定为准，拿不准就去问他们。
