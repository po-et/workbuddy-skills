# 实习报告

定位一句话：**实习报告要让老师看到三件事——你在什么岗位、实际做了什么（有证据）、学到了什么（说得清）。所有事实只来自你自己的真实记录。**

## 何时使用

- 「帮我写实习报告，学校要求 5000 字」
- 「实习总结怎么写才不空」「我只有零散的工作记录」
- 「实习周记模板」「要交 12 篇周记」
- 「鉴定表里的自我鉴定怎么写」
- 「实习答辩老师会问什么」

不适用：
- 编造没做过的实习、虚构经历或数据 → 不做（见边界），改为帮用户把真实的小事写深。
- 简历里的实习经历 → 可简答：用第 3 步的 STAR 压成一行（动词 + 做了什么 + 结果）；完整简历另找简历类技能。
- 毕业论文、课程论文 → 不在本技能范围。

## 第 1 步：先确认学校要求

最多问三件事：
1. 学校或学院有没有下发模板、评分标准？有模板一律以模板为准。
2. 字数、截止时间、提交形式，要不要附周记或日志、几篇，要不要答辩？
3. 手上有哪些原始记录：周记、日报、自己的任务清单、交付物、自己统计过的数字？

没有模板时，默认按下面的四段式、4000 字左右起草，并标 [待确认：字数与格式]。

## 第 2 步：学校常见结构（四段式）

| 部分 | 写什么 | 建议占比 |
|---|---|---|
| 一、实习单位与岗位 | 单位的公开概况 3–5 句；所在部门职能；岗位、职责、实习起止、指导人（按学校要求写） | 10–15% |
| 二、实习内容 | 按任务模块组织，不按日期记流水账；2–3 个核心任务用 STAR 展开，其余一两句带过 | 40–50% |
| 三、收获与反思 | 专业知识怎么用上了；能力上的具体变化（配例子）；自己的不足 | 20–25% |
| 四、问题与建议 | 对自己（下一步补什么）、对课程（可以加什么）、对实习安排（建设性、对事不对人） | 10–15% |

封面、目录、前言、结语按学校模板加；占比是建议值。逐段写法与句式：[references/four-part-template.md](references/four-part-template.md)。

## 第 3 步：把日常记录写成有分量的段落（STAR + 数据）

1. 把记录按"任务模块"归类，而不是按日期排。
2. 挑 2–3 件前后有变化的事：你接手时什么样、你做了什么、之后变成什么样。
3. 套 STAR：情境（S）一句 → 任务（T）一句 → 行动（A）2–4 句，写具体方法、工具、遇到的困难 → 结果（R）带数字或可验证的产出，再加一句反思。
4. 数据规则：只写自己能核实的数（处理了多少条、做了几版、用时从多少降到多少）；单位的经营数据不写，用相对说法代替；记不清的不编，写"约"并说得出估算依据，或者改写交付物。
5. 每段最后一句连回专业：用到了哪门课的什么知识，或发现课上没学到什么。

改写示例（虚构）：
- 记录原文：「周一 整理用户反馈表；周二 继续整理；周三 和组长对分类」
- 改写后：「第 3 周，组里积压了 600 多条未分类的用户反馈，周五例会前需要看到问题分布（S）。我负责分类并做成汇总表（T）。我先抽 50 条试分，和组长对齐出 8 个类别，再用表格筛选和计数批量归类，拿不准的单独标出，每天下班前和组长过一遍（A）。周四交付汇总表，例会据此定下了下一版优先修复的 3 个问题，这套分类后来沿用到每周的反馈整理（R）。这件事让我体会到，市场调研课上"先定口径再统计"在实际工作里最费时间、也最关键。」

## 第 4 步：周记与日志

周记每篇四栏：本周做了什么（3–5 条，动词开头，带交付物）→ 遇到的问题与解决 → 学到的 / 想到的 → 下周计划。日志一行一条：日期 | 做了什么 | 产出 | 用时。周记是报告的素材库：每周写实写细，最后写报告只需挑选。补写周记只能依据真实痕迹（自己的聊天、邮件、日历、文件修改时间），时间线要和实习起止一致。模板、补写回忆清单与填好的示例：[references/weekly-log-template.md](references/weekly-log-template.md)。

## 第 5 步：保密红线

- 不写：单位未公开的经营数据（营收、成本、用户量、转化率等）；客户和用户信息（姓名、电话、订单、聊天内容）；未公开的项目名、产品计划、代码、内部系统截图和文档原文；同事的个人信息。
- 可以写：单位公开信息；自己的工作方法和流程（抽象后）；脱敏后的相对数据；自己的工作量（处理了多少条）。
- 签过保密协议的以协议为准；拿不准的段落发给单位指导人确认能不能写；截图不放或打码。

提交前自查（字数、四段结构、手机号 / 身份证号 / 邮箱 / 金额 / 经营数据字样、自定义敏感词、没填完的 [待补]），直接读 .docx：

```bash
python3 scripts/report_check.py 实习报告.docx --target 5000 --words "客户甲,项目代号X"
```

输出里的号码会打码；"疑似"不等于一定敏感，逐条人工确认。

## 第 6 步：答辩与鉴定表

- 鉴定表"自我鉴定"：实习概况一句 → 主要工作与成果 2–3 句（带事实）→ 收获与不足 1–2 句 → 今后打算一句；用事实代替"表现优秀"这类形容词。
- 单位意见栏由单位填写；指导人让你起草时，只写可核实的事实（岗位、时间、完成的工作），评价用语留给对方改定、签字。
- 答辩高频五问：两分钟介绍实习；最有价值的一件事（数据怎么来的）；专业知识用上了什么；最大的困难与解决；对课程或实习安排的建议。准备 3 个 STAR 故事的口头版，每个 1 分钟。

完整问题清单、回答思路、自我鉴定模板：[references/defense-and-appraisal.md](references/defense-and-appraisal.md)。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话 |
|---|---|---|
| 没有学校模板、不知道字数 | 按四段式、4000 字左右起草，标 [待确认：字数与格式] | 「学校有模板吗？没有的话我先按常见四段式、4000 字左右写，拿到模板再对齐。」 |
| 记录太少、记不清做了什么 | 按周回忆清单引导，翻自己的聊天、邮件、日历；仍然少就写少而真 | 「我们按周回忆：第一周你交出去的第一样东西是什么？」 |
| 信息自相矛盾 | 指出矛盾，给两种理解 | 「实习 4 周却要交 12 篇周记：是按天交日志，还是篇数要求另有规定？」 |
| 要求编造经历、数据或单位评价 | 拒绝，给替代：把真实的事写深 | 「没做过的我不能写；你真实做过的反馈整理，用 STAR 能写成很有分量的一段。」 |
| 记录里有客户信息或内部数据 | 指出位置，给脱敏写法 | 「第 2 段的客户名和月销售额不能写，改成"某客户""销售额环比明显上升"。」 |
| 时间紧，今晚就要交 | 最小可用版：四段骨架 + 2 个 STAR 段 + 收获 3 条 + 建议 2 条，约 2000 字，再附扩写清单 | 「先保证交得出去：骨架加两个核心段落，约两千字，明天按清单扩到要求字数。」 |
| 超出范围（毕业论文、简历全文、单位意见） | 说明边界并转交；单位意见只给事实清单 | 「单位意见要单位填；我可以整理一份事实清单给指导人参考。」 |

脚本退出码：

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 1「--target 应在…」 | 字数目标写错 | 写学校要求的数字，如 5000 |
| 1「没有读到文字」 | 文件是扫描件、图片或空文件 | 用可编辑的原稿 |
| 2「找不到文件」「不支持老式 .doc」「不是有效的 .docx」 | 路径错、.doc 或 WPS 格式 | 检查路径；另存为 .docx 或 .txt |
| 2「编码认不出来」 | 文本文件编码特殊 | 另存为 UTF-8 的 .txt |
| 130 | 手动中断 | 重跑即可（脚本只读，不改文件） |

## 输出契约

交付物固定按这个顺序：
1. 信息确认表：学校要求（模板、字数、截止、周记篇数、答辩）、单位与岗位、实习起止、原始记录清单。
2. 报告正文：封面信息（按学校模板）→ 一、实习单位与岗位 → 二、实习内容 → 三、收获与反思 → 四、问题与建议 → 结语。
3. 保密自查结果：列出删掉或脱敏的地方。
4. 附件（按需）：周记或日志、自我鉴定、答辩准备卡。
5. 待确认清单。

占位符：要用户补的写 [待补：…]（如 [待补：单位指导人姓名]）；按默认值先写、需核实的写 [待确认：…]。

交付前自检（逐条答是/否）：
- [ ] 每个具体事实都能在用户给的记录里找到出处，没有编造？
- [ ] 至少 2 段用了 STAR，结果有数字或可验证的产出？
- [ ] 没有客户信息、单位未公开数据、同事个人信息？
- [ ] 四个部分齐全，字数在要求的 ±10% 内（或已标 [待确认]）？
- [ ] 虚构示例里的内容没有混进用户的报告？
- [ ] 每个 [待补]、[待确认] 都进了待确认清单？

## 示例

示例（虚构）：

> 用户：帮我把这几条记录写成实习报告里的一段：第 3 周整理用户反馈 600 多条；和组长定了分类；做了汇总表，周五例会用了。
>
> 助手：两个问题：① 600 多条是你自己导出、数过的吗？② 例会根据这张表定了什么，你知道吗？
>
> 用户：是我导出的条数。例会定了下一版先修 3 个问题。

交付物：
1. 正文段落：即第 3 步的"改写后"段落（S-T-A-R 四句 + 连回专业的一句）。
2. 第 3 周周记（节选）：本周做了什么——完成 600 多条反馈的分类与汇总表，周四交付；问题与解决——类别边界模糊，先抽 50 条试分再定 8 类；学到的——先定口径再统计；下周计划——把分类表做成每周可复用的模板。
3. 保密自查：条数是本人工作量，可写；反馈原文、用户昵称、产品名未引用。
4. 待确认：[待确认：学校是否要求写单位全称]。

## 常见问题（FAQ）

- **实习就是打杂，怎么写出分量？** 挑一件你改进了做法的小事（比如把重复整理做成模板），写清前后变化；其余杂事按模块归类，一句带过。
- **能不能帮我编一段经历或数据？** 不能。编的内容经不起答辩追问和单位核实；可以帮你把真实经历写深。
- **单位让我自己写鉴定意见怎么办？** 起草一份只列事实的草稿（岗位、时间、完成的工作），评价交给指导人改定并签字。
- **字数不够怎么办？** 不注水：多展开一个 STAR 段，给每条收获配一个例子，在建议里写一条对课程的具体建议。
- **能用单位的数据和截图吗？** 公开的可以，内部的不行；截图不放或打码；签过保密协议的以协议为准。
- **实习报告、实习总结、周记有什么区别？** 周记是每周的原始记录，总结偏回顾与收获，报告要单位岗位、内容、收获、建议四块齐全；具体叫法以学校为准。
- **学校会查重吗？** 以学校要求为准；用自己的记录写、不抄范文，重复率自然低。

## 常见错误（反模式）

- 按日期记流水账 → 看不出能力 → 按任务模块组织，核心任务用 STAR。
- 单位介绍抄官网一大段 → 占字数、没价值，还可能写进未公开信息 → 3–5 句公开概况加部门职能。
- 收获只写"提高了沟通能力" → 没有证据 → 一件事加前后变化。
- 写进客户名、内部数据、内部截图 → 有泄密风险 → 脱敏或不写，跑一遍自查脚本。
- 套网上范文 → 和实际对不上，答辩一问就露馅 → 只用自己的记录。
- 问题与建议写成吐槽 → 显得不专业 → 对事不对人，提可执行的建议。
- 答辩背稿 → 被追问就卡住 → 准备 3 个 STAR 故事的口头版。

## 边界与不做什么

- 不编造实习经历、工作内容、数据或单位评价。
- 不伪造、不代签单位盖章、签名和鉴定意见；单位意见栏由单位填写。
- 不写单位保密信息；保密协议和单位要求优先于学校的字数要求。
- 格式、字数、提交方式以学校和学院的要求为准。
- 不代写毕业论文、课程论文。
