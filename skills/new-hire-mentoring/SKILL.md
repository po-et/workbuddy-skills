# 新人带教

定位一句话：**带教的产出不是「新人听过了」，而是「新人独立做成了」——每一步都要有能验收的任务，和一次具体的反馈。**

## 何时使用

在对话里直接说你的带教情况就行，不用记命令；节点日期脚本由助手在需要时运行，也可以单独在命令行调用。典型说法：

- 「组里来了个应届生，第一次带新人怎么带」
- 「帮我排一下新人前三个月的计划」
- 「新人上手慢、总返工，我该怎么给反馈」
- 「每周一对一聊什么」
- 「快转正了，带教评价的材料怎么整理」

适用：第一次当带教人；新人入职前要排前三个月的计划；新人上手慢、总返工，要调方法或给反馈；要写带教记录、为转正评价准备材料时。转正标准和考核表以本单位制度为准。

不适用（遇到时这样处理）：

- 能不能转正、要不要调岗辞退、劳动争议 → 由单位按制度决定，找人事或专业人士；这里只帮整理证据。
- 新人明显压力大、情绪或健康出状况 → 先关心、减量，建议对方寻求专业帮助，不做诊断。
- 骚扰、歧视等问题 → 走公司正式渠道，不在带教里私了。

## 先判断：新人是谁、你能投入多少

- **新人类型定重点**：应届生缺工作方法，先教怎么拆任务、怎么汇报进度；转行的缺领域知识，先给术语表和业务地图；同行跳槽的缺本团队的规矩和人脉，先讲约定俗成的做法、引荐关键的人。
- **投入要够**：每周一次三十分钟一对一，每天留一个十分钟答疑窗口。做不到就先跟上级说，减你的工作量或换人带。
- **标准先拿到**：岗位说明和转正考核标准要书面的，九十天目标从这里倒推。
- **入职前备好**：设备和权限按公司流程提前申请；第一周日程；必读资料三到五份，不是五十份；一个第一天就能动手的练手任务。

```
第一天  上午：欢迎，介绍团队和常打交道的人，讲清前两周安排；中午一起吃饭
        下午：环境和权限跑通，练手任务开个头
第一周  每天下班前碰十分钟：今天做了什么、明天做什么、卡在哪
        约定规矩：卡住超过三十分钟就来问，不用攒着
        周末前第一次正式一对一：对齐 30 天目标，问「这周和你预想的有什么不一样」
```

## 30/60/90 天目标与任务阶梯

```
阶段     关键词  可验收的产出（按岗位替换）                      带教人做什么
1–30天   会用    认识协作的关键人；独立跑通一个标准流程；          示范→陪做→检查，每天答疑
                 完成两三个练手任务并经复核
31–60天  能做    独立负责一类常规任务；返工比第一个月明显少；      从陪做退到复核，先让新人讲方案再动手
                 能说清本组的上下游
61–90天  能扛    独立完成一个中等任务，从接需求到交付；            只在方案和交付前检查，准备转正材料
                 能给下一位新人讲清一个流程
```

每条目标写成「到[日期]，能[做什么]，以[什么产出]为准」，不写「熟悉业务」「融入团队」。节点日期不用手算，入职日算第 1 天；脚本只用 python3 标准库，落在周末的会给出「挪到前一个工作日」的建议：

```bash
python3 scripts/mentor_dates.py 2026-10-08 2026-10-09                    # 入职日、第一次正式一对一
python3 scripts/mentor_dates.py 2026-10-08 2026-10-09 --out 带教日程.md   # 另存为文件
```

第一个日期换成入职日，第二个换成第一次正式一对一的日期；之后每七天一次，共十三次。节点落在周末或节假日，就挪到前一个工作日（脚本只认周末，法定节假日和调休以官方通知为准）。

任务由易到难：难度有四个旋钮——范围（一小块→一整件）、模糊度（给步骤→给目标→只给问题）、协作面（只找你→对接一个人→对接多方）、风险（草稿或测试→可撤回的正式工作→对外交付）。**每次只拧一个。**常用阶梯：照着做（复现一个有标准答案的旧任务）→改着做（在现成成果上改一处）→独立做小块（给目标不给步骤，事后复核）→独立做完整（从接需求到交付）。同一级连续两次一次通过再升级；连续两次返工，就退回上一级、补一次示范。

新人上手慢，先分清卡在哪一类，再对症：

- 不知道要什么（标准不清）：给完成标准和一份好样例。
- 知道要什么但不会做（缺方法）：示范一遍，再陪做一遍。
- 会做但总出错（缺习惯）：给一张交付前自查清单。
- 会做但不敢交（缺信心）：把任务切小，多给小步反馈。
- 会做但没时间（被打断太多）：帮他挡掉杂事，排好优先级。

同一类问题连续四周没有进展，和上级一起评估，按制度处理。

## 每周一对一与反馈句式

```
一对一（三十分钟，新人主讲）
1 新人说（十分钟）：这周完成了什么、卡在哪、哪件事比预期多花了时间
2 带教人问（十分钟）：下周最难的是哪件？有没有不好意思问的问题？这周谁帮了你？
3 反馈（五分钟）：一条认可、一条改进，都用下面的句式
4 下周约定（五分钟）：一到三件任务、完成标准、检查时间；带教人答应的事也写上
```

反馈句式：**具体行为＋影响＋建议**。

```
句式  [什么时候]你[做了什么]，[带来了什么影响]。下次可以[具体怎么做]。
改进  周二的周报你把三个风险都放在最后一段，李经理没看到第二个，差点误了截止时间。
      下次把风险放第一段，每条写上负责人和日期。
认可  评审前你先把接口文档发给了测试同学，他们提前发现两个问题，评审省了半小时。
      这个做法以后保持。
别说  「你太粗心了」「态度要端正」「这都不会？」——只有评价没有行为，新人不知道改什么。
```

认可不少于改进；批评私下说，认可可以当众说。反馈趁热，当天或第二天就说，攒到一对一细节就模糊了。一对一不取消，要改期也只改一次。

## 带教记录

每周一条，当场写，一次五分钟；写转正评价时从记录里摘证据，不凭印象。模板、填好的样例和「按转正标准摘证据」的做法见 [references/mentoring-log.md](references/mentoring-log.md)。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（模板） |
|---|---|---|
| 缺关键信息（岗位、入职日、转正标准、投入时间、练手任务） | 一次最多问 3 个：岗位与背景、入职日期、有没有书面转正标准；其余先按默认（每周 30 分钟一对一、每天 10 分钟答疑、练手任务用「复现一个有标准答案的旧任务」）排，标 [待确认] | 「先问三件：新人什么岗位、什么背景？哪天入职？转正标准有书面的吗？其余我先按默认排，标了 [待确认]。」 |
| 输入自相矛盾（每周只能投入 30 分钟，却要每天陪做；入职两周就要「独立负责」） | 指出冲突，给两种调整方案 | 「每周 30 分钟排不下"每天陪做"。二选一：跟上级申请减你的工作量，或改成每天 10 分钟答疑＋每周一次示范。」 |
| 反馈素材只有评价没有事实（「他太粗心」） | 不编新人的行为；追问一件具体的事：什么时候、做了什么、带来什么影响 | 「"粗心"他没法改。最近一次是哪件事、哪天、错在哪、造成了什么？给我一件，我按句式改写。」 |
| 超出本技能范围（转正结论、劳动争议、心理健康、骚扰歧视） | 不下结论；只整理证据；转人事、专业人士或公司正式渠道 | 「能不能转正由单位按制度定。我可以把带教记录里的证据按转正标准逐条整理出来。」 |
| 时间紧，只要最小可用版 | 最小版三样：第一周日程、30 天目标三条（可验收）、一对一四段提纲；60/90 天目标和记录模板标 [待补]，下周再补 | 「最小版：第一周怎么过、30 天三个目标、一对一提纲。60/90 天下周再排。」 |
| 用户坚持越界（替我写「不予转正」结论、给新人贴心理标签、编几条新人的问题） | 守住边界，给能做的替代 | 「结论由单位按制度下，我也不编新人的行为；可以把你记录的事实按转正标准整理成证据清单。」 |

## 输出契约

先问：新人岗位与背景、入职日期、转正标准、你每周能投入的时间、团队手头能拿来练手的真实任务（一次最多三个问题）。交付物按这个顺序：

1. **节点日期表**：13 次一对一和第 30/60/90 天，用脚本算，周末和节假日已标出。
2. **30/60/90 目标表**：每条「到[日期]，能[做什么]，以[什么产出]为准」。
3. **前四周任务阶梯**：每周一到三件，注明这一级拧的是哪个难度旋钮。
4. **一对一提纲**：四段式，写上第一次的具体问题。
5. **反馈**：按「具体行为＋影响＋建议」改写好的两三条；只改写用户给的事实，没有事实的写 [待补]。
6. **带教记录模板**与**待确认清单**。

不下「能不能转正」的结论，只帮整理证据。

占位符规则：`[待补：转正标准原文]` 用于只有用户或单位能提供的信息，不编；`[待确认：每周投入 30 分钟]` 用于我按默认先排的内容。

交付前自检（逐条答是/否，有「否」先改再交）：

- [ ] 每条目标都能验收，没有「熟悉业务」「融入团队」这类说法？
- [ ] 节点日期用脚本算过，周末已挪到前一个工作日，节假日注明以官方通知为准？
- [ ] 任务阶梯每次只拧一个难度旋钮？
- [ ] 反馈都是「具体行为＋影响＋建议」，而且只用了用户给的事实？
- [ ] 没有下「能不能转正」的结论？
- [ ] 所有 [待补]、[待确认] 都列进了待确认清单？

## 示例

**示例（虚构场景）**：用户说「新人上手慢怎么办，交代的事总要返工，我该怎么给反馈」。

助手先问（一次三个）：① 最近一次返工是哪件事、错在哪？② 新人入职多久、什么背景？③ 交代任务时给过完成标准或样例吗？

用户补充：「应届生，入职三周。让他整理周报数据，两次都把上周的数据复制错了行，李经理发现后我们重做了；我交代时只是口头说了一下，没给样例。」

最终交付：

```text
卡点判断：会做但总出错（缺习惯）＋ 不知道要什么（标准不清）——交代时没有完成标准和样例。

对症做法：
1 给完成标准和一份好样例：把上周正确的周报发他，标出数据来源和三个核对点。
2 给一张交付前自查清单：□ 数据日期是本周 □ 行和表头对得上 □ 和上周比有没有异常跳变
3 接下来两周你先复核再发给李经理；连续两次一次通过，就退回只抽查。

反馈（具体行为＋影响＋建议）：
改进  这两周整理周报数据时，你两次把上周的数据复制错了行，李经理发现后我们又重做了一遍。
      下次交之前按这三条自查清单过一遍，先发我复核，再给李经理。
认可  [待补：这两周他做得好的一件具体的事]——认可不少于改进，给我一件，我来改写。

下一次一对一：先问他「你觉得这两次出错卡在哪」，再给上面的改进反馈；约定下周周报先发你复核。

待确认清单：认可素材 1 条 [待补]。
```

**从这个示例提炼的最佳实践**：先分清卡在哪一类再对症；反馈只用用户给的事实，缺认可素材就标 [待补] 去问，不编；改进一定配一个可执行的动作（自查清单、先复核）；用「连续两次一次通过」作为退出复核的标准。

更多示例：[examples/graduate-90-days.md](examples/graduate-90-days.md)（应届生前三个月：节点日期、30/60/90 目标、四周阶梯、一对一提纲的全套交付）。

## 常见问题（FAQ）

**Q：每周真的抽不出 30 分钟怎么办？**
A：先跟上级说，减你的工作量或换人带。投入不够时带教效果一定打折，这不是新人的问题。

**Q：新人不敢问问题怎么办？**
A：第一周就约定「卡住超过三十分钟就来问」，每天留十分钟答疑窗口；一对一里专门问一句「有没有不好意思问的问题」。

**Q：新人是同行跳槽来的，资历比我还深，怎么带？**
A：重点换成本团队的规矩和人脉：讲约定俗成的做法，引荐关键的人；任务阶梯可以从高一级起步。

**Q：反馈说重了，怕打击积极性？**
A：用「具体行为＋影响＋建议」只讲事不讲人；认可不少于改进；批评私下说，认可可以当众说。

**Q：转正评价怎么写？**
A：从带教记录里按转正标准逐条摘证据，写清「到哪天、做成了什么、以什么产出为准」；不凭印象，结论由单位按制度下。

**Q：同一个问题一直不改怎么办？**
A：先按五类卡点重新判断、换对症的办法；同一类问题连续四周没有进展，和上级一起评估，按制度处理。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 放养：丢一堆文档说「先看看」，两周没人管 | 新人不敢问，也不知道做得对不对 | 第一天就给练手任务，一对一排进日历 |
| 代做：新人一卡住你就接过来自己做 | 你越来越累，新人一直学不会 | 先问「你打算怎么做」，让新人动手，你只指下一步；实在要示范，做完让新人再独立做一遍 |
| 只批评：只在出错时出现 | 新人只记得挨骂，不知道什么是做对了 | 每次一对一至少一条具体认可；出错复盘只讲事、讲流程，不讲人 |
| 信息轰炸：第一周塞几十份资料 | 看不完也记不住，反而更焦虑 | 必读资料三到五份，其余用到时再给 |
| 模糊标准：只说「做好一点」 | 新人不知道「好」是什么样 | 给完成标准和一份好样例 |
| 一次拧好几个难度旋钮 | 返工了也分不清是哪一项太难 | 每次只拧一个；连续两次返工就退回上一级 |
| 攒到一对一才反馈 | 细节已经模糊，新人对不上号 | 当天或第二天就说 |
| 凭印象写转正评价 | 没有证据，容易失真、不公平 | 从带教记录里按标准摘证据 |
| 一对一说取消就取消 | 新人觉得不被重视，问题越积越多 | 一对一不取消，要改期也只改一次 |

## 边界与不做什么

- 转正、调岗、辞退由单位按制度决定；有劳动争议找人事或专业人士。
- 新人明显压力大、情绪或健康出状况：先关心、减量，建议对方寻求专业帮助；需要调整安排的，征得本人同意后找上级或 HR 按制度处理，不做诊断。
- 遇到骚扰、歧视等问题，走公司正式渠道，不在带教里私了。
