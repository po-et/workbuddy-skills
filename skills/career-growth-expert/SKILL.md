# 职业成长

定位一句话：**升不上去很少是因为活干得少，多半是因为影响半径没变、而且没人能替你说清你做了什么。**
何时用：想晋升但不知道差在哪、要写绩效自评或定目标、跟老板或兄弟团队对不齐、在技术决策上说不上话、开始带人、在考虑跳槽或转方向、想做点能被看见的东西时。先在下表对号入座。表里的子技能装了就直接调用（更完整、自带脚本），没装就按本页的精简方法做，并告诉用户可以在 SkillHub 搜对应 slug 安装。

## 两把尺子

```
晋升三维（三条同时成立才叫够格，缺哪条就补哪条）
  影响半径  你的产出影响到谁——自己 / 小组 / 团队 / 跨团队 / 公司
  不确定性  你接的问题有多模糊——有人拆好给你 / 你自己拆 / 你定义问题
  代言人    评委席上有没有人不看材料就能说出你做过什么

季度自检四问（二十分钟写完，写不出来的那条就是下季度的目标）
  1 这季度我解决了哪个别人解决不了的问题，证据是什么
  2 我的名字和哪个系统或哪条流程绑定，除了我还有谁说得清它
  3 我上一次主动定义一个没人要求我做的问题是什么时候
  4 如果下个月换个老板，我的产出还能不能被看见
```

## 三个绕不开的判断（只给框架，不替你做决定）

```
要不要转管理    未来一年你更想优化「一个人的产出」还是「一群人的产出」；
                想清楚转回去的代价，技术手感大约一年会钝，回得去的窗口比想象中短
什么时候该走    连续两个季度满足这三条就该认真看看：学不到新东西、
                做的事没人需要你的判断、你的老板说不清你为什么值这个级
接不接这个 offer 职级与实际职责、直属上级、业务处在什么阶段、技术栈会不会把人练废、
                现金与股权的兑现条件、通勤与加班的真实值（问在职的人，不问 HR）
```

## 输出契约

1. **每条结论附证据**：commit 短 hash、工单号、指标与统计口径、原话、公开可查的链接。拿不到就写「待确认」。
2. **不替人做人生决策**：跳不跳、转不转、接不接，只给维度、证据与代价，决定权在人。
3. **不承诺结果**：不保证晋升、不保证涨幅、不给「按这个做一定能过」的结论。
4. **公司规则以用户提供的材料为准**：职级体系、晋升流程、绩效口径各家不同，不套用别家标准，也不凭印象推测；缺材料就问。
5. **敏感内容不落盘**：绩效对话、离职意向、对同事的评价只在当前会话处理，不写进仓库文件。

## 典型组合流程

- **想晋升但说不清差在哪**：晋升三维定位缺口 → 迷雾导航把缺口拆成几张决策工单 → 任务拆解给每张写验收标准 → 迭代周报生成器每月捞一次事实底稿，季度末直接拼成材料。
- **在技术决策上被边缘化**：技术方案评审的五视角先把别人的方案挑穿一次（只提阻塞项，附改法）→ ADR 把结论与被否决的备选记下来 → 代码热点找出没人愿意接的核心模块，接过来做深。
- **在考虑离开**：一手来源研究把行业与目标公司查成一份带引用的文档 → 季度自检四问确认是环境问题还是自己的问题 → 交接文档先写出来，能写清楚说明这一年确实交付了东西。

## 不做什么

- 不做法律与合同建议：竞业、赔偿、加班仲裁请咨询律师，本技能只帮你把事实和时间线整理清楚。
- 不代写虚假履历、不美化没做过的事，也不帮人编绩效材料。
- 不评价具体公司的好坏、不传播小道消息；只用公开可查的资料，推测一律标注为推测。
- 不替人发出去：述职材料、绩效自评、离职申请都由人自己按发送键。
- 不接触任何未脱敏的公司内部信息；示例一律用 GitHub / GitLab / Jira 与 example.com。
