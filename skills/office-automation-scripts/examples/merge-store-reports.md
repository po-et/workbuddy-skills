# 示例：合并门店报表，遇到表头不一致的文件

> 以下为示例。门店名、金额为虚构；脚本输出是在测试文件夹里实际运行 `scripts/merge_csv.py` 的结果，只把绝对路径截短成 `…/`。

## 1. 用户提问

> 每周一要把各门店发来的销售表合成一张给财务，现在 4 家店，年底会到 20 家。能不能自动化？

## 2. 助手澄清（只问三个）

1. 每次合并大概花多久？
2. 门店发来的是 CSV 还是 xlsx？表头都一样吗？能贴一个表头吗？
3. 以后谁维护？你的电脑能运行 Python 吗？

用户回答：每次 40 分钟；都是 CSV，表头是「门店,日期,品类,销售额」；我自己维护，电脑能跑 Python。

## 3. 助手交付

```text
一、算账
  每周耗时 = 40 分钟 × 1 次 = 40 分钟
  搭建 3 小时 + 一年维护 1 小时 = 240 分钟 [待确认：维护耗时为估计值]
  每周省下 = 40 − 5（跑完核对）= 35 分钟
  回本 = 240 ÷ 35 ≈ 7 周 → 结论：做（门店增加到 20 家后，每周省得更多）
二、选层：第 3 层 Python 脚本。数据分在多个文件、步骤固定、你自己维护且能跑 Python。
三、方案：python3 scripts/merge_csv.py 门店报表 --out 合并结果.csv
四、运行：门店发来的 CSV 全放进「门店报表」文件夹，在它的上一级目录运行上面的命令
    核对：屏幕上每个文件的行数相加 = 「共 N 行」；再抽 3 行和原表对
    撤回：脚本只新建「合并结果.csv」，不改任何原文件，删掉结果即可
五、待确认清单：维护耗时 [待确认]；「门店报表」文件夹的实际位置 [待补]
```

## 4. 第一次运行：有一个文件被跳过

用户运行后贴回的输出：

```text
合并 01-一店.csv                      3 行  UTF-8
合并 02-二店.csv                      2 行  UTF-8
合并 03-三店.csv                      2 行  GBK
跳过 04-四店.csv                 表头不同（少了 销售额；多了 销售金额）

共 7 行，来自 3 个文件，跳过 1 个。结果：…/合并结果.csv
核对：上面各文件行数相加应等于 7；再随机抽 3 行和原表对一下。
```

助手的回复：

> 合并成功了 3 个文件，四店被跳过：它的最后一列叫「销售金额」，其他店叫「销售额」。三店的文件是 GBK 编码，脚本已自动识别，不用处理。
> 修正办法二选一：① 请四店以后按统一表头导出（推荐，从源头解决）；② 这次先把 04-四店.csv 第一行的「销售金额」改成「销售额」，再重跑同一条命令。结果文件会被整体替换，不会重复追加。

## 5. 改完表头后重跑

```text
合并 01-一店.csv                      3 行  UTF-8
合并 02-二店.csv                      2 行  UTF-8
合并 03-三店.csv                      2 行  GBK
合并 04-四店.csv                      1 行  UTF-8

共 8 行，来自 4 个文件，跳过 0 个。结果：…/合并结果.csv
核对：上面各文件行数相加应等于 8；再随机抽 3 行和原表对一下。
```

合并结果（`合并结果.csv`，UTF-8 带 BOM，Excel 直接打开不乱码）：

```text
门店,日期,品类,销售额,来源文件
一店,2026-09-21,饮品,1260,01-一店.csv
一店,2026-09-21,烘焙,830,01-一店.csv
一店,2026-09-22,饮品,1105,01-一店.csv
二店,2026-09-21,饮品,990,02-二店.csv
二店,2026-09-22,饮品,1020,02-二店.csv
三店,2026-09-21,烘焙,640,03-三店.csv
三店,2026-09-22,烘焙,700,03-三店.csv
四店,2026-09-21,饮品,880,04-四店.csv
```

核对：3 + 2 + 2 + 1 = 8，与「共 8 行」一致。

## 6. 这个示例说明了什么

- 表头不一致时脚本不会硬合并，而是跳过并说清「少了什么、多了什么」，由用户决定怎么改。
- 编码不同（UTF-8 / GBK）混在一起也能合并，每个文件用了哪种编码都打印出来，便于追查。
- 重跑是安全的：输出先写临时文件再整体替换，本次的输出文件也不会被当成输入再合并一次。
