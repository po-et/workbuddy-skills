# 上新文案

定位一句话：**新品文案卖的不是参数，而是「谁在什么时候用它解决了什么、用完是什么感觉」——每个卖点都从功能走到场景、再走到情绪，每一步都要有凭据。**

## 何时使用

用户这样说时用本技能：

- 「下周上新一款保温杯，只有参数表，新品卖点怎么写」——手上只有参数表和产品图，不知道从哪写起
- 「帮我写 5 个上新标题，要能放在详情页首屏」
- 「新品还有两周开售，公众号和短视频的预热文案怎么排」——要排预热、首发、返场的节奏
- 「把这段详情页文案改成 30 秒口播」——同一个卖点改写到不同平台
- 「帮我查查这版文案有没有违禁词」——发布前的风险词粗筛

不适用（遇到时这样处理）：

- 药品、医疗器械、保健食品的广告宣称 → 只做风险提示，这类广告须经审查，交法务或合规人员；不替用户判断某句话是否合法。
- 投放出价、渠道预算、转化率预测 → 不在本技能范围，不承诺转化率和销量。
- 界面上的按钮、弹窗、报错文字 → 转「UI 文案」（ui-microcopy）。

## 先判断什么：动笔前收齐六样

```
产品  品类、规格参数、价格与首发优惠、开售日期、是否限量及数量
凭据  每个卖点背后的证据：检测报告、专利、原料来源、实测数据、试用反馈——没凭据的卖点先放一边
人群  谁用、谁付钱（常常不是同一个人）；他们现在用什么凑合、对它哪里不满
场景  一天里什么时刻、在哪、因为什么会用到它
对手  同价位竞品详情页首屏都在强调什么；你的差异只挑一两个
风险  是否属于食品、保健食品、化妆品、医疗器械、药品、母婴用品——这些品类的宣称有专门规定，先标红
```

六样里缺哪样就先问哪样。凭据缺得最多时，宁可少写一个卖点，也不要先写上去「回头再补」。

## 卖点提炼：功能 → 场景 → 情绪

流程：先把所有参数列成行，每行往右推两格；推不到场景的参数只放进参数表，不当卖点。

```
功能（可验证）          场景（谁、何时、在哪）                情绪（省掉的麻烦或得到的感觉）   凭据
单手按压开盖            骑车等红灯、抱着孩子时单手喝水         手不够用时也不狼狈               实拍视频
装热水 8 小时后仍温     早上 7 点装的水，下午 3 点开会还能喝   不用满楼找饮水机                 检测报告（待补编号）
杯身 350 毫升、重 260 克 塞进通勤包侧袋不鼓包                  出门少一件要惦记的东西           实测称重
筛选  三个卖点封顶；首屏只讲「场景最常见、情绪最强、凭据最硬」的那一个
```

示例产品是虚构的通勤保温杯，数字只作格式示意，实际以你的检测报告和实测为准。情绪这一格写具体的麻烦和感受，不写「幸福感」「品质生活」这类放在哪个产品上都成立的词。

场景和情绪写不出来时用笨办法：翻同类商品的差评、追评和问答，把用户原话抄下来，按「什么时候、在哪、为什么不满」归类；出现最多的三类就是你的场景素材，文案里尽量用用户自己的词，而不是行业术语。

## 标题公式与正文结构

```
公式1 人群或场景 + 痛点 + 解法   早八通勤党：单手就能喝到热水的保温杯
公式2 具体数字 + 可验证结果      早上装的热水，下午开会还是温的（需有检测或实测）
公式3 对比旧方式                不用再找饮水机：一天的热水装进包里
公式4 新品身份 + 核心差异        新品｜单手开盖保温杯，骑车等灯也能喝
公式5 提问                      为什么你的保温杯总在包里漏水？
自检  至少含一个用户会搜的词；有数字就有凭据；不用「最」「第一」「100%」「全网最低」
```

按平台挑公式：电商标题要装进搜索词（品类词 + 属性词 + 场景词）；公众号标题要让人想点开，公式 1、3、5 更合适；短视频封面字要一眼看懂，控制在十个字上下。

正文结构（五段，顺序固定）：

```
1 开头  先给场景或痛点，不从品牌介绍开始
2 卖点  最多三个，每个按「功能—场景—情绪—凭据」写
3 信任  检测、材质、工艺、授权使用的真实试用反馈；不编评价、不编销量
4 顾虑  尺寸重量、清洗方法、售后规则，以及不适合谁
5 行动  首发价、开售时间、数量限制、在哪买
```

一个卖点段写出来是这样：「早上 7 点装的热水，下午 3 点开会时倒出来还是温的。杯身是双层真空结构，不用满楼找饮水机，也不用将就一口凉水。保温数据见检测报告（待补编号）。」——场景在前，功能居中，情绪收尾，凭据跟在后面。

## 三平台改写与上新节奏

三个平台分工不同：短视频负责让人看到，公众号负责讲清楚，详情页负责下单，但主卖点那一句话三处必须一致。

| 平台 | 篇幅 | 结构一句话 |
|---|---|---|
| 电商详情页 | 首屏一句主卖点（12 字以内）＋分屏 | 痛点场景 → 三个卖点各占一屏（图 + 一句话 + 凭据小字）→ 细节与参数 → 用法 → 包装清单 → 售后 |
| 公众号推文 | 正文 1,200–2,000 字 | 一个具体的人和场景 → 问题 → 产品怎么解决 → 真实的研发或选材故事 → 首发福利 → 购买路径 |
| 短视频口播 | 30–60 秒，一句不超过 15 个字 | 0–3 秒钩子 → 痛点演示 → 两个卖点现场演示 → 价格与首发福利 → 一句行动指令；写完念出声计时 |

上新节奏（T 为开售日）：T-14 至 T-7 悬念 → T-6 至 T-3 揭晓 → T-2 至 T-1 倒计时 → T 日三平台同步发 → T+1 至 T+7 返场。预热里的限量数字、首发价、原价必须真实可兑现。

各平台的详细结构、同一卖点的三种写法、30 秒口播完整示意、每个阶段的预热模板和开售后的复盘方法，见 [references/platforms-and-schedule.md](references/platforms-and-schedule.md)。

## 合规风险与风险词粗筛

绝对化用语（最、第一、国家级等）广告法有限制；普通商品不说治疗、预防疾病；食品不暗示保健或治疗功能；化妆品的美白、防脱等功效要有依据，部分类别需注册或备案；保健食品、医疗器械、药品的广告须经审查。这几类一律交法务或合规审核后再发，具体以现行法规和平台规则为准。

写完后粗筛一遍风险词（只是提醒，不代替人工和合规审核）：

```bash
python3 {baseDir}/scripts/risk_words.py copy.txt                     # UTF-8 的 .txt 或 .md
python3 {baseDir}/scripts/risk_words.py copy.txt --extra 特效,神器    # 追加自己的词
```

脚本只读不改文件，只用 Python 标准库；按绝对化用语、医疗用语、功效宣称、绝对承诺、空泛词五类列出命中的行和处理建议，有命中时退出码为 3。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（模板） |
|---|---|---|
| E1 缺关键信息：六样收不齐，只有参数表 | 先问最影响文案的 1–3 样：凭据 → 人群与场景 → 开售日期与价格；其余先按常见写法写，价格、日期写「待补」，默认值写「待确认」 | 「先确认三件事：每个参数有什么凭据？谁用、谁买？哪天开售、首发价多少？其余我先写，标了『待补』『待确认』的你再补。」 |
| E2 信息自相矛盾：参数表写保温 12 小时，检测报告写 8 小时；既说「限量」又说「不限量」 | 摘出矛盾的两处，给两个理解；以凭据为准，用户确认前这个数字不进标题和首屏 | 「这两处对不上：参数表写……，报告写……。按报告写①……，还是②你有新的检测结果？」 |
| E3 数字或对比没有凭据：「比某某强 3 倍」「销量第一」 | 删掉或标「待补」，不写进正文；比较要有能公开的依据，也不贬低竞品 | 「『强 3 倍』需要能公开的依据，我先删了。有检测数据的话发我，再加回来。」 |
| E4 敏感品类：食品、保健食品、化妆品、医疗器械、药品、母婴用品 | 先标红；风险词和敏感宣称单列一张表，每条给替换写法并注明「需合规审核」 | 「这个品类的宣称有专门规定。有风险的句子我单列了一张表，发布前请交法务或合规审核。」 |
| E5 坚持要写「最好」「第一」「治愈」「永久」 | 不写进文案；说明风险，给具体数字或演示的替换写法；最终由用户与合规人员决定 | 「这句我不写，它属于高风险宣称。可以换成……（具体数字或演示），发不发请合规同事把关。」 |
| E6 超出范围：投放出价、预测转化率、代发布 | 说明不在本技能范围；只交文案和节奏表 | 「投放和转化预测不在我这里做，我把文案和上新节奏表交给你，发布由你们来。」 |
| E7 时间紧，只要最小可用版 | 交四件：主卖点一句（功能—场景—情绪—凭据）＋ 3 个标题（注明公式）＋ 详情页首屏一句 ＋ 30 秒口播；正文与节奏表随后补 | 「先给你能马上用的四件：主卖点、三个标题、首屏一句和 30 秒口播，其余我随后补齐。」 |

脚本 `risk_words.py` 的退出码与报错：

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 0 | 没有命中风险词表 | 仍需人工通读；敏感品类照样交合规审核 |
| 3 | 有命中，已逐条列出 | 按建议改写，写进风险表并注明「需合规审核」 |
| 1「参数错误」「内容为空」 | 没给文件路径，或文件里没有文字 | 按 `risk_words.py 文件路径` 重跑；从标准输入读用 `-` |
| 2「找不到文件」「是文件夹」「没有读取权限」 | 路径错，文件名有空格没加引号，权限不够 | 检查路径，文件名含空格时用引号包住 |
| 2「像是 Word、PDF」「不是 UTF-8 文本」 | 传了 .docx、.pdf，或 GBK 编码的文本 | 把文案复制进 UTF-8 的 .txt 或 .md 再扫 |
| 130 | 按了 Ctrl+C | 重新运行即可 |

## 输出契约

交付物按下面的固定顺序给出；用户只要其中一部分时，只交那部分，开头注明「本次只交：……」，格式不变：

0. **缺料清单**（六样没收齐时）：缺什么、影响哪一部分。
1. **卖点阶梯表**：功能｜场景｜情绪｜凭据，三个卖点封顶，标出首屏讲哪一个。
2. **五个备选标题**：每个注明用了哪个公式、适合哪个平台。
3. **正文五段**：开头 → 卖点 → 信任 → 顾虑 → 行动，顺序固定。
4. **三平台改写稿**：每一稿开头写清平台和篇幅（字数或秒数）；口播稿附念出声的实测时长，没测就写「待确认」。
5. **上新节奏表与各阶段预热文案**：T 换成具体日期。
6. **风险表**：风险词和敏感宣称逐条列出，每条给替换写法并注明「需合规审核」；附风险词脚本结果。
7. **待补清单**：每条注明用在哪一部分。

占位符规则：凭据编号、价格、日期、限量数这类用户没给、也不能编的，写「待补」（可带说明，如「检测报告编号待补」）；按常见写法先填、要用户确认的，写「待确认」。发布前全部清空。

交付前自检（逐条答「是 / 否」，有一条「否」就先改再交）：

- [ ] 每个数字旁都注了凭据（检测、实测还是用户反馈），拿不准的标了「待补」
- [ ] 卖点不超过三个，首屏只讲一个
- [ ] 主卖点那一句话在三个平台的写法口径一致
- [ ] 风险词脚本跑过，命中项都进了风险表并给了替换写法
- [ ] 没有编造销量、评价、专家背书、原价和限量
- [ ] 每一稿开头写了平台与篇幅，口播写了实测时长或「待确认」

## 常见问题（FAQ）

**问：只有参数表，没有检测报告，能写吗？**
答：能写卖点阶梯，但凭据格写「待补」；没凭据的卖点不上首屏和标题，凭据到位再加。

**问：能帮我编几条好评、写个销量吗？**
答：不编。信任段只用检测、材质、工艺和授权使用的真实试用反馈。

**问：三个平台能用同一套文案吗？**
答：不能。详情页重信息，公众号重故事，口播重节奏；但主卖点那一句话三处必须一致。

**问：「最」「第一」真的一个都不能用吗？**
答：绝对化用语广告法有限制；换成具体数字或现场演示更有说服力。具体以现行法规和平台规则为准，拿不准的交合规审核。

**问：风险词脚本没命中，就算合规了吗？**
答：不算。脚本只是粗筛，词表覆盖不全；敏感品类和功效宣称一律交法务或合规人员审核。

**问：预热期要写限量多少只才有吸引力？**
答：写真实、能兑现的数字；「原价」要真实成交过，限时限量要真的限。

**问：口播超时了怎么办？**
答：删句子，不加快语速；念出声重新计时。

**问：能直接帮我发布或者投放吗？**
答：不代发布、不代投放；交付文案、节奏表和风险表，发布由你们按平台流程来。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 参数堆砌 | 用户看不出和自己有什么关系 | 每个参数都推到场景，推不动就进参数表 |
| 卖点太多 | 首屏什么都想说，结果什么都没记住 | 首屏一个，全页不超过三个 |
| 三个平台一套文案 | 平台分工不同，一套文案三处都不合适 | 详情页重信息，公众号重故事，口播重节奏 |
| 用「极致」「颠覆」「黑科技」 | 放在哪个产品上都成立，没有信息量 | 换成具体数字或现场演示 |
| 没凭据的数字和对比，贬低竞品 | 有合规风险，也经不起追问 | 删掉或标「待补」；比较要有能公开的依据 |
| 预热承诺兑现不了 | 开售当天就失信 | 只写确定能给的福利；原价真实成交过，限量真的限 |
| 开头从品牌介绍讲起 | 用户还没看到和自己有关的事就划走了 | 先给场景或痛点 |
| 情绪写「幸福感」「品质生活」 | 空泛，任何产品都能用 | 写具体省掉的麻烦和感受 |

## 边界与不做什么

- 不写虚假或兑现不了的承诺：不编销量、评价、专家背书、媒体报道、原价和限量。
- 医疗、功效类表述只提示风险，不判断某句话是否合法；涉及食品、保健食品、化妆品、医疗器械、药品、母婴的，发布前交法务或合规人员审核。
- 不写贬低竞品的内容，不对比较广告做法律判断。
- 不承诺转化率和销量，不代发布、不代投放。
- 不使用未授权的肖像、音乐、字体、图片和他人文案。
