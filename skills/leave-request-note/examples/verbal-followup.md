# 完整示例：电话请过事假，事后补书面（实际比原计划多半天）

> 示例。人名、日期、事由都是虚构的，只演示写法。

## 1. 用户原话

> 上周电话里跟主管请过两天事假，现在要补一份书面申请

## 2. 助手先问（一次问完，不超过 3 个）

1. 哪天几点、给谁打的电话，对方当时怎么答复的？
2. 实际休了哪几天？和电话里说的一样吗？如果多了，多出来的时间当时有没有告诉主管？
3. 事由写到什么程度可以（涉及隐私的，写「家中有事须本人处理」就够）？手上有没有能附的材料？

## 3. 用户补充

> 11 月 16 日早上 8 点半给王经理打的电话，他说可以。本来请 16、17 两天，结果老家房子过户手续第三天上午才办完，18 号下午回来上班的。17 号晚上微信跟他说了要多请半天，他回了「好」。我有办事的受理回执。

## 4. 天数核对（脚本实际输出）

```bash
python3 scripts/leave_days.py 2026-11-16 2026-11-18 --to-half am
```

```
未标注节假日与调休：区间内如有法定节假日或调休上班日，用 --off / --work 标注后重算
核对：以上只按你给的日期计算；按工作日还是自然日计、半天怎么算，以本单位考勤口径为准。
```

## 5. 交付物

【补假申请正文】

```
补假申请
王经理：
11月16日（星期一）8:30，我因老家房屋过户手续须本人到场办理，通过电话向您请事假2天（11月16日至17日），您当时同意；17日晚我通过微信告知需延长半天，您回复同意。现补交书面申请：实际自11月16日（星期一）上午至11月18日（星期三）上午，共2.5天，比原计划多半天，原因是过户手续第三天上午才办完。18日下午已正常到岗。
附件：办事受理回执复印件
申请人：[待补：姓名]    2026年11月23日
```

【系统「请假理由」一行版】

```
事假（补录）：11月16日电话经王经理同意，实际11月16日—18日上午共2.5天，比原计划多半天（手续延误，17日已微信报备），附受理回执。
```

【提醒】

- 补录本该在返岗第一天交，这次已经晚了几天，今天就交；交的时候当面或发消息说一句「补交上周的事假申请」。
- 聊天记录截图自己留存备查，一般不必附；公司要求附的，按制度来。
- 这 2.5 天是否扣薪、怎么计入考勤，以公司制度和考勤记录为准，本技能不做判断。

【待补 / 待确认】

- [待补]：姓名。
- [待确认]：公司系统里补录走的是「事假」还是单独的「补假」类型，以系统选项为准。

## 6. 交付前自检

| 检查项 | 结果 |
|---|---|
| 写清当时的请假过程：哪天几点、向谁、什么方式、对方怎么答复 | 是 |
| 起止按实际发生写，多出的半天写明原因和报备情况 | 是 |
| 「共 2.5 天」与脚本结果一致 | 是 |
| 没有编造：事由、时间、报备过程都来自用户 | 是 |
| 没有对扣薪、考勤定性下结论 | 是 |
