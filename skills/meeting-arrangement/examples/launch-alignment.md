# 完整示例：跨三个部门对齐上线时间（30 分钟决策会）

> 示例。人名、部门、日期、会议室和链接都是虚构占位符；议程表是 `scripts/agenda_slots.py` 的实际输出。本技能只产出文本，发邀请、订会议室由用户自己操作。

## 1. 用户原话

> 下周要跟三个部门对齐上线时间，帮我安排个会

## 2. 助手先问（一次不超过三个）

1. 要定的具体是什么？有几个候选日期？谁有权拍板？
2. 三个部门各谁来，各自带什么信息？
3. 希望哪天前有结论？线上还是线下？

## 3. 用户补充

> 定上线日期，候选 10 月 20 日和 27 日，张经理拍板。研发小王带压测结果，测试李老师讲风险和依赖，市场部只要知道结果就行。下周二前要定，线下加线上。我来主持不了，小赵主持，小李记录。

## 4. 交付物

**① 判断：开。** 要当场拿到一个决定（上线日期），需要研发和测试来回讨论取舍，决策人能到场；市场部只需知会，不进会，会后收纪要。

**② 会议卡**（发邀请前先请张经理过目）

```
【会议卡】
会议：[项目名] 上线时间对齐        类型：决策会    时长：30 分钟    形式：线下加线上
目标：散会时确定上线日期与回滚预案负责人
决策人：[张经理]    主持：[小赵]    记录：[小李]
必需者：[小王]（压测数据）、[李老师]（风险与依赖）
知会者：[市场部]，会后收纪要
会前材料：《上线方案对比》，开会前一个工作日发出
```

**③ 议程表**（先把每项写成一行存为 `launch.txt`，再用脚本排时间并检查）

```
开场：目标和今天要做的决定|开场|[小赵]（主持）|3|—
现状与选项：10/20 与 10/27 两个日期|知会|[小王]|5|确认 A、B 两个选项
讨论与决策|决策|[张经理]|15|选定上线日期及前提条件
风险与依赖：回滚预案、市场部物料|讨论|[李老师]|4|风险清单与各自负责人
复述决定与待办|收尾|[小李]（记录）|3|待办表
```

```bash
python3 scripts/agenda_slots.py --length 30 --start 14:00 --file launch.txt --title 决策会
```

**④ 会前材料清单**（开会前一个工作日发出，最前面一页摘要）

- 《上线方案对比》：背景、两个候选日期、推荐方案及理由、需要张经理决定什么；标明「请会前读完」。
- 小王：压测结果（带到会上，只讲变化和异常）。
- 李老师：风险与依赖清单，每条写上负责人。

**⑤ 邀请文案**

```
标题：[决策] [项目名] 上线时间对齐｜30 分钟
时间：10 月 13 日（周二）14:00–14:30
地点：[会议室] ／ 线上：https://example.com/meeting/0000
目标：散会时确定上线日期和回滚预案负责人
议程：1 现状与选项  2 讨论与决策  3 风险与依赖  4 待办确认
会前请：读完附件《上线方案对比》（约 5 分钟）；[小王] 带上压测结果
决策人：[张经理]  记录人：[小李]
不能参加的，请回复并指定一位能代你表态的同事
```

**⑥ 会中记录模板**（给小李）

```
D 决定  「上线日期定为 [日期]，前提是 [条件]」
A 待办  事项 + 负责人 + 截止时间 + 怎样算完成
Q 待议  没谈完或离题的，写下谁负责、何时再议
```

**⑦ 纪要模板**：用 [references/templates.md](../references/templates.md) 第 4 节，会后 24 小时内发出，「决定」一栏先请张经理确认措辞；市场部在抄送里。

## 5. 交付前自检

| 检查项 | 结果 |
|---|---|
| 先给了开不开的判断和理由 | 是 |
| 会议卡有目标、决策人、参会人及角色、时长、形式 | 是 |
| 议程每项有负责人和产出，合计等于会议时长，最后留了复述待办 | 是（脚本检查通过） |
| 人名、会议室、链接都是占位符，没替用户编 | 是 |
| 没有替用户发邀请、订会议室 | 是 |
