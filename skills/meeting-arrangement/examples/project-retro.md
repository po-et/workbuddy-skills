# 完整示例：60 分钟项目复盘会的议程和邀请

> 示例。项目、人名、日期、链接都是虚构占位符；议程表是 `scripts/agenda_slots.py --md` 的实际输出。

## 1. 用户原话

> 帮我写一份 60 分钟的项目复盘会议程和会议邀请

## 2. 助手先问

1. 复盘哪个项目、原定目标是什么？有没有现成的数据（进度、质量、成本）？
2. 谁来、谁有权定改进措施？
3. 希望散会时得到什么：几条改进、各自谁负责？

## 3. 用户补充

> 复盘官网改版项目，目标是 9 月底上线，实际晚了两周。项目经理有进度数据。组里 6 个人都来，部门负责人定改进措施。想要三条能落地的改进和负责人。

## 4. 交付物

**① 判断：开。** 需要多人各自提供看法、当场归类并拍板三条改进，文档评论替代不了讨论和决定。复盘只谈事和流程，不追究个人。

**② 议程表**（复盘骨架：回顾目标 → 对比结果 → 分析原因 → 保持与改进 → 待办；先各自写，免得第一个发言的人定了调）

`retro.txt`：

```
开场：目标、规则（只谈事和流程，不追究个人）|开场|[主持人]|5|—
回顾目标与对比结果|知会|[项目经理]|10|目标与实际的差距清单
各自先写：做得好的、要改的（静默书写）|讨论|全员|10|每人 3 张便签
轮流讲并归类|讨论|[主持人]|15|归好类的问题清单
选出三条改进并定负责人|决策|[部门负责人]|15|三条改进及负责人
复述决定与待办|收尾|[记录人]|5|待办表
```

```bash
python3 scripts/agenda_slots.py --length 60 --start 15:00 --file retro.txt --title 项目复盘 --md
```


**③ 会前材料**：项目经理提前一个工作日发一页摘要——原定目标、实际结果、时间线上的关键节点；标明「请会前读完」，会上不逐页讲。

**④ 邀请文案**

```
标题：[复盘] 官网改版项目复盘｜60 分钟
时间：[日期]（周[ ]）15:00–16:00
地点：[会议室] ／ 线上：https://example.com/meeting/0000
目标：散会时得到三条能落地的改进措施，每条有负责人和完成时间
议程：1 回顾目标与结果  2 各自书写  3 轮流讲并归类  4 选出三条改进  5 待办确认
会前请：读完项目经理发的一页摘要；想好各自眼中「做得好的一件事、要改的一件事」
规则：只谈事和流程，不追究个人
决策人：[部门负责人]  主持：[主持人]  记录：[记录人]
```

**⑤ 会后**：纪要 24 小时内发出，三条改进各写负责人、截止时间、怎样算完成；在下次周会上过一遍进度。纪要模板见 [references/templates.md](../references/templates.md) 第 4 节。
