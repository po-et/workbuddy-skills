# 会议安排

定位一句话：**一场会值不值得开，看散会时有没有多出一个决定，或者一张「谁在什么时候做完什么」的清单；两样都没有，这场会就不该开。**

## 何时使用

用户这样说时用本技能：

- 「下周要跟三个部门对齐上线时间，帮我安排个会」
- 「这件事到底要不要开会，还是发封邮件就行」
- 「帮我写一份 60 分钟的项目复盘会议程和会议邀请」
- 「会议议程怎么写」「写个会议邀请」
- 「开完会纪要和待办怎么记」

适用场景：要组织跨人或跨部门的讨论、评审、复盘、启动会，需要写议程、会前材料和邀请，或者拿不准一件事该开会还是发邮件时。本技能只产出文本，发邀请、订会议室、进日历由你自己操作。

不适用（遇到时这样处理）：

- 要求直接发邀请、订会议室、写进日历：说明本技能只产出文本，把邀请文案交给用户自己发。
- 绩效、辞退、劳动纠纷、投诉调查的谈话，合同谈判或法律争议相关的会：先找 HR、法务或律师，本技能只帮整理议程框架。
- 股东会、董事会、业主大会等有法定程序的会：通知期限、表决规则以章程和相关规定为准，找专业人士把关。

## 第一步：先判断要不要开

```
逐题回答，任何一题答「是」就先别开，改用右边的办法
只是单向通知，不需要大家当场回应？          是 → 邮件或文档，附「有疑问请回复」
一个人就能拍板，只是想让大家知道？          是 → 决策人直接定，结果书面通知
意见可以各自写，不需要来回讨论？            是 → 在文档里评论收集意见
只和一两个人有关？                          是 → 直接找当事人聊
材料还没准备好，开了也只是「先碰一下」？    是 → 备齐材料再约
五题都是「否」，而且散会时能拿到一个决定、一份清单或一版方案，才开
```

不开会时，用这段消息代替：

```
主题：[事项]，请在[周三 18:00]前回复
背景：[两三句话说清现状]
需要你做的：[同意 / 提意见 / 补数据]，直接回复即可
默认处理：截止前没有异议，就按[方案 A]执行
```

## 第二步：目标、参会人、时长、议程、会前材料

目标只写一句：「散会时我们要得到____」。空里填的必须是一样东西——一个决定、一份排期、一张风险清单、一版方案。填不出来，回到第一步。

```
参会人按角色排，每个名字都要说得出为什么在场
决策人  有权拍板的那一个人；他来不了就改期，不要「先讨论着」
必需者  提供关键信息或负责执行的人
主持人  控时间、收口；尽量不兼记录
记录人  只记决定、待办和待议问题
知会者  不进会，会后收纪要
规模    经验上，要做决定的会尽量不超过 8 人；人更多就先小范围定，再大范围同步
```

```
时长
一个决定或一个问题   25–30 分钟
两三个议题           50–60 分钟
超过 90 分钟         拆成两场，或先用文档把「知会」部分消化掉
想给大家留出赶下一场的时间，可以设成 25、50 分钟，从知会项里压出这 5 分钟；跨时区的写清各地时间
```

议程每一项写五样：议题、类型（知会／讨论／决策）、负责人、时长、产出。决策项尽量放前面，趁大家注意力还在；前后有依赖的（先定方案才能排期）按依赖排；能写进材料的知会项不在会上念；最后 5 分钟（30 分钟以内的短会至少 3 分钟）固定留给复述决定与待办。

会前材料提前一个工作日发，最前面放一页摘要：背景、可选方案、推荐方案及理由、需要大家决定什么；标明「请会前读完」，会上不逐页讲；需要谁带着答案来的问题，点名写清。

决策会、头脑风暴、项目复盘、启动会、站会各自的目标、时长和议程骨架见 [references/meeting-types.md](references/meeting-types.md)；复盘会先让每人独立写下看法再讨论，只谈事和流程，不追究个人。

以上定下来的，写成一张会议卡，发邀请前先请决策人过目：

```
【会议卡】
会议：[项目名] 上线时间对齐        类型：决策会    时长：30 分钟    形式：线下加线上
目标：散会时确定上线日期与回滚预案负责人
决策人：[张经理]    主持：[小赵]    记录：[小李]
必需者：[小王]（压测数据）、[李老师]（风险与依赖）
知会者：[市场部]，会后收纪要
会前材料：《上线方案对比》，开会前一个工作日发出
```

## 模板：30／60 分钟议程与邀请文案

- **30 分钟决策会**：开场 3 → 现状与选项 5 → 讨论与决策 15 → 风险与依赖 4 → 复述决定与待办 3。
- **60 分钟多议题会**：开场 5 → 知会 10 → 讨论 20 → 决策 15 → 待议区 5 → 复述决定与待办 5。
- **邀请文案**：标题带类型和时长，写时间、地点、目标、议程、会前要做什么、决策人和记录人，最后一句「不能参加的，请回复并指定一位能代你表态的同事」。

完整模板（含可直接粘贴的议程文件、邀请文案、纪要、主持人话术）见 [references/templates.md](references/templates.md)。议程的起止时刻不手算，用脚本排并自动检查合计时长、收尾复述、负责人和产出：

```bash
python3 scripts/agenda_slots.py --length 30 --start 14:00 --file agenda.txt --title 决策会
python3 scripts/agenda_slots.py --length 60 --start 16:00 --file agenda.txt --md --date 2026-10-13 --also-tz Europe/Berlin
```

`agenda.txt` 每行一项「议题|类型|负责人|分钟|产出」；加 `--date` 与 `--also-tz` 换算各地时间，落在对方 07:00 前或 21:00 后会标出来。

## 第三步：会中记录、会后纪要与待办

```
会中只记三类
D 决定  「上线日期定为 10 月 20 日，前提是压测通过」
A 待办  事项 + 负责人 + 截止时间 + 怎样算完成
Q 待议  没谈完或离题的，写下谁负责、何时再议
主持人每到一个议题的时间就收口：「这项先定成 X，还有异议的会后找我」；拿不到决定的，写进 Q
```

主持人应对跑题、一人说太久、卡住不动、没人表态、线上会的几句话，和纪要模板（决定、待办、待议、跟进），都在 [references/templates.md](references/templates.md)。

纪要在会后 24 小时内发出，发出前请决策人确认「决定」一栏的措辞，免得会后各自理解不同；每条待办在截止前一天提醒负责人，逾期的放在下次例会第一项过。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（一句模板） |
|---|---|---|
| 缺关键信息（要解决什么、谁拍板、哪天前要结果） | 一次最多问三个；人名、日期、会议室没给的留方括号，交付物里标 [待补] 或 [待确认] | 「先确认三件事：这场会要定什么、谁有权拍板、希望哪天前有结果。人名和会议室我先留空。」 |
| 输入自相矛盾（「30 分钟过 5 个议题」「只是通知大家，但要大家讨论」） | 指出矛盾，给两种做法让用户选；议程超时脚本会直接报错 | 「5 个议题 30 分钟排不下：要么只留 2 个需要当场定的，其余会前发材料；要么改成 60 分钟。选哪个？」 |
| 决策人来不了 | 不「先讨论着」：改期，或改成文档收集意见、由决策人书面拍板 | 「张经理来不了，这场会定不下来。建议改期，或者先发文档收意见，由他书面拍板。」 |
| 超出本技能范围（发邀请、订会议室、绩效或法律相关的谈话、法定程序的会） | 只给文本；敏感谈话先找 HR 或法务；法定程序找专业人士 | 「邀请我写好了，由你来发；涉及辞退的谈话，建议先和 HR 对一下流程再约。」 |
| 时间紧，只要最小可用版 | 交三样：一句话目标、三行议程（议题＋负责人＋产出）、一段邀请；会前材料和纪要模板之后再补 | 「先给你最小版：目标一句、议程三行、邀请一段，现在就能发。」 |
| 用户坚持越界（替他发邀请、编参会人意见、在邀请里写保密内容） | 守住：只产出文本；不编他人意见；保密内容不写进邀请正文，改为会上口头说明或单独发给相关人 | 「保密的数据不放进邀请正文，我在邀请里写『详见会上说明』，材料单独发给必需者。」 |
| 其实不用开会 | 按第一步的五道题给出判断和理由，直接交替代消息 | 「这件事一个人就能拍板，建议不开会：我把通知消息写好了，你看一下。」 |

脚本 `scripts/agenda_slots.py` 的退出码与报错：

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 0 | 排好了；「检查」里的 [提醒] 不影响退出码 | 按提醒补负责人、产出或收尾 |
| 1「超过会议时长」 | 各项分钟数加起来比 `--length` 多 | 删一项、把知会项写进会前材料，或延长会议 |
| 1「应有 5 段」「分钟数应是正整数」 | 议程某行格式不对 | 每行写成「议题\|类型\|负责人\|分钟\|产出」，分钟写整数 |
| 1「开始时间应写成 HH:MM」「--length 应在 1–480」 | 时间或时长写错 | 用 24 小时制，如 14:00；时长写分钟数 |
| 1「需要同时给 --start 和 --date」「时区名不认识」 | 跨时区换算缺参数或时区名写错 | 用 IANA 名称，如 Asia/Shanghai；Windows 上可能要先装 tzdata 包 |
| 2「找不到议程文件」「写不了」 | `--file` 路径不对，或 `--out` 目录不存在 | 检查路径；存成 UTF-8 文本 |
| 130 | 按了 Ctrl+C | 重新运行即可 |

## 输出契约

先问：要解决什么事、谁有权拍板、涉及哪些人、希望哪天前有结果、线上还是线下；缺哪项问哪项，一次不超过三个问题。

交付物按这个顺序，不增不减：

1. **判断**：开还是不开，附一句理由；不开就直接给替代消息，到此为止。
2. **会议卡**：目标、决策人、参会人及角色、时长、形式。
3. **议程表**：时间、议题、类型、负责人、产出（用脚本排时间并附检查结果）。
4. **会前材料清单**：谁准备什么、哪天发出。
5. **邀请文案**。
6. **会中记录模板**（D／A／Q）与**纪要模板**。

格式规则：全部是可复制的纯文本或 Markdown；时间写到分钟，跨时区注明时区；链接只用 example.com 占位，会议室写 [会议室]；用户没给的人名、日期、数据留成方括号，不替他编。占位符：需要用户补的写 `[待补：……]`，按默认值填了、需要他核对的写 `[待确认：……]`。

交付前自检（逐条答「是」才交）：

- [ ] 先给了开或不开的判断和一句理由？
- [ ] 目标只写了一样东西（一个决定、一份清单或一版方案）？
- [ ] 决策人明确，并且能到场？
- [ ] 议程每项都有负责人和产出，合计等于会议时长，最后留了复述决定与待办的时间？
- [ ] 人名、会议室、链接、日期都是用户给的或方括号占位，没有编造？
- [ ] 没有替用户发邀请、订会议室或写入任何日历？

## 示例

示例（人名为虚构）：

**用户**：这件事到底要不要开会，还是发封邮件就行？

**助手**（先问）：两个问题：这件事要定什么，谁有权拍板？需要大家当场讨论，还是知道结果就行？

**用户**：下个月起周报换新模板，组长已经定了，就是让大家知道，顺便收一下意见。

**助手**（交付）：

判断：**不开。** 第一步的五道题里，「只是单向通知」和「一个人就能拍板」都答「是」；意见可以各自写，不需要来回讨论。用这段消息代替：

```
主题：下月起周报换新模板，请在[周三 18:00]前回复意见
背景：从[11 月第一周]起，周报统一用新模板（见附件），组长已确认。主要变化：[待补：一两句说清改了哪几栏]。
需要你做的：看一眼附件，有意见直接回复；没有意见不用回
默认处理：截止前没有异议，就从[11 月第一周]起按新模板执行
```

- 待补：主要变化那一句、附件。待确认：截止时间和起始周。
- 如果回复里出现了需要来回讨论的分歧，再约一场 25 分钟的会，只讨论分歧那一项。

## 常见问题（FAQ）

**Q：能不能直接帮我发邀请、订会议室？**
A：不能，本技能只产出文本；邀请文案可以直接复制，发送和预订由你自己操作。

**Q：决策人来不了，先开着讨论行吗？**
A：不建议。决策人不在，讨论一小时的结论多半是「再请示」；改期，或先书面收集意见，由决策人书面拍板。

**Q：会议最短开多久？**
A：一个决定或一个问题 25–30 分钟就够；站会 15 分钟；超过 90 分钟就拆成两场。

**Q：人太多怎么办？**
A：要做决定的会尽量不超过 8 人；只需要知道结果的人列为知会者，不进会、会后收纪要。

**Q：线上会要注意什么？**
A：提前 5 分钟开好会议室、试好共享屏幕；每个议题结束前，点名问一句还没开口的关键人；跨时区写清各地时间。

**Q：纪要什么时候发、发给谁？**
A：会后 24 小时内发给参会人和知会者；发前请决策人确认「决定」一栏的措辞。

**Q：会议要录音录像可以吗？**
A：提前告知参会人并遵守本单位规定；保密内容不写进邀请正文。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 议程只有标题（「讨论上线」），没写产出 | 开完不知道结论是什么 | 每项写清产出：一个决定、一张清单或一版方案 |
| 决策人不在场 | 讨论一小时，结论是「再请示」 | 决策人来不了就改期，或改为书面拍板 |
| 材料会上才发，会上现念 | 大家当场读材料，讨论时间被吃掉 | 提前一个工作日发，最前面一页摘要，标明请会前读完 |
| 邀请只写「讨论一下」 | 别人不知道要准备什么，也判断不了自己该不该来 | 邀请里写目标、议程、会前要做什么 |
| 人越拉越多 | 一半人只是旁听 | 按角色排，只需要知道结果的列为知会者 |
| 主持人兼记录人 | 两样都没做好 | 主持和记录分开 |
| 只记讨论过程，不记决定 | 会后没人说得清定了什么 | 只记 D 决定、A 待办、Q 待议 |
| 待办写「大家跟进」 | 没有具体负责人，就是没人负责 | 每条待办写负责人、截止时间、怎样算完成 |
| 说好 30 分钟开了 50 分钟 | 后面的人全被拖住 | 主持人到点收口，没定的写进待议 |
| 会后不发纪要 | 一周后每个人记得的版本都不一样 | 24 小时内发纪要，决策人先确认措辞 |
| 例会从不回头审 | 没用的例会一直占着日程 | 每季度问一次：这个例会还要不要开、能不能缩短 |

## 边界与不做什么

- 只产出文本：不发邀请、不订会议室，不接入、不读写任何日历、邮箱或会议系统，发送和预订由你自己操作。
- 不替你做业务决定；议程里的「推荐方案」由你或负责人填写，本技能只帮你把选项和取舍理清楚。
