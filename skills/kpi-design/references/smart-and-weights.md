# SMART 五问与权重、计分规则（展开版）

SKILL.md 里只留了每条一句话；这里是完整说明，写卡片和分权重时对照用。

## SMART 五问：每个指标都要过

- **S 具体**：换一个人读，会不会理解成别的？「提升客户满意度」要改成「季度满意度评价中 4–5 分的占比」。
- **M 可衡量**：现在就能取到数吗、谁来取？取不到的数先建数据，本期不进考核。
- **A 可达成**：拿过去四个周期的实际值做基线，目标值一般落在历史中位数与历史最好值之间；远高于历史最好值的，要写清靠什么资源实现。
- **R 相关**：这个数涨了，上一级目标一定受益吗？不一定的，删。
- **T 有时限**：统计周期与考核周期一致；季度考核不要用年底才出数的指标。

答不上来的，改写或删除；不要为了凑满五个字母硬写。

## 权重规则

- 三到六项；单项建议不低于 10%（再低等于不考核，只会分散注意力），不高于 40%（一项定生死，刷分动机最强）。
- 权重表达「这个周期最想要什么」，不是工作量占比；各项平均分配，通常说明还没想清楚重点。
- 协作紧密的岗位，留 10%–20% 权重给团队指标，避免人人只顾自己的数。
- 红线不进权重：安全事故、数据造假、合规问题单列为扣分或一票否决项。
- 所有人的个人目标加总，要能覆盖上一级目标并留出余量，否则会出现「人人达标、部门没完成」。

## 三档计分

每个指标给三档：门槛、目标、挑战。低于门槛记 0 分，达门槛 60 分，达目标 100 分，达挑战 120 分封顶，档间线性折算。

算例（数字是为演示算法假设的，不是建议值）：某指标门槛 80、目标 100、挑战 110。

```
实际 75   低于门槛                      → 0 分
实际 90   在门槛与目标之间：60 + (90 − 80) ÷ (100 − 80) × 40 = 80 分
实际 105  在目标与挑战之间：100 + (105 − 100) ÷ (110 − 100) × 20 = 110 分
实际 130  超过挑战                      → 120 分封顶
```

「越低越好」的指标（逾期应收占比、缺陷数）把方向反过来：门槛是能接受的最高值，挑战是最低值，公式里的差值同样按「离门槛有多远」算。

## 权重表自查

把指标表存成 CSV（表头：指标,类型,权重,口径），跑：

```bash
python3 scripts/kpi_check.py kpi.csv
```

脚本查的就是上面这些规则：合计 100%、单项 10%–40%、结果类不低于 60%、指标 3–6 个、口径不空也不只是重复指标名、「待建数据」不占权重、红线不占权重、不考代码行数这类数。退出码含义见 SKILL.md「信息不全或出错时」。
