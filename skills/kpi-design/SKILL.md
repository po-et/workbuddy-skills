# KPI 制定

定位一句话：**KPI 不是把能数的都数一遍，而是挑出三到六个「做好了目标大概率达成、想刷也刷不动」的数，再把怎么算写死。**
何时用：年度或季度要给团队、岗位定考核指标；新设岗位还没有指标；老指标跑偏了，大家都在冲某一个数；上级给了一个大目标要拆到人。探索性、从零到一的项目结果难以预先量化，更适合用 OKR 或里程碑评审，不要硬套 KPI。

## 先判断三件事

1. **考核用还是管理用。** 挂钩奖金、晋升的考核指标要少而硬，三到六个；日常管理看板可以多，但不进考核。两者混在一张表里，是 KPI 失控最常见的起点。
2. **上一级目标定了没有。** KPI 是目标的翻译，不是目标本身。部门今年要什么、要到多少，没有这句话就先回去问，不要从岗位说明书倒推指标。
3. **这个岗位能控制什么。** 指标必须落在岗位能影响的范围内：客服不该为产品退货率背全责，研发不该背营收。能影响但控制不了的，只放低权重的协同项，或者只观察不考核。

两组概念先分清，后面每个指标都要标上：

```
结果 vs 过程   看「数的是什么」：结果是要的东西（回款、续约、故障数），过程是做的动作（拜访、响应、评审）
滞后 vs 领先   看「什么时候知道」：滞后指标出数时已无法补救，领先指标能提前预警、及时调整
常见对应       结果多为滞后，过程多为领先；例外：商机储备金额是阶段性结果，却领先于回款
配比建议       考核以结果为主，结果类权重合计不低于 60%；过程指标用来预警和辅导，单独重押必被刷
```

## 制定流程：七步从目标到卡片

```
第 1 步 写目标    上一级目标写成「一句话 + 一个数 + 截止时间」，如「2027 年华东区回款 3000 万元」
第 2 步 拆因子    问「这个数由哪几项相乘或相加」：回款 = 成交客户数 × 客单价 × 回款率，拆到岗位能影响的那层为止
第 3 步 选指标    每个关键因子选一个结果指标；最关键的一两个再配一个领先指标，用来提前预警
第 4 步 过 SMART  逐条回答下面五问，答不上来的改写或删除
第 5 步 写口径    按卡片模板填齐：分子、分母、周期、取数位置、剔除规则、负责人、版本
第 6 步 分权重    按下文规则分配，合计 100%，每项附一句理由
第 7 步 回算防刷  用上一周期真实数据试算：好员工和差员工能不能拉开？有没有人不干正事也能拿高分？
```

SMART 五问，每个指标都要过：

- **S 具体**：换一个人读，会不会理解成别的？「提升客户满意度」要改成「季度满意度评价中 4–5 分的占比」。
- **M 可衡量**：现在就能取到数吗、谁来取？取不到的数先建数据，本期不进考核。
- **A 可达成**：拿过去四个周期的实际值做基线，目标值一般落在历史中位数与历史最好值之间；远高于历史最好值的，要写清靠什么资源实现。
- **R 相关**：这个数涨了，上一级目标一定受益吗？不一定的，删。
- **T 有时限**：统计周期与考核周期一致；季度考核不要用年底才出数的指标。

权重与计分规则：

- 三到六项；单项建议不低于 10%（再低等于不考核，只会分散注意力），不高于 40%（一项定生死，刷分动机最强）。
- 权重表达「这个周期最想要什么」，不是工作量占比；各项平均分配，通常说明还没想清楚重点。
- 协作紧密的岗位，留 10%–20% 权重给团队指标，避免人人只顾自己的数。
- 红线不进权重：安全事故、数据造假、合规问题单列为扣分或一票否决项。
- 每个指标给三档：门槛、目标、挑战。低于门槛记 0 分，达门槛 60 分，达目标 100 分，达挑战 120 分封顶，档间线性折算。
- 所有人的个人目标加总，要能覆盖上一级目标并留出余量，否则会出现「人人达标、部门没完成」。

把指标表另存为 kpi.csv（表头：指标、类型、权重、口径），用一行命令自查：

```bash
python3 -c "import csv;r=list(csv.DictReader(open('kpi.csv',encoding='utf-8-sig')));print('权重合计',sum(float(x['权重']) for x in r));[print('需检查',x['指标']) for x in r if not 10<=float(x['权重'])<=40 or not x['口径'].strip()]"
```

## KPI 卡片模板：每个指标一张

```
指标名称    ________    类型：结果 / 过程；领先 / 滞后
对应目标    上一级目标 ________；本指标影响它的路径 ________
定义        一句话说清数什么、不数什么
计算公式    分子 ________ ÷ 分母 ________；单位 ________
统计周期    自然月 / 季度；以每期最后一天 24 点的数据快照为准
取数位置    系统或报表 ________；取数人 ________；复核人 ________
剔除规则    如：内部测试单、重复单、客户主动撤回的单
三档目标    门槛 ____ / 目标 ____ / 挑战 ____；计分规则同上
权重        ____%；理由 ________
防刷对冲    最省力的刷法 ________；对冲指标或抽检规则 ________
口径版本    v1，生效日期 ________；周期内冻结，变更须双方书面确认
```

口径写到什么程度才够：换一个人、用同一份数据算，得出同一个数。以满意度为例，「客户满意度」只是个名字；「当月已结工单中，客户在结单后 48 小时内提交的评价里 4–5 分的占比，未评价的工单不进分母」才是口径。写完再追问三句：分母里包括什么、不包括什么；时间以下单、完成还是到账为准；两份报表对不上时以哪份为准。

## 三个岗位示例

销售（区域销售经理，季度考核）：

```
回款额          结果/滞后  35%  当期实际到账金额，扣除退款；预收未确认的不计
新签合同毛利额  结果/滞后  20%  按合同毛利计，防止低价冲量
逾期应收占比    结果/滞后  15%  期末逾期超 90 天的应收 ÷ 期末应收总额，越低越好
有效商机新增数  过程/领先  20%  进入报价阶段、且客户决策人参与过沟通的商机；只留了电话的线索不算
老客户续约率    结果/滞后  10%  到期客户中按期续约的比例
对冲：月底压货、放宽账期冲回款，由逾期应收占比兜住；刷商机，由报价阶段定义加每月抽检兜住
```

客服（一线客服，月度考核）：

```
一次解决率      结果       35%  已结工单中，7 天内同一客户未就同一问题再次进线的比例
满意度          结果       25%  评价 4–5 分的占比；当月评价不足 30 条时按团队均值计
质检得分        过程       20%  每人每月随机抽检不少于 10 单，按统一评分表打分
首次响应达标率  过程/领先  10%  在约定时长内首次响应的工单占比
工单处理量      过程       10%  由系统派单，个人不能挑单
对冲：只考处理量会抢简单单、草草结单，由一次解决率和系统派单兜住；诱导好评在质检中扣分
```

研发（后端工程师，季度考核）：

```
需求按期交付率  结果  35%  按评审时承诺日期交付且验收通过的需求 ÷ 当期应交付需求；需求变更经产品书面确认后重新承诺
线上缺陷逃逸    结果  25%  上线后 30 天内定位到本人负责模块的严重缺陷数，越少越好
技术专项里程碑  结果  20%  季度初约定一到两项，如核心接口慢查询清零，按里程碑验收
协作评价        过程  20%  产品、测试与上下游季度打分，去掉最高分和最低分后取平均
红线：违规操作导致重大故障，当期得分封顶 60 分
不要考：代码行数、提交次数、加班时长——最容易刷，也和价值无关
```

## 最常见的走样

1. **指标能被刷。** 指标一旦成为目标，就不再是好指标（古德哈特定律）。每个指标写一句「最省力的刷法」，再配对冲：数量配质量，速度配返工率，结果配过程抽检。
2. **只考核好量的。** 接单量、拜访数、代码行数好数，就只考这些；客户健康度、代码可维护性难数，就没人管。难量化的用「里程碑 + 评审人 + 评分标准」来考，承认它主观，但把谁来评、按什么评写清楚。
3. **口径每月变。** 月中改分母、临时剔除「特殊单」，员工会认定分数是算给人看的。口径带版本号和生效日期，周期内冻结；非改不可时，新旧口径的两套数并列一个周期。
4. **指标太多。** 十二个指标各占 8%，等于没有重点，精力被平均摊薄。
5. **目标值拍脑袋。** 没有历史基线时，先跑一个周期「只记录不考核」。
6. **把不可控的算给个人。** 大盘下滑、政策变化带来的波动，要事先约定调整规则，而不是事后讨价还价。

## 输出契约

1. 先交目标拆解树（上一级目标 → 因子 → 指标），再交卡片；用户没给上一级目标就先问，不自行编目标数。
2. 每个指标一张卡片，口径字段不留空；暂时取不到数的标「待建数据」，不进权重。
3. 一张权重表：合计 100%，每项一句理由，结果类合计不低于 60%。
4. 每个指标附「最省力的刷法」和对冲办法。
5. 目标值只给计算方法和建议区间，依据用户提供的历史数据；没有数据就留空，不编数字。
6. 格式为 Markdown 表格或卡片，可直接粘进文档和表格。

## 边界与不做什么

- 不替组织定目标数：目标是经营决策，本技能只负责拆解与校验。
- 不做薪酬、奖金系数、末位淘汰设计；绩效结果要用于调薪、调岗、解除劳动合同时，程序与合法性请 HR 和劳动法律师把关，本技能不做法律判断。
- 不评价具体员工，不替主管打分；用户贴来的员工数据先去掉姓名、工号。
- 不接入任何业务系统，取数由用户或数据团队完成。
- 指标跨部门冲突（例如销售要放宽账期、财务要压应收）需要双方负责人当面对齐，本技能只负责把冲突摆清楚。
