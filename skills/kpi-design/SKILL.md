# KPI 制定

定位一句话：**KPI 不是把能数的都数一遍，而是挑出三到六个「做好了目标大概率达成、想刷也刷不动」的数，再把怎么算写死。**

## 何时使用

年度或季度要给团队、岗位定考核指标，新设岗位还没有指标，老指标跑偏了、大家都在冲某一个数，上级给了一个大目标要拆到人，都适用。文字对话即可；手里有现成指标表，直接贴出来或给 CSV 文件。用户这样说时用本技能：

- 「帮我定 KPI，销售团队今年回款目标 3000 万，下面 8 个人」→ 走七步流程，先交目标拆解树
- 「客服的绩效指标怎么设，现在只考核接单量，大家都抢简单单」→ 先点出走样（能被刷），再重设并配对冲
- 「研发岗 KPI 权重怎么分，四个指标各 25% 合不合理」→ 按权重规则改，跑脚本自查
- 「满意度这个指标，口径怎么写才没人吵」→ 只写卡片里的口径字段
- 「上级给了一个大目标，怎么拆到每个人」→ 第 1–2 步：写目标、拆因子

模糊说法怎么接：「KPI 是什么」「和 OKR 有什么区别」是概念问题，两三句答完，再问要不要落到具体岗位；只说「帮我定 KPI」、没给岗位和目标，先问下文「信息不全或出错时」表里的三个问题。多轮对话按「拆解树 → 卡片 → 权重表 → 防刷」分轮交付，每轮等用户确认；用户要一次给全，就按输出契约一次交齐，缺的标 [待确认]。

不适用：

- 探索性、从零到一的项目：结果难以预先量化，说明原因后建议用 OKR 或里程碑评审，不硬套 KPI。
- 薪酬、奖金系数、末位淘汰、调岗或解除劳动合同：转 HR 和劳动法律师；本技能只把指标和口径写清。
- 评价某位员工、替主管打分：不做；可以帮着把评分标准写清楚。

## 先判断三件事

1. **考核用还是管理用。** 挂钩奖金、晋升的考核指标要少而硬，三到六个；日常管理看板可以多，但不进考核。两者混在一张表里，是 KPI 失控最常见的起点。
2. **上一级目标定了没有。** KPI 是目标的翻译，不是目标本身。部门今年要什么、要到多少，没有这句话就先回去问，不要从岗位说明书倒推指标。
3. **这个岗位能控制什么。** 指标必须落在岗位能影响的范围内：客服不该为产品退货率背全责，研发不该背营收。能影响但控制不了的，只放低权重的协同项，或者只观察不考核。

两组概念先分清，后面每个指标都要标上：

```
结果 vs 过程   看「数的是什么」：结果是要的东西（回款、续约、故障数），过程是做的动作（拜访、响应、评审）
滞后 vs 领先   看「什么时候知道」：滞后指标出数时已无法补救，领先指标能提前预警、及时调整
常见对应       结果多为滞后，过程多为领先；例外：商机储备金额是阶段性结果，却领先于回款
配比建议       考核以结果为主，结果类权重合计不低于 60%；过程指标用来预警和辅导，单独重押必被刷
```

## 制定流程：七步从目标到卡片

```
第 1 步 写目标    上一级目标写成「一句话 + 一个数 + 截止时间」，如「2027 年华东区回款 3000 万元」
第 2 步 拆因子    问「这个数由哪几项相乘或相加」：回款 = 成交客户数 × 客单价 × 回款率，拆到岗位能影响的那层为止
第 3 步 选指标    每个关键因子选一个结果指标；最关键的一两个再配一个领先指标，用来提前预警
第 4 步 过 SMART  逐条回答下面五问，答不上来的改写或删除
第 5 步 写口径    按卡片模板填齐：分子、分母、周期、取数位置、剔除规则、负责人、版本
第 6 步 分权重    按下文规则分配，合计 100%，每项附一句理由
第 7 步 回算防刷  用上一周期真实数据试算：好员工和差员工能不能拉开？有没有人不干正事也能拿高分？
```

SMART 五问（每条的例子和追问见 [references/smart-and-weights.md](references/smart-and-weights.md)）：

- **S 具体**：换一个人读，不会理解成别的。
- **M 可衡量**：现在就能取到数、知道谁来取；取不到的先建数据，本期不进考核。
- **A 可达成**：目标值一般落在过去四个周期的历史中位数与历史最好值之间。
- **R 相关**：这个数涨了，上一级目标一定受益；不一定的，删。
- **T 有时限**：统计周期与考核周期一致。

权重与计分规则（理由和计分算例见同一文件）：

- 三到六项；单项不低于 10%、不高于 40%；结果类合计不低于 60%；协作紧密的岗位留 10%–20% 给团队指标。
- 权重表达「这个周期最想要什么」，不是工作量占比；各项平均分配，通常说明还没想清楚重点。
- 红线不进权重：安全事故、数据造假、合规问题单列为扣分或一票否决项。
- 每个指标给三档：低于门槛 0 分，达门槛 60 分，达目标 100 分，达挑战 120 分封顶，档间线性折算。
- 所有人的个人目标加总，要能覆盖上一级目标并留出余量。

把指标表另存为 kpi.csv（表头：指标、类型、权重、口径），跑脚本自查权重合计、单项范围、结果类占比、空口径、红线和不该考的指标：

```bash
python3 scripts/kpi_check.py kpi.csv          # 退出码 0 通过、3 有问题要改；加 --json 输出 JSON
```

## KPI 卡片模板：每个指标一张（最常用）

```
指标名称    ________    类型：结果 / 过程；领先 / 滞后
对应目标    上一级目标 ________；本指标影响它的路径 ________
定义        一句话说清数什么、不数什么
计算公式    分子 ________ ÷ 分母 ________；单位 ________
统计周期    自然月 / 季度；以每期最后一天 24 点的数据快照为准
取数位置    系统或报表 ________；取数人 ________；复核人 ________
剔除规则    如：内部测试单、重复单、客户主动撤回的单
三档目标    门槛 ____ / 目标 ____ / 挑战 ____；计分规则同上
权重        ____%；理由 ________
防刷对冲    最省力的刷法 ________；对冲指标或抽检规则 ________
口径版本    v1，生效日期 ________；周期内冻结，变更须双方书面确认
```

口径写到什么程度才够：换一个人、用同一份数据算，得出同一个数。以满意度为例，「客户满意度」只是个名字；「当月已结工单中，客户在结单后 48 小时内提交的评价里 4–5 分的占比，未评价的工单不进分母」才是口径。写完再追问三句：分母里包括什么、不包括什么；时间以下单、完成还是到账为准；两份报表对不上时以哪份为准。

销售、客服、研发三个岗位的整套指标（含权重、口径和对冲）见 [examples/role-kpi-examples.md](examples/role-kpi-examples.md)。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（模板） |
|---|---|---|
| 没给上一级目标（最常见） | 只问三个：目标（一句话 + 数字 + 截止时间）、岗位与人数、考核周期；其余按本页规则先填并标 [待确认]，目标值留空 | 「先确认三件事：这一期部门要达成什么、数字多少、截止哪天？是哪个岗位、几个人？按月还是按季考核？其余我先按常见做法填，标了 [待确认] 的请你核对。」 |
| 没有历史数据却要目标值 | 三档目标只给算法、不填数；建议先跑一个周期只记录不考核 | 「没有历史数据我不编目标值。先给算法：拿到四个周期的实际值后，目标落在中位数与最好值之间；这一期建议只记录、不考核。」 |
| 输入自相矛盾（权重合计不是 100%、单项超过 40%、同一指标既说是结果又说是过程） | 指出冲突在哪几项，给两种改法让用户选 | 「权重合计 110%，多出的 10% 在 A 和 B 上。两种改法：A 从 30% 降到 20%；或者 B 改为只观察、不进权重。你选哪种？」 |
| 格式不对（表里没有权重或口径列，权重写成「高 / 中 / 低」） | 给可复制的表头；高中低请用户换成百分数，或我按「高 > 中 > 低、合计 100%、单项 10%–40%」先给一版并标 [待确认] | 「表里缺『口径』列，复制这行当表头：指标,类型,权重,口径。权重请写成百分数；要我先按高中低排一版也行，我会标 [待确认]。」 |
| 超出范围（奖金系数、末位淘汰、劳动争议、给某人打分） | 说明不做，转 HR 和劳动法律师；员工数据先去掉姓名、工号 | 「奖金系数和末位淘汰涉及薪酬制度和劳动法，要由 HR 和劳动法律师把关；我先把考核指标和口径写清楚，你拿去和他们对。」 |
| 时间紧，只要最小可用版 | 交最小版：三个指标，各一句口径、一个权重、一句防刷，外加一条红线；卡片其余字段标 [待补]，下一轮补齐 | 「先给你最小可用版：三个指标，各有口径、权重和防刷办法，外加一条红线；完整卡片下一轮补。」 |
| 用户坚持越界（要我直接定目标数、按指标给某员工打低分） | 守住边界，给能做的替代 | 「目标数是经营决策，我不替你定；给我过去四个周期的实际值，我帮你算出建议区间。」 |
| 指标暂时取不到数 | 卡片照写，口径标「待建数据」，本期权重填 0、只观察 | 「这个指标现在取不到数，先标『待建数据』，本期不进权重，等数据建好下期再进。」 |

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 0，「全部通过」 | 权重、口径、结果类占比都符合规则 | 继续写卡片 |
| 3，「[需修改] …」 | 查出问题，逐条带行号列出 | 按提示改表，再跑一次 |
| 1，「缺少必填参数」「表头缺少：…」 | 没给文件，或表头不是 指标/类型/权重/口径 | 复制报错里给的表头；命令写成 python3 scripts/kpi_check.py kpi.csv |

## 输出契约

交付物按下面的顺序，每次都一样：

1. **目标拆解树**：上一级目标 → 因子 → 指标。用户没给上一级目标就先问，不自行编目标数。
2. **指标卡片**：每个指标一张，按模板字段填齐；口径不留空，暂时取不到数的标「待建数据」、不进权重。
3. **权重表**：指标、类型、权重、一句理由；合计 100%，结果类合计不低于 60%。
4. **防刷对冲表**：每个指标「最省力的刷法」和对冲办法。
5. **待确认清单**：汇总所有 [待确认] 和 [待补]，写明需要谁提供。

占位符规则：[待补] = 只能由用户提供、我不编的内容（目标数、历史数据、取数系统、负责人）；[待确认] = 我按本页常见做法先填的默认值，要用户点头；「待建数据」= 现在取不到数的指标。目标值只给计算方法和建议区间，依据用户提供的历史数据。格式为 Markdown 表格或卡片，可直接粘进文档和表格。

交付前自检（每条都答「是」才交）：

- [ ] 权重合计 100%，每项在 10%–40%，结果类合计不低于 60%？
- [ ] 进考核的指标 3–6 个，红线单列、没有占权重？
- [ ] 每张卡片的口径写了分子、分母、周期、取数位置，或标了 [待补]？
- [ ] 每个指标都有「最省力的刷法」和对冲？
- [ ] 没有任何我编出来的目标数、历史数据或系统名？
- [ ] 所有 [待确认]、[待补] 都进了待确认清单？

## 示例

（示例，场景虚构）

> 用户：研发岗 KPI 权重怎么分？现在是按期交付、线上缺陷、代码行数、协作评价四个指标，各 25%，合不合理？

助手：信息够用，不追问，直接给结论和改后的表；拿不准的标 [待确认]。

**结论**：不合理，两处要改。代码行数最容易刷、也和价值无关，换掉；四项平均分配，说明还没想清这个周期最想要什么。

| 指标 | 类型 | 权重 | 理由 |
|---|---|---|---|
| 需求按期交付率 | 结果 | 35% | 本周期最想要的是按承诺交付 |
| 线上缺陷逃逸 | 结果 | 25% | 质量兜底，赶工期不能拿质量换 |
| 技术专项里程碑 | 结果 | 20% | 替换代码行数；季度初约定一到两项，按里程碑验收 [待确认：具体专项] |
| 协作评价 | 过程 | 20% | 产品、测试与上下游打分，去掉最高分和最低分后取平均 |

- 结果类合计 80%。红线单列、不占权重：违规操作导致重大故障，当期得分封顶 60 分。
- 防刷：按期交付率的最省力刷法是把承诺日期报宽 → 承诺日期在需求评审时定，需求变更经产品书面确认后才重新承诺；缺陷逃逸靠「严重缺陷」的判定标准兜底 [待补：由测试负责人给出判定标准]。
- 自查脚本输出（把上表存成 kpi.csv 后运行）：

```
读取 kpi.csv（UTF-8）：进考核的指标 4 个，权重合计 100%，其中结果类 80%
结论：全部通过
```

- 待确认清单：技术专项的具体内容（研发负责人）；严重缺陷判定标准（测试负责人）；三档目标值（需要过去四个周期的实际数据）。

更多完整示例：销售团队从一句目标到整套卡片的多轮对话见 [examples/sales-team-kpi.md](examples/sales-team-kpi.md)；三个岗位的指标表见 [examples/role-kpi-examples.md](examples/role-kpi-examples.md)。

## 常见问题（FAQ）

**KPI 和 OKR 有什么区别，该用哪个？** KPI 考核必须守住的结果，挂钩奖金，要少而硬；探索性、从零到一、结果难以预先量化的项目，更适合 OKR 或里程碑评审。

**没有历史数据，目标值怎么定？** 先跑一个周期「只记录不考核」拿到基线；有了四个周期的数据，目标一般落在历史中位数与最好值之间。我不替你编数字。

**权重能不能平均分？** 不建议。权重表达这个周期最想要什么，平均分配通常说明重点还没想清；单项 10%–40%，结果类合计不低于 60%。

**指标定几个合适？** 进考核的三到六个；日常管理看板可以多，但不进考核。

**周期中途发现口径有问题，能改吗？** 口径带版本号和生效日期，周期内冻结；非改不可时双方书面确认，新旧口径的两套数并列一个周期。

**能直接帮我录进绩效系统或发给团队吗？** 不能。本技能不接入任何系统、不代发，交付的是 Markdown 表格和卡片，由你粘贴和发布。

**考核结果能直接用来调薪或末位淘汰吗？** 本技能不做薪酬和末位淘汰设计；用于调薪、调岗、解除劳动合同时，程序与合法性请 HR 和劳动法律师把关。

**时间很紧，能先给个简版吗？** 可以：三个指标，各一句口径、一个权重、一句防刷，外加一条红线；完整卡片下一轮补。

## 常见错误（反模式）

每条：错误做法 → 为什么错 → 正确做法。

1. **指标能被刷** → 指标一旦成为目标，就不再是好指标（古德哈特定律）→ 每个指标写一句「最省力的刷法」，再配对冲：数量配质量，速度配返工率，结果配过程抽检。
2. **只考核好量的**（接单量、拜访数、代码行数）→ 难数的客户健康度、代码可维护性就没人管 → 难量化的用「里程碑 + 评审人 + 评分标准」来考，承认它主观，但把谁来评、按什么评写清楚。
3. **口径每月变**（月中改分母、临时剔除「特殊单」）→ 员工会认定分数是算给人看的 → 口径带版本号和生效日期，周期内冻结；非改不可时，新旧口径的两套数并列一个周期。
4. **指标太多**（十二个指标各占 8%）→ 等于没有重点，精力被平均摊薄 → 进考核的留三到六个，其余放管理看板。
5. **目标值拍脑袋** → 没有基线，目标要么够不着、要么白送 → 先跑一个周期「只记录不考核」。
6. **把不可控的算给个人**（大盘下滑、政策变化带来的波动）→ 事后讨价还价，考核失去公信力 → 事先约定调整规则。
7. **考核指标和管理看板混在一张表** → KPI 失控最常见的起点 → 考核的少而硬，看板的可以多但不进考核。
8. **考代码行数、提交次数、加班时长** → 最容易刷，也和价值无关 → 换成交付、缺陷、里程碑这类结果指标。

## 边界与不做什么

- 不替组织定目标数：目标是经营决策，本技能只负责拆解与校验。
- 不做薪酬、奖金系数、末位淘汰设计；绩效结果要用于调薪、调岗、解除劳动合同时，程序与合法性请 HR 和劳动法律师把关，本技能不做法律判断。
- 不评价具体员工，不替主管打分；用户贴来的员工数据先去掉姓名、工号。
- 不接入任何业务系统，取数由用户或数据团队完成。
- 指标跨部门冲突（例如销售要放宽账期、财务要压应收）需要双方负责人当面对齐，本技能只负责把冲突摆清楚。
