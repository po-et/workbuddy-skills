# 社团招新

定位一句话：**招新不比谁的报名表长，比的是一个月后还有多少人在参加活动。** 招新前想清楚要什么人，招新时说真话，招进来 7 天内让新人做成一件事。

## 何时使用

- 「下周百团大战，我们社团摆摊怎么吸引人」
- 「招新推文标题怎么写，正文写什么」
- 「报名表要收哪些信息，隐私说明怎么写」
- 「报名的人太多，面试怎么安排、怎么筛」
- 「招进来的新人，第一次活动后就不来了」
- 「导出的报名表有重复，帮我统计去重」

不适用（遇到时这样处理）：

- 社团注册、年审、经费报销、指导老师聘请：以学校团委或社团管理部门的规定为准，本技能不涉及，建议直接问他们。
- 你是去参加社团面试的新生：转「学生会面试」技能（`student-union-interview`）。
- 商业拉新、地推返利、刷阅读量点赞：不做。

学生会各部门招新可以参照本流程，但选拔条件和程序以学校团委、学生会章程为准。

## 第 1 步：招新前定位与名额

先回答四个问题，写成一张定位卡：

1. 我们是干什么的？一句话，不超过 20 字。
2. 新人来了第一个月具体做什么？列 3 件事。
3. 需要付出什么？每周时间、会费或器材费，如实写。
4. 今年要几个人？

名额按需要的稳定成员倒推：**名额 ≈ 需要的稳定成员数 ÷ 往年留存率**。留存率用你们往年「报名 → 学期末还在参加活动」的人数算；没有记录就先估一个保守值并标 [待确认]，今年开始记。

示例（数字为假设）：需要 20 个稳定成员，往年留存约四成 → 名额约 50 人。

## 第 2 步：海报与推文

五个标题公式（示例都是虚构的，换成你们的真实内容）：

| 公式 | 示例 |
|---|---|
| 身份召唤 + 具体收获 | 「手机党也能进：摄影社教你拍出第一张校园大片」 |
| 数字 + 场景 | 「每周一次外拍，一学期攒一本自己的影集」 |
| 问题 + 反差 | 「不会乐器，也能进乐队吗？」 |
| 时间地点 + 行动 | 「周六上午，一食堂门口，来领你的第一张明信片」 |
| 成员原话 | 「"大一进来时我连快门在哪都不知道"——摄影社新人手记」 |

规矩：不用「最」「第一」「100%」；不承诺加分、奖学金、保研这类社团给不了的东西；照片和成员原话用真的，并征得本人同意。

推文七段：标题 → 一句话我们是谁 → 你能在这里做什么（3 个具体活动 + 真实照片）→ 我们想找什么样的你 → 时间投入与费用 → 怎么报名（表单二维码 + 截止时间）→ 招新日程与社团公共联系方式。完整模板和海报文字模板见 [references/post-template.md](references/post-template.md)。

海报三秒原则：远看只看得清社团名、一句卖点、二维码、时间地点。微信群二维码有有效期（以微信当前规则为准），印在海报上容易失效，海报上放报名表或公众号的码。

## 第 3 步：摆摊动线与话术

摊位分三区，顺着人流方向摆：

- 吸引区（最前）：作品、成品、能上手的体验（拍一张、弹一下、答一题）。
- 讲解区（中间）：1–2 人，按话术卡讲 30 秒。
- 登记区（侧后）：扫码填表，别堵在正前方。

人手：招呼 1 人（站在摊位前一两步，不拦路）、讲解 1–2 人、登记 1 人、机动或拍照 1 人；高峰期提前排班轮换。

30 秒话术：用一个问题开场（「你平时用手机拍照多吗？」，别说「了解一下吗」）→ 一句话介绍 → 一个具体活动 → 邀请体验或扫码 → 道谢。

常见回应：

- 「没时间」→ 说清最低投入：「每周一次活动，其余自愿。」
- 「零基础」→ 「第一个月就是带新手的。」（前提是真的有新手安排）
- 「要交钱吗」→ 如实说金额和用途，没有就说没有。
- 「我再看看」→ 递一张宣传卡：「欢迎来看我们周六的公开活动。」不纠缠。

完整话术卡、动线示意和排班表见 [references/booth-script.md](references/booth-script.md)。场地和时间以团委或社团管理部门的通知为准；不拉扯、不堵路、不强迫扫码，不在摊位上用纸质表格收集手机号。

## 第 4 步：报名表（最少必要信息）

| 类别 | 字段 | 说明 |
|---|---|---|
| 必要 | 姓名、年级、专业或学院、一个联系方式（手机号或微信号，二选一）、意向部门 | 年级、部门做成单选或多选题，别让人自由填写，统计才不乱 |
| 按需 | 学号 | 只有学校社团系统或第二课堂登记要求时才收，并写明用途 |
| 选填 | 相关经历或作品链接、每周可投入时间、可参加面试的时段 | 标明选填 |
| 不收 | 身份证号、家庭住址、家庭经济情况、照片、生日、宿舍号 | 招新用不到 |

放在表单开头的隐私告知：

```
你填写的信息只用于[社团名]本次招新的联系和面试安排，由[招新负责人职务]保管，不会提供给其他个人或组织。招新结束后[N]周内删除未录取同学的信息。有疑问请联系[社团公共邮箱或公众号]。提交即表示你同意以上用途。
```

这是《个人信息保护法》中告知同意、最少必要等原则在招新场景的通用做法，具体以学校规定为准。导出的表格不发大群；共享在线表格只给负责人权限（设置方法以所用工具的官方帮助为准）。完整报名表模板见 [references/signup-form.md](references/signup-form.md)。

## 第 5 步：面试与筛选

1. 先定标准再面试：3 条必要条件（例如能保证每周一次活动）+ 2 条加分项，每条 1–3 分，按表打分。
2. 形式选一种：5–8 分钟短面谈、作品审核，或一次试活动（让对方体验真实的社团日常，最能看出合不合适）。
3. 报名截止后 2–3 天内发面试通知，给 2–3 个时段选。
4. 录取和未录取都要通知；未录取的邀请参加公开活动。
5. 不以外貌、地域、家庭背景筛人；不问与社团无关的隐私；不搞羞辱式「压力面」，不设饭局酒局。

打分表和各类通知模板见 [references/signup-form.md](references/signup-form.md)。

## 第 6 步：招新后 7 天留人计划

| 时间 | 做什么 |
|---|---|
| 第 0 天（录取当天） | 发录取通知；建新人群（邀请制），群公告写清第一次活动的时间地点 |
| 第 1–2 天 | 发新人手册（社团介绍、本学期日程、有事问谁）；给每个新人配一个老成员搭子 |
| 第 3–5 天 | 第一次活动 |
| 第 6–7 天 | 发活动照片和作品；3 题匿名回访；公布下一次活动 |

第一次活动的设计原则：90 分钟以内、每个新人都有事做、结束时有一件成品。结构：破冰 15 分 → 体验核心技能 45 分 → 成果展示 20 分 → 预告下次 10 分。

记三个数：录取人数 → 第一次活动到场人数 → 第四周仍在参加的人数。明年定名额就用它。

## 第 7 步：报名表统计与去重（脚本）

把问卷或表单工具导出的结果存成 CSV（只能导出 .xlsx 的，用 Excel 或 WPS「另存为」CSV；导出入口以所用工具的官方帮助为准），在本技能目录下运行：

```bash
python3 scripts/signup_stats.py 报名表.csv
python3 scripts/signup_stats.py 报名表.csv --out 去重后.csv
python3 scripts/signup_stats.py 报名表.csv --col 意向部门=第一志愿 --col 意向部门=第二志愿 --json
```

- 识别列：自动认姓名、学号、联系方式、年级、专业、意向部门、提交时间；认不出的用 `--col 字段=列名` 指定。联系方式、意向部门可以是多列。
- 去重：学号相同或联系方式相同视为同一人，保留最后提交的一条；「无」「同手机号」这类占位答案不参与判重；姓名 + 年级 + 专业相同但学号和联系方式都不同的，只列为「疑似重复」请人工确认。
- 统计：按年级、专业、意向部门（多选拆开计人次）计数；有两列以上志愿时另计第一志愿；列出缺联系方式、缺意向部门的行。
- 只读：默认只打印结果，联系方式和学号脱敏；给 `--out` 才写新文件（先写临时文件再替换，不覆盖输入文件，目标已存在要加 `--force`）。支持 UTF-8、GBK 和 UTF-16 编码。

先用样例试跑：`python3 scripts/signup_stats.py examples/sample_signups.csv`。样例数据全部虚构，手机号用不存在的 100 号段；应输出「15 行 → 11 人（合并 4 条重复）」，并提示 1 组疑似重复、2 行缺字段。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（模板） |
|---|---|---|
| 缺关键信息（只说「帮我做招新」） | 先问 3 个：社团做什么、今年要多少人、哪天招新以及摆不摆摊；其余按「线下摆摊 + 线上表单 + 一次短面谈」写，标 [待确认] | 「先告诉我三件事：社团一句话是做什么的、今年想招多少人、哪天招新、摆不摆摊。其余我按常见流程先写，标 [待确认] 的你再改。」 |
| 要求自相矛盾（写「零基础友好」却要求交作品） | 指出矛盾，给两种理解 | 「你说零基础友好，报名表又要求作品——是[零基础也收，作品选填]，还是[有基础优先，作品必填]？推文写法不一样。」 |
| 想在推文里写做不到的承诺（「加入必得综测加分」） | 删掉，换成社团真能给的；坚持也不写 | 「加分不是社团能决定的，写了容易被投诉。换成我们真能给的：……」 |
| 报名表想收身份证号、住址、照片 | 说明不必要和风险，给替代字段 | 「招新用不到身份证号和住址，收了还要担保管责任。学校系统确实要学号的，单独写明用途。」 |
| 想批量加好友、自动拉群、刷阅读量、爬别的社团的报名信息 | 拒绝，说明边界，给合规做法 | 「批量加好友和刷量违反平台规则，账号可能被限制。我们用海报二维码 + 自愿进群 + 公开活动来拉人。」 |
| 时间紧（明天就摆摊） | 最小可用版：一句话定位 + 30 秒话术 + 最少字段报名表 + 海报文字 | 「今晚先做四样：一句话定位、30 秒话术、报名表、海报文字。推文和留人计划摆完摊再补。」 |
| 超出范围（社团注册、经费、社团纠纷） | 转学校团委或社团管理部门 | 「这部分以学校团委或社团管理部门的规定为准，建议直接问他们。」 |
| 表头认不出、脚本报错 | 按下表查退出码；让用户发表头原文，代写 `--col` 参数 | 「脚本没认出『意向部门』这一列，把表头那一行发我，我给你写好 --col 参数。」 |

脚本退出码：

| 退出码 / 报错开头 | 原因 | 修正办法 |
|---|---|---|
| 0 | 成功 | — |
| 1 `参数错误` | `--col` 写法不对、列名不存在、`--out` 指向输入文件或已存在未加 `--force`、`--top` 为负数 | 按提示里列出的表头改列名；换一个输出文件名 |
| 2 `读不了文件` / `写不了文件` | 路径不存在、传了文件夹、没有权限、编码无法识别、输出文件夹不存在 | 检查路径；用 Excel 或 WPS 另存为「CSV UTF-8」 |
| 3 `表格内容无法识别` | 空文件、只有表头、传了 .xlsx 或 .xls、找不到学号和联系方式列 | 另存为 CSV；用 `--col 联系方式=列名` 指定 |
| 130 | 按了 Ctrl+C | 重新运行即可，输入文件不会被改动 |

## 输出契约

完整招新方案按以下固定顺序给出。用户只要其中一部分（例如只要话术）时，只给那部分，顺序与占位规则不变：

1. 定位卡：一句话定位、新人第一个月做的 3 件事、时间与费用、名额和倒推过程。
2. 招新日程：倒排时间表（开始宣传 → 摆摊 → 报名截止 → 面试 → 录取 → 第一次活动）。
3. 推文与海报文字：3 个备选标题 + 七段正文 + 海报四要素。
4. 摆摊方案：三区动线 + 排班 + 30 秒话术卡。
5. 报名表：字段表 + 隐私告知。
6. 筛选流程：打分表 + 通知模板。
7. 7 天留人计划：日程 + 第一次活动流程。
8. 数据统计（用户提供 CSV 时）：脚本命令、结果解读、需要人工确认的行。

占位规则：社团名、日期、地点、费用等用户没给的写 [待补]；需要用户核实的数字（名额、留存率）写 [待确认]；照片、成员原话、往届数据只用用户提供的。

交付前自检（逐条答是/否）：

- [ ] 推文没有「最 / 第一 / 100%」，也没有加分、保研等做不到的承诺？
- [ ] 报名表字段都在「必要 / 按需 / 选填」内，并附了隐私告知？
- [ ] 时间投入和费用写清楚了（没有就写「无」）？
- [ ] 成员原话、照片、数据都来自用户提供，没有编造？
- [ ] 跑了脚本的：疑似重复交给人工确认，转述结果时联系方式保持脱敏？
- [ ] 发推文、建群、发通知都只给草稿，由用户自己操作？

## 示例

示例（虚构）。用户：「我们是光圈摄影社，下周六百团大战摆摊，想招 40 人左右，零基础也收，会费 30 元一学期（打印作品和外拍交通）。帮我写摆摊话术和推文标题。」

助手先问一个问题：「新人第一个月具体会做哪几件事？话术里要说得出来。」用户：「第一周手机摄影入门课，第二周校园外拍，第四周办一次作品小展。」

交付（节选，结构完整）：

> **推文标题（3 选 1）**
> ① 手机党也能进：光圈摄影社带你拍出第一张校园大片
> ② 一个月：一节入门课、一次外拍、一场属于你的作品小展
> ③ 不会用相机，也能进摄影社吗？
>
> **30 秒话术卡**
> 开场：「同学，你平时用手机拍照多吗？」
> 介绍：「我们是光圈摄影社，零基础也收。」
> 具体活动：「第一周上手机摄影入门课，第二周校园外拍，第四周给新人办作品小展。」
> 邀请：「这边扫码报名，截止到[日期待补]。」
> 应答「要交钱吗」：「一学期会费 30 元，用在打印作品和外拍交通上。」
> 结束：「谢谢你停下来看！周六的公开外拍也欢迎来。」
>
> **待确认**：摊位位置 [待补]；报名截止日期 [待补]；公开外拍是否对非成员开放 [待确认]。

完整招新包（定位卡、日程、推文全文、报名表、7 天留人计划）见 [examples/photography-club-kit.md](examples/photography-club-kit.md)；脚本样例数据见 [examples/sample_signups.csv](examples/sample_signups.csv)。

## 常见问题（FAQ）

**Q：报名的人很多，面试来的人很少，怎么办？**
A：报名到面试别隔太久（截止后 2–3 天内通知），给几个时段选，面试前一天提醒一次。

**Q：招新推文阅读量很低怎么办？**
A：不要刷量。请现有成员转发到自己的班级群和朋友圈，摆摊时引导扫码关注，标题用上面的公式重写。

**Q：能不能直接帮我发推文、帮我拉群？**
A：不能。我只起草，发布和建群由你们自己操作；公众号等平台的功能以其官方文档为准。

**Q：面试要不要搞得很严格？**
A：兴趣社团一般以双向了解为主；一次试活动往往比严格面试更能看出合不合适。

**Q：会费要不要写在推文里？**
A：要，写清金额和用途。事后才说收费，最伤信任。

**Q：要不要收学号？**
A：学校社团系统或第二课堂登记要求时才收，并在隐私告知里写明用途。

**Q：新人第一次活动后就不来了，怎么办？**
A：看 7 天计划里有没有让他做成一件事、有没有老成员搭子；用 3 题匿名回访找原因。

**Q：表格里「大一」「2026级」混着写，脚本会分开统计吗？**
A：会，脚本不猜你们的年级口径。这次先在表格里统一写法再跑；下次把年级做成单选题。

## 常见错误（反模式）

- 推文写成社团简介大全 → 新人只关心「我能做什么、要花多少时间」→ 用七段结构，先说新人能做的 3 件事。
- 承诺加分、保研、奖学金 → 兑现不了，招来的人也会走 → 只写社团真能给的。
- 摊位前摆满桌子，人站在桌子后面 → 路过的人没有停下的理由 → 把能上手的体验放在最前面。
- 开口就是「同学了解一下吗」→ 最容易被拒绝 → 用一个和对方有关的问题开场。
- 报名表收身份证号、住址 → 没必要，还有泄露风险 → 最少必要字段 + 隐私告知。
- 年级、部门让人自由填写 → 统计一团乱 → 做成单选或多选题。
- 录取后一周没动静 → 新人热情最高的时候被浪费 → 7 天内办第一次活动。
- 只通知录取的人 → 未录取的人一直在等 → 录取和未录取都通知。

## 边界与不做什么

- 只起草文案、表格和方案，不代发推文、不代建群、不代发通知；所有发送动作由你们确认后自己操作。
- 不做违反平台规则的引流：个人微信自动化、批量加好友或自动拉群、刷阅读量点赞、爬取他人或其他社团的数据。
- 报名信息只用于招新：不收身份证号、住址等与招新无关的敏感信息；未录取者的信息按告知的期限删除；隐私要求以学校规定和相关法律为准。
- 推文里的照片、成员原话、数据必须真实并征得本人同意；示例里的社团、人物、数字都是虚构的。
- 社团注册、年审、经费、纠纷以学校团委或社团管理部门的规定为准。
- 筛选不歧视，不设饭局酒局，不搞羞辱式面试。
