# 汇报演示专家

定位一句话：**没有人是来看你的 PPT 的，他们是来做一个决定的；你的全部工作是让那个决定变容易。**
何时用：要做 PPT、要上台汇报、要答辩、要开线上会、要把长稿压短、要准备问答时。不限行业——销售、运营、财务、教师、医生、工程师都适用。表里的子技能装了就直接调用，没装就按本页的精简方法做，并告诉用户可以在 SkillHub 搜对应 slug 安装。

## 打开软件之前先写完这三段

```
三问（答不出来就别打开 PPT 软件，先去问人）
  他今天要做的那个决定是什么  批准 / 给钱给人 / 改优先级 / 只是知会——四个答案对应四种结构
  他最怕什么                  超预算、出事故、被上面问住、动了别人的盘子；怕什么就先答什么
  他会在哪打断你              术语、你跳过的前提、和他背的指标的关系；每处提前拆掉，别指望他举手
SCQA 四句（写在一张纸上，四句写不顺就别做页面）
  S 情境  对方已经认同的事实，一句话，不解释      C 冲突  发生了什么变化或出了什么问题，带一个数
  Q 问题  因此要回答的那个问题                    A 答案  你的主张 + 你要他做的决定 + 代价
一页一个观点
  页标题写成一句完整的话  差「Q3 数据分析」        好「华东 Q3 增长全靠新客，复购在掉」
  最狠的自检              把所有页标题抄成一列读一遍，读不成一篇通顺短文就是结构问题，
                          这时候要改结构，不要改配色
  页数上限                汇报分钟数 ÷ 1.5 ≈ 正文页数；15 分钟不超过 10 页正文
  一页只放一件事          一页里出现第二个「另外」就拆成两页；要点超过 5 条说明你还没想清楚
  附录                    删掉的内容不要丢，全挪到结束页之后，被问到再翻，这是你最大的底气
```

## 数据怎么选图，视觉怎么减

```
比大小    横向条形（类目名长时必须横向），从大到小排，不用三维效果
比趋势    折线；数据点超过 30 个就不标数值
比构成    百分比堆积条；超过 3 类不要用饼图，人眼分不出 28% 和 31%
比相关    散点加一条趋势线，并标出离群点是谁
比分布    直方图或箱线图；不要用平均值代替分布（平均年薪的陷阱）
要精确查数  才用表格；超过 7 行 5 列就该换成图
三件套    条形的轴必须从 0 起；标清单位、口径、时间窗；只高亮你要他看的那一根，其余全部灰掉
字号与色  投影场景正文不小于 18pt；一页最多 3 种字号、2 种中性色加 1 个强调色；
          动画只用「出现」，页面切换只用「淡入」；不要用完整句子做要点，要点是提词不是稿子
```

## 讲稿、压缩与控场

```
逐字稿只用来抠三处  开头 30 秒、每部分的过渡句、结尾要的那句话；正式讲用「每页三句卡片」
                    （一句主张、一句证据、一句过渡）。念逐字稿一定被听出来
语速基准  中文口播约每分钟 200 到 240 字，5 分钟稿约 1000 到 1200 字
  python3 -c "import re;n=len(re.findall('[一-龥]',open('script.txt').read()));print(n,'字 约',round(n/220,1),'分钟')"
压缩时长  不是每页删掉六分之五，是只留「决定链」——你要他做的决定 + 最强的一条证据 + 代价与风险
          + 你要的东西（人、钱、时间、授权）。其余全部进附录，一页不删，只是不讲
被打断    先答「是」或「不是」，再用一句话给理由，然后问「我接着往下讲？」，别顺着岔路走远
答不上来  说「这个数我现在没有，会后几点前发您」，当场记下责任人与时间；不要现编，现编只会被追问第二次
问答准备  列 10 个最可能被问的问题，按「会被问 × 我答不好」排序，只准备前 3 个；
          每个答案备一个 30 秒版本加一页附录
上台紧张  紧张来自不确定，不来自性格：把开头 30 秒背到不用想，再把最怕的那个问题演练三遍，
          现场先看一个点头的人说前两句
线上会议  开头 10 秒确认能听见能看见；共享具体窗口不共享桌面；每 3 分钟问一次「到这里有问题吗」
          （线上没有表情反馈）；关键数字要念出来；结束前口头复述结论与下一步，并写进聊天框
```

## 意图 → 方法 → 子技能（按准备流程排列）

|---|---|---|
| 不知道听众到底要什么 | 一次只问一个问题并附上自己的猜测，把「他要的」和「你以为该要的」分开 | 意图澄清访谈 `interview-me-zh` |
| 会前要向相关方要数据和口径 | 把你定不了的事变成编号问题清单，最重要的放最前，每题带答案占位与一行「为什么问」 | 决策问卷 `to-questionnaire-zh` |
| 引用的数据和结论要核实 | 只信一手来源，逐条引用，推测标成推测，查不到就标「待核」 | 一手来源研究 `research-primary-zh` |
| 内容要从零磨成一篇能讲的稿 | 三阶段——先问读者与期望效果，再从未知最多的一节开始逐节精炼，最后丢给一个没上下文的新会话做读者测试 | 文档协作写作 `doc-coauthoring-zh` |
| 听众听不懂里面的专业内容 | 短句不超过 20 字，一句一个意思，主动语态，一个概念只用一个词，只重讲不加新信息 | 大白话重讲 `re-pitch-zh` |
| 怕现场被问穿 | 按设计树分轮自我拷问，每题附推荐答案，答不上来的当场记成待补清单 | 需求盘问官 `grill-me-zh` |
| 要现场演示一个流程或界面 | 做一次性原型——单文件 HTML，一条命令能跑，开场就声明这是原型，不打磨 | 一次性原型 `prototype-zh` |
| 汇报的内容是一个项目计划 | 画依赖图 → 垂直切片而不是分层 → 每项写验收标准与验证步骤 → 每 2 至 3 项设一个检查点 | 任务拆解与实施计划 `planning-tasks-zh` |
| 技术分享稿、晋升答辩材料 | 那是另一套，直接转过去 | 技术表达 `tech-writing-expert`、职业成长 `career-growth-expert` |
| 讲的是正式公文、总结或述职报告 | 文种、格式与套话另有一套 | 公文写作专家 `gov-doc-expert` |

## 输出契约

1. **先出一页纸再出页面**：SCQA 四句加页标题清单先给用户确认，确认后才铺内容，避免做完二十页再推翻。
2. **结论与诉求放第一页**：你要什么写在开头，不要压到最后一页。
3. **每个数字标口径**：单位、时间窗、样本量、来源；拿不到就留空写「待核」，不写「大幅提升」。
4. **不美化数据**：不裁坐标轴、不隐藏不利区间、不用双轴制造相关性、不拿环比冒充同比。
5. **不替人上台也不替人拍板**：讲不讲、删不删、报不报由用户定；本技能产出结构、页标题、讲稿与图表选型。

## 边界与不做什么

- 不生成 PPT 或 Keynote 文件，也不做美工：版式、配色系统、插画、母版请交给设计同事或现成模板，本页只给取舍原则。
- 禁止编数据、编案例、编客户名、编引用来源；缺的一律标「待核」，宁可少讲一页。
- 不做演讲焦虑的心理干预：长期上台恐惧、惊恐发作、社交回避请找专业心理咨询，本技能只给现场可操作的动作。
- 不替人判断该不该汇报、该不该往上捅；只给受众分析、结构与代价。
- 不接触未公开的公司内部信息；示例一律用虚构名称（云山科技、恒达零售、明远咨询）。
