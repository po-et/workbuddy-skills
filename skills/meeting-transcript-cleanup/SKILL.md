# 会议录音整理

定位一句话：**纪要不是把转写稿删短，而是回答三个问题：定了什么，谁在什么时候之前做什么，还有什么没定。其余内容都为这三件事服务。**

## 何时使用

手上已有会议软件导出或人工听写的转写文本（带不带说话人、时间戳都行），要整理成能发出去的纪要；会开完大家对「到底定了什么」说法不一；要从一场长会里把待办捞出来。用户通常这样说：

- 「这是周会的转写稿，帮我整理成纪要，重点列待办」
- 「会议记录太乱了，全是嗯啊那个，看不出谁负责什么」
- 「从这份评审会记录里把决议、待办和负责人捞出来」
- 「开完会大家对定了什么说法不一，帮我对一下原稿」
- 「这是访谈逐字稿，帮我精校一下，不用做纪要」（精校模式，见下文第 5 问）

不适用：

- **只有录音或视频、没有文字**：本技能不转写。请用户先用会议软件自带的转写或其他转写工具生成文字稿再来；只想剪音频本身，交给音频剪辑类技能。
- **会前写议程、会议通知**：直接简答，或交给写作类技能；本技能只处理开完会的转写稿。
- **判断会上的决定是否合规、纪要能否当证据**：说明要问法务或律师，本技能只整理内容。

## 先判断什么：动手前问清五件事

1. **纪要给谁看。** 只给参会人对齐，可以简；给缺席者和上级，要补背景；给客户或外部，措辞要审，内部讨论不外发。
2. **这是什么会。** 决策会（评审、立项）以决议为主；同步会（周会、站会）以进展和待办为主；讨论会（头脑风暴、复盘）以观点分组和未决问题为主。
3. **转写稿质量如何。** 有没有说话人标注：「说话人1」对应谁要问用户，不猜；有没有时间戳；专有名词、人名、数字错得多不多。
4. **有没有议程。** 有就按议程分议题；没有就按话题切换处切段。
5. **要不要逐字引用。** 涉及客户承诺、合规事项、有争议的决定时，关键句保留原话。用户要的若是访谈、讲座的精校稿而不是纪要，就只删语气词、重复和明显口误，保留原有顺序与句式，不抽决议。

## 整理流程：六步

```
第 1 步 通读打标    先不改字，给每段打标：【决】决议 【办】待办 【疑】未决 【数】数字 【争】分歧 【闲】闲聊
第 2 步 切分议题    按议程或话题转换处（「下一个」「另外说一下」「回到刚才」）切段；
                   同一议题前后散落的发言合并到一起，注明起止时间
第 3 步 去掉口语    按下方规则改成书面语，只改表达，不改意思和语气强度
第 4 步 抽决议待办  按下方判定标准抽取，每条附时间戳
第 5 步 标未决待核  未决问题写清卡在哪、谁推动；听不清、疑似错字、前后矛盾的数字，一律标【?】
第 6 步 回查原稿    每条决议和待办回到时间戳处再读一遍，确认没有张冠李戴
```

超过一小时的会，按 15 到 20 分钟一段做第 1 步，全部打完标再按议题合并。给上级的一页版只留决议和待办，给参会人的详版再加议题要点。

第一遍打标可以先用脚本粗筛候选句，再人工逐条核对（关键词只能召回候选，漏掉的靠通读）：

```bash
python3 {baseDir}/scripts/tag_candidates.py transcript.txt
python3 {baseDir}/scripts/tag_candidates.py meeting.srt --out candidates.md
```

脚本按【决】【办】【疑】【数】【争】五类列出候选行（带行号和时间戳），统计说话人标签；说话人是「说话人1」这类编号时，提示先请用户对上姓名。支持 txt、md、srt、vtt，自动识别 UTF-8 与 GB18030 编码；只用 Python 标准库，不联网，不改原稿。用户直接把文字贴在对话里时不必跑脚本，按同样的五类通读打标。

转写稿常见三类硬伤，先处理，再去口语：

- **说话人对不上**：从称呼与应答关系推断，例如有人说「小王你盯一下」，紧接着答「我来跟」的多半是小王。把推断依据列给用户确认，确认前保留原标签；多人抢话、重叠的片段，归属不清就标【?发言人不明】。
- **同音错字与术语**：先从议程和会议材料里整理一份术语表（产品名、人名、项目代号、英文缩写），整理时统一替换；拿不准的保留原文并标【?】，不要挑一个读着通顺的词填进去。
- **数字**：「十五」与「五十」、「一点五」与「一五」最容易错；与上下文对不上的一律标【?】，不按常理改。

去口语规则：

- 删语气词和口头禅：嗯、啊、那个、就是说、对对对、然后然后。
- 删重复和自我纠正，只保留纠正后的说法：「周三，不对，周四上线」写成「周四上线」。
- 长句改成「谁 + 做什么 + 结果」，一句一个意思。
- 不改变立场强度：「我觉得可能不太行」不能改成「反对」，写「对此有顾虑」；「原则上同意」不能改成「同意」。
- 一个反例：原话「这个方案我个人觉得风险有点大，但如果大家都觉得可以，我也不反对」，写成「李老师同意该方案」是错的；应写「李老师认为方案风险偏大，但表示不反对多数意见」。
- 口头数字统一格式：「百分之三十」写成「30%」，「下礼拜三」换成具体日期，对应不上日期的标【待确认】。

决议与待办的判定标准：

- **决议**：有决定权的人明确表态且在场没人反对，或会上明确说了「就这么定」。只是有人提议、没人拍板的，一律归入未决。
- **待办**四要素：做什么（动词开头、能验收）、负责人（具体到一个人，不写「大家」「技术侧」）、截止时间（具体日期）、依据（时间戳）。缺任何一项就标【待确认】，不替他们补。

## 保留原话的场合

以下内容照录原话，加引号并注明说话人与时间戳，其余一律改写。原话要引完整，截掉条件或转折就等于改了意思：「可以做，但得先过安全评审」不能只引「可以做」。

- **承诺与数字**：交付日期、金额、指标目标、服务时限，如「3 月 15 日前一定上线」。
- **分歧与保留意见**：谁不同意、理由是什么，避免事后「我当时没同意」。
- **带条件的拍板**：如「预算批下来就做」，条件本身就是决议的一部分，改写容易丢。
- **客户或用户原声**：需求与投诉的原话，不替客户概括。
- **敏感表述**：涉及人事、合规、法律风险的话，保留原话并提醒用户决定是否写入纪要，或改写为「另行沟通」。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（一句模板） |
|---|---|---|
| E1 缺关键信息：说话人只有编号、不知道会议日期、不知道纪要发给谁 | 只问这三个；其余先按默认处理：按「只给参会人看」的详版整理，整理人、缺席名单写【待补】，推不出的日期和负责人写【待确认】 | 「整理前确认三件事：说话人1、2、3 各是谁？会是哪天开的（『下周三』要换成日期）？纪要只发参会人吗？没确认的我先标【待确认】。」 |
| E2 输入格式不对：发来的是音频、视频、截图，或文本乱码、明显缺段 | 音视频不转写，请用户先导出文字稿；截图请贴文字版；乱码请另存为 UTF-8（脚本会自动试 GB18030）；时间戳跳段处标【?缺段 起止时间】 | 「这是音频文件，我这边不转写；用会议软件导出文字稿后发我，几分钟就能出纪要。」 |
| E3 前后矛盾：同一件事两个日期、两个数字，或两个人都说自己负责 | 不替他们选：两种说法都列出并注时间戳，放进「待核实」，问决定人以哪个为准；会上当场更正过的，采用更正后的说法并注明位置 | 「00:12 说周三上线，00:40 又说周四，以哪个为准？两处我先都标【?】。」 |
| E4 超出范围：要转写、要判断决定是否合规或能否当证据、要写绩效或处分意见 | 转写交给转写工具；合规与证据问法务或律师；人事评价不写进纪要，由用户自己决定怎么处理 | 「纪要只记会上说了什么；这件事能不能当证据，要问律师，原始录音请原样保存。」 |
| E5 时间紧，只要最小可用版 | 只出三段：决议、待办（四要素缺的标【待确认】）、未决；议题要点、待核实随后补；标题行写「状态：最小版」 | 「先给你最小版：决议、待办、未决三段，马上能发；议题要点我随后补。」 |
| E6 用户坚持越界：要把没拍板的写成决议、替缺席的人写承诺、删掉反对意见 | 守住：没拍板的写成「倾向于……，待某某确认」；缺席者的事写成待办并标【待确认】；分歧保留，措辞可以缓和 | 「会上没人拍板，我写成『倾向于周四上线，待李老师确认』；直接写成决议，事后容易各说各话。」 |
| 原稿超长（一两个小时、几万字） | 请用户分段发，每段 15–20 分钟；每段先打标，收齐后按议题合并；急用先出最小版 | 「稿子很长，分三段发我；每段我先打标，收齐后合成一份纪要。」 |

脚本出错时：

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 0 | 正常输出候选 | 按候选逐条回原稿核对 |
| 1「参数错误」 | 没给文件路径、参数拼错，或 `--out` 与原稿同名 | 按提示的用法重跑；`--out` 换个文件名 |
| 2「读不到文件 / 读取失败 / 写不了输出文件」 | 路径不对、给的是文件夹、编码无法识别、输出目录不存在或没权限 | 核对路径；把转写稿另存为 UTF-8 文本；`--out` 换到可写目录 |
| 3「文件里没有可读的文字」 | 空文件，或字幕只有时间轴 | 重新导出转写稿 |
| 130「已中断」 | 按了 Ctrl+C | 直接重跑，原稿不受影响 |

## 输出契约

交付物按固定顺序输出 Markdown，某段没有内容写「无」，不删段：

```
0 标题行：【会议名称】纪要｜状态：完整版 / 最小版｜待确认 N 项
1 基本信息：时间、方式、主持、整理、参会、缺席；依据（转写稿文件名）
2 决议：内容——决定人（时间戳），承诺与带条件的拍板附原话
3 待办：事项（动词开头）｜负责人｜截止日期｜时间戳｜状态
4 议题要点（同步会换成「上周完成 / 本周计划 / 风险」四栏表）
5 未决问题：问题｜卡在哪｜下一步推动人｜时间
6 待核实：【?】时间戳 + 原文
7 请主持人确认：汇总全部【待确认】【?】项，确认后再发全员
```

完整模板、同步会四栏表、一页版、精校稿格式见 [references/templates.md](references/templates.md)。

- 每条决议和待办附时间戳；原稿没有时间戳的，附原文里的一句关键短语，方便回查。
- 保留原话用「」，注明说话人与时间戳。
- 篇幅通常压到原稿的一到两成；决策会可以更短。
- 待办表的「状态」一栏供下次开会先过一遍：完成、延期（新日期与原因）、取消（谁同意的）。

占位符只用这几种，不编内容：

- 【待确认】：会议内容里缺失或对不上、要找会上的人确认的——负责人、日期、数字、推断出的说话人。
- 【?】：疑似转写错误、听不清、前后矛盾，后面附原文与时间戳；归属不清的发言标【?发言人不明】。
- 【待补】：原稿里本来就没有、由用户补的基本信息——整理人、缺席名单、会议起止时间。
- 【整理者注】：整理者补充的背景或解释，和会议结论分开。

交付前自检（每条答「是」才交）：

- [ ] 每条决议都能在原稿找到拍板的话，时间戳可回查？
- [ ] 每条待办四要素齐全，缺的已标【待确认】，没有「大家」「尽快」？
- [ ] 引用的原话完整，没截掉条件或转折？
- [ ] 立场强度没被改动（「有顾虑」没写成「反对」）？
- [ ] 全部【待确认】【?】都进了「请主持人确认」，数目与标题行一致？
- [ ] 要外发的版本里没有闲聊、玩笑、人事评价和隐私内容？

## 常见问题（FAQ）

**问：转写稿没有说话人标注，还能整理吗？**
答：能。按称呼与应答关系推断，推断依据列给你确认；推不出的标【?发言人不明】。决议和待办照样抽，负责人可能先标【待确认】。

**问：会开了两个小时，转写稿几万字，怎么发？**
答：分段发，每段 15–20 分钟。每段我先打标，收齐后按议题合并成一份；着急就先要最小版。

**问：能直接帮我把纪要发到群里或邮件吗？**
答：不代发。我给你能直接粘贴的正文；建议先把「请主持人确认」清单发给主持人，确认后再发全员。

**问：纪要和精校稿有什么区别？**
答：纪要按议题重组，只留决议、待办和要点，通常压到原稿的一到两成；精校稿保留原顺序和句式，只删语气词、重复和口误。说清要哪种，我按对应格式出。

**问：有人说了「我觉得可以」，算不算决议？**
答：不算。决议要有决定权的人明确表态、在场没人反对，或明确说了「就这么定」；否则进未决，写成「倾向于……，待某某确认」。

**问：转写把人名、产品名识别错了怎么办？**
答：给我一份术语表（人名、产品名、项目代号），我统一替换；拿不准的保留原文标【?】，不挑一个读着通顺的词硬填。

**问：中英混杂的会议能整理吗？**
答：能。纪要默认用中文，专有名词和引用的原话保留原文；要英文纪要请提前说。

## 常见错误（反模式）

最佳实践先记三条：只写拍板了的事；待办四要素缺一个就标【待确认】；拿不准的地方回原稿，不靠猜。

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 把讨论当决议：有人说「我觉得可以」就写「会议同意」 | 事后有人不认，纪要失去信用 | 只写有人拍板的；其余进未决，写「倾向于……，待某某确认」 |
| 负责人写团队或「大家」，截止时间写「尽快」 | 没人认领、没法跟进 | 具体到一个人、一个日期；缺了标【待确认】 |
| 去口语时顺手改了语气和立场 | 「有顾虑」变「反对」，会把分歧激化 | 只改表达、不改立场强度；拿不准就引原话 |
| 按时间顺序记流水账 | 同一议题散在几处，读的人拼不起来 | 按议题合并，注明起止时间 |
| 自己补全没听清的内容，猜人名、猜数字 | 错一个数字可能就是错一笔钱、一个期限 | 保留原文标【?】，放进待核实 |
| 删掉分歧只留结论 | 事后「我当时没同意」，各说各话 | 写清谁不同意、理由是什么，关键句引原话 |
| 引原话截掉条件或转折 | 「可以做，但得先过安全评审」只剩「可以做」，意思变了 | 原话引完整 |
| 相对日期照抄「下周三」「月底」 | 纪要转发几天后就对不上 | 按会议日期换成具体日期，推不出的标【待确认】 |
| 把闲聊、玩笑、对个人的评价写进纪要 | 外发后伤人，也有隐私风险 | 删掉；人事相关内容由用户决定写不写 |
| 没经主持人或决定人确认就群发 | 错误扩散后很难收回 | 先发「请主持人确认」清单，确认后再发全员 |
| 把整理者自己的判断写成会议结论 | 纪要变成整理者的观点 | 补充说明单独标【整理者注】 |

## 边界与不做什么

- 不做录音转文字：需要用户提供转写文本；只有音频的，先用会议软件或转写工具生成文字稿。
- 不替会议做决定：没拍板的事不写成决议，也不替参会人补承诺。
- 不代发纪要，不代表任何参会人确认纪要内容。
- 纪要要用作劳动争议、合同纠纷等场合的证据时，原始录音与逐字稿需原样保存，证据效力问题请咨询律师。
- 涉及个人隐私、薪酬、人事评价的内容，默认不写入外发纪要，由用户决定；也不从发言里评价某个人的表现。
- 录音与转写稿是否告知过参会人、能否外传，按公司规定与当地法规处理，拿不准时问法务。
