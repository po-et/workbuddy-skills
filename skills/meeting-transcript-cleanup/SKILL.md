# 会议录音整理

定位一句话：**纪要不是把转写稿删短，而是回答三个问题：定了什么，谁在什么时候之前做什么，还有什么没定。其余内容都为这三件事服务。**
何时用：手上已有会议软件导出或人工听写的转写文本（带不带说话人、时间戳都行），要整理成能发出去的纪要；会开完大家对「到底定了什么」说法不一；要从一场长会里把待办捞出来。只有录音、没有文字时，先用转写工具生成文本再来。

## 先判断什么：动手前问清五件事

1. **纪要给谁看。** 只给参会人对齐，可以简；给缺席者和上级，要补背景；给客户或外部，措辞要审，内部讨论不外发。
2. **这是什么会。** 决策会（评审、立项）以决议为主；同步会（周会、站会）以进展和待办为主；讨论会（头脑风暴、复盘）以观点分组和未决问题为主。
3. **转写稿质量如何。** 有没有说话人标注：「说话人1」对应谁要问用户，不猜；有没有时间戳；专有名词、人名、数字错得多不多。
4. **有没有议程。** 有就按议程分议题；没有就按话题切换处切段。
5. **要不要逐字引用。** 涉及客户承诺、合规事项、有争议的决定时，关键句保留原话。用户要的若是访谈、讲座的精校稿而不是纪要，就只删语气词、重复和明显口误，保留原有顺序与句式，不抽决议。

## 整理流程：六步

```
第 1 步 通读打标    先不改字，给每段打标：【决】决议 【办】待办 【疑】未决 【数】数字 【争】分歧 【闲】闲聊
第 2 步 切分议题    按议程或话题转换处（「下一个」「另外说一下」「回到刚才」）切段；
                   同一议题前后散落的发言合并到一起，注明起止时间
第 3 步 去掉口语    按下方规则改成书面语，只改表达，不改意思和语气强度
第 4 步 抽决议待办  按下方判定标准抽取，每条附时间戳
第 5 步 标未决待核  未决问题写清卡在哪、谁推动；听不清、疑似错字、前后矛盾的数字，一律标【?】
第 6 步 回查原稿    每条决议和待办回到时间戳处再读一遍，确认没有张冠李戴
```

超过一小时的会，按 15 到 20 分钟一段做第 1 步，全部打完标再按议题合并。给上级的一页版只留决议和待办，给参会人的详版再加议题要点。

第一遍打标可以先用一行命令粗筛决议、待办、搁置三类候选句，再人工逐条核对（关键词只能召回候选，漏掉的靠通读）：

```bash
python3 -c "import re;[print(i,l.strip()) for i,l in enumerate(open('transcript.txt',encoding='utf-8'),1) if re.search(r'定了|就这么|拍板|负责|我来|你来|跟进|截止|之前|下周|月底|周[一二三四五六日]|先不|先放|回头|再议',l)]"
```

转写稿常见三类硬伤，先处理，再去口语：

- **说话人对不上**：从称呼与应答关系推断，例如有人说「小王你盯一下」，紧接着答「我来跟」的多半是小王。把推断依据列给用户确认，确认前保留原标签；多人抢话、重叠的片段，归属不清就标【?发言人不明】。
- **同音错字与术语**：先从议程和会议材料里整理一份术语表（产品名、人名、项目代号、英文缩写），整理时统一替换；拿不准的保留原文并标【?】，不要挑一个读着通顺的词填进去。
- **数字**：「十五」与「五十」、「一点五」与「一五」最容易错；与上下文对不上的一律标【?】，不按常理改。

去口语规则：

- 删语气词和口头禅：嗯、啊、那个、就是说、对对对、然后然后。
- 删重复和自我纠正，只保留纠正后的说法：「周三，不对，周四上线」写成「周四上线」。
- 长句改成「谁 + 做什么 + 结果」，一句一个意思。
- 不改变立场强度：「我觉得可能不太行」不能改成「反对」，写「对此有顾虑」；「原则上同意」不能改成「同意」。
- 一个反例：原话「这个方案我个人觉得风险有点大，但如果大家都觉得可以，我也不反对」，写成「李老师同意该方案」是错的；应写「李老师认为方案风险偏大，但表示不反对多数意见」。
- 口头数字统一格式：「百分之三十」写成「30%」，「下礼拜三」换成具体日期，对应不上日期的标【待确认】。

决议与待办的判定标准：

- **决议**：有决定权的人明确表态且在场没人反对，或会上明确说了「就这么定」。只是有人提议、没人拍板的，一律归入未决。
- **待办**四要素：做什么（动词开头、能验收）、负责人（具体到一个人，不写「大家」「技术侧」）、截止时间（具体日期）、依据（时间戳）。缺任何一项就标【待确认】，不替他们补。

## 保留原话的场合

以下内容照录原话，加引号并注明说话人与时间戳，其余一律改写。原话要引完整，截掉条件或转折就等于改了意思：「可以做，但得先过安全评审」不能只引「可以做」。

- **承诺与数字**：交付日期、金额、指标目标、服务时限，如「3 月 15 日前一定上线」。
- **分歧与保留意见**：谁不同意、理由是什么，避免事后「我当时没同意」。
- **带条件的拍板**：如「预算批下来就做」，条件本身就是决议的一部分，改写容易丢。
- **客户或用户原声**：需求与投诉的原话，不替客户概括。
- **敏感表述**：涉及人事、合规、法律风险的话，保留原话并提醒用户决定是否写入纪要，或改写为「另行沟通」。

## 整理前后对照与输出模板

整理前（说话人已由用户确认：说话人1 是李老师，说话人2 是小张，说话人3 是小王）：

```
[00:12:05] 说话人1：嗯那个，就是说，登录页改版这个事，我们，我们这周能上吗？
[00:12:14] 说话人2：这周够呛，那个，接口还没联调完，最快，最快下周三吧。
[00:12:22] 说话人1：下周三行，那就下周三，小王你盯一下。
[00:12:25] 说话人3：可以，我来跟。那埋点要不要一起加？
[00:12:31] 说话人1：埋点……先不加吧，回头再说，看数据组那边排期。
[00:12:40] 说话人2：还有验证码那个供应商，价格涨了百分之三十，要不要换，得有人拍板。
[00:12:48] 说话人1：这个我得问一下老板，先放着。
```

整理后：

```
议题：登录页改版上线时间（00:12:05–00:12:48）
决议：登录页改版定于下周三上线（本周来不及），原因是接口联调未完成。
      李老师原话：「下周三行，那就下周三，小王你盯一下。」（00:12:22）
待办：小王｜跟进登录页改版上线｜下周三，具体日期【待确认】｜00:12:22–00:12:25
未决：是否同步加埋点——待数据组排期后再议，推动人【待确认】（00:12:31）
未决：验证码供应商涨价 30%，是否更换——李老师请示上级后定，时间【待确认】（00:12:40）
```

输出模板：

```
【会议名称】纪要
时间【日期 起止】  方式【线下 / 线上】  主持【】  整理【】  参会【】  缺席【】
依据：【转写稿文件名】，时间戳对应原稿

一、决议
  1. 【决议内容】——【决定人】（时间戳）
二、待办
  事项（动词开头） ｜ 负责人 ｜ 截止日期 ｜ 时间戳
三、议题要点
  议题 1【标题】（起止时间）：现状 / 讨论要点 / 分歧双方的观点与理由
四、未决问题
  问题 ｜ 卡在哪 ｜ 下一步推动人 ｜ 时间
五、待核实
  【?】时间戳：疑似转写错误或待核数字，附原文
```

周会、站会这类同步会，把第三节换成按项目或按人的四栏表，决议和待办照旧：

```
项目或成员 ｜ 上周完成 ｜ 本周计划 ｜ 风险与需要谁帮忙
```

## 最常见的错误

1. 把讨论当决议：有人说了句「我觉得可以」，就写成「会议同意」。
2. 负责人写团队或「大家」，截止时间写「尽快」。
3. 去口语时顺手改了语气和立场。
4. 按时间顺序记流水账，同一议题散落各处。
5. 自己补全没听清的内容，猜人名、猜数字。
6. 删掉分歧只留结论，事后各说各话。
7. 把闲聊、玩笑、对个人的评价写进纪要。
8. 没经主持人或决定人确认就群发。
9. 把整理者自己的判断写成会议结论；确需补充背景或解释的，单独标【整理者注】。

## 输出契约

1. 默认按上面的模板输出 Markdown：决议、待办、议题要点、未决问题、待核实，顺序固定。
2. 每条决议和待办附时间戳；原稿没有时间戳的，附原文里的一句关键短语，方便回查。
3. 不编内容：负责人、日期、数字缺失一律写【待确认】；说话人对应不上的先问用户。
4. 保留原话用「」，注明说话人与时间戳。
5. 篇幅通常压到原稿的一到两成；决策会可以更短。
6. 末尾附一份「请主持人确认」清单：汇总全部【待确认】和【?】项，确认后再发全员。
7. 待办表可加一列「状态」，下次开会先过一遍上次的待办：完成、延期（新日期与原因）、取消（谁同意的）。

## 边界与不做什么

- 不做录音转文字：需要用户提供转写文本；只有音频的，先用会议软件或转写工具生成文字稿。
- 不替会议做决定：没拍板的事不写成决议，也不替参会人补承诺。
- 纪要要用作劳动争议、合同纠纷等场合的证据时，原始录音与逐字稿需原样保存，证据效力问题请咨询律师。
- 涉及个人隐私、薪酬、人事评价的内容，默认不写入外发纪要，由用户决定。
- 录音与转写稿是否告知过参会人、能否外传，按公司规定与当地法规处理，拿不准时问法务。
