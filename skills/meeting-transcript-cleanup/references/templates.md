# 纪要模板与变体

SKILL.md 的「输出契约」规定了交付顺序和占位符；这里是可以直接复制的完整模板。模板里的空「【】」是填空位，填不上的按占位符规则写【待补】或【待确认】，不留空。

## 1 标准纪要（决策会、评审会、讨论会）

```
【会议名称】纪要｜状态：完整版｜待确认 N 项
时间【日期 起止】  方式【线下 / 线上】  主持【】  整理【】  参会【】  缺席【】
依据：【转写稿文件名】，时间戳对应原稿

一、决议
  1. 【决议内容】——【决定人】（时间戳）
     原话（承诺、数字、带条件的拍板才引）：「……」
二、待办
  事项（动词开头） ｜ 负责人 ｜ 截止日期 ｜ 时间戳 ｜ 状态
三、议题要点
  议题 1【标题】（起止时间）：现状 / 讨论要点 / 分歧双方的观点与理由
四、未决问题
  问题 ｜ 卡在哪 ｜ 下一步推动人 ｜ 时间
五、待核实
  【?】时间戳：疑似转写错误或待核数字，附原文
六、请主持人确认
  1. 【待确认 / ? 项】：需要谁确认什么
```

某一段没有内容就写「无」，不删段，读的人才知道不是漏了。

## 2 同步会变体（周会、站会）

第三节换成按项目或按人的四栏表，决议和待办照旧：

```
项目或成员 ｜ 上周完成 ｜ 本周计划 ｜ 风险与需要谁帮忙
```

## 3 给上级的一页版

只留三段：决议、待办、需要上级拍板的未决问题；每条一行，附时间戳。议题要点和待核实留在给参会人的详版里。

## 4 下次开会先过上次的待办

待办表的「状态」一栏只用这几种写法：

```
进行中 ｜ 完成 ｜ 延期（新日期与原因） ｜ 取消（谁同意的）
```

下次开会第一项就是把上次的待办逐条过一遍，更新状态后再进入新议题。

## 5 精校稿（访谈、讲座，不做纪要）

用户要的是逐字稿的精校版而不是纪要时：保留原有顺序与句式，只删语气词、重复和明显口误，不抽决议、不按议题重组。

```
[时间戳] 发言人：精校后的句子
[时间戳] 发言人：听不清或拿不准的地方保留原文，标【?原文】
```

精校前后对照一句：原文「嗯那个，就是说，我们，我们这周能上吗」→ 精校「我们这周能上吗」。
