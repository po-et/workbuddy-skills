# 待办的写法与消息拆解

回到 [SKILL.md](../SKILL.md)。一行一件；脚本 `scripts/brief.py` 按下面的标记排序、查冲突，看不懂的会标 [待确认] 放进「风险与冲突」。

## 标记速查

| 写法 | 含义 | 例子 |
|---|---|---|
| `截止:9-24` | 截止日期；也认 `2026-09-24`、`9/24`、`9月24日`、`今天`、`明天`、`后天` | `交季度预算表 截止:9-24` |
| `!` 或 `！` | 影响大：上级、客户、多人协作、钱、对外承诺 | `合同终稿 截止:9-25 ！` |
| `@人名` | 这个人在等你（会进「需要回复的人」） | `课表调整回复 截止:明天 @李老师` |
| `等:人名` 或 `等：人名` | 你在等他（两天内到期的会进「风险与冲突」，提醒上午先催） | `合同终稿 截止:9-25 等:小王` |
| `10:00 事项` / `10:00-11:00 事项` | 有时间点的安排（会查时间重叠） | `10:30-11:00 牙医复诊` |
| 行首的 `-`、`*`、空格 | 会被自动去掉，列表直接粘进来即可 | `- 整理发票 截止:9-30` |

只写月-日时按「今天」所在年份理解；年底写「1-05」这类早于今天半年以上的日期，按明年理解并标 [待确认]。

## 看不懂的写法（脚本会标 [待确认]）

- `截止:周五`、`截止:下周三`：相对说法，先换算成具体日期再写，换算不了就问用户。
- `25:00`、`10:75`：不存在的时间，不排进日程。
- `11:00-10:00`：结束早于开始，按只占开始时刻处理。

## 只有消息时，先拆成待办

每条消息问三件事：要我做什么（动作）？什么时候之前（截止）？谁在等、我在等谁（相关人）？

| 消息原话（虚构） | 拆成的待办行 |
|---|---|
| 张经理：明天上午 10 点前把活动预算发我，要按新模板 | `活动预算（新模板） 截止:明天 ! @张经理` |
| 小李：评审会从周三改到周四下午 3 点，你那边可以吗？ | `回复评审会改期 截止:今天 @小李` |
| 客户王总：合同盖章版什么时候能寄出？（盖章在等法务） | `回复合同盖章版寄出时间 截止:今天 ! @王总 等:法务` |
| 物业：本周五 9:00-12:00 停电检修 | 不是待办：助手在第 3 步并进「风险与冲突」 |

拆不出截止的，不写 `截止:`，它会排在最后，不进「今天必须完成」。

## 天气与新闻

只转述用户给的摘要，一句话，并进「一句话提醒」或「风险与冲突」（如「有小雨，出门带伞」）；没给就不写，不联网查。
