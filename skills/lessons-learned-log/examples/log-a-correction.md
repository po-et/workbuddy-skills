# 示例：被纠正后记一条（先查重，再更新旧条）

> 以下为示例。记录目录是一份示例目录，脚本输出是对它实际运行 `scripts/lessons_search.py` 的结果；日期按示例当天 2026-09-26 写。

## 1. 用户的纠正

> 刚才你把文件路径写错了——只给了 report.html，我根本找不到。记一下这个坑，以后别再犯。

## 2. 助手先查，不急着新开一条

从这次的事抽关键词：对象「路径、文件位置」，动作「交付」。

```bash
python3 scripts/lessons_search.py ~/lessons 路径 文件位置 交付
```

```text
[19] 文件与路径.md | 交付文件只写了相对路径，用户找不到 | 有效 2026-09-19
    正确做法：交付物一律写完整路径，如 /Users/xiaowang/周报/report.html
    验证方式：交付前把路径粘到文件管理器地址栏，能直接打开
[11] 文件与路径.md | 网页结果的链接写成了相对地址 | 有效 2026-06-01
    正确做法：链接写完整路径，交付前自己点一遍
    验证方式：在另一个目录的终端里打开链接，能直接打开
[1] 写作与格式.md | 周报里把推测写成了结论 | 有效 2026-08-30
    正确做法：没有出处的数字标「估计」并写明依据，或删掉
    验证方式：交付前逐个数字问一遍「出处在哪」
共 3 条
```

第一条和这次同根因（默认用户和我在同一个目录），所以**更新它**，不另开新条。

## 3. 助手交付

```text
已更新：~/lessons/文件与路径.md 里的「交付文件只写了相对路径，用户找不到」（同根因，不新开条目）
改了 4 行：
  关键词    追加「文件名」
  现象      追加「2026-09-26 又只给了文件名，用户说『路径写错了』」
  类别      被用户纠正（第 2 次）→（第 3 次）
  最后验证  2026-09-19 → 2026-09-26
格式检查：python3 scripts/lessons_search.py ~/lessons --lint → 检查了 6 条，格式都合格
提醒：这个坑已经出现 3 次，光记录不够。建议升级成固定规则，写进我的常驻指令：
      「交付物一律写完整路径，交付前自己打开一次」——要我按这句加上吗？
```

更新后的完整条目：

```markdown
### 交付文件只写了相对路径，用户找不到
- 关键词：路径, 文件位置, 交付, 链接, 文件名
- 触发场景：把报告、表格、网页结果交给用户时
- 现象：用户回复「report.html 在哪？打不开」；2026-09-26 又只给了文件名，用户说「路径写错了」
- 根因：默认用户和我在同一个目录，实际不在
- 正确做法：交付物一律写完整路径，如 /Users/xiaowang/周报/report.html
- 验证方式：交付前把路径粘到文件管理器地址栏，能直接打开
- 类别：被用户纠正（第 3 次）
- 最后验证：2026-09-26
- 状态：有效
```

## 4. 这个示例说明了什么

- 记之前先按关键词查：同根因就更新旧条（次数加一、补现象、改日期），条目不会越攒越重复。
- 交付里写清文件完整路径和改了哪几行，用户能核对。
- 同一个坑到第 3 次，要从「记录」升级成「规则」；改常驻指令属于改用户的配置，先问再做。
