# 辩论稿

定位一句话：**辩论稿不是议论文，而是一套作战方案：先让评委接受你的尺子（标准），再用这把尺子量双方。标准立不住，稿子写得再漂亮，场上一问就散。**

**文件导航**：本页保留主流程，按需要打开对应文件。

| 要完成的事 | 读取或运行 |
|---|---|
| 先看一份完整交付 | [正方一辩示例](examples/lilun-zhengfang-yibian.md)，论据未核实的位置只是占位 |
| 看英文词速如何落地 | [英文限时立论示例](examples/english-timed-constructive.md)，只有逻辑与假设场景 |
| 检查自己的论证、准备反方拆解 | [七种拆解句式](references/rebuttal-patterns.md) |
| 已有辩题，要直接填空准备 | [完整骨架](references/skeleton.md) |
| 量限时稿、删超长稿 | `scripts/speech_timer.py`；中文和英文命令见下文 |

## 先选交付范围

用户只要立论、攻辩、自由辩或结辩其中一部分时，只交付那部分；不要为了完整骨架补出用户没要的稿子。

不适用：

- 演讲比赛稿、议论文、竞选稿：没有对方、没有质询，写法不同，转交演讲稿或写作类技能；只想借「定义→标准→论点」的结构，直接简答即可。
- 比赛正在进行、要场外实时提词：不提供，见「边界与不做什么」。
- 要对辩题涉及的法律、医学、金融问题下专业结论：本技能只帮你把权威来源引用对，结论请教指导老师或专业人士。

## 先判断：赛制、辩题问法、持方

动笔前拿到主办方规则：各环节几分钟、攻辩能否连续追问、自由辩怎么计时、结辩能否提新论据。下文按常见的四人制说，环节名称以你的赛制为准。辩题原文、持方、立论时长三样缺一样就先问，其余可以先按默认值写（见「信息不全或出错时」）。

| 辩题问法 | 例 | 立论先要立住的东西 |
|---|---|---|
| 「是不是」 | X 是否属于/导致 Y | 关键词定义清楚，外加一条完整的证据链 |
| 「哪个更」 | X 利大于弊；X 比 Y 更重要 | 比较标准：用什么尺子比、为什么用这把尺子 |
| 「该不该」 | 应当/不应当推行 X | 三问：问题是否存在、方案能否解决、代价能否接受 |

## 立论稿：定义 → 标准 → 论点（分五步写）

```
第 1 步 定义：辩题里每个关键词写成一句可检验的界定——对象、范围、时间。
        引用词典或通行说法要写明出处；对方最可能挑战的那个词，备一个例子说明为什么这样界定才合理。
第 2 步 标准：一句话说清「今天应当看什么来判断」，如「判断该不该推行 X，要看它能否以[可接受的代价]解决[问题]」。
        检查点：对方挑不出毛病、但对我方更有利；只对我方成立的标准，对方一句话就能否掉。
第 3 步 论点：两到三个，每个都是「主张＋论据＋回到标准」三件套；按不同维度分（个人与社会、短期与长期），
        别让两个论点其实是一件事。论据分量：可查证的数据或研究 > 公认事实 > 具体案例 > 类比；
        每条注明出处，查不到的标「[待核]」。名言和排比代替不了论据。
第 4 步 预判：列出对方最可能的三个攻击点，在立论里各埋一句回应，只占位不展开。
第 5 步 计时：主办方时长 × 同口径的实测语速 = 字数或词数上限，写到九成，留出强调和停顿。
```

草稿存成 lilun.txt（UTF-8 纯文本），第二个参数填你实测的每分钟字数，`--limit` 填主办方时长：

```bash
python3 scripts/speech_timer.py lilun.txt 250 --limit 3:00
```

输出全文计数、预计时长、九成线和每段计数，标出最长的两段；超时退出码为 3。方括号占位和【】标题不计入计数。中文口径是汉字和数字各算 1 字、英文词算 2 个等效字；英文撇号、连字符词（如 `don't`、`one-size-fits-all`）不拆开，全角字母会转半角。

英文稿用词/分钟，不能把实测英文词速直接当中文的字速：

```bash
python3 scripts/speech_timer.py english.txt 150 --language en --limit 3:00
```

英文模式按英文词和数字串各 1 词计数，不接受汉字；中英混合稿用默认中文口径。实测时，把读完一分钟的正文另存为一小段，先用同一个脚本、同一个模式数出单位数量，再把该计数作为语速。年份、数字和缩写的实际读法可能更长，先按读法展开再计时，最后整稿实读三遍；脚本估算不保证上场时长。未提供语速时，中文暂按 250 字/分钟、英文暂按 150 词/分钟并标 [待确认]。

## 攻辩、自由辩与结辩

攻辩（质询）按「链」准备，每条链三到四问：

```
1 共识问：预期双方可接受的前提，同时准备对方否认时的追问
2 前提问：把对方论点背后没说出口的前提问出来
3 矛盾问：让这个前提撞上对方自己的定义、标准或另一个论点
4 收束句：不再提问，按对方实际回答引用；只有明确承认时才能说「对方承认了……」
示例（对方论点：X 能提高效率）
  您方同意，效率要同时看投入和产出吧？→ 您方说的提高效率，是假设投入不变吗？
  → 可您方二辩刚才说推行 X 要额外培训，这算不算投入增加？→ 所以对方的「提高效率」只算了产出。
要求：每问能用「是/不是」或一个词回答；对方两种答法都提前写好追问；不问「您方怎么看……」，
      开放式问题等于把时间送给对方再立论一次。允许追问时，对方绕开就重述一次，再绕就点明未回答的具体前提，切下一条链。
      未回答不等于承认；对方否认前提时，要求其给出相反的依据，或转去比较双方标准，不沿用预设的收束句。
```

自由辩赛前画一张战场表，最多三个战场：

| 战场 | 我方守住的一句话 | 进攻问题（三个） | 备用例子或数据 | 主责 |
|---|---|---|---|---|
| 定义 | …… | …… | …… | 二辩 |
| 标准 | …… | …… | …… | 三辩 |
| 事实与后果 | …… | …… | …… | 一辩、四辩 |

每次发言先接后打：先回应对方上一句，再抛自己的问题。同一个问题对方连续两次不接，点破后换战场；每个战场指定一人做小结；时间过半时由四辩检查还有哪个战场没打。

结辩赛前只写框架，第 2、3 段留空，现场按双方原话填，不背整稿：

```
1 锁定分歧：「今天双方真正的分歧是……」（一到两个）
2 逐一裁决：引用对方场上原话，说明在双方都认可的标准下，为什么我方占优
3 回到标准：重申标准，指出对方论证在标准下缺了哪一环
4 收尾：回到立论里的一个画面或例子，不喊口号；能否提新论据以规则为准，一般不提
```

## 反方拆解句式与完整骨架

七种拆法：拆定义（拿反例测范围）、拆标准（问漏掉的维度）、拆因果（问排除了其他原因没有）、拆样本（问比例）、拆可行（问谁来做、钱从哪来、多久见效）、拆代价（问谁承担）、拆滑坡（问每一步是否必然）。正方拆对方时一样适用；写完立论，逐条拿来查自己的稿子。每种的现成句式、自查方法和正反两方用法演示见 [references/rebuttal-patterns.md](references/rebuttal-patterns.md)。

不预设立场的完整骨架（立论全文填空、攻辩链、战场表、结辩框架、论据出处清单）见 [references/skeleton.md](references/skeleton.md)，整份复制，方括号逐个替换。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（模板） |
|---|---|---|
| 缺辩题原文、持方或立论时长 | 只问这三个；赛制按常见四人制、语速按 250 字/分钟先写，标 [待确认] | 「先确认三件事：辩题原文（一字不差）、你方持方、立论几分钟？其余我按常见四人制先写，标了 [待确认] 的你再核对。」 |
| 还没抽签，持方未定 | 不替用户选边；正反两方各给「定义＋标准＋论点提纲」，抽签后再写全稿 | 「持方由抽签定，我不替你选。先给你正反两版提纲，抽到哪边就展开哪边。」 |
| 辩题与持方对不上，或信息自相矛盾 | 指出矛盾，给两种理解让用户选，不自行猜 | 「辩题是『X 利大于弊』，你要论证的却是弊大于利——你其实在反方，还是辩题原文是『弊大于利』？」 |
| 用户给的数据、名言查不到出处 | 保留但标 [待核]，写明去哪查和查不到时的替代说法；不润色成确定的事实 | 「这条我查不到出处，先标 [待核]。上场前找不到原始来源就换掉——被问出处答不上，比没有这条更伤。」 |
| 稿子超时，或字数和时长对不上 | 跑 `scripts/speech_timer.py` 找最长的段；按「修饰和排比 → 重复的例子 → 第三论点」删，定义和标准不删 | 「按你的语速这稿要 3 分 40 秒，超了 40 秒；最长的是第二论点，先从那里删修饰。」 |
| 时间紧，只要能上场的最小版 | 最小版：定义一句＋标准一句＋两个论点（各一句主张、一个论据位、一句回到标准）＋结尾一句，约 300 字；外加一条攻辩链 | 「来不及就先上最小版：三百字左右的立论骨架加一条攻辩链，能撑住场；有时间再补第三论点和战场表。」 |
| 超出本技能范围 | 演讲稿、作文转交写作类技能；专业结论只帮用户找权威原文，判断请教老师或专业人士 | 「演讲稿没有对方质询，写法不同，建议用演讲稿类技能；我可以帮你把论点和论据这部分理顺。」 |
| 用户坚持越界：编数据或名言、比赛中实时提词、攻击对方辩手个人 | 不做，说明原因，给合规替代（逻辑论证、可查来源、赛前准备） | 「数据我不能编，被查出来整队失分；我告诉你去哪查，查不到时怎么用推理把这个论点撑住。」 |
| 回复太长被截断或中途断了 | 按输出契约的编号分段交付；用户说「继续」就从下一个未交付的编号接着写，不从头重写 | 「上一条停在第 3 部分自由辩战场表。回复『继续』，我从第 4 部分结辩框架接着写。」 |

计时脚本的退出码与报错：

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 0 | 正常；给了 `--limit` 时表示没超时 | 看九成线提示，超过九成线就再删一点 |
| 1「语速……超出接受范围」「时限……看不懂」「参数有误」 | 中文语速不在 100–450 字/分钟、英文不在 50–400 词/分钟，数值无效，时限认不出，或参数缺失 | 确认 `--language` 与实测单位；时限写成 3:00、180 或 三分钟 |
| 1「英文模式里有汉字」 | 给英文词速模式传了中文或混合稿 | 混合稿改用 `--language zh`，按同一等效字口径实测语速 |
| 1「没有可计时的正文」 | 文件里只有【】标题或方括号占位 | 先把稿子写出来再计时 |
| 2「找不到文件」「是 Word/PDF 等文档」「编码认不出来」 | 路径不对、传了 .docx，或编码不是 UTF-8/GBK | 核对路径；另存为 UTF-8 的 .txt |
| 3 | 超出时限 | 按提示的字数删，删稿顺序见上表 |
| 130 | 按了 Ctrl+C | 重新运行即可，脚本不改任何文件 |

## 输出契约

先问清：辩题原文、持方、赛制和各环节时长、辩手分工、已有材料；辩题一个字都不改。立场按用户的持方写。

交付物按固定顺序（用户只要其中几部分时只给那几部分，编号和顺序不变）：

```
0 已知与假设    辩题原文、持方、各环节时长、实测语速、分工；默认值标 [待确认]
1 立论稿全文    标计时模式、字数或词数、预计时长（按同口径实测语速）
2 攻辩问题链    两到三条，每条「共识→前提→矛盾→收束」，对方两种答法都写好追问
3 自由辩战场表  最多三个战场，每个战场有主责
4 结辩框架      第 2、3 段留 [待补：场上原话]
5 对方最强的三个论点  每个写明我方在哪回应，帮用户准备防守
6 论据出处清单  每条：用在哪—论据—出处—状态（已核/[待核]）—查不到时怎么说
7 自检结果      下面六条逐条写「是/否」
```

占位符：`[待核]` 论据出处没核实，上场前必须查到，查不到按清单里的替代说法改；`[待补]` 只有用户或场上才有的内容（对方原话、队员真实经历、队内已有材料）；`[待确认]` 按默认值假设的赛制信息。不用「某某」「XX」这类看不出要补什么的占位。论据只用查得到的：不编数据、不编名人名言、不编研究。

内容超过一屏时按编号分几条发，每条末尾写「下一部分：编号＋名称」；中断后从下一个编号接着写。

交付前自检（逐条判断是/否，有一条「否」就改完再交）：

1. 辩题原文一字未改？
2. 标准能用一句话说清，且对方挑不出明显毛病？
3. 每个论点都有「主张＋论据＋回到标准」？
4. 立论计数 ≤ 时长 × 同口径语速 × 0.9（用 `scripts/speech_timer.py` 核对，英文模式按词）？
5. 每条论据都有出处或标了 [待核]，没有编造的数据、名言、研究？
6. 全文没有针对对方辩手个人的攻击？

## 示例

（示例）攻辩问题被绕开——

**用户**：攻辩问题总被对方绕开。辩题「大学生兼职利大于弊」，我们是反方，我准备的问题是「您方怎么看兼职对学习的影响？」

**助手先问**：对方立论的核心论点是什么？攻辩能不能连续追问？

**用户**：对方说兼职能锻炼能力。可以连续追问。

**助手交付**：

> 诊断：「您方怎么看……」是开放式问题，对方可以借这个问题再立一遍论。被绕开不是对方狡猾，是问题给了他空间。改成一条链（打对方「兼职锻炼能力」）：
>
> 1. 共识问：您方同意，大学生的课余时间是有限的吧？
> 2. 前提问：您方说兼职锻炼能力，是说它比把同样的时间用在专业学习、实习或社团上锻炼得更多吗？
>    答「是」→ 追问：发传单、端盘子，比专业实习更锻炼专业能力吗？
>    答「不是」→ 追问：那锻炼能力就不是兼职独有的好处，这一点最多打平，对吗？
> 3. 矛盾问：您方一辩说判断标准是成长的净影响 [待补：以对方场上原话为准]，那兼职占掉的学习时间，在净影响里算不算代价？
> 4. 收束句：对方只算了兼职的收益，没算它占掉的时间；按对方自己的标准，这笔账还没算完。
>
> 用法：每问只让对方答「是 / 不是」或一个词；对方绕开就原样再问一次，再绕就点明「对方两次没有回答」，切下一条链。

同一辩题的正方一辩立论稿全文、三条攻辩链、战场表、结辩框架和论据出处清单，见 [examples/lilun-zhengfang-yibian.md](examples/lilun-zhengfang-yibian.md)。

## 常见问题（FAQ）

**Q：稿子太长了怎么办？**
A：先用 `scripts/speech_timer.py` 量出每段字数，从最长的段删；顺序是修饰和排比、重复的例子、第三论点（挪到攻辩里用）。定义、标准和每个论点「回到标准」那一句不删。

**Q：英文稿和中英混合稿怎么计时？**
A：纯英文用 `--language en`，语速填实测词/分钟；混合稿用默认中文等效字口径，同一个脚本数出一分钟实读段落的计数再填语速。不能拿“150 英文词/分钟”填进默认中文模式。数字与缩写展开成读法，替换占位后重跑，最后整稿实读核验。

**Q：对方不接招，绕开问题或者不回应我方标准，怎么办？**
A：先核对赛制允许追问；允许时把问题重述一次，仍未回应就说「对方还未说明[具体前提]，我方对此的依据是[已核论据]」，切下一条链。不同意我方标准时，问其替代标准，并用同一事实比较两把尺子为何公平；不能把不同意或沉默写成“承认”。自由辩同一个问题连续两次不接，就换战场，由主责在小结引用对方原话和具体缺口。

**Q：抽到了自己不认同的持方怎么办？**
A：比赛立场不等于个人观点。先找这一方最站得住的标准，再按标准找论据；本技能帮任一方写得更严谨。

**Q：查不到数据，能不能先编一个？**
A：不能。查不到就用公认事实、逻辑推演或能核实的具体案例，并标 [待核]；被对方追问出处答不上，比没有这条数据更伤。

**Q：对方说我方定义太窄、偷换概念，怎么接？**
A：定义里写明依据，再备一个例子：「我方的界定符合辩题的通常含义，依据是……；按对方的界定，[反例]也算，这显然不合理。」这句话要在立论前就准备好。

**Q：立论要背下来吗？结辩要不要提前写整稿？**
A：立论要熟到能脱稿，按实测语速计时练三遍。结辩只写框架，第 2、3 段留空，现场按双方原话填。

**Q：一辩、二三辩、四辩的准备怎么分？**
A：一辩立定义、标准和论点；二辩、三辩各负责一条攻辩链和一个自由辩战场；四辩写结辩框架，自由辩时间过半时检查还有哪个战场没打。

**Q：比赛时能不能帮我实时提词？**
A：不能，场外支援违反赛风。赛前把攻辩链、战场表和对方最强三论点的回应准备好，场上照着打。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 把立论稿写成议论文：名言开头、排比收尾 | 评委判的是论证，名言和排比代替不了论据 | 按「定义→标准→论点」写，名言最多一句且注明出处 |
| 标准只对我方成立 | 对方一句话就能否掉，全场失去尺子 | 选对方挑不出毛病、但对我方更有利的标准 |
| 两个论点其实是一件事 | 对方一次就能打掉两个 | 按不同维度分：个人与社会、短期与长期 |
| 攻辩问「您方怎么看……」 | 开放式问题把时间送给对方再立一遍论 | 每问能用「是/不是」或一个词回答，两种答法都备好追问 |
| 结辩提前背整稿 | 和场上交锋对不上，评委听得出是背的 | 只写框架，第 2、3 段按双方原话现场填 |
| 编数据、编名言、编研究 | 一被追问出处，整队失分，也违反赛风 | 查不到的标 [待核]，换成逻辑论证或可查来源 |
| 稿子写满时长 | 场上一紧张就超时被打断 | 写到九成，留出强调和停顿 |
| 自由辩不分工，满场乱打 | 战场散了，对方逐个击破 | 赛前画战场表，每个战场指定主责和小结人 |
| 拿对方辩手的相貌、口音、学校开玩笑 | 违反赛风，评委扣分 | 拆论证，不拆人 |

## 边界与不做什么

- 不替用户对辩题做价值判断：持方由抽签或用户决定，本技能只帮任一方写得更严谨；稿子里的观点是比赛立场，不代表对现实议题的定论。
- 赛制、时长、评分标准以主办方规则为准，与本页说法冲突时听主办方的。
- 比赛进行中不提供场外支援；不写针对对方辩手个人的攻击（相貌、口音、学校），拆的是论证，不是人。
- 辩题涉及法律、医学、金融等专业结论时，论据引用权威机构或正式文献原文；本技能不做专业判断，拿不准的请教指导老师或相关专业人士。
