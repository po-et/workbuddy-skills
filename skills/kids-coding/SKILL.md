# 儿童编程

定位一句话：**6–12 岁学编程，要的是「把一个想法做成能动起来的东西」的经验，不是提前学完语法，也不是攒证书。**

## 何时使用

用户这样说时用：

- 「孩子 7 岁对编程感兴趣，从哪开始」
- 「Scratch 学了一年，什么时候转 Python」
- 「我完全不会编程，孩子卡住了我怎么帮」
- 「要不要报班、考级、刷题」
- 「帮孩子排一个 8 周计划」「第 3 周做完了，接下来呢」

也就是：孩子对编程好奇、想开始；图形化学了一阵，不知道下一步；家长自己不会编程，不知道怎么陪；在犹豫要不要刷题、考级时。工具只说类别，不推荐任何机构和课程。

多轮怎么走：第一轮先定起点（年龄、学过什么、每周几次），给出 8 周计划和本周第一个项目；之后请家长每周带着项目日志回来说「做完了什么、卡在哪」，按检查点决定顺延还是往下走。

不适用：

- 13 岁以上或成人零基础：转编程入门技能 `coding-for-beginners`。6 岁以下不排编程计划：5 岁左右可以看低龄版图形化工具官网标注的适用年龄，以玩为主、家长陪着；更小的孩子不在本技能范围。
- 推荐机构、课程、比赛，或代做作业、竞赛题、考级题：不做；可以按下文「试听看四件事」帮你评估课程大纲，陪孩子自己调试。
- 竞赛和考级的规则、升学政策：以主办方和教育部门的官方发布为准。

## 先判断：图形化起步，还是 Python 起步

第 1 步，回答五个问题：

```
1 能不看键盘、比较顺地打出英文单词吗？
2 能看懂简单的英文提示（如 error、name、print）吗？
3 在图形化工具里自己用过「重复」「如果」「变量」吗？
4 能专注做一件事 30 分钟以上吗？
5 想做的东西在图形化里已经很费劲（算术、文字处理、数据）吗？
```

第 2 步，按年龄套用：

- **6–8 岁**：图形化起步，不管上面答了几个「是」。拖拽积木没有打字门槛，改一处马上看到效果。图形化工具一般分低龄版和标准版，设计年龄以官网标注为准（常见标注：低龄版 5–7 岁，标准版 8 岁以上）。
- **9–10 岁**：「是」有四个及以上，可以直接学 Python，或图形化和 Python 双线并行；三个以下，先图形化。
- **11–12 岁**：对做游戏、动画兴趣不大，对数字和文字更感兴趣的，可以直接从 Python 开始。
- **已经学过图形化的**：第 1、3、5 题都答「是」，就是转 Python 的时候，先走下面的两周过渡。

第 3 步，定节奏和设备：6–8 岁每次 20–30 分钟，9–12 岁每次 40–60 分钟，每周 2–3 次（参考值）。一台普通电脑就够；图形化可以用平板，Python 需要带键盘的电脑；不必一开始就买机器人套件。正式开始前，先让孩子自由摆弄工具一两次，不布置任务。编程也算屏幕时间，按家里的约定来，可参考手机管理 `kids-screen-time`。

## 8 周计划：每周一个小项目

每个项目分三次做：**照做**（跟着示例做出来）→ **改**（至少改三处：颜色、速度、规则）→ **加**（加一个自己的点子），最后花两分钟演示给家人看。题材换成孩子喜欢的东西（恐龙、足球、宠物），概念不变；哪一周没做完就顺延，不赶进度。每次开头花 3 分钟看上次的日志，结尾花 2 分钟写下「下次想加什么」，下次就从这句开始。每个项目做完，截一张图或录 30 秒演示，按周编号存进作品集文件夹，这比证书更能说明学到了什么。

八周的主线：第 1–6 周各学一个新概念——顺序与坐标、循环、事件与输入、条件、变量与计分、列表与克隆；第 7 周在纸上设计自选项目，第 8 周把它做完、修 bug、演示。每周有一个图形化项目（6–9 岁）和一个 Python 项目（9–12 岁），外加一条「孩子能做到」的检查点，全表见 [references/8-week-plan.md](references/8-week-plan.md)。

第 4 周的 Python 示例：

```python
# 保存为 guess.py；macOS/Linux 运行 python3 guess.py，Windows 运行 py guess.py
import random
answer = random.randint(1, 100)
while True:
    n = int(input("猜一个 1 到 100 的数："))
    if n > answer:
        print("大了")
    elif n < answer:
        print("小了")
    else:
        print("猜中了！")
        break
```

检查点里的「故意出错」，在这里就是输入 abc：程序报错停下。让孩子读一读报错的最后一行，想想怎么办，这就是第一次调试。修好之后的写法放在全表文件里，给家长对答案用。

8 周后看三件事：能不能独立做完一个小项目；遇到 bug 会不会先自己查；能不能把作品讲给别人听。三件都做到，开第二轮，项目变大，两周一个；做不到的，换个题材重做第 5–8 周，不往后赶。

## 从图形化转到 Python：两周过渡

不急着开新课，先用两周「翻译」旧作品。第 1 周对照积木学写法（积木的具体名字以所用工具为准）：

```
说「你好」               →  print("你好")
询问并等待，得到回答     →  name = input("你叫什么？")
把「分数」设为 0         →  score = 0
把「分数」增加 1         →  score = score + 1
重复 10 次               →  for i in range(10):
一直重复                 →  while True:
如果……那么……否则         →  if 条件:  和  else:
1 到 10 之间的随机数     →  random.randint(1, 10)
```

第 2 周，挑一个孩子做过的图形化项目（问答、猜数字、计分都行），用 Python 重写成文字版，不要画面。做完再进入 8 周计划的 Python 一列。过渡期里照样可以玩图形化，两边不冲突；想做带画面的游戏，图形化反而更快。

中文用户最常见的两个报错：一是用了中文标点，代码里的括号、引号、冒号、逗号都要在英文输入法下打，只有引号里面的字可以是中文；二是缩进不齐，冒号后面的下一行统一缩进 4 个空格，不和 Tab 混用。

安装：从 Python 官网下载 3.x 版本，Windows 安装时勾选添加到 PATH 的选项。官方安装包自带 IDLE 编辑器，打开文件按 F5 就能运行，孩子不必先学命令行。

## 家长不会编程怎么陪：当提问者，不当修理工

- **只需要懂五个词**：顺序像菜谱的步骤，循环像跳绳数到十，条件像「下雨就带伞」，变量像记分牌，列表像购物清单。看作品时问一句「这里哪一块是循环？」就够了。
- **手不碰键盘鼠标**：可以指着屏幕问，不替孩子点、不替孩子改。
- **卡住时问三句**：「你想让它做什么？」「它现在实际做了什么？」「你最后改的是哪一处？」很多 bug 就藏在第三句的答案里。
- **看报错不慌**：报错不是失败，是程序在告诉你哪一行出了问题。和孩子一起念一遍最后一行，找到行号，就解决了一半。
- **限时求助**：卡住超过 20 分钟（6–8 岁 10 分钟）就停下，休息一下、回看示例、把问题讲给玩偶听；再不行，查工具自带的教程。家长不直接给答案。
- **让孩子当老师**：每周花 5 分钟，让孩子教你做一个小功能，你真的跟着做。讲得清楚，才是真会了。
- **项目日志**：日期、做了什么、遇到什么问题、怎么解决、下次想加什么。低龄孩子口述，家长代记。
- **看作品只问不评分**：「最难的是哪部分？」「哪里是你自己想出来的？」「再加一个功能，你加什么？」
- **兴趣掉了**：先换成他正迷的题材，再缩短单次时间，或者约一个同学结伴做；还不行就停一两个月。
- **分享作品护隐私**：不用真名、学校和照片；评论区家长一起看。

## 最佳实践：五条就够

1. **一次一个项目**：照做 → 改三处 → 加一个自己的点子 → 两分钟演示，比赶进度重要。
2. **短时多次**：6–8 岁每次 20–30 分钟，9–12 岁 40–60 分钟，每周 2–3 次，放在作业做完后的轻松时段。
3. **家长只提问、不动手**：卡住先问三句，超时再一起查教程，不直接给答案。
4. **用作品集代替证书**：每周一张截图或 30 秒演示，外加孩子能讲清一个作品是怎么做的。
5. **兴趣优先**：题材跟着孩子走；兴趣掉了先换题材、缩短时间，不硬推。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话 |
|---|---|---|
| 缺关键信息 | 先问三个：年龄或年级、学过什么（没学过／图形化学了多久／学过 Python）、每周能安排几次；其余默认：家里有带键盘的电脑、孩子自己感兴趣，标 [待确认] | 「先问三件事：孩子几岁？之前学过什么、学了多久？每周大概能安排几次？」 |
| 年龄不在 6–12 岁 | 13 岁以上转 `coding-for-beginners`；6 岁以下不排计划，5 岁左右只说明可看低龄版工具标注的适用年龄、以玩为主 | 「本技能按 6–12 岁设计。孩子 14 岁的话，用编程入门技能更合适。」 |
| 信息互相矛盾（「学了一年 Scratch，但没用过变量」；「8 岁，想直接学 C++ 打竞赛」） | 指出矛盾，给两种理解，按五个问题重新判断 | 「学了一年却没用过变量，是课上都在照做，还是用过但不知道叫变量？我们用五个问题重新看起点。」 |
| 问题和编程无关（数学作业、英语） | 说明本技能只管编程入门，简短回答或请用户找对应的技能 | 「这是数学作业的问题，不在编程入门的范围里；要的话我简单说一下思路。」 |
| 时间紧，只要最小可用版 | 最小版 = 起点结论一句 + 本周一个项目（照做、改、加）+ 卡住三问 | 「先给你这周能开始的：从图形化起步，这周做『角色走一圈』，卡住就问这三句。」 |
| 代码跑不起来 | 先按卡住三问排查，再看报错最后一行，检查中文标点和缩进；仍不行请用户把最后一行报错发来 | 「把报错的最后一行发我；先看看括号、引号、冒号是不是在中文输入法下打的。」 |
| 用户坚持越界（推荐机构、代写比赛作品、要「保证获奖」「提高智力」的说法） | 守住边界，给能做的替代 | 「比赛作品得孩子自己做；我可以陪他复盘自己的作品，讲清楚每一步。」 |
| 孩子抗拒、兴趣掉了 | 按顺序试：换题材 → 缩短单次时间 → 约同学结伴 → 暂停一两个月 | 「先换成他最近迷的题材，每次缩到 15 分钟；还不行就停一两个月，不强求。」 |

## 输出契约

交付物按这个顺序，缺的信息写 [待补] 或 [待确认]：

1. **起点判断**：五个问题的答案、结论（图形化、Python 或双线）和一句理由。
2. **8 周计划表**：按孩子年龄选列，题材换成孩子的兴趣，每周带检查点。
3. **本周第一个项目**：照做、改、加三次各做什么，每次多长时间。
4. **家长提问卡**：卡住三问和看作品三问，可以打印出来贴在电脑旁。
5. **代码示例**：只给能在标准 Python 3 里运行的短代码，写明运行方法；图形化起步时写「不适用」。
6. **下一步**：8 周结束时按「三件事」的结果，给出第二轮计划或重做哪几周。

规则：不承诺——不写竞赛成绩、升学加分、提高智力之类的话；工具只说类别，不推荐机构和课程。

占位符：[待补] = 需要家长提供的信息（孩子喜欢的题材、每周具体时段）；[待确认] = 我按默认值写的内容（设备、每周次数、低龄版还是标准版）。

交付前自检（逐条答是或否）：

- [ ] 起点结论与年龄规则一致（6–8 岁一定是图形化起步）？
- [ ] 每周都有检查点，题材换成了孩子的兴趣？
- [ ] 代码在标准 Python 3 里运行过，并写了运行方法？
- [ ] 没有机构、课程、比赛推荐，也没有「保证获奖」「升学加分」「提高智力」？
- [ ] 家长的角色是提问，不是替孩子改？

## 示例

**示例**（孩子情况为虚构）

用户：「孩子 7 岁对编程感兴趣，儿童编程从哪开始？」

助手：「先问三件事：他最近最迷什么（恐龙、足球、游戏……）？家里有电脑还是只有平板？每周大概能安排几次、每次多久？」

用户：「迷恐龙。有台笔记本，也有平板。周末两天都行，每次半小时左右。」

交付：

> **起点判断**：7 岁，按年龄规则直接图形化起步，五个问题暂时不用答；9 岁前后再用它们判断何时加 Python。平板和笔记本都能用；7 岁可以先试低龄版，觉得太简单就换标准版，以工具官网标注的适用年龄为准 [待确认]。
>
> **8 周计划**（图形化一列，恐龙题材）：
>
> | 周 | 新概念 | 项目 | 检查点 |
> |---|---|---|---|
> | 1 | 顺序、坐标 | 小恐龙走一圈、打招呼 | 改一个数，先说会发生什么 |
> | 2 | 循环 | 恐龙蛋一直摇晃、转圈 | 说出「重复几次」由哪个数决定 |
> | 3 | 事件与输入 | 方向键控制恐龙移动 | 指出程序在哪一步等人输入 |
> | 4 | 条件 | 恐龙碰到火山就回到起点 | 故意做一个让程序出错的操作 |
> | 5 | 变量与计分 | 恐龙吃果子计分，10 分过关 | 说清分数在什么时候变 |
> | 6 | 列表与克隆 | 天上掉下一群小陨石 | 多加一个克隆体并跑通 |
> | 7 | 自选项目：设计 | 纸上画出三幕恐龙故事 | 写下「做什么、怎样算做完」 |
> | 8 | 自选项目：完成 | 修 bug、加说明、演示给家人看 | 讲清一个自己修掉的 bug |
>
> **本周第一个项目**：周六 30 分钟，照着示例让小恐龙走一圈、说「你好」；周日 30 分钟，改三处（颜色、速度、说的话），再加一个自己的点子，最后两分钟演示给家人看。
>
> **家长提问卡**：卡住时问「你想让它做什么？它现在实际做了什么？你最后改的是哪一处？」；看作品时问「最难的是哪部分？哪里是你自己想出来的？再加一个功能，你加什么？」
>
> **代码示例**：不适用（图形化起步）。
>
> **下一步**：每周末把项目日志（做了什么、卡在哪、下次想加什么）发我；8 周后看三件事——独立做完一个小项目、遇到 bug 先自己查、能讲给别人听。

学过一年 Scratch 的 10 岁孩子怎么判断、怎么过渡到 Python 的完整示例，见 [examples/scratch-to-python-10yo.md](examples/scratch-to-python-10yo.md)。

## 常见问题（FAQ）

**Q：几岁开始合适？**
A：本技能按 6–12 岁设计：6–8 岁图形化起步，9 岁以后用五个问题判断要不要加 Python。

**Q：要不要报班？**
A：先用免费工具在家试几周，确认兴趣还在；要报班，试听时看下文「常见错误」末尾的四件事。

**Q：考级、竞赛有用吗？**
A：证书只说明考过某些题。先让孩子独立做完几个自己想做的项目、讲清自己写的代码；比赛规则和升学政策以主办方和教育部门的官方发布为准。

**Q：我完全不会编程，能陪吗？**
A：能。懂五个词（顺序、循环、条件、变量、列表），手不碰键盘，卡住时问三句，就够了。

**Q：只有平板可以吗？**
A：图形化可以用平板；学 Python 需要带键盘的电脑。

**Q：孩子只想玩游戏，不想做项目怎么办？**
A：把项目题材换成他正在玩的游戏，做一个简化版；做出来能玩，兴趣就回来了。

**Q：学编程会不会让屏幕时间太长？**
A：编程也算屏幕时间，按家里的约定来，可参考 `kids-screen-time`；出现视力下降、眼睛不适，找眼科医生。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 过早刷题：还没独立做完几个自己想做的项目，就去刷竞赛题、在线评测题 | 编程变成做题，兴趣最先被消耗 | 先能讲清自己写的代码，再谈算法 |
| 只看证书和等级 | 证书只说明考过某些题 | 看作品集，以及孩子能不能讲清其中一个作品是怎么做的 |
| 只看视频不动手 | 看一小时教程，不如自己动手做二十分钟 | 每次都要动手做出一个东西 |
| 照抄能跑就结束 | 没改过就说明没真正理解 | 每个项目至少改三处，才算学过 |
| 家长替孩子修 bug、追求作品好看 | 作品不再是孩子的，他也没学到调试 | 家长只提问；作品是孩子的，丑一点没关系 |
| 以为要数学好、英语好才能学 | 把孩子挡在门外 | 图形化起步不需要；Python 用到的英文单词不多，边用边认 |
| 和别人家孩子比进度 | 学到几级、上了几节课都说明不了什么 | 看做成了什么 |
| 一开始就买贵的硬件 | 兴趣还没确认 | 先用免费软件确认兴趣还在 |
| 和作业、补习排在一起 | 孩子会把它归成「又一门课」 | 放在周末或作业做完后的轻松时段 |

考虑报班时，试听看四件事：孩子自己动手的时间占一半以上吗？课后拿得到孩子自己写的源文件吗？老师会让孩子讲解自己的代码吗？有没有「保证获奖」「升学加分」之类的承诺？有这类承诺就要警惕。

## 边界与不做什么

- 不推荐具体培训机构、课程、比赛或付费平台；用户给出课程大纲时，可以按上面四件事帮忙评估。
- 不代做作业、竞赛题或考级题；可以讲思路，陪孩子自己调试。
- 竞赛和等级考试的规则、报名和升学政策，以主办方和教育部门的官方发布为准；孩子想参加，先确认是他自己想去，这里只帮他复盘自己的作品。
- 需要注册账号的平台由家长操作，并先确认平台的年龄要求。
- 视力下降、眼睛不适，找眼科医生；孩子明显抗拒，就暂停一两个月，不强求。
