# 示例：技术岗 JD，从澄清到交付六件套

以下为示例，公司、业务与数字均为虚构；薪资、值班频率等都来自示例中「用户」给出的信息，不是助手编的。

## 1. 用户原话

> 帮我写个 JD，招一个三年左右经验的 Java 后端。用人部门给了这么一段：「急招 Java 开发，35 岁以下，985/211 优先，抗压能力强，熟悉 Spring Boot、MySQL、Redis、Kafka，有高并发经验，能接受加班。」

## 2. 助手先问（只问 3 件，其余先按默认写并标【待确认】）

1. 为什么现在招？入职半年后，这个人做出什么就算招对了？
2. 上面这些条件里，缺了哪几条就一定不给面试？
3. 薪资区间与结构批了没有？工作地点、坐班还是远程、多久值一次班？

> 用户：新业务，要把商家进货从电话下单搬到线上，这个人负责订单链路；半年后能独立负责订单服务上线，扛住月底进货高峰。必须的是：三年左右 Java 后端、MySQL 和 Redis 的原理、线上故障排查经验；Kafka、高并发、同行业算加分。薪资批了，税前月薪 25–35K，14 薪。杭州，坐班，每 4 周值班一周。流程是两轮技术面加一轮 HR 面，大约两周。

## 3. 助手交付

### ① 岗位摘要

后端开发工程师（Java）｜杭州，到岗办公｜汇报对象【待确认：订单组负责人】｜25–35K × 14 薪，税前月薪

### ② JD 正文

```markdown
**后端开发工程师（Java）**

我们做面向商家的进货系统，已服务【待补：商家数量】家商家；接下来要把进货从电话下单搬到线上，这个岗位负责其中的订单链路。

**你会做**
1. 负责订单服务的设计、开发与线上维护，保障月底进货高峰期间核心接口稳定
2. 参与技术方案评审，推动下单流程从电话到线上的改造落地
3. 定位并解决线上问题，参与值班（约每 4 周一次，每次一周）

**我们需要你**
1. 三年左右 Java 后端经验，能独立负责一个服务从设计到上线
2. 熟悉 MySQL、Redis 的原理与常见问题
3. 能讲清一次你主导的线上故障排查

**加分项（非必须）**：消息队列（如 Kafka）使用经验；高并发场景经验；同行业经验

**你能得到**：25–35K × 14 薪（税前月薪）；【待补：奖金或期权规则】；杭州到岗办公；【待确认：导师与晋升通道】

**流程**：两轮技术面 + 一轮 HR 面，约两周给结论；投递 jobs@example.com，邮件标题「姓名-后端-年限」
```

### ③ 用人经理确认单

| 必要条件 | 缺了就不面？ | 对应面试问题 | 及格标准 |
|---|---|---|---|
| 三年左右 Java 后端，独立负责过一个服务 | 是 / 否 | 「讲一个你从设计到上线负责的服务」 | 说得清设计取舍和上线后的问题 |
| MySQL、Redis 原理与常见问题 | 是 / 否 | 「缓存和数据库不一致，你遇到过怎么处理」 | 能讲出一次真实处理过程 |
| 主导过线上故障排查 | 是 / 否 | 「讲一次你主导的故障排查」 | 说得出定位步骤与复盘改进 |

JD 里没写的要求，面试时不要临时加码。

### ④ 风险提示清单

脚本粗筛用人部门的原话（本机实际运行结果）：

```
$ python3 {baseDir}/scripts/jd_risk_scan.py dept.txt
共 1 行，命中 2 处（命中不等于违规，逐条人工看）：
第 1 行［年龄］「35 岁」：急招 Java 开发，35 岁以下，985/211 优先，抗压能力强，熟悉 Sp……
    → 删除年龄限制，改写经验与能力，如「3–5 年相关经验」
第 1 行［学校标签］「985、211」：急招 Java 开发，35 岁以下，985/211 优先，抗压能力强，熟悉 Sp……
    → 改写为能力证据；学校标签缩窄人才池，也容易被视为学历歧视
是否合规由 HR 或法务按现行规定判断；误报（如「女装」「品牌形象」）可忽略。
```

| 原句 | 问题 | 处理 |
|---|---|---|
| 35 岁以下 | 年龄限制，高风险 | 已删除，改写为「三年左右 Java 后端经验」 |
| 985/211 优先 | 学校标签 | 已删除，用「独立负责过一个服务」等能力证据代替 |
| 急招 | 岗位名称不加「急聘」「高薪」这类字眼 | 已删除 |
| 抗压能力强 | 形容词，无法验证 | 改为「参与值班」「讲清一次故障排查」 |
| 能接受加班 | 没写事实 | 改为值班频率（每 4 周一次）；日常加班情况【待确认】 |

正文已按清单检查，仍需 HR 复核。

### ⑤ 待补 / 待确认清单

- 【待补】商家数量（正文第一段）；奖金或期权规则（「你能得到」）
- 【待确认】汇报对象（岗位摘要）；导师与晋升通道（「你能得到」）；日常加班情况（风险清单）

## 4. 这个示例体现的做法

- 只问 3 个问题就动笔；其余用【待补】【待确认】占位，不编商家数、福利。
- 用人部门原话里的高风险表述不照搬，改写理由写进风险清单。
- 必要条件 3 条、加分项 3 条分开列，并落到面试问题上。
