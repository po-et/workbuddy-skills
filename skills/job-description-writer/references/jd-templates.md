# 三份 JD 模板：技术岗、运营岗、实习生

按岗位类型取用一份即可，不要三份一起贴给用户。【】里是要替换的内容：用户给了就填，没给的写成【待补：……】或【待确认：……】，规则见 SKILL.md「输出契约」。

三份模板共用同一骨架：一句话钩子 → 你会做 → 我们需要你 → 加分项（非必须）→ 你能得到 → 流程与投递方式。

## 技术岗（后端开发工程师）

适用：研发、测试、运维类岗位。侧重服务与可用性目标、值班频率，以及一次能讲清的线上故障排查。

```
【一句话：团队在做什么，这个岗位为什么现在要招】
你会做：
1. 负责【某业务】服务的设计、开发与线上维护，保障【可用性或性能目标】
2. 参与技术方案评审，推动【某项技术改造】落地
3. 定位并解决线上问题，参与值班（约每【N】周一次）
我们需要你：
1. 【N】年左右【语言】后端经验，能独立负责一个服务从设计到上线
2. 熟悉【数据库、缓存、消息队列】中至少两项的原理与常见问题
3. 能讲清一次你主导的线上故障排查
加分项（非必须）：【高并发经验】【开源贡献】【同行业经验】
你能得到：【月薪区间 × 薪数】+【奖金或期权规则】；【办公方式】；【导师与晋升通道】
流程：【两轮技术面 + 一轮 HR 面，约两周】；投递 jobs@example.com，标题「姓名-后端-年限」
```

## 运营岗（用户运营）

适用：运营、市场、增长类岗位。侧重季度指标、活动从方案到复盘的完整经历、表格分析能力。

```
【一句话：产品阶段、用户规模、这个岗位要解决的增长或留存问题】
你会做：
1. 负责【某类用户】的拉新、激活与留存，季度目标为【指标 + 数值】
2. 策划并执行运营活动，从方案、上线到复盘全程负责
3. 搭建用户分层与触达策略，每周复盘关键数据
我们需要你：
1. 【N】年左右用户运营经验，独立负责过完整活动并说得出数据结果
2. 会用表格工具做基础分析（透视表、分组对比）
3. 能写清楚活动规则与用户通知
加分项（非必须）：【社群经验】【SQL】【同行业经验】
你能得到：【薪资区间 × 薪数】；【活动预算与试错空间】；【成长路径】
流程：【一轮业务面 + 一轮 HR 面】；投递 jobs@example.com，附一页你做过的活动复盘
```

## 实习生（数据分析实习生）

适用：实习、校招。不写工作年限，改看课程、项目、竞赛；写清每周到岗天数、最短实习时长、导师与留用机会。

```
【一句话介绍团队】；实习期【起止月份】，每周到岗【N】天，【地点或可远程】
你会做：
1. 在导师指导下完成日常取数与报表维护
2. 参与一个专题分析，从提出问题到写出结论，结束前独立汇报一次
我们需要你：
1. 【年级与专业方向，或同等能力】，能保证每周【N】天、至少【M】个月
2. 会用 SQL 或 Python 做基础数据处理
3. 能把分析结论讲给非专业的人听，课程报告或项目作品均可证明
你能得到：日薪【金额】，【餐补或房补】；一对一导师；【留用机会，如实写有或没有】
流程：【一轮面试，一周内给结论】；投递 jobs@example.com，附简历与一份作品（课程作业也可以）
```

## 套用后的检查

- 每个【】都已替换，或改写成【待补：……】【待确认：……】并进了待补清单。
- 「你会做」按时间占比排序，第一条是最主要的工作。
- 「我们需要你」不超过 5 条；加分项另列，写明「非必须」。
- 跑一遍 `python3 {baseDir}/scripts/jd_risk_scan.py jd.txt`，命中项逐条人工看。
