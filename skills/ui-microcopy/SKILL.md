# UI 文案

定位一句话：**界面上的每一句字都在回答用户此刻的一个问题；答不上那个问题的文案，写得再顺也是噪音。**
何时用：新写或改写按钮、空状态、报错、弹窗、加载与成功提示、表单文字；要出中英双语版；上线前统一全产品用词。

## 先判断：用户此刻在问什么

```
按钮      点了会发生什么？  → 动词 + 对象：「保存草稿」「发送邀请」
空状态    为什么是空的？我能做什么？  → 原因 + 一个能点的下一步
错误提示  出了什么事？怪我吗？怎么办？  → 发生了什么 + 怎么解决，不怪用户
确认弹窗  能撤回吗？会失去什么？  → 具体动作 + 后果 + 与动作同名的按钮
加载      还在动吗？要等多久？  → 正在做什么；等得久就给进度
成功反馈  成了吗？结果在哪？  → 结果 + 去哪看或下一步
表单      填什么？什么格式？为什么要？  → 常驻标签 + 格式示例 + 用途说明
```

## 三条原则与写作步骤

**说明后果**：点下去之前就知道会怎样。**给下一步**：任何提示都不是死路。**别让用户猜**：不用「操作」「异常」「非法」这类系统视角的词。

```
1 写场景    谁、在哪个页面、刚做了什么、此刻的状态（着急 / 第一次用 / 刚出错）
2 写问题    把上表对应的问题写成一句话，文案必须正面回答它
3 写中文    动词开头，一句只说一件事；时限、上限、能否恢复等事实从产品规则取，拿不到写【待确认】
4 写英文    不逐字翻译，按英文界面习惯重写；按钮大小写（句首大写或每词大写）全产品只用一种
5 放进界面  在最窄屏幕、最长语言下看会不会截断；英文通常比中文长，按钮和标签留余量
```

## 六类文案：模板、中英对照与反例

**按钮**
```
正例  保存草稿 Save draft  发送邀请 Send invite  删除项目 Delete project
反例  删除弹窗里的「确定 OK」  其实是付款的「提交 Submit」  「点击这里 Click here」
```

**空状态**
```
首次使用  还没有项目。新建一个，邀请同事一起编辑。[新建项目]
          No projects yet. Create one and invite your team to edit it together. [New project]
搜索无果  没有找到与「季度报表」相关的文件。试试更短的关键词，或检查拼写。
          No files match "quarterly report". Try a shorter keyword or check the spelling.
反例      暂无数据 / No data    ← 没说为什么，也没给出路
```

**错误提示**
```
模板  发生了什么 +（能说的话）为什么 + 怎么办；用户已填的内容保留
正例  文件超过 20 MB，无法上传。压缩后重试，或拆成几个小文件。
      This file is larger than 20 MB. Compress it or split it into smaller files, then try again.
字段  请输入 11 位手机号 / Enter an 11-digit phone number  ← 说正确格式，贴在出错的字段旁
反例  上传失败（错误码 413）/ Error 413     输入非法 / Invalid input     系统异常，请稍后再试
```

**确认弹窗**
```
标题  删除「年度预算」？ / Delete "Annual budget"?
正文  表内 12 个工作表会一起删除，30 天内可在回收站恢复。【天数按产品规则填】
      All 12 sheets will be deleted. You can restore them from Trash within 30 days.
按钮  [删除] [取消] / [Delete] [Cancel]          ← 主按钮重复标题里的动词
反例  确定要执行此操作吗？[确定][取消] / Are you sure? [OK] [Cancel]
```
能撤销的操作不弹确认，直接执行并给「撤销 / Undo」；确认弹窗留给不可逆、或会影响别人的动作。

**加载与成功反馈**
```
加载  1 秒内不提示；1–10 秒写正在做什么「正在导入… / Importing…」；超过 10 秒给进度，并允许取消或先离开：
      正在导入 3/12 个文件，完成后会通知你。 / Importing 3 of 12 files. We'll notify you when it's done.
成功  已发送给小王，可在「已发送」中查看。 / Sent to Xiao Wang. You can find it in Sent.
反例  操作成功！/ Success!        ← 没说成了什么、结果在哪
```
1 秒、10 秒取自 Jakob Nielsen 总结的响应时间经验值，团队有规范按规范。勾选、切换开关这类显而易见的操作不弹成功提示，界面状态的变化本身就是反馈。

**表单标签与占位符**
```
标签    手机号 / Phone number                        ← 名词短语，始终可见
占位符  例：138 0000 0000 / e.g., 138 0000 0000      ← 只放格式示例，一输入就消失，不能代替标签
说明    仅用于接收验证码，不会公开 / Only used for verification codes. Never shown publicly.
必填    只标少数的那一类：多数字段必填时，只给少数标「选填 / Optional」
反例    标签写成「请输入您的手机号码」；格式要求只写在占位符里
```

## 20 条自查清单

```
按钮    1 单看按钮就知道点了会发生什么（动词 + 对象）
        2 危险操作的按钮写出动作（删除、移除），不写「确定」
        3 同一动作全产品一个词：删除与移除、保存与存储不混用
        4 成对按钮主次分明，主按钮与弹窗标题的动词一致
空状态  5 说了为什么是空的      6 给了一个能点的下一步      7 搜索无结果时回显关键词并给改法
错误    8 说了发生什么和怎么办，不只有错误码
        9 不责怪用户：没有「非法」「您输入有误」「违规操作」
       10 出错后已填内容保留     11 字段错误贴在该字段旁，写出正确格式
弹窗   12 标题写出具体动作和对象     13 正文说清能否撤回、影响范围
       14 可撤销的操作改用「撤销」，不弹确认
反馈   15 超过 1 秒有「正在……」，超过 10 秒有进度或可取消
       16 成功提示说结果在哪；显而易见的操作不弹提示
表单   17 标签常驻，占位符只放示例     18 敏感字段写明用途
通用   19 没有「操作成功」「系统异常」「请稍后再试」这类零信息句
       20 英文在最窄屏不截断；文中的时限、上限等事实都有产品规则出处，没有的标【待确认】
```
改存量文案时，先把第 5、9、12、19 条的典型坏句捞出来（locales/ 换成放文案的目录）：

```bash
grep -rnE '操作成功|操作失败|系统异常|请稍后再试|非法|暂无数据|确定要执行|Are you sure|Invalid|Success!' locales/
```

## 输出契约

交付一张表：`位置 | 触发时刻 | 中文 | English | 回答了用户的哪个问题`。
- 关键文案（删除确认、付款按钮、报错）给 2 个版本并说明差别，由用户选。
- 文案里的事实——上限、保留天数、能否恢复、多久到账——都标出处；产品没定的写【待确认】，不替产品编规则。
- 改稿保留原文一列，逐条说改了什么、为什么，不整段重写。
- 最后附 20 条自查结果：哪几条没过、为什么。

## 边界与不做什么

- 不写用户协议、隐私政策、免责声明等法律文本，也不判断文案是否合规，请交给法务。
- 不写操纵性文案：羞辱式拒绝按钮（「不了，我不想省钱」）、虚假倒计时、把「取消订阅」藏起来的措辞。
- 不替团队定品牌语气：活泼还是克制按团队的写作规范；没有规范时先问一句再写。
- 只做中文与英文；其他语言的本地化请找专业译者与母语审校。
- 不替代可用性测试：文案好坏，最终看真实用户能否不看帮助就完成任务。
