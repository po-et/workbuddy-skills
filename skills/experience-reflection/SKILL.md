# 心得体会

定位一句话：**心得体会不是把活动复述一遍，而是讲清「那件事里哪一刻改变了我的看法，我接下来打算怎么做」——而且每一段经历、每一句原话、每一个数字，都得是你自己的。**

## 何时使用

用户这样说时用本技能：

- 「单位培训结束了，要交一篇心得体会」
- 「读书活动要写读书心得，800 字」
- 「暑期社会实践、实习、志愿服务结束了，写实践心得」
- 「听了一场讲座（开了个会），要交学习心得」
- 「我写的心得全是套话，帮我改具体一点」
- 「要求 3000 字，我不知道怎么写满」

不适用（遇到时这样处理）：

- 看电影、纪录片、剧集之后写感想：转「观后感」技能。
- 军训结束写心得：转「军训心得」技能（军训专用）。
- 以单位名义上报的学习情况报告等公文：转「公文写作」技能；本技能只写个人署名的心得。
- 回顾一学期、一季度自己做了什么：转「个人总结」技能。

## 第 1 步：先采素材，再动笔

心得写不具体，几乎都是因为动笔前没有素材。先问这五个问题（一次最多问三个，缺哪个问哪个；都缺时先问第 1、2、5 个）：

1. **什么活动**：名称、时间、主办方，你是参加者、主讲人还是组织者？字数和提交要求是什么？
2. **哪一刻印象最深**：一句话、一个案例、一个画面、一个数字，还是自己的一次失误？
3. **为什么是它**：它让你想起自己以前的哪件事、哪个做法？
4. **看法变了没有**：以前你以为……，现在觉得……？
5. **回去做什么**：真打算做的一两件事，什么时候做，怎样算做到？

答不上来的留 [待补]，不替用户编。想不起「触动点」时，让用户从五类里挑：

| 触动点类型 | 开头怎么写 | 真实性要求 |
|---|---|---|
| 一句话 | 先写那句话和当时的场景，再写你为什么停了一下 | 记得原话才加引号；只记得意思就写「大意是」 |
| 一个案例 | 两三句复述案例的关键转折，再接「这让我想到……」 | 只写讲的人说过的细节，不补情节 |
| 一个画面 | 白描时间、地点、动作，少用形容词 | 写你亲眼看到的 |
| 一个数字 | 写数字和出处，再写你原来以为是多少 | 数字必须有出处，没有就不用 |
| 一次失误 | 写做错了什么、谁指出的、你当时的反应 | 写你自己的，不写别人的糗事 |

## 第 2 步：按「经历—触动—思考—行动」成文

| 部分 | 回答什么 | 占比 | 写法要点 |
|---|---|---|---|
| 经历 | 什么时候、什么活动、我做了什么 | 约 15% | 两三句交代，不抄议程，不罗列全部内容 |
| 触动 | 哪一刻最触动我 | 约 20–25% | 写细节：原话、画面、数字；800 字只写一个 |
| 思考 | 为什么触动我、和我的哪件事有关、看法怎么变了 | 约 35% | 用「以前我以为……，现在我明白……」「这让我想起……」接上自己的经历 |
| 行动 | 回去具体做什么 | 约 20–25% | 每条写清做什么、什么时候、怎样算做到；一般两三条，不超过四条 |

结尾一两句，回扣开头的触动点，不喊口号。

思考和行动是最容易「替用户编」的地方：助手可以把用户说过的想法讲清楚、讲深一层，但**新提炼的结论、助手建议的行动，都要在句后标 [待确认]**，由用户认可后再删掉标记。

## 三档篇幅：800 / 1500 / 3000 字

| 档位 | 触动点 | 段落与小标题 | 各部分约字数 |
|---|---|---|---|
| 800 字 | 1 个 | 5–6 段，不用小标题 | 经历 120，触动 180，思考 280，行动 170，结尾 50 |
| 1500 字 | 1 主 + 1 辅 | 8–14 段，可用 2–3 个小标题 | 经历 200，触动 350，思考 550，行动 300，结尾 100 |
| 3000 字 | 2–3 个，各成一节 | 开头 + 三节（每节走一遍「触动—思考—小行动」）+ 总行动 + 结尾 | 开头 300，三节各约 700，总行动 450，结尾 150 |

用户给了别的字数，按比例缩放。字数不够时加的是第二个触动点，或给思考加一层（以前为什么那样做、反过来会怎样）；不是重复口号、抄材料。超了先删经历段里的议程复述。

字数每次用同一个口径数，结果才前后一致。本技能统一数「不含空白的字符（含标点）」，可以把正文存成文本后运行：

```bash
python3 -c "import sys; t=open(sys.argv[1], encoding='utf-8').read(); print(sum(1 for c in t if not c.isspace()))" 正文.txt
```

这个数和 Word、WPS 的「字数」可能略有出入；收稿方有指定口径时以收稿方为准。

## 第 3 步：按场景调整

- **培训**：触动点多来自讲师的案例或实操中的失误；思考落到自己的岗位；行动写成可检查的工作改进（哪项流程、哪天之前）。
- **读书**：触动点是书里的一段话或一个人物处境；引文照原书抄录并注篇名或页码；内容简介不超过全文五分之一。
- **实践**（社会实践、实习、志愿服务）：触动点多是一个人或一个场景；写到服务对象时不写全名和可识别身份的细节，未成年人尤其如此；走访户数、服务时长只写有记录的。
- **讲座、会议**：触动点是主讲人的一个观点或案例；记得原话才加引号。涉及文件、讲话原文的，只用用户提供的原文并提醒核对出处，不凭记忆生成原文。

## 套话：清单与替换思路

每个套话都在回避一个具体信息。替换的办法是追问「具体是哪个？」，把答案写进去；答不出就删。最常见的八个：

| 套话 | 替换思路 |
|---|---|
| 受益匪浅、收获颇丰 | 写出一件具体收获：学会了什么、改掉了什么 |
| 深刻认识到……的重要性 | 写看法的变化：以前怎么想、怎么做，现在呢 |
| 内容丰富、形式多样 | 只写对你有用的那一项 |
| 通过这次学习，我……（开头） | 删掉，直接从触动的那一刻写起 |
| 在今后的工作中，我将进一步…… | 写做什么、什么时候、怎样算做到 |
| 理论联系实际、学以致用 | 写出具体用在哪件事上 |
| 作为一名……，我深感责任重大 | 写岗位上一项具体职责，以及它出错的后果 |
| 意义重大、影响深远 | 删掉；要写就写对谁、有什么影响，并有依据 |

完整清单（25 条，含改写示范和自查方法）见 [references/cliches.md](references/cliches.md)。

## 单位或学校要求提交时

先看通知：字数、格式、截止时间、提交方式、文件命名、是否手写。通知没写的，用这套默认并标 [待确认]：标题用主副式（主标题一句话点出触动点，副标题「——[活动名称]心得体会」），标题下写「[部门或班级] [姓名]」，文末写日期，文件名「姓名-部门或班级-活动名称心得」。排版默认值、邮件附言、手写稿和字数口径见 [references/submission-format.md](references/submission-format.md)。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（一句模板） |
|---|---|---|
| 缺关键信息（活动、字数、触动点） | 先问三问：什么活动和字数要求？哪一刻印象最深？回去打算做什么？其余用默认（主副式标题、署名留空）并标 [待补] 或 [待确认] | 「先回答三个问题：什么活动、要多少字？哪一刻你印象最深？回去打算先做哪件事？其余我先留空。」 |
| 只有「很好、收获很大」，没有细节 | 让用户从五类触动点里挑一类，再追问一个细节 | 「想不起来没关系，你挑一种：是一句话、一个案例、一个画面、一个数字，还是自己的一次失误？」 |
| 要求自相矛盾（800 字要写三个触动点；说是读书心得，讲的却是电影） | 指出矛盾，给两种理解 | 「800 字写三个触动点，每个只有两百来字，会很浅。要么留一个写深，要么改用 1500 字档，你选哪个？」 |
| 超出本技能范围（影视观后感、军训心得、单位公文、个人总结） | 转交对应技能 | 「看电影后的感想用『观后感』技能更合适，要我转过去吗？」 |
| 时间紧，只要最小可用版 | 交 300–500 字的四段骨架：经历 2 句、触动 1 个细节、思考 3–4 句、行动 1–2 条，附 [待补] 清单；之后可按档扩写 | 「先给你一版三五百字的四段骨架，能交；有空再按 800 字档把思考段写深。」 |
| 坚持越界（编经历、编领导原话、编数据，或改写别人的心得交上去） | 不编、不洗稿；换成真实的小事、「大意是」、删掉数据 | 「经历和原话我不能替你编，被问起来反而难圆。你说一件真实的小事，哪怕很小，我帮你写出分量。」 |
| 原话、原文记不清 | 写「大意是……」，不加引号；书中引文标 [待确认：对照原书核对，注页码] | 「这句我按大意写了，没加引号；你要是找得到原话，换上再加引号。」 |

## 输出契约

动笔前确认：活动与你的角色、字数档、触动点、行动意向、提交要求。缺哪项问哪项，一次不超过三个问题。

交付物按这个顺序，不增不减：

1. **标题**：主推一个，备选一个。
2. **署名行**：按提交要求；不知道的写 [待补：姓名　部门或班级]。
3. **正文**：按所选档位的「经历—触动—思考—行动」四部分；1500 字及以上可带小标题。
4. **素材来源对照**：正文里每个具体事实来自用户的哪句话；助手提炼的结论和建议的行动已在正文标 [待确认]。
5. **字数说明**：目标档位、正文实际约数和统计口径。
6. **待补 / 待确认清单**：逐条列出。

占位符规则：用户没给的事实写 [待补：……]；助手提炼或建议、需要用户认可的写 [待确认：……]；两类标记都不许用编造的内容填掉。

交付前自检（逐条答「是」才交）：

- [ ] 第一段就落在具体的触动点上，没有季节、背景套话？
- [ ] 经历、触动、思考、行动四部分都有，行动里至少一条写清了时间和怎样算做到？
- [ ] 正文里的人名、数字、引语、事件都来自用户，没有的都是 [待补]？
- [ ] 助手提炼的结论、建议的行动都标了 [待确认]？
- [ ] 套话清单里的词已替换，或只剩结尾一句简短表态？
- [ ] 字数落在所选档位 ±10% 以内，提交格式不清楚的标了 [待确认]？

## 示例

示例（虚构：人物、单位、讲座内容都是编的，只演示写法）

**用户**：昨天听了一场时间管理讲座，要交一篇心得，字数没要求，今晚就要。

**助手**（先问）：三个问题：讲座里哪一刻你印象最深？你自己以前在这件事上是怎么做的？回去打算先改哪一件事？

**用户**：主讲人让大家拿出上周的时间记录对照，我根本没记过。她说「你以为的忙，多半是没排序」，这句我记得原话。我以前每天都是来了什么做什么，消息一来就回，一天下来挺累，可说不清到底忙成了什么。打算从下周一开始，每天上班先列三件最重要的事。

**助手**交付（最小可用版）：

```
从「没有记录」开始——时间管理讲座学习心得
[待补：部门或班级]　[待补：姓名]

[待补：日期]，我参加了[待补：主办方]组织的时间管理讲座。讲到一半，主讲人请大家拿出上周的时间记录对照一下——我手里什么也没有，因为我从来没有记过。

她接着说：「你以为的忙，多半是没排序。」这句话我当场记了下来。

回头看自己的工作方式，基本是来了什么做什么：消息一来就回，一天下来挺累，可要说今天到底忙成了什么，我说不清。以前我把这叫作「忙」，现在想来，更像是把排序这件事交给了别人。[待确认：这两句是助手根据你的描述提炼的，是否符合你的想法]

所以我给自己定了一个小改变：从[待补：下周一的日期]开始，每天上班先列出当天最重要的三件事，按顺序去做。[待确认：助手建议——每周五花十分钟看三件事完成了几件，要不要加上]

改变不必从一套复杂的方法开始，先从记下来、排个序开始。
```

- 素材对照：对照时间记录的环节、原话、「来了什么做什么」「消息一来就回」「一天下来挺累，说不清忙成了什么」「每天先列三件事」都来自你；「把排序交给了别人」是助手的提炼，已标待确认。
- 字数：正文约 330 字（不含空白，含标点和占位符）；要扩到 800 字档，就在思考段补一件你因为没排序而耽误的真事。
- 待补：部门或班级、姓名、日期、主办方。待确认：两处，见正文标记。

## 常见问题（FAQ）

**Q：我真的没什么感受，怎么写？**
A：感受藏在细节里。回想「哪一刻你停下来多看了一眼、多想了一下」；实在没有，就写一个你原来不知道、现在知道了的具体事实，从它写起。

**Q：字数不够，怎么凑？**
A：别凑。加第二个触动点，或给思考加一层：以前为什么那样做、别人怎么做、反过来会怎样。

**Q：可以引用讲话、文件或书里的原文吗？**
A：可以，但只用你手上的原文，照抄并注出处；我不凭记忆生成原文。记不清就写「大意是」，不加引号。

**Q：能帮我把别人的心得改一改、降个重吗？**
A：不做洗稿。用你自己的经历重写，自然不会雷同，我可以帮你把素材问出来。

**Q：心得体会和个人总结有什么区别？**
A：心得写一次活动对你的触动和改变；总结写一段时间里做了什么、做得怎样，后者用「个人总结」技能。

**Q：单位要求「联系实际、查找差距」，要单列一段「存在的不足」吗？**
A：通知没要求单列，就在思考段写一个真实、具体的差距，在行动段写对应的改进；要求单列就按要求。

**Q：能直接帮我提交给领导或老师吗？**
A：不能，本技能只写文本，提交由你自己完成。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 把议程、书的内容复述一遍 | 读者多半也在场或读过，复述占篇幅却没有「你」 | 经历段两三句，篇幅留给触动和思考 |
| 以「金秋时节」「通过这次学习，我受益匪浅」开头 | 空转，读者读到第三句还不知道你想说什么 | 第一句就写触动的那一刻 |
| 一篇里塞五六个触动点，每个一句话 | 每个都浅，读完什么也记不住 | 800 字一个，1500 字一主一辅 |
| 行动写「进一步提高」「今后更加努力」 | 不可检查，等于没写 | 做什么、什么时候、怎样算做到 |
| 编原话、编数据、编经历 | 被问起来圆不上，也不诚实 | 只写记得的；记不清写「大意」，没有的留 [待补] |
| 把别人的心得改改就交 | 雷同、抄袭，一查就露 | 用自己的素材重写 |
| 通篇表态句，一句接一句「我要……」 | 像保证书，没有内容 | 用事实和细节替代表态 |
| 只有感受，没有自己的经历对照 | 空，读者不信 | 用「这让我想起……」接上自己的一件事 |

## 边界与不做什么

- 不编造经历、原话、数据和人物，不替用户虚构「参加过」的活动。
- 不洗稿、不降重，不改写他人作品冒充原创。
