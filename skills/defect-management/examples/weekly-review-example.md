# 示例：从导出 CSV 到每周缺陷复盘

> 示例对话。CSV 为构造数据（人名、模块、标题均虚构），故意放了几处「脏数据」：一行重复导出、一个不在词表里的状态「待确认」、一个写成「上周五」的创建时间、三种日期写法、带英文逗号的标题。下面的脚本输出是真实运行结果。

## 对话

**用户**：这是从 TAPD 导出的本迭代缺陷（bugs.csv），帮我做本周（9/19–9/25）的缺陷复盘，周六开会用。

**助手**：先确认两点：①统计日按 2026-09-26（周六）算可以吗？②状态「待确认」在你们项目里是什么意思——还没开始处理，还是已经不算缺陷了？

**用户**：统计日就 9/26；「待确认」是测试刚提、开发还没确认的。

## 运行

第一次不带额外参数，脚本在「数据问题」里报：`未识别的状态（按未关闭计）：待确认×1`。按用户的解释把它归为待处理，再跑一次：

```bash
python3 scripts/defect_stats.py bugs.csv --today 2026-09-26 --since 2026-09-19 --until 2026-09-25 --open-status 待确认 -o review.md
```
