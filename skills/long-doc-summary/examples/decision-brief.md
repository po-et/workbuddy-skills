# 示例：开会表态前的 300 字决策摘要

**示例**（报告名称、页码和全部数字都是虚构的，用来演示交付格式）

## 对话

用户：「这份报告讲了什么？四十页，明天开会我要表态。」（附《自助收银试点评估报告》PDF）

助手：「两个问题：明天要表态的具体是哪件事——比如同不同意报告里的某项建议？你对门店运营熟不熟？」

用户：「表态同不同意『年内推广到全部门店』。我是财务，门店运营不太熟。」

助手判断：用途是决策，读者是运营外行 → 默认 300 字版 + 未决问题；术语换成白话；按决策用途多做一道工序，把「成立的前提」逐条列出，请读者判断。

## 交付

```
给谁：你（财务，明天会上表态）　用途：决策（同不同意「年内推广到全部40家门店」）
原文：《自助收银试点评估报告》，共40页；覆盖范围：全文
未覆盖：附录B的门店原始数据表是扫描件，数字未逐项核对 [待确认]

【300字版】（实数279字）
《自助收银试点评估报告》建议年内把自助收银推广到全部40家门店（P31）。依据是为期8周的试点：三家试点门店的客单价比试点前8周提高12%（P9），高峰时段平均排队时长从6.5分钟降到3.8分钟（P11）；作者测算单店改造约18万元，约14个月回本（P22、P24）。
这个建议成立要靠三个前提：回本测算假设客单价提升一直保持12%，且每店能少排2名收银员（P24）；三家试点门店都在商圈，社区店没有试过（P36）；试点期间有同期促销，作者承认客单价提高可能部分来自促销（P36）。
报告没有给出社区店的数据，也没有给出扣除促销影响后的客单价变化（见未决问题）。

【一句话结论】（38字）
报告建议年内推广到全部40家门店；前提是商圈试点效果能复制到其他门店（推断）

【三条要点】（按表态需要排序）
1. 回本测算（约14个月）依赖两个假设：客单价提升一直保持12%、每店少排2名收银员（P24）
2. 试点只有三家商圈门店、为期8周，社区店没有试过（P5、P36）
3. 试点门店客单价比试点前8周提高12%，但作者承认可能部分来自同期促销（P9、P36）

【论据与数据】
- 数字：客单价提高12%（口径：三家试点门店，对比试点前8周；时间：试点期8周；位置P9）
- 数字：高峰时段平均排队时长6.5分钟→3.8分钟（口径：三家试点门店高峰时段；位置P11）
- 数字：单店改造约18万元，约14个月回本（口径：设备加改造；位置P22、P24）
- 推理链：因为试点门店客单价上升、排队变短，所以作者建议推广（P31）；这一步依赖的假设是商圈试点的结果能代表全部门店（推断）

【未决问题】
- 社区店的效果如何，报告没有数据（P36 只提到「社区店未试」）
- 扣除同期促销后，客单价还提高多少，报告没有测算
- 读者如果要行动，还缺：社区店试点数据、扣除促销影响后的客单价变化、回本测算在客单价不涨时的结果

【成立的前提】（请你按自己掌握的情况判断，决策用途专用）
[ ] 其余门店的客流和客单价结构与三家商圈门店接近
[ ] 客单价提升不是主要来自同期促销
[ ] 每店确实能少排2名收银员

【我的看法】（这是我的看法，不是原文内容）
表态时可以先确认上面三个前提；三个都拿不准时，「先扩大到几家社区店试点」比直接同意或反对更有依据。

需要100字或1000字版本可以直接说。
```

## 交付前自检记录

- 第一行写了给谁、用途、覆盖范围：是。
- 每个数字都与原文一致并带位置：是（附录B扫描件未核对，已写进「未覆盖」）。
- 每个判断句都有主语：是（「报告建议」「作者测算」「作者承认」）。
- 限定条件带上了：是（三家商圈门店、8周、同期促销）。
- 我的评价单列：是（「我的看法」一栏）。
- 字数：用 `python3 -c "import sys;print(len(''.join(open(sys.argv[1],encoding='utf-8').read().split())))" summary_300.txt` 数得 279，在 300 字上下一成以内。
