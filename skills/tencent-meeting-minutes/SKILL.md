# 腾讯会议纪要

定位一句话：**让群里扫一眼就知道：定了什么、谁在哪天前做什么、还有什么没定。** 脚本负责把腾讯会议导出的文本解析、规范化、挑出候选句；判断和成稿由人（或助手按规则）完成。

与已有技能「会议录音整理」的分工：本技能专做**腾讯会议导出文本**的解析与规范化；手里只有录音、视频，或是其他来源的笔记，交给「会议录音整理」。

## 何时使用

- 「这是腾讯会议导出的转写，帮我整理成纪要发群」
- 「会议记录太长了，帮我提炼决议、待办和负责人」
- 「待办里的『下周三前』『本周内』帮我换算成具体日期」
- 「转写里全是『发言人1、发言人2』，帮我规范一下」
- 「会上有哪些问题没定下来？」

不适用（遇到时这样处理）：
- 只有录音或视频、还没有文字：先用腾讯会议自带的转写功能（以当前版本为准），或交给「会议录音整理」。
- 写会议邀请、议程：直接简答或交给写作类技能。
- 把纪要自动发到企业微信群：发送交给「企微机器人」技能，同样先预览、确认后再发。

## 流程

1. **导出**（通用描述，以腾讯会议当前版本为准）：会后在历史会议或录制相关页面找到这场会议的转写或纪要入口并导出；能否导出、导出格式取决于账号版本、会议是否开启录制与转写、你的权限。优先导出纯文本；导出 Word/PDF 的，另存为 UTF-8 纯文本，或全选复制到 .txt。官方说明：腾讯会议官方帮助中心，搜「云录制」「转写」「纪要」「导出」相关条目（章节名以帮助中心当前目录为准）。
2. **解析**：跑脚本，得到发言人统计、候选句、规范化转写。
3. **判定**：候选句 → 决议 / 待办 / 未决问题；补负责人；相对时间换算成日期。
4. **成稿**：按「输出契约」的骨架写群消息版；需要存档再出存档版。
5. **核对**：发给主持人或记录人确认后再发群。

**第 2 步 解析**（路径相对本技能目录）：

```bash
python3 scripts/parse_transcript.py 转写.txt --normalized 规范化.txt -o 解析.md
python3 scripts/parse_transcript.py 转写.txt --rename 发言人2=刘洋 --speakers 王磊,陈静,赵敏,刘洋
python3 scripts/parse_transcript.py 转写.txt --format json
```

脚本逐行尝试这些常见形态（格式不固定，所以宽松匹配）：

| 形态 | 例子 | 说明 |
|---|---|---|
| A | `王磊 00:00:05`（内容在下一行） | 也认 `00:00:05 王磊`；只有两段时间时，同名出现 ≥2 次才认，防止把「定在明天 15:30」当成发言人 |
| B | `[00:12] 林晓：内容` | 也认【】 |
| C | `孙悦（00:01:05）：内容` | 冒号后为空时，内容在下面几行 |
| D | `00:01:48 周航：内容` | |
| E | `林晓：内容` | 没有时间；同名出现 ≥2 次或在带时间的行里出现过才认；「结论：」「备注：」这类小标题不当发言人 |

其余情况：会议主题、时间、参会人等开头的行记为元信息；分页符、分隔线、整行括号注释（如「(录音中断)」）和认不出的行**原样保留并计数**，在报告末尾逐行列出。格式实在特殊时用 `--pattern`（自定义正则，命名分组 name、可选 time、text），或用 `--speakers` 给出名单。编码自动尝试 UTF-8、GB18030，带 BOM 的 UTF-16 自动识别。

报告内容：发言人统计（段数、字数、占比、首末次时间、估算时长）、待办候选（附负责人线索、截止线索）、决议候选、未决问题候选、元信息行、未解析行。候选是按线索词挑的，有误报也有漏报，**不能原样当结论**。

**第 3 步 判定规则**（细则与相对时间换算表见 [references/minutes-template.md](references/minutes-template.md)）：
- 决议：有明确结论且后面没被推翻；后面出现「再议」「待定」的，移到未决问题。
- 待办：动词 + 对象 + 交付物，落到一个人；「我来」= 说话人；「由 X 牵头」= X；「大家」「技术侧」写 [待认领]。
- 截止：以会议日期为基准换算成 YYYY-MM-DD，并在纪要里写「按 X 日会议日期换算」；拿不准的标 [待确认]；「尽快」不换算，写 [待补]。
- 未决问题：写清卡在哪、需要谁决定、何时前决定。会上已被认领的问题改为待办。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（模板） |
|---|---|---|
| 缺会议日期、主持人、记录人 | 只问这 1–3 个；日期缺失时截止时间先写原话 + [待确认] | 「会议是哪天开的？『周五前』要换算成日期。主持和记录是谁？」 |
| 发言人显示为「发言人1、2」 | 问是谁；或按参会名单推断并标 [待确认]；用 `--rename` | 「发言人2 是谁？我先按参会名单推断为刘洋，标了 [待确认]。」 |
| 前后矛盾（先说周五放量，后说压测不过不放） | 写成带条件的决议，或列为未决问题，给两种理解让用户选 | 「这里有两种理解：①周五放量、条件是压测通过；②放量未定。按哪种写？」 |
| 转写把人名、术语识别错 | 纪要里用正确写法，存档版附校正表；不改原话含义 | 「转写里的『压策』我按『压测』处理，附了校正表。」 |
| 时间紧，只要最小版 | 只出三段：决议（≤3 条）、待办表（事项 / 负责人 / 日期）、未决问题 | 「先给最小版三段，存档版晚点补。」 |
| 超出范围：评价谁表现好、写绩效、判断谁对谁错 | 不做，只记录事实与结论 | 「纪要只记录定了什么和谁做什么，不评价个人。」 |
| 用户坚持把薪酬、人事、客户隐私写进群消息 | 建议只放进限定范围的存档版，由主持人决定发给谁 | 「这部分不建议发群，我放进存档版，发给谁请主持人定。」 |

脚本退出码：

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 0 | 成功 | — |
| 1「--rename 的写法是 旧名=新名」等 | 参数写错 | 按提示改；`--pattern` 必须含 `(?P<name>...)` |
| 2「找不到文件 / 无法识别文件编码 / 写文件失败」 | 路径、编码或输出目录问题 | 检查路径；`--encoding gb18030`；确认输出目录存在 |
| 3「没有认出任何发言」 | 格式不在支持范围 | 看它打印的前 5 行，用 `--speakers` 或 `--pattern`，或把格式改成「姓名 00:12:34」换行接内容 |
| 提示「名字不在 --speakers 名单里」 | 名单漏了人 | 把名字补进名单重跑 |
| 130 | Ctrl+C 中断 | 重跑即可 |

## 输出契约

群消息版按这个顺序，缺哪块写「无」，不跳号：
1. 抬头：`【会议纪要】主题｜日期 周X｜主持｜记录`
2. 一、决议（编号列表）
3. 二、待办（事项 —— 负责人，日期前）
4. 三、未决问题（问题 —— 需要谁决定，何时前）
5. 四、下次会议（没有就删掉这一节）
6. 结尾：日期换算基准 + 「如有遗漏请在 X 日前回复记录人」

存档版在此基础上加参会人、依据行号、讨论要点、发言统计、术语校正表，模板见 [references/minutes-template.md](references/minutes-template.md)。

占位符：推断的写 [待确认]；没人认领写 [待认领]；缺信息写 [待补]。

交付前自检（逐条判是/否）：
- [ ] 每条待办都有一个负责人（或 [待认领]）和具体日期（或 [待确认] / [待补]）。
- [ ] 每条决议都能在转写里找到出处行号。
- [ ] 后面被推翻的「决议」已移到未决问题。
- [ ] 相对时间已换算，并写明按哪天换算。
- [ ] 未解析行已看过，没有漏掉实质内容。
- [ ] 群消息版没有敏感信息，也没有对个人的评价。

## 示例

> 示例对话，转写为构造样例，人名与业务均为虚构。输入全文与脚本真实输出见 [examples/two-transcript-formats.md](examples/two-transcript-formats.md) 的样例 A。

**用户**：（上传 `sample-a.txt`）帮我把这次周会整理成纪要发群。

**助手**：先跑了解析脚本：识别 7 段发言，元信息 3 行，未解析 1 行（分页符）。两个问题：①「发言人2」是谁？②主持、记录是谁？会议日期我按文件里的 2026-09-24（周四）换算。

**用户**：发言人2 是刘洋；王磊主持，赵敏记录。

**助手（群消息版）**：

```
【会议纪要】支付网关 9 月第 4 周周会｜2026-09-24 周四｜主持 王磊｜记录 赵敏
一、决议（2 条）
1. 周五（9 月 25 日）灰度从 20% 放到 50%，前提是压测通过；压测资源未到位则停在 20%。
2. 对账差异先人工冲正，根本修复方案下次会议再议。
二、待办（3 条）
1. 确认压测资源是否到位并给出结论 —— 赵敏，2026-09-24 18:00 前 [待确认：「周四下班前」即会议当天]
2. 完成退款回调重复入账的人工冲正，完成后在群里同步 —— 陈静，2026-09-25 前 [待确认：「本周内」按本周最后一个工作日]
3. 收集国庆封网前要上线的需求 —— 王磊（收集），各需求负责人 2026-09-25 15:00 前报送
三、未决问题（1 条）
1. 退款回调重复入账的根本修复方案 —— 需王磊组织讨论，下次会议 [待确认] 定
四、其他：国庆封网自 2026-09-29 开始；评审会定在 2026-09-25 15:30。
日期按 2026-09-24 会议日期换算。如有遗漏或不准确，请在 2026-09-25 前回复赵敏。
```

判定说明：脚本把「如果周五前压测资源还没到位……」也列成待办候选，它其实是决议 1 的条件，已并入决议；「压测资源谁来盯？」在会上已被赵敏认领，所以不列为未决问题。

## 常见问题（FAQ）

**腾讯会议如果已经自动生成了纪要，还需要这个吗？** 自动纪要可以当输入之一，和转写对照着用；本技能补的是负责人、具体日期、出处行号和统一格式。

**转写里人名、术语识别错了怎么办？** 纪要里用正确写法，存档版附「转写写法 → 正确写法」校正表；不要改动发言的原意。

**全是「发言人1、发言人2」怎么办？** 问用户或按参会名单推断并标 [待确认]，再用 `--rename 发言人1=张三` 重跑，统计和规范化转写都会用新名字。

**导出的是 Word 或 PDF？** 另存为 UTF-8 纯文本，或全选复制到 .txt 再跑；格式乱的话先看报告里的未解析行。

**能直接发到群里吗？** 我给出群消息版全文；发送交给「企微机器人」技能，先预览、你确认后再发。

**会议很长（两小时以上）怎么办？** 脚本不受长度影响；先看规范化转写按议题分段，再逐段判定，纪要按议题分组。

**和「会议录音整理」有什么区别？** 那个从录音或其他来源的笔记整理；本技能专门解析、规范化腾讯会议导出的文本。

## 常见错误（反模式）

- 把候选句原样当待办 → 线索词会误报（条件句、复述）→ 按判定规则逐条确认。
- 待办写「大家」「技术侧」负责 → 最后没人做 → 落到一个人，否则写 [待认领] 提醒主持人。
- 截止写「尽快」「下周」 → 无法跟踪 → 换算成具体日期并写明换算基准。
- 按发言顺序写流水账 → 群里没人读完 → 按决议 / 待办 / 未决问题归类。
- 替发言人「润色」立场 → 纪要失真 → 保留原意，存档版附行号。
- 拿字数占比评价谁贡献大 → 误导 → 只用来看讨论是否被少数人主导。
- 跳过未解析行 → 可能漏掉记录人写的结论 → 每行都看一遍。

## 边界与不做什么

- 只处理用户提供的导出文本；不登录用户的腾讯会议账号，不下载或抓取他人的会议录制与转写。
- 不编造会上没说过的决议、负责人或日期；拿不准就标注。
- 不评价参会人的表现，不用于绩效判断。
- 敏感内容（薪酬、人事、客户隐私、未公开财务数据）不进群消息版。
- 不代替用户发群；发送前由用户确认。
- 腾讯会议的菜单、按钮、导出格式以官方帮助中心与当前版本为准，本技能不编造。
