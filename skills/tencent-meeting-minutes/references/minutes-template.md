# 纪要模板与判定细则

## 一、群消息版（发群用，控制在一屏内）

```
【会议纪要】<主题>｜<YYYY-MM-DD 周X>｜主持 <姓名>｜记录 <姓名>
一、决议（N 条）
1. <决议内容，含条件/范围>
二、待办（N 条）
1. <动词 + 对象 + 交付物> —— <负责人>，<YYYY-MM-DD 时刻> 前
三、未决问题（N 条）
1. <问题> —— 需 <谁> 决定，<日期> 前 [待确认]
四、下次会议：<时间 / 议题>（没有就删掉这一节）
如有遗漏或不准确，请在 <日期> 前回复 <记录人>。
```

## 二、存档版（发邮件、存文档用）

```
# <主题> 会议纪要
- 时间：<YYYY-MM-DD HH:MM–HH:MM>    形式：腾讯会议
- 主持：<姓名>    记录：<姓名>
- 参会：<姓名列表>    缺席：<姓名列表>（如知道）
- 转写来源：<导出文件名>，解析 <N> 段发言，未解析 <M> 行（已人工查看）

## 决议
| # | 决议 | 依据（行号 / 发言人） | 条件或范围 |

## 待办
| # | 事项 | 负责人 | 截止 | 完成标准 | 依据 |

## 未决问题
| # | 问题 | 卡在哪 | 需要谁决定 | 何时前 |

## 讨论要点（可选，每个议题 1–3 句，只写结论性信息）

## 附：发言统计（脚本输出，仅供了解讨论分布，不作评价）
## 附：术语与人名校正表（转写写法 → 正确写法）
```

## 三、候选句怎么判定

脚本给的是「候选」，判定规则如下：

| 候选类型 | 保留条件 | 排除或改归类 |
|---|---|---|
| 决议 | 有明确结论（定了、决定、同意、就按），且后面没有被推翻 | 后面有「再议」「待定」「先不定」→ 移到未决问题；只是个人建议（「我建议」）→ 不算 |
| 待办 | 有具体动作，能落到一个人 | 条件句（「如果……就先……」）→ 并入对应决议的条件；只是复述别人已认领的事 → 合并 |
| 未决问题 | 会上没有结论、需要后续决定 | 同一问题会上已有人认领并给出时间 → 改为待办 |

负责人：
- 「我来 / 我负责 / 我跟进 / 我这边」→ 说话人本人。
- 「X 负责 / 由 X 牵头 / 让 X 跟进」→ X。
- 多人共同负责 → 拆成一人一条，或写「主责 X，协助 Y」。
- 「大家」「技术侧」「后面看」→ 写 [待认领]，放进纪要里提醒主持人会后指定。
- 汇总类事项（「大家明天前把需求报给我」）→ 负责人写收集人，并注明「各需求负责人报送」。

## 四、相对时间换算（以会议日期为 D）

| 原话 | 换算 | 备注 |
|---|---|---|
| 今天、今晚、下班前 | D | 「下班前」写成 D 18:00 [待确认]，除非团队有约定 |
| 明天、明早 | D+1 | |
| 周X、周X前、这周X | D 所在自然周的周X | 如果那天已经过去，写原话 + [待确认]，问是不是下周 |
| 下周X | D 下一自然周的周X | |
| 本周内 | 本周最后一个工作日 | [待确认] |
| 月底 | 当月最后一天 | 遇周末或节假日，标 [待确认] |
| N 天内、N 个工作日内 | D+N（工作日要跳过周末和节假日） | 节假日不确定时标 [待确认] |
| 尽快、后面、回头 | 不换算 | 写 [待补]，请负责人给日期 |

纪要里要写清「按 YYYY-MM-DD 会议日期换算」，方便别人核对。

## 五、规范化转写的格式

脚本 `--normalized` 输出每段一行：

```
[00:01:42] 赵敏：我来跟进压测资源，周四下班前给结论。评审会定在明天 15:30
〔元信息 L1〕会议主题：支付网关 9 月第 4 周周会
〔未解析 L19〕—— 第 2 页 ——
```

- 同一发言人被换行切开的内容合并成一行；中文之间不加空格，中英文之间加一个空格。
- 元信息行与未解析行保留在原来的位置，前面带原文行号，方便回查。
- `--rename` 只改显示名，不改原话。

## 六、不写进群消息的内容

薪酬、绩效、人事变动、客户个人信息、未公开的财务数据、对个人的评价。确需记录的，只放进限定范围的存档版，并问主持人发给谁。
