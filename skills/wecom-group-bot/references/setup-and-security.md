# 添加机器人、保管 key、频率控制与泄露处置

## 一、在群里添加机器人（通用步骤，以企业微信客户端当前界面为准）

1. 在企业微信（桌面端或手机端）打开要推送的群聊。
2. 打开群的设置或群信息页面（通常在群聊右上角），找到与「群机器人」「添加机器人」相关的入口。
3. 选择新建一个机器人，填写名称（建议写清用途，如「发布日报」「订单告警」），完成创建。
4. 创建完成后界面会给出 webhook 地址，其中 `key=` 后面那段就是 key。**立即**按下一节存进环境变量，不要发到群里、不要截图外传。
5. 回到终端，先用 dry-run 预览，再发一条测试消息确认能收到。

找不到入口时，常见原因（逐条排查，均以官方说明为准）：客户端版本较旧；群的类型不支持添加机器人；所在企业对该功能做了限制。前两条自己能查，第三条问企业微信管理员。

官方说明去哪里查：企业微信开发者中心 →「群机器人配置说明」；错误码 →「全局错误码」。章节名以文档站当前目录为准，本技能不提供链接，避免链接失效或被仿冒。

## 二、key 放哪里

| 场景 | 做法 |
|---|---|
| 自己电脑（macOS / Linux） | 终端执行 `export WECOM_BOT_KEY='<key 或完整地址>'`；长期使用写进只有自己能读的 shell 配置文件 |
| Windows PowerShell | `$env:WECOM_BOT_KEY = '<key 或完整地址>'` |
| 定时任务（cron 等） | 在任务脚本里从只有本用户可读的文件加载，文件权限设为仅本人可读（如 `chmod 600`） |
| CI / 流水线 | 用平台提供的「密钥 / Secret 变量」，并开启日志打码 |
| 项目里的 `.env` | 必须写进 `.gitignore`；仓库里只放 `.env.example`，里面写 `WECOM_BOT_KEY=` 留空 |
| 多个群 | 一个群一个变量，如 `WECOM_BOT_KEY_OPS`；发送时 `--key-env WECOM_BOT_KEY_OPS` |

检查变量有没有设置、又不把值打印出来：

```bash
python3 -c "import os; v=os.environ.get('WECOM_BOT_KEY',''); print('已设置，末 4 位', v[-4:]) if v else print('未设置')"
```

## 三、频率控制（官方有频率限制，具体以文档为准）

发送方自己做，比等接口报 45009 再处理好得多：

1. **合并**：同一时间窗口内的多条告警合并成一条列表。
2. **去重**：同一「告警指纹」（服务 + 指标 + 级别）在窗口内只发第一条，后续只计数，窗口结束发汇总。
3. **分级**：只有最高级别才 @ 人；低级别只发不 @；夜间非紧急的合并进早报。
4. **排队**：多个任务共用一个机器人时，由同一个发送进程排队发，不要各发各的。
5. **留余量**：按官方文档的限额留出余量，不要贴着上限发。
6. **不要绕**：不要多建几个机器人轮流发来规避限额——那是在绕平台规则，也会让群里更吵。

收到 45009 时：脚本不会自动重试。等一段时间（至少一个限流窗口，窗口长度以文档为准）再发，同时检查是不是上游在刷告警。

## 四、key 泄露了怎么办（按顺序做）

判定为泄露的情况：key 或完整地址出现在代码仓库（哪怕已删除，历史里还在）、聊天记录、截图、工单、日志、CI 输出、公开文档里。

1. **止血**：在群的机器人管理里移除这个机器人，然后重新添加一个新的，拿到新 key。持有旧 key 的人就不能再往群里发消息了。（如果客户端提供重置 webhook 地址的选项，也可以用，以当前界面为准。）
2. **换钥**：把所有用到旧 key 的地方（电脑、服务器、CI 密钥变量）更新为新 key，逐一用 dry-run + 一条测试消息验证。
3. **清理**：从聊天记录、工单、文档里删掉旧 key；进了 git 的，删除文件不够，要用历史改写工具清理并通知协作者重新拉取——但**第 1 步做完之前清理历史没有意义**，顺序不能反。
4. **排查**：回看群里有没有来源不明的消息；有的话提醒群成员不要点其中的链接。
5. **防再犯**：脚本输出一律打码（本技能的脚本只显示后 4 位）；日志不要打印完整请求 URL；提交前用密钥扫描工具或 pre-commit 检查；不要把 key 贴进任何对话（包括和 AI 的对话）。

## 五、定时发送

先手动跑通 dry-run 与一次 `--send`，确认模板和群都对，再挂定时任务。定时任务里要写绝对路径，并把输出记到日志里便于排查：

```bash
# 例：工作日 18:00 发送日报（路径换成你自己的；环境变量由加载的文件提供）
0 18 * * 1-5  . "$HOME/.wecom_bot_env" && python3 /path/to/wecom-group-bot/scripts/wecom_bot_send.py --type markdown --file /path/to/daily.md --send >> "$HOME/wecom-bot.log" 2>&1
```

内容每天变的，建议「生成内容」和「发送」分成两步：生成脚本写出 `daily.md`，人看一眼再发；完全无人值守的，只用在格式固定、已确认过模板的消息上。
