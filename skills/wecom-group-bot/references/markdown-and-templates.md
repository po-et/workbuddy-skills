# markdown 写法要点与三类消息模板

> 本页的语法范围按企业微信开发者中心「群机器人配置说明」中 markdown 类型的通用写法整理；客户端渲染效果和支持范围可能随版本变化，**以官方文档与实际发出的效果为准**。第一次用某种写法时，先发到自己的测试群看效果。

## 一、markdown 类型能用的写法

| 写法 | 例子 | 说明 |
|---|---|---|
| 标题 | `## 【日报】支付服务 2026-09-26` | `#` 到 `######` |
| 加粗 | `**今日完成**` | |
| 链接 | `[查看详情](https://example.com/report/0926)` | 链接文字要能说明去哪 |
| 行内代码 | `` `order-service` `` | 适合服务名、命令；不要依赖多行代码块 |
| 引用 | `> 整体：正常` | 适合放一句话结论 |
| 字体颜色 | `<font color="info">正常</font>` | 只用三种内置颜色：`info`（绿）、`comment`（灰）、`warning`（橙红） |
| @ 群成员 | `<@userid>` | 要的是企业微信 userid，不是手机号；拿不到 userid 就改用 text 类型 @ 手机号 |

不要依赖的写法：表格、图片、嵌套列表、多行代码块、其他 HTML 标签——在这种类型里不一定按预期渲染。需要表格时，把表格放在链接后面的页面里，消息只放摘要。

> 如果你在官方文档里看到了其他 markdown 变体类型（支持范围不同），按文档说明使用；本技能的脚本只实现 `text` 和 `markdown` 两种。

## 二、写消息的四条规矩

1. **第一行就是结论**：看通知栏预览的人只看得到第一行。
2. **一条消息只说一件事**：日报一条、告警一条，不要把告警塞进日报里。
3. **长内容给链接**：正文放 3–5 行摘要 + 详情链接；参考上限据公开文档是 text 2048 字节、markdown 4096 字节（UTF-8，一个汉字约 3 字节），以官方文档为准，脚本预览会显示字节数。
4. **颜色只标状态**：绿色=正常/已恢复，橙红=需要处理，灰=备注；整条消息全是颜色等于没有颜色。

## 三、模板

### 1. 日报（markdown）

```
## 【日报】<项目/服务> <YYYY-MM-DD>
> 整体：<font color="info">正常</font>   ← 有风险时改成 <font color="warning">有风险</font>
**今日完成**
1. <事项 1（结果，不写过程）>
2. <事项 2>
**明日计划**
1. <事项>
**风险 / 需要支持**：<一句话；没有就写「无」>
[详细记录](<链接>)
```

### 2. 告警（text，需要 @ 值班人时）

```
【告警】<级别 P0/P1> <服务名> <指标> 异常
现象：<指标> = <当前值>（阈值 <阈值>），持续 <N> 分钟
开始时间：<HH:MM>
影响：<受影响的功能/用户范围；不确定写「评估中」>
处理人：请值班同学确认并回复「已接手」
详情：<监控面板链接>
```

发送时加 `--at-mobile <值班手机号>`。恢复时再发一条：

```
【已恢复】<服务名> <指标> 已恢复正常，持续 <N> 分钟。原因：<一句话或「排查中」>
```

### 3. 告警（markdown，不需要 @ 人时）

```
## <font color="warning">【P1 告警】</font><服务名> <指标> 异常
> 当前 <当前值>，阈值 <阈值>，已持续 <N> 分钟
**开始时间**：<HH:MM>
**影响**：<范围>
[监控面板](<链接>)
```

### 4. 提醒（text）

```
【提醒】<事件>：<时间>（<星期>）<地点/链接>
需要做的：<动作>，<截止时间>前完成
有问题找：<负责人>
```

示例：`【提醒】国庆封网：9 月 29 日 18:00 起。需要上线的需求请在 9 月 28 日 12:00 前报给王磊。`

## 四、拆条与合并

- 日报超长：拆成「摘要一条 + 链接」，不要拆成三条连发。
- 告警风暴：同一服务同一指标，N 分钟内只发第一条，之后每隔一段时间发一条「仍在持续，已累计 X 次」汇总；恢复时发一条「已恢复」。N 和间隔按你们的值班习惯定，并给官方频率限制留余量（具体限额以官方文档为准）。
- 多个服务同时告警：合并成一条「当前 3 个服务告警」列表，逐个 @ 负责人会刷屏。
