# 发布前自查（为了回收后好分析）与清洗规则

> 与已有技能「问卷设计」的分工：题目怎么问、选项怎么设计、问卷结构，交给「问卷设计」。这里只列**会直接影响回收后数据处理**的检查项。腾讯问卷里具体怎么设置（必填、跳转、选项上限等），以腾讯问卷当前界面为准。

## 一、发布前自查（8 条）

| # | 检查项 | 不做的后果 |
|---|---|---|
| 1 | 每道题有编号，题干互不重复（如「Q5 整体满意度」） | 导出后列名撞车，分不清哪列是哪题 |
| 2 | 单选题选项互斥、覆盖完整，必要时有「其他」「不适用」 | 答案被迫乱选，频数失真 |
| 3 | 多选题在题干标明「多选」，需要时限制最多选几项 | 导出后分不清单选多选；人均选项数没法比较 |
| 4 | 量表方向全卷一致（如 1=非常不满意 … 5=非常满意），分值个数一致 | 均值没法比较，还可能算反 |
| 5 | 必填和跳转逻辑按每条分支各填一遍 | 大量缺失或跳错题，n 对不上 |
| 6 | 需要分群分析的变量（身份、渠道、使用时长）一定要问 | 回收后才发现没法做交叉表 |
| 7 | 只收集必要的个人信息，收集时写明用途 | 隐私风险；分析时还要额外脱敏 |
| 8 | 自己填 2–3 份测试答卷，导出后跑一遍脚本，确认每列都能被识别，然后按平台方式清掉测试答卷或记下它们的序号 | 正式数据里混入测试答卷；到回收后才发现列识别不了 |

## 二、清洗规则（顺序固定，每一步都记进报告的「清洗规则」）

1. **去掉完全相同的行**：同一份答卷被重复导出或重复提交。脚本默认执行。
2. **按身份去重**（可选）：有用户标识列时，同一人多次作答只保留第一次：`--dedupe-by 列名`。
3. **剔除测试答卷**：按序号或提交时间手动删掉测试期间的答卷（脚本不会自动判断）。
4. **答题过快**：阈值要有依据——例如请几位同事按正常速度填一遍，取最快者用时的一半左右作为阈值（经验做法，按问卷长度调整），写进报告：`--min-seconds 60`。没有依据就不要过滤，只报告用时分布。
5. **直线作答**：多道 1–5 分量表题全部同一分值。脚本默认只标记不删除，因为真心全打 4 分的人也存在；确认是敷衍作答再用 `--drop-straightline`。
6. **逻辑矛盾**：如「从未使用」却给功能打分。脚本不判断，需要按题目逻辑人工筛。
7. **开放题无效回答**：「无」「没有」「随便」不删整份答卷，只在开放题归纳时不计入主题。

## 三、导出与格式（以腾讯问卷当前界面为准）

- 在问卷的数据或统计相关页面找下载原始数据的入口；导出 Excel 的，用 Excel 或 WPS「另存为」CSV UTF-8。
- 另存时如果中文乱码，改用「CSV UTF-8」选项；实在不行，脚本加 `--encoding gb18030` 读取。
- 多选题在导出文件里可能是「一列多个选项用分隔符连接」，也可能是「每个选项一列」，两种脚本都能认；认不出时用 `--type` 指定。
- 官方说明：腾讯问卷帮助中心中与「数据下载」「导出」相关的章节（章节名以帮助中心当前目录为准）。

## 四、列类型对照（脚本怎么认，认错了怎么改）

| 你看到的列 | 脚本会认成 | 认错时 |
|---|---|---|
| 序号、提交时间、答题时长、IP | 元信息，不统计 | `--type 列名=single` 强制统计 |
| 3–12 种取值、重复很多 | 单选 | 实际是开放题：`=open` |
| 单元格里有 ┋ 或 ; 分隔 | 多选 | 实际是单选文字里恰好有分号：`=single` |
| 「题干-选项」相邻多列，单元格 0/1 | 一道多选题 | 不想合并：`--no-group`，或对其中一列 `--type` 拆开 |
| 0–10 的整数 | 量表（题干没有「满意、评分、推荐」等词时列入待确认） | 实际是编码过的单选：`=single` |
| 「非常满意 … 非常不满意」 | 量表，按 1–5 换算 | — |
| 年龄、金额等数值 | 待确认 | `=numeric` 出均值、中位数、最小最大 |
| 长短不一的文字 | 开放题 | — |
