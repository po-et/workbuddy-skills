# 示例：审核被驳回，两条理由一次改完再提审

> 对话与驳回文字均为示例，不是官方原文；处理真实驳回时以你收到的原文为准。

## 对话

**用户**：小程序被驳回了，理由有两条：
> 1. 你的小程序存在诱导分享行为，请修改后再提交。
> 2. 你的小程序涉及收集用户手机号，但未在《用户隐私保护指引》中声明。
>
> 下周一要上线，怎么改最快？要不要申诉？

**助手**：两条都能改，先确认三件事：
1. 分享相关的功能在哪个页面？有没有「分享后才能……」的设计，或者分享卡片、弹窗里的文案？
2. 手机号是在哪里拿的？一进小程序就要，还是下单时才要？
3. 隐私保护指引里现在声明了哪些信息？

**用户**：测试结果页有个按钮「分享到 3 个群查看完整报告」。手机号是首页一打开就弹授权。隐私指引只声明了位置。

**助手**：这两条都是真实存在的问题，不建议申诉，改完重新提审最快。下面是修改清单和提审说明。

## 交付物

```
【定位】
驳回 1 → 测试结果页的「分享到 3 个群查看完整报告」：以分享换取内容，属于常见的诱导分享情形
驳回 2 → 首页进入即请求手机号，且隐私保护指引未声明手机号

【修改清单】（按顺序做）
1. 测试结果页：完整报告直接展示；分享按钮改为「分享给朋友」的可选操作，不与任何内容或奖励挂钩；
   分享卡片文案同步检查，删除「不看后悔」这类诱导措辞
2. 全局搜一遍同类设计：跑 python3 scripts/mp_precheck.py 项目目录，看 INDUCE 项是否清零
3. 手机号改到用户点击「下单」时才请求；拒绝后可以用填写方式继续，浏览不受影响
4. 后台《用户隐私保护指引》补充「手机号」的声明，用途写「下单时用于联系收货人」
5. 把已声明项整理成 declared.txt，跑 --declared 比对，确认代码里没有其他未声明的接口
6. 关闭开发者工具的「不校验合法域名」，用体验版真机从首页点遍所有入口

【再提审说明】
本次修改（对应 [日期] 的驳回意见）：
1. 「存在诱导分享行为」→ 已删除测试结果页「分享到 3 个群查看完整报告」的设计，完整报告无需分享即可查看；
   分享改为可选操作，未与任何奖励挂钩
2. 「涉及收集用户手机号但未声明」→ 已在《用户隐私保护指引》中补充手机号的声明；
   手机号仅在用户点击下单时请求，拒绝后可手动填写，首页无需授权即可浏览
体验路径：首页 → 开始测试 → 查看结果
测试账号：无需登录

【时间安排】
今天改完并自测 → 明天上午提审 → 预留一次被驳回再改的时间；
后台如有加急入口可以使用（次数与条件以后台为准），但不要把上线安排押在加急上
```

## 为什么不申诉

申诉适用于「驳回所指的问题不存在」。这两条都能在页面上找到对应设计，申诉大概率被维持原判，还会耽误时间。直接修改并在说明里逐条对应驳回原文，是最快的路径。
