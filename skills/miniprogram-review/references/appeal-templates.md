# 申诉、再提审说明与发布节奏

> 申诉、加急、分阶段发布、版本回退的入口、次数和条件都以小程序后台为准；规则以《微信小程序运营规范》及官方平台通知的最新版本为准。

## 一、先判断：改，还是申诉

| 情况 | 做法 |
|---|---|
| 驳回指出的问题确实存在（哪怕只有一部分） | 改完重新提审，在提审说明里逐条写改了什么。不要申诉 |
| 驳回所指的页面或功能不存在，或描述与事实明显不符 | 可以申诉，用事实和复现路径说明 |
| 看不懂驳回指的是哪里 | 先按原文逐字定位；仍不清楚，用申诉或咨询渠道请求指明具体页面 |

## 二、申诉模板

```
【申诉说明】
小程序名称：[ ]　版本号：[ ]　提审日期：[ ]
驳回原文：「[逐字粘贴，不要概括]」

一、驳回所指的功能
页面路径：[首页 → XX → XX]（附截图编号 [ ]）

二、事实说明
[客观描述该功能如何运作，以及为什么不属于驳回所述情形。
 例：该页面的分享按钮为可选操作，不分享也能完整使用全部功能；没有设置任何与分享挂钩的奖励。]

三、可供核实的方式
体验路径：[ ]
测试账号：[账号] / [密码]（审核期间有效）

四、已做的调整（如有）
[为避免误解，已将 XX 文案改为 XX]

恳请重新审核。如仍有不符合之处，请告知具体页面，我们会及时修改。
联系人：[ ]
```

写法要点：
- 逐条回应，一条驳回对应一段说明；只讲事实，附路径和截图。
- 语气克制，不评价审核，不争论规则本身，不写「其他小程序也这样」。
- 不承诺做不到的事，不编造资质或数据。
- 不在任何材料里写 AppSecret、服务器密码等密钥；测试账号用专用账号。

## 三、再提审说明模板（改完重新提审时用）

```
本次修改（对应 [日期] 的驳回意见）：
1. 「[驳回原文第 1 条]」→ 已 [删除/修改] [页面路径] 的 [内容]，现在 [修改后的表现]
2. 「[驳回原文第 2 条]」→ 已在《用户隐私保护指引》中补充 [信息类型] 的声明，仅在 [场景] 时请求
体验路径：[首页 → XX → XX]
测试账号：[账号] / [密码]（专用测试账号，审核期间有效）
```

## 四、测试账号说明模板（首次提审就需要登录时）

```
本小程序的 [核心功能] 需要登录后使用。
测试账号：[账号]　密码：[密码]（专用测试账号，含示例数据，审核期间不会修改）
体验路径：[首页 → 我的 → 登录 → XX]
未登录状态下可浏览：[首页、XX 列表]
```

## 五、加急与发布节奏

- **加急**：后台有加急审核入口时可以使用，次数与条件以后台为准。加急不是保证，排期不要依赖它。
- **留余量**：审核时长以官方为准；上线日前至少留出一次「被驳回—修改—再提审」的时间。
- **拆小版本**：大改动拆成几个小版本分别提审，被驳回时影响面小、定位快。
- **审核期间**：后端接口、测试账号保持可用；不做影响审核环境的变更；提审版本和上线后的表现一致，不做「审核时隐藏、上线后打开」的开关。
- **发布**：审核通过后手动发布，或按后台提供的选项设置通过后自动发布（以后台为准）。
- **分阶段发布**：后台提供分阶段（灰度）发布时，先放小比例用户，观察报错与反馈，再全量。
- **回退**：后台提供版本回退能力时可用于紧急止损（次数与条件以后台为准）；更稳妥的是修复后再提审一个版本。
