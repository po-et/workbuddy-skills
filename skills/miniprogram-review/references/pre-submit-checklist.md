# 提审前自查清单（7 项，逐项可打勾）

> 下面都是**常见要求**，不是条款原文。具体规则以《微信小程序运营规范》及官方平台通知的最新版本为准。
> 官方资料去哪查（名称以官方为准）：微信公众平台的小程序后台（版本管理、服务类目、用户隐私保护指引、服务器域名等设置）；微信开放文档中小程序的「运营规范」「服务类目」「用户隐私保护」相关章节；后台公告与站内信里的平台通知。

## 1. 类目与资质

- [ ] 列出小程序的全部功能，每一项都能在已选的服务类目里找到对应。
- [ ] 需要资质的类目，资质已上传且在有效期内。
- [ ] 名称、简介、图标与实际功能一致，没有写了但没做的功能，也没有做了但类目不覆盖的功能。
- [ ] 个人主体：确认所需类目对个人主体开放（个人主体可选类目有限，以官方类目表为准）。

常见坑：用工具类类目上线了交易或社区功能；简介承诺的功能还没开发完。

## 2. 隐私保护指引与授权时机

- [ ] 用 `scripts/mp_precheck.py` 列出代码里所有涉及用户信息的接口，与后台《用户隐私保护指引》的声明逐项对照（可以把已声明项整理成 `declared.txt` 用 `--declared` 比对）。
- [ ] 用不到的接口调用已删除，不为「以后可能用」提前声明和收集。
- [ ] 位置类接口按常见要求写进 app.json 的 `requiredPrivateInfos`，并在 `permission` 里写清用途说明（字段与适用接口以官方文档为准）。
- [ ] 授权在用户点击对应功能时才请求；启动时（app.js、首页 onLoad）不弹授权。
- [ ] 拒绝授权后，基础功能仍然能用，页面不白屏。
- [ ] 头像昵称用官方提供的填写能力，不强制获取。
- [ ] 登录页或设置页有可点开的用户协议与隐私政策。

## 3. 登录与测试账号

- [ ] 能先浏览的内容不强制登录；首页不是只有一个登录按钮。
- [ ] 必须登录才能体验的，准备了专用测试账号：有示例数据、不绑定真实用户信息、审核期间不改密码、不停用。
- [ ] 提审说明里写清测试账号、密码和体验路径（字段名称以后台为准）。
- [ ] 验证码登录、线下扫码、特定硬件等审核人员无法自行完成的环节，写清替代的体验方式；后台支持补充材料时附截图或录屏（以后台为准）。

## 4. 内容安全

- [ ] 页面、图片、文案不含违法违规、色情低俗、暴力、侵权内容。
- [ ] 用户能发布内容（评论、图片、昵称、音视频）的：有审核机制（机器检测加人工）、举报入口和处置流程，并且所选类目允许用户发布内容、具备相应资质。
- [ ] 官方提供内容安全检测能力，接口名称、版本与调用限制以官方文档为准。

## 5. 支付与虚拟支付

- [ ] 有交易的：支付能力已开通，类目允许交易。
- [ ] 实物交易：价格、运费、售后规则写清楚。
- [ ] 虚拟商品或服务（会员、课程、虚拟币等）：已查阅官方关于虚拟支付的最新说明，iOS 端的限制与虚拟支付能力的开通条件以官方为准。
- [ ] 不引导用户到小程序外付款来绕开规则。
- [ ] 抽奖、红包、积分等营销活动：规则、时间、奖品、参与方式写清楚，参与不以分享为条件。

## 6. 页面可用性与白屏

- [ ] 在开发者工具里**关闭**「不校验合法域名」一类选项后再测；服务器域名已在后台配置。
- [ ] 所有请求走 HTTPS 域名，没有 http、IP 地址、localhost。
- [ ] 用体验版在真机上从首页点遍所有入口；再拒绝全部授权走一遍；再在弱网下走一遍。
- [ ] 空数据、加载失败、拒绝授权各有兜底提示，不出现空白页。
- [ ] 没有「敬请期待」「开发中」的空壳入口，没有测试数据和测试文案。
- [ ] 审核期间后端接口、测试账号保持可用，不做影响审核环境的发布。
- [ ] 跑一次 `mp_precheck.py`，页面缺文件、跳转目标未注册、tabBar 配置错误都已修掉。

## 7. 诱导分享、诱导关注与夸大宣传

- [ ] 分享、转发、邀请好友、关注公众号都不是获得功能、奖励或继续使用的条件。
- [ ] 没有「分享到 N 个群解锁」「不转不是 XX」「集赞领取」之类的文案，分享卡片文案也检查过。
- [ ] 没有诱导添加个人微信、跳转外部的设计。
- [ ] 宣传用语与实际一致，不夸大功效或收益。

## 提审当天

- [ ] 版本说明写清本次改了什么（被驳回过的，逐条对应驳回意见，模板见 `appeal-templates.md`）。
- [ ] 测试账号、体验路径复制进提审说明后，自己按路径走一遍。
- [ ] 上线时间留出审核余量，不把发布日卡在审核当天（审核时长以官方为准）。
