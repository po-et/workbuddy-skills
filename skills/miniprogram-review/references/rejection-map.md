# 驳回原因 → 修改动作 对照表

> 左列是驳回通知里常见的说法归类，不是官方原文；处理时以你收到的驳回原文为准，逐字对照。所有要求以《微信小程序运营规范》及官方平台通知的最新版本为准。

## 用法

1. 把驳回原文逐条拆开，每条单独处理，不要只改「看起来最重要」的那条。
2. 每条先定位到具体页面或功能（驳回里常附截图或页面路径）。
3. 在下表找到对应行，做「修改动作」，再按「再提审说明怎么写」写进提审说明。
4. 确认是误判的，才考虑申诉（模板见 `appeal-templates.md`）。

## 对照表

| 驳回里常见的说法 | 通常指向 | 修改动作 | 再提审说明怎么写 |
|---|---|---|---|
| 所选类目与实际功能不符 / 功能超出类目范围 | 某个功能不在已选类目里 | 补充对应类目并上传资质；拿不到资质的功能先下线；同步改简介 | 「已新增 XX 类目并上传资质」或「已下线 XX 功能，入口已删除」 |
| 缺少资质 / 资质不符合要求 | 类目需要的证照没交或过期 | 按类目要求补交；无法取得就调整功能 | 列出新上传的资质名称与有效期 |
| 未按要求填写或更新《用户隐私保护指引》 / 声明与实际不符 | 代码用了但没声明的接口，或声明了却没用到 | 跑扫描脚本列出接口，补全或删减声明；删掉用不到的调用 | 「已在隐私保护指引中新增 XX 的声明，用途为 XX」 |
| 强制授权 / 未经同意收集信息 / 授权时机不当 | 一进小程序就要手机号、位置，或拒绝后不能用 | 授权挪到用户点击对应功能时；拒绝后基础功能可用；提供取消 | 「首页已改为无需授权即可浏览，手机号仅在下单时请求，拒绝后可继续浏览」 |
| 需要登录才能体验，未提供测试账号 | 审核人员进不去核心功能 | 准备专用测试账号；首页开放可浏览内容 | 写账号、密码、体验路径，并注明审核期间有效 |
| 功能不完整 / 存在测试内容 / 页面显示「敬请期待」 | 空壳入口、测试数据、未完成页面 | 补齐或删除入口；替换测试数据与文案 | 「已删除未完成的 XX 入口，替换全部测试数据」 |
| 页面无法打开 / 白屏 / 加载失败 | 服务器域名未配置、http 或 IP 地址、接口宕机、页面文件缺失 | 配置域名、改 HTTPS；修复缺失页面与错误跳转；审核期间保持接口可用；关闭「不校验合法域名」后真机复测 | 「已修复 XX 页面加载失败问题，真机体验版验证通过」 |
| 存在诱导分享、诱导关注行为 | 以分享、邀请、关注换取功能或奖励，或诱导性文案 | 分享改为可选，奖励与分享脱钩；删除诱导文案（含分享卡片） | 「已删除 XX 页面『分享到群解锁』的设计，全部功能无需分享即可使用」 |
| 涉及虚拟支付 / 虚拟商品交易不符合要求 | 会员、课程、虚拟币等的支付方式 | 查阅官方关于虚拟支付的最新说明，按要求调整 iOS 端支付或开通相应能力 | 写清调整后的支付方式与适用端 |
| 用户发布内容缺少审核机制 / 类目不允许用户发布内容 | 评论、上传、昵称等用户内容 | 接入内容安全检测、人工审核、举报入口；补充允许用户发布内容的类目与资质，或关闭发布功能 | 「已接入内容审核与举报处理，XX 类内容先审后发」 |
| 名称、简介、图标与功能不符 / 涉嫌侵权 | 描述夸大或使用了他人商标、形象 | 修改描述；提供授权证明或替换素材 | 列出修改项或已上传的授权文件名称 |
| 营销活动规则不清 / 夸大宣传 | 抽奖、红包、积分规则缺失，或宣传与实际不符 | 写清规则、时间、奖品与参与方式；删除夸大用语 | 「活动页已补充完整规则说明」 |
| 引导用户到小程序外交易或添加个人联系方式 | 外链收款、私域引流 | 删除相关引导，交易留在合规渠道内 | 「已删除 XX 页面的外部引导」 |
| 缺少用户协议或隐私政策 | 登录、注册时看不到协议 | 在登录页、设置页提供可点开的协议与隐私政策 | 写明入口位置 |

## 连续被驳回怎么办

- 同一原因驳回两次以上：多半是「改了表面没改根源」。回到驳回截图，检查是否还有同类入口（分享卡片、活动弹窗、分包页面）没改到。
- 每次驳回理由不同：说明问题分散，提审前按 `pre-submit-checklist.md` 全量过一遍，一次改完再提。
- 确实看不懂驳回原因：先按原文逐字定位；仍不清楚时，通过官方提供的咨询或申诉渠道询问具体页面（渠道以后台为准）。
