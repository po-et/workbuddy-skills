# 输出证据与路径规则

## 三种证据分别判断

1. `test_mapping` 是文件名/模块路径线索，`execution_proven` 固定为 `false`。没有同名测试不等于没有测试，有同名测试不等于运行过。
2. `coverage_mapping` 描述输入报告条目与源码路径的关系，不推断报告对应哪个提交。路径匹配后取报告百分比；不可靠匹配时百分比为 `null`。
3. `churn` 来自只读 `git log` 的近期路径记录。无法读取 Git 时记录原因，改动次数不作为有/无改动的确定结论。

## 匹配字段

| 字段 | 含义 |
|---|---|
| `confidence: exact` | 分隔符与 `.` / `..` 规范化后完全相同；大小写不折叠 |
| `confidence: suffix_unique` | 最长相同尾部只有一个报告候选，没有其他源码争用 |
| `confidence: ambiguous` | 最长后缀并列、同一条目被多个源码争用或规范化后多个键碰撞 |
| `confidence: unmatched` | 没有报告路径候选 |
| `matched_path` | 可靠匹配时使用的报告键；歧义 / 未匹配时为 `null` |
| `candidates` | 确定性排序的报告候选路径 |
| `source_candidates` | 多个源码争用同一证据时的源码列表 |

`src/x.py` 对 `left/x.py` 100% 与 `right/x.py` 0% 是歧义；不会挑第一项。单个报告 `user.py` 对两个模块的 `src/user.py` 也是歧义。已经精确对应的源码保留该条证据，其他试图复用它的源码保持歧义。

测试命名映射还包括 `convention_unique`、`convention_multiple`：在同一模块作用域内找到一份或多份测试命名线索。这些状态不作为执行覆盖率。

## 解析与未知值

- lcov 的 DA 行号须为正整数、命中须为非负整数；LF / LH 同时提供，LH 不大于 LF，并与 DA 明细一致。记录须以 `end_of_record` 结束。重复相同行去重；冲突报错。
- Cobertura 按唯一行号计算命中。缺失文件名、非法行号/命中、NaN 或超出 0–1 的 line-rate 报错；重复行冲突报错。支持 XML 命名空间。
- 没有明细但有合法 `line-rate` 时保留该百分比；行数与命中数为 `null`。不存在「0.5 自动变成 100%」的替代算法。
- 可执行行总数为 0，且没有可用百分比时覆盖率是 `null`，不是 0%。输入报告缺少某个源码的条目也是 `null`。
- 同一文件混用摘要和明细、重复摘要冲突、映射后冲突均报输入错误；不会在本技能中猜测合并。

## 输出与门禁

`gaps` 列出缺少明确测试命名线索且达到 `--min-lines` 的源码；`zero_coverage` / `low_coverage` 来自可靠匹配的报告数据；`coverage_unknown` 仅在提供报告时列出未知或歧义；`source_findings` 保存所有扫描源码的完整证据。

`--strict` 对 high 与提供报告时的未知/歧义返回 1；低覆盖阈值只产生 warn。输入错误返回 2 且不产生成功 JSON。JSON 数值 `0` 与 `null` 含义不同，不能用真假值替代判定。

默认只读输入。`--output` 是唯一主动写入功能，写用户指定的 Markdown 文件；不允许覆盖扫描到的源码、测试或报告输入。不要把输出设成项目配置、其他未扫描业务文件；脚本不能识别所有文件用途。
