# PPT 制作

定位一句话：**一套清楚的 PPT，只读每页的标题就能读懂整个故事；每页只证明一个结论，页面上别的东西都是在给这个结论作证。**

何时用：手上有报告、数据表、会议纪要或调研材料，要做成一套幻灯片；或者已经有一套片子，又乱又满。本技能管「做」：结构、标题、版式、图表、配色字号和统一性。上台怎么讲、怎么应对提问，不在这里。

## 先判断：给谁看、看完做什么、讲还是读

```
受众        谁看？领导、客户、评审还是同事？他们对这件事已经知道多少？
看完做什么  批准、拍板、给资源，还是只需要知道进展？写成一句：「看完这套片子，XX 会同意 YY」
讲还是读    上台讲的：一页一个点，字少图大，细节放进备注
            发出去读的（邮件、群里转发）：可以多写几句，但每页仍然只证明一个结论
篇幅        给多长时间？经验上按一页 1–2 分钟估页数
模板        有公司或学校的模板就用模板；没有再按本页的配色字号底线自己定
```

检查点：写不出「看完这套片子，XX 会同意 YY」这一句，先别打开 PPT 软件。

## 六步流程：从材料到成片

**第 1 步　写一页纸故事线。** 不开 PPT，先在一页纸上填完这张表：

```
受众：                    看完要他做：
一句话结论：
支撑 1：                  证据（数据、事例、原话）：
支撑 2：                  证据：
支撑 3：                  证据：
需要对方拍板或支持的事：
```

结构四选一：结论先行（先给答案，再给三个理由），适合向上汇报；问题、原因、方案，适合提建议；现状、目标、差距、行动，适合做计划；按时间线，适合复盘。支撑点三个左右，互相不重叠。检查点：把结论和三个支撑念给没看过材料的人听，他能复述出来。

**第 2 步　每页一句结论式标题。** 故事线里的每一句，变成一页的标题。标题是一句完整的话，有主语、有判断，最好带数字，不超过两行。

```
主题式（不要）   结论式（要，示例数据）
市场分析         华东市场增速放缓，新增量主要来自三线城市
用户调研结果     一半以上的新用户卡在注册第二步的验证码
下一步计划       10 月先改验证码流程，两周上线
```

检查点：把所有标题按顺序抄成一列，只读这一列就能读懂整个故事。读不通时回第 1 步改故事线，别在页面上修修补补。

**第 3 步　选版式。** 标题定了再选版式，版式替标题作证。一页只用一种版式，一页想放两种，说明该拆成两页。

- **对比**：左右两栏或表格，比较方案 A 和 B、改前和改后。两边的维度顺序一致，推荐的一边用强调色。
- **流程**：3 到 6 个步骤横排，或做成时间线。超过 6 步就拆页或分组。
- **数据**：一张图、一句结论、1 到 3 个标注，数据来源写在页脚。
- **引用**：放大一句用户原话或专家观点，下面写出处。引用必须真实，说得出是谁、在哪说的。
- 另外两种常用的：一个关键大数字配一句解释；只放章节名的过渡页。

**第 4 步　按要表达的关系选图表。**

```
要说明的关系              用什么图                        注意
几个类别比大小            条形图或柱形图，按数值排序       类别名长就用横向条形图
随时间变化                点多用折线图，点少用柱形图       时间从左到右，间隔一致
占比，类别不超过 5 个      饼图或环形图                     各部分加起来必须是 100%
占比，类别多或要比几组     堆积条形图                       别拿几个饼图并排比
两个指标之间的关系        散点图                           两个坐标轴都写单位
从起点到终点的增减构成    瀑布图                           起点和终点用同一种颜色
要查精确数字              表格                             只留要看的列，别整张贴
```

通用规则：柱形图和条形图的数值轴从 0 开始；不用 3D；能直接标数值就不用图例；要强调的一项用强调色，其余用灰色；图表标题写结论，不写「XX 情况」；来源和统计口径写在页脚。

**第 5 步　守住配色与字号底线。**

- 配色：一个主色、一个强调色，加黑白灰。同一个含义全套用同一种颜色，比如「我方」始终是蓝色。强调色只用来标「请看这里」，一页一两处。红绿同时出现时加文字或形状区分，照顾色弱的读者。主题颜色在「设计 → 变体 → 颜色」里定，别每页手动挑色。
- 字号（16:9 页面的经验底线，不是标准）：标题 28–36 磅；上台讲的正文不小于 18 磅，发出去读的不小于 14 磅；图表标注不小于 12 磅；页脚和来源 10–12 磅。
- 字体：全套不超过两种，一种中文、一种西文和数字；投影时黑体类的无衬线字体更清楚。
- 文字量：上台讲的一页不超过 6 行，发出去读的不超过 12 行。放不下就拆页，别靠缩小字号塞进去。

**第 6 步　统一性检查。** 能在母版里改的都去母版改（视图 → 幻灯片母版）：标题位置和字号、正文样式、页码、来源的位置，改一次全套生效，别逐页拖动。然后逐页过一遍：同类元素样式一致（同级标题、同类图表、同类图标）；数字格式一致（单位、小数位、千分位）；同一个概念全套只用一个叫法；对齐用「排列 → 对齐」和参考线，不靠眼睛。

## 模板：10 页和 20 页大纲

10 页，一个项目或方案的汇报，约 15 分钟：

```
页    这页要说的一句话（换成你的结论）                 版式
1     封面：主标题就是一句话结论，副标题写汇报人和日期    封面
2     结论先行：建议做 X，因为 A、B、C，需要您批准 Y     三要点
3     背景：为什么现在要处理这件事                     大数字
4     现状：问题有多大，影响到谁                       数据
5     原因：问题主要出在哪一环                         流程
6     方案：比较 2 到 3 个选项，推荐其中一个             对比
7     效果：做完能改善多少，基于什么假设                 数据
8     计划：谁、什么时候、做到什么程度                   流程（时间线）
9     风险和需要的支持                                表格
10    请您决定：重复结论，列出要拍板的事                 三要点
附录  细节数据、方法说明，不计页数，被问到再翻
```

20 页，季度或年度复盘，约 30 分钟：

```
页      这页要说的一句话                                     版式
1       封面                                                封面
2       执行摘要：三句话讲完目标完成情况、主要原因、下阶段重点    三要点
3       目录：三部分，每部分一句话                             流程
4       章节页：回顾                                         过渡
5–8     目标与实际的差距；做得好的两件事；没做好的两件事；原因    数据、对比、引用
9       章节页：分析                                         过渡
10–13   用户、市场、竞品、自身能力，各一页，每页一个发现          数据、引用、对比
14      章节页：计划                                         过渡
15–18   下阶段目标；三项重点举措；路线图；资源和预算              大数字、流程、表格
19      风险与应对                                           表格
20      需要的决定和支持                                     三要点
```

## 「一页一结论」改写示例

改前，一页塞了好几个结论，标题是主题词（示例数据，均为虚构）：

```
标题：用户调研结果
· 访谈 12 位用户，回收问卷 300 份
· 54% 的用户在注册第二步放弃
· 用户觉得验证码收得太慢
· 老用户更喜欢新版首页
· 客服每天接到 20 多个注册相关的咨询
· 竞品已经支持一键登录
· 建议优化注册流程
```

改后，拆成三页，每页一个结论，其余挪进备注或附录：

```
第 1 页  标题：一半以上的新用户在注册第二步放弃，卡点是验证码
         版式：数据。漏斗图列出每一步的留存，第二步用强调色，其余灰色；页脚写问卷时间和份数
第 2 页  标题：用户抱怨最多的是「验证码要等太久」
         版式：引用。放大两句用户原话，下面注明访谈编号
第 3 页  标题：先上一键登录，两周能改完
         版式：对比。现流程和新流程各一栏，预计效果写明依据的假设
挪走的   「老用户更喜欢新版首页」和本套结论无关，放附录
         「客服每天 20 多个咨询」放进第 1 页的备注，被问到时再讲
```

## 交付前自检清单与体检脚本

```
结构  □ 只读标题能读懂整个故事   □ 第 2 页就给出结论      □ 最后一页写清要对方做什么
单页  □ 每页只有一个结论         □ 标题是一句完整的话      □ 没有「如下图所示」这种空标题
图表  □ 图表标题写的是结论       □ 数值轴从 0 开始        □ 有来源和口径   □ 没有 3D 和多余图例
视觉  □ 颜色只有主色、强调色和灰  □ 字号不低于底线          □ 字体不超过两种  □ 元素对齐
文字  □ 数字、单位、术语全套一致  □ 没有错别字             □ 缩写第一次出现时写了全称
文件  □ 嵌入字体或另存一份 PDF    □ 压缩过图片，能发邮件     □ 清掉批注和隐藏信息  □ 文件名带日期和版本
```

嵌入字体在「文件 → 选项 → 保存」里勾选；压缩图片在「图片格式 → 压缩图片」；批注和隐藏信息用「文件 → 信息 → 检查问题 → 检查文档」清理。菜单名按 Windows 版 PowerPoint 中文版写；Mac 版和 WPS 演示有同名功能，位置略有不同。

体检脚本只读 .pptx、不改文件，只用 python3 标准库。它按放映顺序列出每页标题（标题串读），并找出没用标题占位符的页、主题词式标题、过长标题、偏满的页、被自动缩小的文字、低于字号底线的文字，最后统计全套手动指定的字体和颜色。只统计页面上显式设置的字号，从母版继承的不算；阈值是经验值，可以按需要改。Keynote 做的片子先导出为 .pptx 再查。

```python
# 保存为 pptx_check.py；只读 .pptx，不改文件，只用标准库
import re
import sys
import zipfile
import xml.etree.ElementTree as ET
from collections import Counter

A = "{http://schemas.openxmlformats.org/drawingml/2006/main}"
P = "{http://schemas.openxmlformats.org/presentationml/2006/main}"
R = "{http://schemas.openxmlformats.org/officeDocument/2006/relationships}"
MIN_PT = float(sys.argv[2]) if len(sys.argv) > 2 else 18   # 字号底线：投影讲的 18，发出去读的可放到 14


def slide_order(z):
    """按 presentation.xml 里的顺序排页；文件名里的编号不一定等于放映顺序"""
    names = z.namelist()
    if "ppt/presentation.xml" in names and "ppt/_rels/presentation.xml.rels" in names:
        rels = {r.get("Id"): r.get("Target") for r in ET.fromstring(z.read("ppt/_rels/presentation.xml.rels"))}
        ids = [s.get(R + "id") for s in ET.fromstring(z.read("ppt/presentation.xml")).iter(P + "sldId")]
        return [rels[i].lstrip("/") if rels[i].startswith("/") else "ppt/" + rels[i] for i in ids]
    return sorted((n for n in names if re.match(r"ppt/slides/slide\d+\.xml$", n)),
                  key=lambda n: int(re.findall(r"\d+", n)[-1]))


def text_of(el):
    return " ".join("".join(t.text or "" for t in p.iter(A + "t")) for p in el.iter(A + "p")).strip()


fonts, colors, problems = Counter(), Counter(), []
with zipfile.ZipFile(sys.argv[1]) as z:
    order = slide_order(z)
    print(f"共 {len(order)} 页；字号底线 {MIN_PT:g} 磅\n\n标题串读（只看这一列，应该能读懂整个故事）：")
    for no, name in enumerate(order, 1):
        sld = ET.fromstring(z.read(name))
        title, body = None, []
        for sp in sld.iter(P + "sp"):
            ph = sp.find(f"{P}nvSpPr/{P}nvPr/{P}ph")
            kind = ph.get("type") if ph is not None else None
            if kind in ("title", "ctrTitle"):
                title = text_of(sp)
            elif kind not in ("dt", "ftr", "sldNum") and sp.find(P + "txBody") is not None:   # 日期、页脚、页码不算正文
                body += [t for t in (text_of(p) for p in sp.iter(A + "p")) if t]
        print(f"  {no:>2}. {title if title else '（没有标题占位符）'}")
        if title is None:
            problems.append(f"第 {no} 页：没用标题占位符，各页标题位置会跳，大纲视图里也看不到")
        elif len(re.sub(r"\s", "", title)) <= 8 and not re.search(r"\d", title):
            problems.append(f"第 {no} 页：标题「{title}」像主题词，改成一句带判断的结论")
        elif sum(1 if ord(ch) > 0x2E7F else 0.5 for ch in title) > 30:           # 汉字按 1、英文数字按半个字算
            problems.append(f"第 {no} 页：标题太长（约 {len(title)} 字符），可能超过两行")
        chars = sum(len(re.sub(r"\s", "", t)) for t in body)
        if len(body) > 6 or chars > 120:
            problems.append(f"第 {no} 页：正文 {len(body)} 段、{chars} 字，偏满，考虑拆页或挪进备注")
        for fit in sld.iter(A + "normAutofit"):
            if fit.get("fontScale"):
                problems.append(f"第 {no} 页：文字被自动缩小到 {int(fit.get('fontScale')) / 1000:g}%，内容放不下了")
        small = [r for r in sld.iter(A + "r") if r.find(A + "rPr") is not None
                 and r.find(A + "rPr").get("sz") and int(r.find(A + "rPr").get("sz")) / 100 < MIN_PT]
        if small:
            sizes = sorted({int(r.find(A + "rPr").get("sz")) / 100 for r in small})
            problems.append(f"第 {no} 页：{len(small)} 处文字小于 {MIN_PT:g} 磅（{'、'.join(f'{s:g}' for s in sizes)} 磅），"
                            f"例「{(small[0].findtext(A + 't') or '')[:12]}」")
        for f in sld.iter():
            if f.tag in (A + "latin", A + "ea") and not f.get("typeface", "+").startswith("+"):
                fonts[f.get("typeface")] += 1
        colors.update(c.get("val") for c in sld.iter(A + "srgbClr"))

print("\n问题：" if problems else "\n没发现问题。")
for line in problems:
    print("  " + line)
print(f"\n全套手动指定的字体 {len(fonts)} 种：{'、'.join(fonts) or '无（都跟主题走）'}")
print(f"全套手动指定的颜色 {len(colors)} 种：{'、'.join(c for c, _ in colors.most_common(8)) or '无（都跟主题走）'}")
```

## 输出契约

1. **一页纸故事线**：受众、看完要他做什么、一句话结论、三个支撑和各自的证据、需要的决定。
2. **逐页大纲表**：页码、结论式标题、版式、页面内容、图表类型、数据来源，一页一行。
3. **每页文字稿**：标题加要点（上台讲的不超过 6 行），图表写清横轴、纵轴和强调哪一项，备注里写口头补充的细节。
4. **待补清单**：缺的数据、缺的图、要确认的统计口径，每条注明用在第几页。
5. **体检结果**（用户给了 .pptx 时）：脚本输出，加逐页修改建议。

本技能不带生成 .pptx 的工具，成片由用户在 PowerPoint、WPS 演示或 Keynote 里按大纲制作。PowerPoint 可以用「开始 → 新建幻灯片 → 幻灯片(从大纲)」导入 Word 大纲，标题 1 成为页标题、标题 2 成为要点，具体以你的软件版本为准。

## 边界与不做什么

- 只管「做」：结构、标题、版式、图表、视觉统一。上台怎么讲、怎么控场和回答提问，不在本技能范围。
- 不编数据、不编引语：图表里的每个数、页面上的每句原话都要有出处，缺的写【待补】。
- 不替用户做业务判断：结论由材料和作者决定，本技能只负责把它讲清楚。
- 公司或学校有模板和视觉规范的，以模板为准；本页的配色字号数值是经验底线，不是标准。
- 图片、图标、字体注意版权，商用字体和网上搜来的图片先确认授权。
- 含内部数据或个人信息的材料只在本机处理，交付前用「检查文档」清理批注和隐藏信息。
