# PPT 制作

定位一句话：**一套清楚的 PPT，只读每页的标题就能读懂整个故事；每页只证明一个结论，页面上别的东西都是在给这个结论作证。**

## 何时使用

用户这样说时用本技能：

- 「帮我把这份季度报告做成一套 PPT，先列个大纲」——手上有报告、数据表、会议纪要或调研材料
- 「PPT 每页标题怎么写，才不像目录一样空」
- 「这套 PPT 太乱了，交之前帮我检查一遍」——已经有一套片子，又乱又满
- 「这么多数据，该用什么图」
- 「15 分钟的汇报，做几页合适」
- 「帮我跑一下体检，看看字号、标题和字体」

本技能管「做」：结构、标题、版式、图表、配色字号和统一性。

不适用（遇到时这样处理）：

- 上台怎么讲、怎么控场、怎么回答提问 → 不在本技能范围，转「PPT汇报演示」（presentation-expert）。
- 要直接生成 .pptx 文件 → 本技能不带生成工具；交付故事线、逐页大纲和文字稿，由用户在 PowerPoint、WPS 演示或 Keynote 里做。
- 结论本身对不对、数据要怎么算 → 不替用户做业务判断；周报月报的口径和表结构可转「报表制作」（report-making）。

## 先判断：给谁看、看完做什么、讲还是读

```
受众        谁看？领导、客户、评审还是同事？他们对这件事已经知道多少？
看完做什么  批准、拍板、给资源，还是只需要知道进展？写成一句：「看完这套片子，XX 会同意 YY」
讲还是读    上台讲的：一页一个点，字少图大，细节放进备注
            发出去读的（邮件、群里转发）：可以多写几句，但每页仍然只证明一个结论
篇幅        给多长时间？经验上按一页 1–2 分钟估页数
模板        有公司或学校的模板就用模板；没有再按本页的配色字号底线自己定
```

检查点：写不出「看完这套片子，XX 会同意 YY」这一句，先别打开 PPT 软件。

## 六步流程：从材料到成片

**第 1 步　写一页纸故事线。** 不开 PPT，先在一页纸上填完这张表：

```
受众：                    看完要他做：
一句话结论：
支撑 1：                  证据（数据、事例、原话）：
支撑 2：                  证据：
支撑 3：                  证据：
需要对方拍板或支持的事：
```

结构四选一：结论先行（先给答案，再给三个理由），适合向上汇报；问题、原因、方案，适合提建议；现状、目标、差距、行动，适合做计划；按时间线，适合复盘。支撑点三个左右，互相不重叠。检查点：把结论和三个支撑念给没看过材料的人听，他能复述出来。

**第 2 步　每页一句结论式标题。** 故事线里的每一句，变成一页的标题。标题是一句完整的话，有主语、有判断，最好带数字，不超过两行。

```
主题式（不要）   结论式（要，示例数据）
市场分析         华东市场增速放缓，新增量主要来自三线城市
用户调研结果     一半以上的新用户卡在注册第二步的验证码
下一步计划       10 月先改验证码流程，两周上线
```

检查点：把所有标题按顺序抄成一列，只读这一列就能读懂整个故事。读不通时回第 1 步改故事线，别在页面上修修补补。

**第 3 步　选版式。** 标题定了再选版式，版式替标题作证。一页只用一种版式，一页想放两种，说明该拆成两页。

- **对比**：左右两栏或表格，比较方案 A 和 B、改前和改后。两边的维度顺序一致，推荐的一边用强调色。
- **流程**：3 到 6 个步骤横排，或做成时间线。超过 6 步就拆页或分组。
- **数据**：一张图、一句结论、1 到 3 个标注，数据来源写在页脚。
- **引用**：放大一句用户原话或专家观点，下面写出处。引用必须真实，说得出是谁、在哪说的。
- 另外两种常用的：一个关键大数字配一句解释；只放章节名的过渡页。

**第 4 步　按要表达的关系选图表。**

```
要说明的关系              用什么图                        注意
几个类别比大小            条形图或柱形图，按数值排序       类别名长就用横向条形图
随时间变化                点多用折线图，点少用柱形图       时间从左到右，间隔一致
占比，类别不超过 5 个      饼图或环形图                     各部分加起来必须是 100%
占比，类别多或要比几组     堆积条形图                       别拿几个饼图并排比
两个指标之间的关系        散点图                           两个坐标轴都写单位
从起点到终点的增减构成    瀑布图                           起点和终点用同一种颜色
要查精确数字              表格                             只留要看的列，别整张贴
```

通用规则：柱形图和条形图的数值轴从 0 开始；不用 3D；能直接标数值就不用图例；要强调的一项用强调色，其余用灰色；图表标题写结论，不写「XX 情况」；来源和统计口径写在页脚。

**第 5 步　守住配色与字号底线。**

- 配色：一个主色、一个强调色，加黑白灰。同一个含义全套用同一种颜色，比如「我方」始终是蓝色。强调色只用来标「请看这里」，一页一两处。红绿同时出现时加文字或形状区分，照顾色弱的读者。主题颜色在「设计 → 变体 → 颜色」里定，别每页手动挑色。
- 字号（16:9 页面的经验底线，不是标准）：标题 28–36 磅；上台讲的正文不小于 18 磅，发出去读的不小于 14 磅；图表标注不小于 12 磅；页脚和来源 10–12 磅。
- 字体：全套不超过两种，一种中文、一种西文和数字；投影时黑体类的无衬线字体更清楚。
- 文字量：上台讲的一页不超过 6 行，发出去读的不超过 12 行。放不下就拆页，别靠缩小字号塞进去。

**第 6 步　统一性检查。** 能在母版里改的都去母版改（视图 → 幻灯片母版）：标题位置和字号、正文样式、页码、来源的位置，改一次全套生效，别逐页拖动。然后逐页过一遍：同类元素样式一致（同级标题、同类图表、同类图标）；数字格式一致（单位、小数位、千分位）；同一个概念全套只用一个叫法；对齐用「排列 → 对齐」和参考线，不靠眼睛。

## 模板与改写示例

- **10 页大纲**（一个项目或方案的汇报，约 15 分钟）：封面 → 结论先行 → 背景 → 现状 → 原因 → 方案 → 效果 → 计划 → 风险和支持 → 请您决定，另附附录。
- **20 页大纲**（季度或年度复盘，约 30 分钟）：封面 → 执行摘要 → 目录 → 回顾（4 页）→ 分析（4 页）→ 计划（4 页）→ 风险与应对 → 需要的决定和支持，三个章节各有过渡页。

逐页的「这页要说的一句话」和版式见 [references/outline-templates.md](references/outline-templates.md)。「一页塞了七条，拆成三页」的改前改后见 [examples/one-slide-one-point.md](examples/one-slide-one-point.md)。

## 交付前自检清单与体检脚本

```
结构  □ 只读标题能读懂整个故事   □ 第 2 页就给出结论      □ 最后一页写清要对方做什么
单页  □ 每页只有一个结论         □ 标题是一句完整的话      □ 没有「如下图所示」这种空标题
图表  □ 图表标题写的是结论       □ 数值轴从 0 开始        □ 有来源和口径   □ 没有 3D 和多余图例
视觉  □ 颜色只有主色、强调色和灰  □ 字号不低于底线          □ 字体不超过两种  □ 元素对齐
文字  □ 数字、单位、术语全套一致  □ 没有错别字             □ 缩写第一次出现时写了全称
文件  □ 嵌入字体或另存一份 PDF    □ 压缩过图片，能发邮件     □ 清掉批注和隐藏信息  □ 文件名带日期和版本
```

嵌入字体在「文件 → 选项 → 保存」里勾选；压缩图片在「图片格式 → 压缩图片」；批注和隐藏信息用「文件 → 信息 → 检查问题 → 检查文档」清理。菜单名按 Windows 版 PowerPoint 中文版写；Mac 版和 WPS 演示有同名功能，位置略有不同。

体检脚本只读 .pptx、不改文件，只用 python3 标准库。它按放映顺序列出每页标题（标题串读），并找出没用标题占位符的页、空标题或母版默认文字、主题词式标题、过长标题、偏满的页、被自动缩小的文字、低于字号底线的文字，最后统计全套手动指定的字体和颜色。只统计页面上显式设置的字号，从母版继承的不算；阈值是经验值，可以按需要改。Keynote 做的片子先导出为 .pptx 再查。

```bash
python3 {baseDir}/scripts/pptx_check.py 汇报.pptx       # 字号底线 18 磅，上台投影讲的
python3 {baseDir}/scripts/pptx_check.py 汇报.pptx 14    # 发出去读的片子，底线放到 14 磅
```

在一份故意做乱的测试文件上的实际输出和逐页修改建议，见 [examples/checker-run.md](examples/checker-run.md)。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（模板） |
|---|---|---|
| E1 缺关键信息：只给了材料，没说给谁看、要什么结果 | 只问 3 个：给谁看、看完要他做什么、上台讲还是发出去读以及多长时间；16:9、按一页 1–2 分钟估页数、没模板就按底线，先按默认写并标【待确认】 | 「先确认三件事：给谁看？看完要他做什么？上台讲还是发出去读，给多长时间？其余我先按常见做法排，标了【待确认】的你再改。」 |
| E2 写不出「看完这套片子，XX 会同意 YY」 | 先停在故事线，不排页；从材料里提两个候选结论让用户选 | 「材料里能读出两种结论：①……②……。你想让对方看完同意哪一个？定了我再排页。」 |
| E3 材料自相矛盾：同一个数两处不一样、口径不同 | 摘出两处原文和页码，给两个理解；这个数先标【待确认】，不上标题 | 「报告第 3 页写……，附表写……，口径可能不同。按①……还是②……？定之前这个数不上标题。」 |
| E4 页数和时长对不上：5 分钟要讲 30 页 | 按一页 1–2 分钟折算，给两个方案 | 「5 分钟大约讲 3–5 页。是①压成 5 页、其余进附录，还是②申请更长的时间？」 |
| E5 缺数据、缺图、缺出处 | 不编；写【待补】，进待补清单并注明用在第几页 | 「第 4 页的漏斗图缺各步留存数，先标【待补】，你补上我再定图表。」 |
| E6 要求编数据、编引语，或把坐标轴截断让差距「看起来大一点」 | 不做；说明图表规则，给真实数据下更有说服力的做法 | 「数不能编，轴也不截断。可以用强调色标出这一项、在标题里写清差多少，一样醒目。」 |
| E7 超出范围：要演讲稿、控场技巧，或要直接生成 .pptx | 说明不在范围；讲的部分转 PPT汇报演示，成片由用户在软件里按大纲做 | 「上台怎么讲不在我这里，可以用 PPT汇报演示技能；我把大纲和文字稿交给你，照着做成片。」 |
| E8 时间紧，只要最小可用版 | 交两件：一页纸故事线＋标题串（每页一句结论和版式）；每页文字稿和图表随后补 | 「先给你故事线和每页标题，能直接开始排版；文字稿随后补。」 |

脚本 `pptx_check.py` 的退出码与报错：

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 0 | 没发现问题 | 仍按自检清单人工过一遍图表和文件项 |
| 3 | 发现问题，已逐页列出 | 按逐页修改建议改，改完再跑一次 |
| 1「没给要检查的 .pptx 文件」「字号底线要写数字」 | 参数写错 | 按 `pptx_check.py 文件 [字号底线]` 重跑 |
| 2「是旧版 .ppt」「是 Keynote 文件」 | 格式不对 | 另存或导出为 .pptx 再查 |
| 2「不是有效的 .pptx」 | 改了扩展名的 .ppt、加了打开密码，或文件损坏 | 另存为 .pptx、取消打开密码后再查 |
| 2「找不到文件」「没有找到任何幻灯片」 | 路径错，或不是演示文稿 | 检查路径，文件名有空格时用引号包住 |
| 130 | 按了 Ctrl+C | 重新运行即可 |

## 输出契约

交付物按下面的固定顺序给出；某部分本次不交付，就在原位置写「本次未交付：原因」：

1. **一页纸故事线**：受众、看完要他做什么、一句话结论、三个支撑和各自的证据、需要的决定。
2. **逐页大纲表**：页码、结论式标题、版式、页面内容、图表类型、数据来源，一页一行。
3. **每页文字稿**：标题加要点（上台讲的不超过 6 行），图表写清横轴、纵轴和强调哪一项，备注里写口头补充的细节。
4. **待补清单**：缺的数据、缺的图、要确认的统计口径，每条注明用在第几页。
5. **体检结果**（用户给了 .pptx 时）：脚本输出，加逐页修改建议。

本技能不带生成 .pptx 的工具，成片由用户在 PowerPoint、WPS 演示或 Keynote 里按大纲制作。PowerPoint 可以用「开始 → 新建幻灯片 → 幻灯片(从大纲)」导入 Word 大纲，标题 1 成为页标题、标题 2 成为要点，具体以你的软件版本为准。

占位符规则：【待补】＝用户没提供、也不能编的数据、图、引语出处；【待确认】＝先按默认写了、要用户确认的（受众、时长、统计口径、方案细节）。

交付前自检（逐条答「是 / 否」，有一条「否」就先改再交）：

- [ ] 只读大纲表的标题一列，能读懂整个故事；第 2 页就给出结论，最后一页写清要对方做什么
- [ ] 每页只有一个结论、一种版式，标题是一句带判断的完整的话
- [ ] 每个数字和原话都有出处，没有的标了【待补】
- [ ] 页数和时长匹配（按一页 1–2 分钟）
- [ ] 待补清单里每条都注明了第几页
- [ ] 用户给了 .pptx 的，附了体检脚本输出和逐页修改建议

## 示例

以下为示例，材料与数字均为虚构，来自示例中「用户」给出的材料。

**用户：** 帮我把这份季度报告做成一套 PPT，先列个大纲。（材料要点：注册转化率三个月下降 9 个百分点；问卷显示一半以上的新用户在注册第二步放弃；访谈里抱怨最多的是验证码等太久；打算先上一键登录，研发说两周能改完；也考虑过换短信服务商。）

**助手（先问 3 件事）：** ① 给谁看？② 看完要他做什么？③ 上台讲还是发出去读，给多长时间？

**用户：** 给分管副总看，要他批准一键登录的排期和两个人；上台讲，15 分钟，有公司模板。

**助手（交付，本次先交故事线、大纲和待补清单）：**

```
① 一页纸故事线
受众：分管副总            看完要他做：批准一键登录的排期和 2 个人力
一句话结论：注册转化率三个月掉了 9 个百分点，卡点在验证码，先上一键登录，两周能改完
支撑 1：一半以上的新用户在注册第二步放弃      证据：问卷漏斗【待补：各步留存与问卷时间、份数】
支撑 2：用户抱怨最多的是验证码等太久          证据：访谈原话【待补：访谈编号】
支撑 3：一键登录两周能改完                  证据：研发评估；换服务商的周期【待补】，对比后再定第 6 页结论
需要的决定：批准排期与 2 个人力

② 逐页大纲（10 页版，约 15 分钟，套公司模板）
```

## 常见问题（FAQ）

**问：页数怎么定？**
答：按给你的时间估，一页 1–2 分钟：15 分钟大约 10 页，30 分钟大约 20 页；细节放附录，不计页数。

**问：公司有模板，还要按你的配色字号来吗？**
答：有模板就用模板；本技能的配色字号是经验底线，只在没有模板时用来自己定。

**问：能直接帮我生成 .pptx 文件吗？**
答：本技能不带生成工具。交付故事线、逐页大纲和文字稿；PowerPoint 可以用「幻灯片(从大纲)」导入 Word 大纲，具体以你的软件版本为准。

**问：字号最小能用多少？**
答：经验底线：上台讲的正文不小于 18 磅，发出去读的不小于 14 磅，图表标注不小于 12 磅，页脚和来源 10–12 磅。

**问：体检脚本会改我的文件吗？**
答：不会。它只读 .pptx，只用 Python 标准库，输出问题清单，改动由你在软件里做。

**问：脚本说字号太小，可我看着不小？**
答：脚本只统计页面上显式设置的字号，从母版继承的不算；阈值是经验值，发出去读的片子可以把底线改成 14。

**问：WPS 或 Keynote 做的片子能查吗？**
答：WPS 另存为 .pptx 即可；Keynote 先导出为 .pptx 再查。菜单位置和 PowerPoint 略有不同。

**问：上台讲的和发出去读的，做法有什么不一样？**
答：上台讲的一页一个点、字少图大、细节进备注，一页不超过 6 行；发出去读的可以多写几句，不超过 12 行，但每页仍只证明一个结论。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 标题写主题词：「市场分析」「用户调研结果」 | 只读标题读不出故事 | 写一句带判断的结论，最好带数字 |
| 一页塞好几个结论 | 听众不知道这页要记住什么 | 一页一个结论，其余拆页、挪进备注或附录 |
| 放不下就缩小字号 | 后排看不清，还被自动缩小 | 拆页，或把细节挪进备注 |
| 不写故事线直接开 PPT | 边做边想，越改越乱 | 先写一页纸故事线，写得出「XX 会同意 YY」再动手 |
| 用 3D 图、多余的图例，数值轴不从 0 开始 | 读错比例，看着花 | 平面图，直接标数值，柱形图和条形图从 0 开始 |
| 几个饼图并排比 | 角度差很难比较 | 用堆积条形图 |
| 每页手动挑颜色、逐页拖动标题 | 全套不统一，改一次要改几十页 | 在主题颜色和幻灯片母版里改一次 |
| 「如下图所示」当标题 | 空标题，没有信息 | 图表标题写结论 |
| 编数据、编引语让页面更好看 | 一被追问就站不住 | 每个数、每句原话都有出处，缺的写【待补】 |
| 用文本框当标题，不用标题占位符 | 各页标题位置会跳，大纲视图里也看不到 | 用版式里的标题占位符 |

## 边界与不做什么

- 只管「做」：结构、标题、版式、图表、视觉统一。上台怎么讲、怎么控场和回答提问，不在本技能范围。
- 不编数据、不编引语：图表里的每个数、页面上的每句原话都要有出处，缺的写【待补】。
- 不替用户做业务判断：结论由材料和作者决定，本技能只负责把它讲清楚。
- 公司或学校有模板和视觉规范的，以模板为准；本页的配色字号数值是经验底线，不是标准。
- 图片、图标、字体注意版权，商用字体和网上搜来的图片先确认授权。
- 含内部数据或个人信息的材料只在本机处理，交付前用「检查文档」清理批注和隐藏信息。
