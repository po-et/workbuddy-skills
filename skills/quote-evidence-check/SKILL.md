# 报价证据核对

将两份报价整理为明确的金额、条件与来源，先判断能否比较，再解释录入范围内的差额。脚本只使用 Python 3.9+ 标准库，在本机运行，不调用网络，也不自动保存用户数据。

先读 [输入与输出约定](references/schema.md)。未知金额必须用 `null`；明确报价为零才写 `"0.00"`。候选数字和条件须由使用者逐项核对，不能把“原文有数字”当作已确认。原文缺项、歧义和冲突应留待追问，不补造税费、利息或其他金额。

整理输入时保留各字段的真实来源。人工修正写明“用户补充”与相应内容，不能冒充首次原文。输入改变后，重新核对受影响金额与条件的确认状态；本工具处理当前快照，不维护历史或自动检测确认失效。确认只是输入者的声明，脚本不证明来源真伪或确认过程确实发生。

运行示例（路径相对于本 Skill 目录）：

```bash
python3 scripts/quote_check.py assets/synthetic-missing.json --json-output report.json --markdown-output report.md
```

默认是**省略原文模式**：报告不含 `source` 原文或车型、付款、范围的自由文本，只保留标准字段、金额、确认状态及通用阻断原因。它不是任意数据自动脱敏，输出仍包含报价金额与状态。使用者主动要求包含原文后才添加 `--include-source`；分享前应核查输出范围。

只有七项金额、三类条件均明确、已确认、有来源，且两边三类条件文本一致时，才输出 `B − A` 与七项差额。否则报告保留已知小计、缺项和追问，撤销完整比较。条件只比较去掉首尾空白后的文本是否相等；同义词不会被自动当成等价条件。

将结果明确称为“七项录入范围的费用核对”，不宣传覆盖全部交易费用，不推荐商家、车型或融资方式。报告含已知小计时，说明它可以包含未确认候选，不能据此排名。格式/schema 错误必须先修正，不将错误视为一次有效比较。

`assets/` 中四份文件均为原创合成报价，仅用于体验缺项、补齐、付款条件不一致与一分钱差异，不是实际商家报价。此 Skill 是独立本地工具资产，不代表 WorkBuddy 原生创作或已满足任何参赛资格。
