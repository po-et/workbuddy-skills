# 报价显微镜：独立验收预期

结论：能算出小计还不够。只有车型/配置、付款条件、费用范围一致且已确认，必要金额齐全且已确认时，才能比较录入范围总额；缺失不等于零。本文件在应用实现验收前独立编写，作为手算预期，不代表已通过测试或已有真人使用。

本文件保留独立手算数据，并列出计划中的网页交互验收要求。当前分发的 Skill 仅实现结构化快照核对，不提供网页、原文提取或历史确认同步；后文的网页检查项不表示已经完成。

## 统一口径

- 以下均是原创、可公开的合成报价；车型名称也是合成标签，不对应真实商品。
- 所有税费只是销售报价中录入的金额，不根据裸车价推导税率，不说明任何税收政策。
- 金额单位为元，计算使用整数分。`0` 是已明确报价为零；缺失、待确认、歧义与格式错误均不得转换为零。
- 费用范围是七项：裸车价、报价税费、保险、上牌、服务费、强制装潢及附加项、其他费用。不得把这个人为定义的范围宣传为覆盖实际交易全部费用。
- 初次提取只能得到候选值。下面涉及“可比较”的预期，均以使用者已确认金额与三类条件为前提；原文里出现数字不等于已确认。
- 差额统一定义为 `B - A`。正数表示 B 在已确认录入范围内高于 A，负数表示 B 低于 A。
- “已知小计”不等于“完整总额”。未知项存在时，小计及其算术差可以展示，但不能用来排名、打赢家标记或输出“省下多少钱”。
- 全部示例必须标注为合成；补充回复也必须标注为合成，不假装是真实销售消息。

## 合成案例 1：低裸车价、服务费缺失，补齐后反转

### A 原文

```text
【公开合成案例 1 / A】
车型/配置：样例星河 标准款
付款方式：现金全款
费用范围：裸车价、报价税费、保险、上牌、服务费、强制装潢及附加项、其他费用
裸车价：100000.00 元
报价税费：10000.00 元
保险：5000.00 元
上牌：500.00 元
服务费：0.00 元
强制装潢及附加项：0.00 元
其他费用：0.00 元
```

### B 原文，首次输入

```text
【公开合成案例 1 / B】
车型/配置：样例星河 标准款
付款方式：现金全款
费用范围：裸车价、报价税费、保险、上牌、服务费、强制装潢及附加项、其他费用
裸车价：97000.00 元
报价税费：10000.00 元
保险：5000.00 元
上牌：500.00 元
服务费：待销售确认
强制装潢及附加项：0.00 元
其他费用：0.00 元
```

### 独立手算与首次预期

```text
A = 100000 + 10000 + 5000 + 500 + 0 + 0 + 0 = 115500.00
B 已知小计 = 97000 + 10000 + 5000 + 500 + 0 + 0 = 112500.00
裸车价差额 B - A = -3000.00
已知小计算术差 B - A = -3000.00
B 服务费 = 未知，不是 0
```

即便使用者确认了其余候选，B 仍不能得到完整总额；比较状态必须是无法完整比较。需明确指出 B 服务费未知，并生成相应追问。禁止输出“B 便宜 3000 元”“推荐 B”，也不能给 B 一个赢家徽标。

### 合成补充回复

```text
【公开合成补充回复 / 案例 1 的 B】
现金全款条件不变。服务费：6000.00 元。
```

通过追加来源或手动补充录入 B 服务费 6000.00；如果采用手动输入，来源须是“用户补充”，不能伪造为首次原文中已有。使用者确认补充内容后：

```text
B = 97000 + 10000 + 5000 + 500 + 6000 + 0 + 0 = 118500.00
B - A = 118500 - 115500 = +3000.00
构成 = 裸车价 -3000 + 服务费 6000 + 其余 0 = +3000.00
```

允许的结果是“在已确认录入范围内，B 比 A 高 3000.00 元”。这不是对商家、车型或实际全部交易成本的推荐。

移除补充回复或把 B 服务费重新清空后，必须立即撤销可比较状态；不能保留旧排名或旧“完整总额”。

## 合成案例 2：全部金额齐全，付款条件不同仍不能排名

### A 原文

```text
【公开合成案例 2 / A】
车型/配置：样例山岚 标准款
付款方式：现金全款
费用范围：仅以下七项录入费用
裸车价：99800.00 元
报价税费：9200.00 元
保险：4800.00 元
上牌：600.00 元
服务费：0.00 元
强制装潢及附加项：0.00 元
其他费用：0.00 元
```

### B 原文

```text
【公开合成案例 2 / B】
车型/配置：样例山岚 标准款
付款方式：贷款，24 期
费用范围：仅以下七项录入费用
裸车价：97800.00 元
报价税费：9200.00 元
保险：4800.00 元
上牌：600.00 元
服务费：0.00 元
强制装潢及附加项：0.00 元
其他费用：0.00 元
备注：贷款利息与还款安排未提供，不包含在以上金额中。
```

### 独立手算与预期

```text
A 录入范围合计 = 99800 + 9200 + 4800 + 600 = 114400.00
B 录入范围合计 = 97800 + 9200 + 4800 + 600 = 112400.00
录入金额算术差 B - A = -2000.00
```

两边七个字段即便全部确认，也必须显示付款方式不一致，不能据此判断谁更便宜。贷款利息未提供不能写成利息为零；本应用不得补造月供、APR、还款计划或推导融资推荐。

不能仅靠点击“忽略条件差异”就把它变成完整可比结论。若 UI 允许查看纯金额差，必须持续伴随“条件不一致/不可据此决策”的状态，且不出现赢家、节省金额或推荐。

### 条件类变体，共用同一金额预期

1. 将 B 改为现金全款，但车型/配置改为“样例山岚 旗舰款”：合计不变，因配置不一致仍不可排名。
2. 将车型/付款都补齐一致，但 A 费用范围为“七项均含”，B 原文说明“上牌另计，500 元仅作参考”：B 上牌不能按已确认且范围一致处理。
3. 删除一边的车型或付款方式：必须变成待确认，不能沿用上一次案例的条件。
4. 使用者有明确的新原文补充，表明 B 改为同款现金全款且录入金额维持不变，并确认后：才允许比较该新报价范围，差额为 -2000.00。只改下拉框也应标记为用户补充，不能声称原始贷款报价已经证明现金价格。

```text
付款方式：现金全款
费用范围：裸车价、报价税费、保险、上牌、服务费、强制装潢及附加项、其他费用
裸车价：88888.88 元
报价税费：8000.02 元
保险：3999.10 元
上牌：500.00 元
服务费：0.00 元
强制装潢及附加项：0.00 元
其他费用：0.00 元
```

### B 原文，首次输入

```text
【公开合成案例 3 / B】
车型/配置：样例晨露 标准款
付款方式：现金全款
费用范围：裸车价、报价税费、保险、上牌、服务费、强制装潢及附加项、其他费用
裸车价：88888.88 元
报价税费：8000.02 元
保险：3999.11 元
上牌：500.00 元
服务费：0.00 元
强制装潢及附加项：0.00 元

```

### 独立手算与首次预期

```text
A = 88888.88 + 8000.02 + 3999.10 + 500 + 0 + 0 + 0
  = 96888.90 + 3999.10 + 500
  = 101388.00
B 已知小计 = 88888.88 + 8000.02 + 3999.11 + 500 + 0 + 0
            = 101388.01
已知小计算术差 B - A = +0.01
```

A 其他费用必须显示 0.00 且有原文出处；B 其他费用必须显示未报价。B 服务费和附加项的 0.00 不能因为是零就从界面、报告或导出中消失。B 其他费用未确认金额前不可比较完整总额。

### 合成补充回复及最终预期

```text
【公开合成补充回复 / 案例 3 的 B】
其他费用：0.00 元。其余报价及条件不变。
```

确认后，B 完整录入范围合计 = 101388.01，B - A = +0.01。禁止舍入成无差异，禁止出现 0.009999…，导出和界面均应一致。

## 原文提取的歧义与错误预期

以下是独立的输入片段验收，不表示产品必须支持所有格式；若不支持，应清楚地保留未知/待录入，绝不能静默误读为有效金额。

| 输入片段/操作 | 允许的候选与必须保留的状态 | 不允许的行为 |
|---|---|---|
| `服务费：待确认` 下一行 `其他费用：0 元` | 服务费未知，其他费用候选 0；二者保留各自来源 | 跨行把其他费用的 0 分配给服务费 |
| `裸车价：100000 元；裸车价：95000 元，二选一待确认` | 两个冲突候选，要求用户选定/补充 | 静默选第一个或最后一个并自动确认 |
| `保险：5000 元或5500元，待定` | 区间/冲突，待用户明确 | 取小值、均值或第一个数字作为已确认保险 |
| `保险：5000 元；赠送保养价值2000元` | 最多提取保险 5000 候选，保养价值不直接抵扣保险 | 算成保险 3000 或把 2000 加入必付费用 |
| `裸车价：10 万元` | 支持单位时可候选 100000；不支持时待录入 | 读成 10 元或 10000 元并参与计算 |
| `上牌：500—800 元` | 未确定金额，保留范围或要求补充 | 自动取 500 或 800 作为完整报价 |
| `服务费：0 元（已免）` | 明确为零的候选，仍需用户确认 | 当作缺失；或过滤掉零项 |
| 只有 `服务费` 字样，没有金额 | 未知/待录入 | 默认为零 |
| `服务费：-100 元` | 无效金额/需明确折扣如何记录，不能参与总额 | 悄悄取绝对值、归零或抵扣其他费用 |
| `NaN`、`Infinity`、`1e309` | 明确拒绝，不得产生有效总额 | 导出 NaN/Infinity、字符串拼接或归零后显示成功 |
| `保险：3999.111 元` | 超过两位小数，应要求修正，不静默变成已确认金额 | 不说明就截断/四舍五入并确认 |
| 同一字段出现两个金额，用户手动选定一个 | 记录选定值及原文/用户补充来源，冲突处置可追溯 | 丢掉冲突事实并宣称原文唯一明确 |
| 把已确认 `服务费：6000` 原文改成 `服务费：8000` | 受影响确认失效，重新提取/确认后复算；旧总额不再作为当前结果 | 仍展示已确认 6000 或旧赢家 |
| 切换案例或清空原文 | 旧候选、确认状态、原文定位与比较状态同步更新 | 新原文搭配旧确认、旧条件或旧导出内容 |
| 原文含 `<b>这是普通文本</b>` | 作为文本显示，不解释为 HTML | 把用户原文插入为可执行或改变结构的 HTML |

提取器可以使用不同关键词规则，但必须让使用者看到候选与出处。验收不以某条内部正则的实现为依据，而以结果是否忠实原文、是否正确阻断不确定比较为依据。

## “自己的输入”完整任务验收

这是一项由验收者独立提供的合成任务，不能只调用应用内置样例。它仍是维护者验收，不计为真人采用或真实成交。

### 输入内容

共用条件：车型/配置 = “合成云杉 2026 标准款”；付款方式 = “现金全款”；费用范围 = 上述七项。

| 字段 | A | B | B - A |
|---|---:|---:|---:|
| 裸车价 | 132456.78 | 131456.78 | -1000.00 |
| 报价税费 | 10123.45 | 10223.45 | +100.00 |
| 保险 | 4567.89 | 4667.89 | +100.00 |
| 上牌 | 300.00 | 350.00 | +50.00 |
| 服务费 | 123.40 | 0.00 | -123.40 |
| 强制装潢及附加项 | 999.00 | 1999.00 | +1000.00 |
| 其他费用 | 0.00 | 0.00 | 0.00 |

独立手算：

```text
A = 132456.78 + 10123.45 + 4567.89 + 300 + 123.40 + 999 + 0
  = 142580.23 + 4567.89 + 300 + 123.40 + 999
  = 148570.52
B = 131456.78 + 10223.45 + 4667.89 + 350 + 0 + 1999 + 0
  = 141680.23 + 4667.89 + 350 + 1999
  = 148697.12
B - A = 148697.12 - 148570.52 = +126.60
分项差额复核 = -1000 + 100 + 100 + 50 - 123.40 + 1000 = +126.60
```

### 端到端验收顺序

1. 匿名打开发布链接，选择自己的输入，不借助内置案例结果。
2. 将上表转成两份普通文本粘贴，应用提取候选；若格式不被支持，能清楚地逐项录入，不能无提示失败。七项与条件均确认前不显示可比结论。
3. 完成确认后，看到 A = 148570.52、B = 148697.12、差额 +126.60，分项解释与手算表一致。任何明确 0.00 项都保留。
4. 点击金额或来源入口，能找到正确原文；手动把 B 上牌由 350 改为 450 时，标记用户补充，B 总额更新为 148797.12、差额 +226.60。
5. 清空 B 服务费后，B 已知小计仍为 148797.12，但完整比较被撤销。这里服务费原来为零，清空后小计未变尤其容易暴露“数字没变便继续放行”的错误。
6. 把 B 服务费重新明确为 0.00 并确认，恢复可比较结果；车型改成另一配置则再次阻断。恢复原配置且确认后才再次放行。
7. 导出 Markdown 与 JSON，重新打开，核对金额、状态、来源以及差额；JSON 必须可解析，不能把未知转换为 0。缺项状态也应能导出相应追问。
8. 选择脱敏导出时，先展示导出范围，确认是否包含原文。不得把未被可靠删除的私人原文称为“已自动脱敏”；完整报告应由使用者主动选择。
9. 若提供 JSON 导入，导回刚导出的完整报告应恢复相同数值与明确状态；若首版没有导入，不能宣称具备导回能力。
10. 在手机窄屏完成候选编辑、确认、溯源与导出；操作不依赖悬停，键盘用户能访问关键控件，错误后输入不丢失。
11. 保存必须由使用者主动触发；清除本机保存后，刷新不恢复先前私人报价。不得将正常浏览器缓存或已有登录态误称为已保存业务资料。

## 验收记录与阻断标准

- 每次实测记下应用版本/提交、发布链接、时间、输入、实际结果及截图/导出。此文件的“预期”与实测“实际结果”分开保存。
- 金额错误、把未知当零、条件不一致仍排名、修改原文后沿用旧确认、来源对错报价、未经操作保存/上传私人原文，均属于核心阻断项，不能以样例页面能打开替代修复。
- 维护者测试、AI 测试、陌生真人试用和真实重复使用分开记；没有真人证据时，公开材料只能说已做维护者验证。
- 本文件不为作品打评委分数，不预测获奖，不解释税收政策或推荐金融产品。
