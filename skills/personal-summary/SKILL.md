# 个人总结

定位一句话：**个人总结要回答读者最关心的三件事：这段时间你做成了什么、靠什么做成的、下一段怎么做得更好——每一句都拿得出事实。**

## 何时使用

用户这样说时用本技能：

- 「期末了，班主任让写学期个人总结」
- 「季度末要交个人工作总结，我做的事太杂，不知道写什么」
- 「年终个人总结怎么写出重点」
- 「实习结束了，实习鉴定表里要写个人总结」
- 「试用期到了，转正要交试用期总结」
- 「我写的总结像流水账，帮我改」

不适用（遇到时这样处理）：

- 以部门或单位名义上报的工作总结、情况报告等公文：转「公文写作」技能。本技能只写个人署名、个人视角的总结。
- 一次培训、读书、讲座之后的感想：转「心得体会」技能。
- 述职报告、竞聘演讲、答辩 PPT：可以先用本技能的盘点表整理事实做底稿，但结构和时长按单位通知另写；本技能不做演示稿。

## 第 1 步：先盘点事实，再动笔

总结写成流水账或一片空话，根子都在动笔前没有盘点。先把这段时间的事全部列进一张表：

| 事项 | 我做了什么（动词开头） | 结果与数据（出处） | 别人的反馈（谁说的，原话或大意） | 没做好的地方 |
|---|---|---|---|---|
| [事项] | [负责／完成／组织了……] | [数字，出处：成绩单／后台／周报] | [职务或身份：……] | [具体问题] |

想不起来就翻：日历、周报日报、聊天记录和邮件、任务或工单系统、成绩单、作业和试卷、证书、照片。三条规矩：

- **数据只写有出处的**：估算的写「约」，并注明怎么估的；查不到的写 [待补：数据，出处]。
- **团队成果写清自己的角色**：「我负责其中的……」，不把团队成绩算成个人的。
- **反馈只写真实说过的**：注明是谁说的（职务或身份即可）；没有就不写。

学生版、职场版盘点表模板和十个追问问题见 [references/fact-inventory.md](references/fact-inventory.md)。

## 第 2 步：挑重点

- **按读者挑**：学生版的读者多是班主任、辅导员、家长；职场版是直属上级、人事、评审。他们关心的不一样，见下文「学生版与职场版」。
- **选 2–4 件重点**：结果最大的、最能体现能力的、和下一阶段目标最相关的。其余事项合并成一句「此外，还……」。
- **每件重点三步写**：结论句 → 事实与数据 → 影响（有依据才写）。

## 第 3 步：按「成果—方法—不足—计划」成文

| 部分 | 回答什么 | 默认占比 | 要点 |
|---|---|---|---|
| 成果 | 做成了什么 | 45–50% | 按重要性排序；每段首句是结论，后面跟事实和数据 |
| 方法 | 怎么做成的，哪些做法能复用 | 15–20% | 写具体做法（工具、节奏、习惯），不写「认真负责」 |
| 不足 | 哪里没做好，为什么 | 10–15% | 2–3 条，真实、具体、有原因 |
| 计划 | 下一阶段做什么 | 15–20% | 对应不足和目标：做什么、什么时候、怎样算做到 |

**成绩与不足的比例**：默认「成果＋方法」与「不足」约 4:1 到 5:1。不足太少，读者觉得没有反思、不可信；太多，读起来像检讨书。两种情况要调整：

- 目标没完成的周期：不足升到 20–25%，先写差距和原因，再写补救措施。
- 试用期总结：不足写「已经意识到、正在改、已有进展」的，并写出进展。

## 流水账改成有重点的段落

四个动作：**按主题归并**（不按时间）、**结论放段首**、**数据跟在结论后**、**删掉没有结果的事项**（开过的会、参加过的活动，没产出就不单列）。

示例（虚构）：

```
改前：9 月参加了部门培训，然后跟进 A 项目的需求整理，10 月做了客户回访，还参加了两次周会，11 月协助同事做了活动……

改后：本季度我的主要精力放在客户回访上：共回访[待补：数量]家客户，整理出[待补：数量]条改进建议，其中[待补：数量]条已被采纳。此外，我参与了 A 项目的需求整理，负责[待补：具体部分]。
```

改后的数字全是 [待补]：结构我可以帮你改，数字只能由你按出处填。更多改写对照（学生版、不足、计划）见 [references/rewrite-flow.md](references/rewrite-flow.md)。

## 学生版与职场版

| 维度 | 学生版 | 职场版 |
|---|---|---|
| 读者 | 班主任、辅导员、家长 | 直属上级、人事、评审 |
| 成果写什么 | 学业变化、班级工作、活动、个人成长 | 目标完成度、项目交付、对团队的贡献 |
| 常用数据 | 分数与名次变化、完成率、获奖 | 业务指标、完成数量、时效、质量 |
| 方法写什么 | 学习方法、时间安排 | 工作方法、流程改进、协作方式 |
| 不足怎么写 | 某科薄弱、时间管理、习惯 | 能力短板、流程问题、目标差距 |
| 计划怎么写 | 下学期的学习目标和具体做法 | 下阶段的指标、项目和能力提升 |
| 语气 | 真诚、具体，少口号 | 结论先行，用数据说话 |

五种周期的写法：

- **学期**：以学业为主线，班级工作和活动为辅；成绩只写你拿得出来的。
- **季度**：对照季初目标逐项写完成度；没完成的先写差距。
- **年度**：按三四个板块写，不按月份；写全年最重要的两三件事和能力的变化。
- **实习期**：学到了什么、做成了什么、实习单位的反馈；鉴定表栏位有限时用 500 字档。
- **试用期**：岗位认知 → 独立负责的事 → 主管或导师的反馈 → 改进 → 转正后的计划；只陈述事实，不替用户评价能不能转正。

各部分句式模板、五种周期的详细结构、标题与署名写法见 [references/structure-and-length.md](references/structure-and-length.md)。

## 字数档位

| 档位 | 适用 | 结构 | 各部分约字数 |
|---|---|---|---|
| 500 字 | 鉴定表栏位、系统填报、班会发言 | 不分小标题，四部分各一段 | 成果 220，方法 80，不足 80，计划 100，首尾 20 |
| 1500 字 | 学期、季度总结常规 | 四个小标题，成果写 2–3 件重点 | 开头 100，成果 700，方法 250，不足 200，计划 250 |
| 3000 字 | 年度总结、转正答辩材料 | 四部分，成果按板块分节，可附数据表 | 开头 150，成果 1400，方法 500，不足 400，计划 450，结尾 100 |

用户给了别的字数就按比例缩放。字数用同一个口径数（不含空白的字符，含标点），把正文存成文本后运行：

```bash
python3 -c "import sys; t=open(sys.argv[1], encoding='utf-8').read(); print(sum(1 for c in t if not c.isspace()))" 正文.txt
```

这个数和 Word、WPS 的「字数」可能略有出入，收稿方有指定口径时以收稿方为准。素材不够时照实写短，不用空话凑。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（一句模板） |
|---|---|---|
| 缺关键信息（周期、身份、字数） | 先问三问：总结哪段时间？交给谁看（学生还是职场）？有没有字数和格式要求？其余默认 1500 字、四个小标题，标 [待确认] | 「先确认三件事：总结的是哪段时间？交给老师还是上级？有没有字数和格式要求？」 |
| 只有「做了很多事」，没有具体内容和数据 | 发盘点表让用户填；或追问最花时间的三件事、各自的结果、有没有人评价过；数据位置先放 [待补：数据，出处] | 「先别急着写，我们花五分钟列个清单：这段时间最花时间的三件事是什么，各有什么结果？」 |
| 事实或数据互相矛盾（完成率 120% 却说没完成目标；日期不在总结周期内） | 指出矛盾，给两种理解，请用户选 | 「你说完成率 120%，又说没完成季度目标——是单项超了、总目标没到，还是完成率按别的口径算的？」 |
| 超出本技能范围（单位名义的总结、述职 PPT、心得） | 转交对应技能，或说明只能先做事实盘点 | 「以部门名义上报的总结属于公文，用『公文写作』技能更合适。」 |
| 时间紧，只要最小可用版 | 交 500 字版：成果两条（各一句结论加一个数据）、方法一句、不足一条、计划两条；数据先标 [待补] | 「先给你 500 字的四段版，数据的位置标了待补，填上就能交。」 |
| 坚持越界（夸大数据、把团队成果写成个人的、编领导评价、隐瞒按规定必须说明的问题） | 不写；给合规写法：写有出处的数、写清个人角色、写真实反馈 | 「数据我只按你拿得出出处的写；团队的成果可以写，但要写清你负责的那部分。」 |
| 「不足」写不出来或不想写 | 给三个方向（能力、方法、时间精力分配），挑真实的一条；说明比例的道理 | 「一条不足都不写，反而显得没反思。从能力、方法、时间安排里挑一条真实的，我帮你配上改进措施。」 |

## 输出契约

动笔前确认：周期、学生或职场、读者、字数与格式要求、手头有哪些数据和出处。缺哪项问哪项，一次不超过三个问题。

交付物按这个顺序，不增不减：

1. **事实盘点表**：整理后的版本，每条写明出处，缺的标 [待补]。
2. **标题与署名行**：按要求；不知道的写 [待补：姓名　班级或部门]。
3. **正文**：按所选档位写「成果—方法—不足—计划」；1500 字及以上用小标题。
4. **数据与事实核对单**：正文里出现的每个数字、每条评价，对应到出处。
5. **待补 / 待确认清单**：逐条列出。

占位符规则：用户没给的事实和数据写 [待补：……]；用了默认值、或助手建议的计划与表述，写 [待确认：……]；两类标记都不许用编造的内容填掉。

交付前自检（逐条答「是」才交）：

- [ ] 成果部分每段首句是结论，后面至少有一个事实或数据？
- [ ] 正文里的每个数字、每条评价都能在核对单里找到出处，找不到的都是 [待补]？
- [ ] 团队成果写清了本人的角色？
- [ ] 不足 2–3 条，每条有原因，并在计划里有对应措施？
- [ ] 成绩与不足约 4:1 到 5:1（目标没完成时不足可到 20–25%）？
- [ ] 字数在所选档位 ±10% 以内，格式按要求，不清楚的标了 [待确认]？

## 示例

示例（虚构：人物、部门、数据都是编的，只演示写法）

**用户**：我是新媒体运营，试用期三个月，下周转正答辩要交个人总结，500 字左右。三个月负责公众号日常推送，发了 36 篇；做了一张选题表，部门现在都在用；有一篇阅读量过万；主管说我选题有想法，但排版返工多。

**助手**（先问）：三个问题：36 篇和阅读量是从哪里看的？选题表怎么用、从什么时候开始用的？排版返工多，原因是什么，你已经做了什么改进、有没有变化？

**用户**：数据都是公众号后台看的。36 篇里有 20 篇是我独立选题和写作的，其余 16 篇我负责改稿和排版。三个月关注人数从 1.2 万左右涨到 1.5 万左右，不过里面有两次线下活动带来的，分不清各占多少。选题表分选题、目标读者、预计发布日期、负责人四栏，每周一例会上过一遍，第二个月开始部门在用。另外我还负责了两次线下活动的预告推文。返工主要是字号、行距没统一，图片尺寸不一致；后来我做了一份排版检查清单，每篇发之前对一遍，最近一个月返工从每周两三次降到一次左右。转正后想学数据分析，每月出一份推送数据复盘。

**助手**交付（500 字档）：

```
试用期个人总结
[待补：部门]　[待补：姓名]

自[待补：入职日期]入职以来，我负责公众号的日常推送。现将试用期三个月的工作总结如下。

一、主要成果。三个月共发布推文 36 篇，其中 20 篇由我独立完成选题和写作，16 篇由我负责改稿和排版；1 篇阅读量过万。同期公众号关注人数由约 1.2 万增至约 1.5 万，其中包含两次线下活动带来的增长（数据出处：公众号后台）。另外，我负责了这两次线下活动的预告推文。我整理的选题表，从第二个月起在部门日常选题中使用。主管对我的选题思路给予了肯定。

二、工作方法。选题统一登记在选题表里，分选题、目标读者、预计发布日期、负责人四栏，每周一例会上集中过一遍，避免选题撞车和临时断更[待确认：「避免撞车和断更」是助手概括的作用，是否属实]；排版方面，我整理了一份排版检查清单，每篇发布前逐项核对。

三、不足。主管指出我的排版返工较多，主要原因是字号、行距没有统一，图片尺寸不一致。使用检查清单后，最近一个月返工从每周两三次降到一次左右，但还没有完全避免。

四、下一步计划。一是继续用检查清单，把排版返工降到[待确认：目标，如每月不超过两次]；二是学习数据分析，从[待确认：月份]起每月出一份推送数据复盘。

以上是我试用期的工作总结，请领导审阅。
```

- 核对单：36 篇及 20／16 的分工、阅读量过万、关注人数约 1.2 万到约 1.5 万（公众号后台；活动带来的增长无法拆分，正文照实写「包含」）；两次活动推文、选题表的栏目与用法、第二个月起使用、主管的评价、返工原因与次数变化、每月数据复盘的计划（均为用户所述）。
- 待补：部门、姓名、入职日期。待确认：选题表作用的概括、返工目标、复盘开始的月份。
- 字数：正文约 500 字（不含标题、署名和空白，含标点和占位符）；删去 [待确认] 标记、补上入职日期后约 460 字，在 500 字档 ±10% 以内。

## 常见问题（FAQ）

**Q：没什么成绩，写什么？**
A：成绩不一定是奖项。把「做完的事＋看得见的变化」列出来：某科从多少分到多少分、作业按时交了、接手了什么工作。实在没有变化，就把方法和计划写实。

**Q：数据记不清怎么办？**
A：先查出处：成绩单、后台、周报、工单系统。查不到就写「约」并说明怎么估的，或者干脆不写数字，不要编。

**Q：不足要写多少？会不会影响评价？**
A：2–3 条，约占全文 10–15%。写真实、具体、已经在改的，配上措施，比「有时不够细心」这类空话更显得可靠。

**Q：团队做的成果能写吗？**
A：能，但要写清你的角色，比如「项目由三人完成，我负责其中的……」。

**Q：个人总结和心得体会有什么区别？**
A：总结写一段时间里做了什么、做得怎样；心得写一次活动带来的触动和改变，后者用「心得体会」技能。

**Q：和「公文写作」怎么分？**
A：以单位或部门名义上报的总结是公文，用「公文写作」；以个人名义交给老师或上级的，用本技能。

**Q：能直接套用去年的总结吗？**
A：结构可以沿用，事实和数据必须换成这一期的。照抄去年的「不足」，等于告诉读者一年没改。

**Q：能帮我直接交上去吗？**
A：不能，本技能只写文本，提交由你自己完成。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 按时间顺序记流水账 | 读者找不到重点，做了什么和做成了什么混在一起 | 按主题归并，结论放段首 |
| 只写做了什么，不写结果 | 看不出成效 | 每件重点补上结果和数据 |
| 数据没有出处，或往大了写 | 一核对就失信 | 只写有出处的；估算的注明怎么估 |
| 把团队成果写成个人的 | 失信，也伤同事 | 写清「我负责……」 |
| 不足写成变相夸自己（「太追求完美」），或写空话 | 读者一眼看穿，显得不真诚 | 写真实、具体、有原因的，并配措施 |
| 不足写满半篇 | 像检讨书，成果被淹没 | 控制在 10–15%，目标没完成时不超过 25% |
| 计划写「继续努力」「再接再厉」 | 无法检查 | 写做什么、什么时候、怎样算做到 |
| 通篇感谢领导、感谢同事 | 占篇幅，没有信息 | 结尾一句致谢即可 |

## 边界与不做什么

- 不编造、不夸大数据、成绩、奖项和评价；不把他人成果算到用户名下。
- 不写以单位名义上报的公文（转「公文写作」）。
- 不评价用户的绩效，不判断能否转正；涉及试用期不通过、调岗、解除劳动合同等劳动问题，建议咨询人事、工会、当地劳动保障部门或律师。
- 写到同学、同事时，只写与本人工作相关的必要信息，不写他人的成绩、隐私和负面评价。
- 不替用户提交。
