# 主持词

定位一句话：**主持词不是文章，是念给耳朵听的时间表——每一段都要说清多长、讲完谁上场、出了意外怎么接。**

**急用入口**：现场冷场或超时，直接跳到「冷场与超时的应对话术」；只要填空模板，看 [references/fill-in-template.md](references/fill-in-template.md)；要看一份完整的年会双主持稿，看 [examples/annual-party-dual-host.md](examples/annual-party-dual-host.md)；写完用 `scripts/host_timer.py` 分段计时。

## 何时使用

年会、婚礼、发布会、班会、颁奖典礼、线上会议要写主持稿或串词，或者要把一张流程单变成能直接念的稿子时。用户常这样说：

- 「公司年会我当主持，帮我写开场白和节目串词」
- 「表姐婚礼让我主持，稿子写多少字合适」
- 「这是流程单，帮我把它变成能直接念的主持稿」
- 「颁奖典礼的报幕和颁奖词怎么写」
- 「线上分享会老冷场，嘉宾还总超时，主持人该怎么接」
- 「明天班会我主持，开场白怎么说」

怎么判断该用本技能：需求里有「主持、串词、串场、报幕、开场白、主持稿」，而且念稿的人是主持人。对话里直接提需求即可，附上流程单最好；只要其中一段（只要开场白、只要冷场话术）也行，交付时只给那一段，格式不变。

不适用：

- 领导致辞、个人演讲、婚礼誓词、年终总结发言：念稿的人不是主持人，转交致辞或演讲稿类技能；主持词里只写「有请……致辞」和致辞后的串场。
- 活动策划、预算、场地布置、安全疏散、舞台音视频：找活动执行方和场地方，本技能不做。
- 只问一个小问题（如「串词一般多少字」）：直接按下面的时长换算表简答，不必走完整流程。

## 先判断：先问三样，其余先用默认值

第一轮只问这三样，缺哪样问哪样：

| 先问 | 为什么、要到什么程度 |
|---|---|
| 流程单 | 每个环节谁上、做什么、几分钟、要什么（音乐、PPT、话筒、奖品）；没有就先按活动类型列一张给用户确认 |
| 名单 | 嘉宾姓名、职务、介绍顺序、赞助商全称，以主办方书面确认为准；生僻字标拼音 |
| 时长 | 活动总时长和主持人自己说话的时间分开算，主持词只占其中一小段 |

这两样先按默认值写，在交付物开头标 [待确认]，用户改了再调：

| 可后补 | 默认值 | 为什么、要到什么程度 |
|---|---|---|
| 基调 | 按活动类型取下方六类活动表里的基调 | 喜庆、温情、庄重、专业、轻松，定一个，全场统一 |
| 人数 | 单主持 | 单主持还是双主持；双主持每句标 A 或 B，轮流说，别一人念一大段 |

## 时长换算：每分钟约 220 字

| 段落 | 建议时长 | 字数（按每分钟 220 字） |
|---|---|---|
| 开场白 | 1–2 分钟 | 220–440 字 |
| 每次串场 | 20–40 秒 | 70–150 字 |
| 互动说明 | 30–60 秒 | 110–220 字（互动本身另算） |
| 收尾 | 约 1 分钟 | 约 220 字 |
| 备用段落 | 每段约 30 秒 | 约 110 字，备 2–3 段 |

220 字是正常语速的估算；庄重场合、掌声多的环节会更慢，最后以主持人自己掐表试读一遍为准。稿子存成 script.txt，每段用【开场 · 约 1 分钟】这样的标题开头，一条命令分段计时：

```bash
python3 scripts/host_timer.py script.txt --total 8:00
```

它按段落标题里写的时长逐段对照，列出超时的段、两个停顿之间超过 20 字的长句、「下面有请下一个节目」这类空串词和没替换的方括号占位；庄重场合加 `--rate 200`。

## 四段结构与六类活动要点

- **开场白**：问候 → 点题（活动名称与目的）→ 介绍嘉宾（按确认顺序）→ 宣布开始。
- **串场**：承上（对上一环节说一句具体的话）→ 启下（下一环节的看点）→ 请人（身份在前、姓名在后，名字落在句尾，给掌声留出口）。
- **互动**：一句话讲规则 → 主持人先示范 → 说明限时 → 备好没人响应时的台阶。
- **收尾**：一句回顾 → 按名单致谢 → 后续事项（合影、用餐、离场路线、资料领取）→ 宣布结束。

| 类型 | 基调 | 开场要点 | 串场与互动要点 | 收尾要点 |
|---|---|---|---|---|
| 年会 | 热闹、感谢 | 一句回顾全年，感谢全体同事 | 串词点出部门和人名；抽奖规则念两遍 | 祝福，合影或散场指引 |
| 婚礼 | 温情、庄重 | 介绍新人，感谢双方父母与来宾 | 仪式环节放慢；互动不拿新人隐私、酒量开玩笑 | 请新人敬酒，宣布开席 |
| 发布会 | 专业、简洁 | 发布主题、流程与总时长 | 嘉宾按「职务＋姓名」介绍；问答先报单位和姓名，一人一问 | 资料领取与采访安排 |
| 班会 | 亲切、有主题 | 主题由来，今天要解决什么 | 发言按顺序、计时，让每组都有机会 | 总结结论，布置任务 |
| 颁奖 | 庄重、有仪式感 | 奖项设置一句话 | 奖项 → 评选理由 → 停顿 → 获奖者 → 颁奖嘉宾 | 全体合影，感谢评委 |
| 线上会议 | 清晰、节奏快 | 确认声音画面，讲静音规则、提问方式、是否录制 | 点名发言，聊天区收问题；每个议题结束说一句小结 | 行动项与负责人，会后材料去哪看 |

三句示范，照着这个颗粒度写：

```
【年会串场】刚才市场部的合唱把全场都唱热了。下一个节目来自一群平时只和代码打交道的人——有请技术部带来舞蹈[节目名]！
（空串词对照：「感谢精彩表演，下面有请下一个节目。」——没承上、没看点、没人名）
【颁奖宣读】获得[年度新人奖]的是——（停两秒）——[市场部小王]！有请[颁奖嘉宾]上台颁奖。
【线上会议开场】各位好，我是主持人[小王]。先确认两件事：听得到我声音的请在聊天区扣 1；除发言人外请保持静音。本次会议会录制，共[60]分钟，最后[10]分钟集中问答。
```

## 冷场与超时的应对话术

| 情况 | 现场怎么接（方括号处替换） |
|---|---|
| 互动没人响应 | 「看来大家都在等第一位勇士——[事先打过招呼的同事]，就请您先来！」 |
| 设备出故障 | 「技术同事正在调试，趁这一两分钟，我先考大家一个小问题：[备用问答]。」 |
| 嘉宾没到位 | 「[嘉宾]正在赶来，我们先把[下一环节]提前。」再念一段备用段落 |
| 念错名字 | 立即更正一次，不解释、不开玩笑：「更正一下，是[正确姓名]，抱歉。」 |
| 发言人超时 | 事先约好举牌「还剩 2 分钟」「请收尾」；仍不停就接话：「感谢[李总]的精彩分享，时间关系，更多问题我们会后再交流。」 |
| 整体超时 | 先删主持人自己的串词和可选互动，不压缩颁奖、仪式这类核心环节 |
| 时间富余 | 启用备用互动或备用段落，不临场即兴拖长 |

## 可直接填空的模板

双主持的开场、串场、互动、收尾、备用段落五段填空模板见 [references/fill-in-template.md](references/fill-in-template.md)，每段标题已写好时长，可以直接交给 `scripts/host_timer.py` 计时。单主持时去掉 A、B 标记，合并成一人口吻。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话（模板） |
|---|---|---|
| 没有流程单 | 降级：按活动类型先列一张默认流程单（环节、上场人、时长、物料），时长标 [待确认]，用户改完再写词 | 「你还没给流程单，我先按常见年会流程列了一张，时长都标了 [待确认]；你改完我按它写词。」 |
| 缺名单（嘉宾、获奖者、赞助商） | 先写词，姓名职务一律 [ ] 占位；生僻字请用户标拼音；不编任何名字和职务 | 「名单以主办方书面确认为准，我先用 [职务＋姓名] 占位，拿到名单逐字替换。」 |
| 基调、主持人数没说 | 基调按活动类型默认，人数按单主持，都标 [待确认] | 「我先按单主持、热闹喜庆的基调写；要双主持告诉我，我把每句拆成 A、B。」 |
| 时长对不上（节目加起来超过总时长，或要求 5 分钟开场白） | 指出差多少，给两个方案让用户选：删主持词和可选互动，或调整流程 | 「流程加起来比总时长多 20 分钟：方案一删第二轮互动和两段串词；方案二把颁奖挪到用餐时段。选哪个？」 |
| 信息自相矛盾（名单上的职务和口头说的不同、顺序不同） | 指出矛盾，列两种理解，以主办方书面确认为准 | 「名单里[姓名]是副总经理，你刚才说是总监——按哪个？念错职务比念错名字还尴尬。」 |
| 超出本技能范围（致辞稿、誓词、策划执行、安全疏散） | 致辞、誓词转交致辞或演讲稿类技能；策划执行找活动执行方和场地方 | 「领导致辞不是主持词，建议用致辞类技能写；主持词里我只写请他上台和致辞后的串场。」 |
| 时间紧，只要最小可用版 | 最小版：开场（约 1 分钟）＋每个环节一句串词（身份＋姓名＋一句看点）＋收尾（约 1 分钟）＋两句冷场兜底 | 「来不及就先用最小版：开场、每环节一句串词、收尾和两句冷场兜底，今晚能用；备用段落回头再补。」 |
| 用户坚持越界（拿隐私、身材、地域开玩笑；编获奖名单或领导讲话） | 不写，说明风险，给同样能热场的替代 | 「拿身材和隐私开玩笑，当事人和长辈都可能下不来台，我不写；换成新人自己同意公开的相识故事，一样热场。」 |
| 回复太长被截断或中途断了 | 按流程顺序分段交付，每段有固定标题；用户说「继续」就从下一个环节接着写，不从头重写 | 「上一条写到颁奖环节。回复『继续』，我从抽奖第一轮接着写。」 |

计时脚本的退出码与报错：

| 退出码 / 报错 | 原因 | 修正办法 |
|---|---|---|
| 0 | 体检完成，没有超时 | 照「需要处理」逐条改长句和空串词 |
| 1「语速……不合常理」「时长……看不懂」「总时长必须……」「参数有误」 | `--rate` 不在 120–360，`--total` 为空、非正数、非有限值、溢出或写法认不出，或缺文件参数 | 语速先掐表试读；总时长必须大于 0，写成 8:00、480 或 八分钟 |
| 1「没有要念的正文」 | 稿子里只有标题、占位或舞台提示 | 先写出要念的句子 |
| 2「找不到文件」「不是纯文本」「编码认不出来」 | 路径不对、传了 .docx，或编码不是 UTF-8/GBK | 核对路径；另存为 UTF-8 的 .txt |
| 3 | 有段落超出标题里写的时长，或全稿超出 `--total` | 按提示字数删；先删主持人自己的串词，不压缩核心环节 |
| 130 | 按了 Ctrl+C | 重新运行即可，脚本不改任何文件 |

## 输出契约

先要流程单和名单；没有流程单就先按活动类型列一张给用户确认，再写词。姓名、职务、奖项、赞助商一律用 [ ] 占位或照用户给的原文，不编。

交付物按固定顺序（用户只要其中一段时只给那一段，标题格式不变）：

```
0 已知与假设    活动类型、总时长、主持人数、基调、名单状态；默认值标 [待确认]
1 流程单        用户给的；或按活动类型列的默认版，时长标 [待确认]
2 主持词正文    按流程顺序，每段标题写「段落名 · 预计时长 ≈ 字数」，双主持每句标 A/B
3 备用段落      2–3 段，每段标时长
4 话术卡        冷场与超时话术，可打印成手卡
5 自检结果      下面六条逐条写「是/否」
```

占位符：`[职务＋姓名]`、`[节目名]` 这类写明要填什么的方括号 = 待补信息，按主办方名单逐字替换；`[待确认]` = 按默认值假设的内容（时长、人数、基调）。不用「某某」「XX」这类看不出要补什么的占位。

交付前自检（逐条判断是/否，有一条「否」就改完再交）：

1. 两个停顿之间都不超过 20 字，一口气念得完（`scripts/host_timer.py` 不再列出长句）？
2. 嘉宾姓名、职务与名单逐字一致；没拿到名单的都是 [ ] 占位？
3. 每段都标了时长与字数，且没有超出标注（脚本退出码为 0）？
4. 串词没有「下面有请下一个节目」这种空话，都有承上、看点、人名？
5. 玩笑没有拿人开涮，互动不整蛊？
6. 冷场与超时话术卡已附上？

## 示例

（示例）线上分享会冷场、嘉宾超时——

**用户**：线上分享会老冷场，嘉宾还总超时，主持人该怎么接？

**助手先问**：会议一共多长？几位嘉宾、各讲多久？大家用什么方式提问？

**用户**：60 分钟，两位嘉宾各讲 20 分钟，最后 15 分钟问答，在聊天区提问。

**助手交付**：

```
【开场 · 约 30 秒 ≈ 110 字】
各位好，我是今天的主持人[姓名]。先确认两件事：听得到我声音的，请在聊天区扣 1；
除发言嘉宾外，请大家保持静音。
今天一共 60 分钟：[嘉宾一的职务＋姓名]和[嘉宾二的职务＋姓名]各分享 20 分钟，
最后 15 分钟集中问答。本次会议[会/不会]录制[待确认]。
有问题随时打在聊天区，我会在问答环节按顺序念出来。
首先，有请[嘉宾一的职务＋姓名]。

【超时提醒 · 会前和两位嘉宾约好】
还剩 5 分钟：聊天区私信「还有 5 分钟」
还剩 1 分钟：私信「请收尾」
超时 2 分钟仍未停：开麦接话「感谢[嘉宾姓名]的精彩分享，时间关系，更多问题我们放到问答环节。」

【问答冷场 · 两句兜底】
「大家整理问题的时候，我先替大家问一个：[会前准备好的问题]。」
「刚才聊天区有同事提到[关键词]，[嘉宾姓名]能不能再展开说一句？」
会前请一位同事准备好第一个问题，冷场时先由他开口。
```

完整的年会双主持稿（流程单 → 澄清 → 全部主持词 → 话术卡 → 计时结果 → 自检）见 [examples/annual-party-dual-host.md](examples/annual-party-dual-host.md)。

## 常见问题（FAQ）

**Q：主持稿写多少字合适？**
A：按每分钟约 220 字换算：开场 1–2 分钟约 220–440 字，每次串场 20–40 秒约 70–150 字，收尾约 1 分钟 220 字。最后以主持人掐表试读为准。

**Q：名单还没定，能先写吗？**
A：能。姓名职务用 [ ] 占位，拿到主办方书面名单再逐字替换，生僻字标拼音；替换后再跑一次计时脚本。

**Q：双主持怎么分词？**
A：每句标 A 或 B，轮流说，一人一两句，别让一个人念一大段；宣布开始、宣布结束可以两人合说。

**Q：活动超时了，先删什么？**
A：先删主持人自己的串词和可选互动，不压缩颁奖、仪式这类核心环节；时间富余就启用备用段落，不临场即兴拖长。

**Q：婚礼上能开新人的玩笑吗？**
A：可以讲新人自己同意公开的相识故事；不拿隐私、酒量、身材开玩笑，互动不整蛊。流程和地方习俗以双方家庭和婚庆团队的安排为准。

**Q：领导致辞稿能一起写吗？**
A：致辞不是主持词，交给致辞或演讲稿类技能；主持词里只写请领导上台和致辞后的串场。

**Q：线上会议的主持和线下有什么不同？**
A：开场先确认声音画面、静音规则、提问方式和是否录制；发言要点名，问题从聊天区收，每个议题结束说一句小结，收尾讲清行动项和会后材料去哪看。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 串词写成「感谢精彩表演，下面有请下一个节目」 | 没承上、没看点、没人名，台下听完没印象 | 承上一句具体的话，启下一句看点，身份在前、姓名在后 |
| 名字放在句首 | 掌声没有出口，气氛接不上 | 名字落在句尾：「有请技术部，带来舞蹈[节目名]！」 |
| 一句话写到三四十字 | 念到一半换气，台下听不清 | 两个停顿之间不超过 20 字，长句拆开 |
| 双主持一人念一大段 | 另一位干站，节奏拖沓 | 每句标 A/B，轮流说 |
| 凭记忆写嘉宾姓名、职务 | 念错最伤人，场面难收 | 照主办方书面名单逐字写，生僻字标拼音 |
| 念错名字后解释、开玩笑 | 越描越尴尬 | 立即更正一次：「更正一下，是[正确姓名]，抱歉。」 |
| 超时就压缩颁奖、仪式 | 核心环节缩水，当事人失望 | 先删主持人自己的串词和可选互动 |
| 时间富余就临场即兴 | 容易说错话、冷场 | 启用备用段落或备用互动 |
| 拿隐私、身材、地域开玩笑，设计整蛊互动 | 当事人下不来台，场面失控 | 集体互动，给没人响应时留台阶 |

## 边界与不做什么

- 不编造嘉宾信息、获奖名单、领导讲话内容和数据。
- 不写低俗段子，不拿隐私、身材、地域、宗教或政治话题开玩笑，也不设计整蛊式互动。
- 发布会里涉及产品参数、价格、功效和合规表述的句子，以主办方法务或公关审定稿为准。
- 大型活动的安全、应急疏散、舞台与音视频技术，不在本技能范围，找活动执行方和场地方。
- 婚礼流程与地方习俗，以双方家庭和婚庆团队的安排为准。
