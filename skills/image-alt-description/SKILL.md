# 图片描述

定位一句话：**先弄清这张图在页面里替读者做什么，再动笔；同一张图放在不同位置，描述可以完全不同。**

## 何时使用

用户这样说时用：

- 「帮我写个 alt，这张是小王在白板前给团队讲排期的照片」
- 「这张图怎么描述？藏青色开衫的主图，上架要用」
- 「给图表配段文字说明：2026 年 1–6 月月销售额折线图」
- 「这张图要发社媒，帮我配句话」
- 「网页上这几个图标按钮的 alt 怎么写」「这张图只是装饰，还要写 alt 吗」

也就是：给网页、App、文档、公众号里的图写替代文本（alt）；给商品图写描述；给社媒上的图配文；把一张数据图表讲成文字，给看不到图或没空看图的人。

怎么给我图（只有第一项必填，其余缺了我先问「放在哪、给谁看」，再按默认值写并标 [待确认]）：

```text
图片：直接上传 / 图片链接 / 用文字描述画面（看不到原图时按文字描述写，交付里注明「未见原图」）
放在哪：网页正文 / 按钮或链接 / 商品详情页 / 社媒帖子 / 文档或报告
用途：无障碍 alt / 商品描述 / 社媒配文 / 图表文字化
上下文：图旁边的文字或页面主题；商品资料（颜色、面料、尺码）；图表的原始数据
```

交互顺序：判断类型 → 缺信息就问（一次最多两个问题）→ 按用途套模板 → 数字符 → 按输出契约交付。

不适用：

- 从长相认人，或推断年龄、种族、健康等敏感属性：不做；身份从图注或用户给的资料里取。
- 医学影像、化验单、伤情照片的解读：只描述画面，解读请找医生。
- 整站无障碍合规评估（逐条对照 WCAG）：请找专业无障碍测评人员；生成或修改图片也不在本技能范围。

## 先判断：这张图在干什么

```
装饰（分隔花纹、氛围背景、与旁边文字重复的配图）  alt=""，读屏软件直接跳过；alt 属性本身不能省，缺了有的读屏会念文件名
功能（图标按钮、图片链接）                        写动作或去向：放大镜图标写「搜索」，不写「放大镜」
信息（照片、示意图、截图）                        写这张图在这里要传达的那一件事
图中有字（海报、横幅、截图里的报错）              把字原样写出来，字就是信息
复杂图（图表、流程图、地图）                      alt 只说「是什么 + 结论」，完整数据放正文或图下表格
商品图、社媒配图                                  alt 之外还要一段写给人看的文字，见下文「四种用途」
```
判断不出时问一句：**把这张图删掉，这一页少了什么？** 少的那部分就是要写的内容；什么都没少，就是装饰图。

同一张照片（李老师站在报告厅讲台前）放三个地方，三种写法：

```
校庆新闻稿      李老师在校庆典礼上致辞，台下坐满校友          ← 读者要知道谁、在什么场合
报告厅预约页    报告厅内景：讲台正对约 200 个阶梯座位，两侧各一块投影幕  ← 读者要判断场地够不够用
博客页眉装饰    alt=""                                        ← 删掉它，这一页什么都没少
```
一组图（商品多图、活动九宫格）：第一张写总述，其余只写和前一张不同的地方，别每张重复一遍品名。

## 写作流程：四步

```
1 定读者与位置  读屏用户、买家还是粉丝；写进 alt、详情页还是正文
2 抓主体        一句话：谁或什么 + 在做什么 / 处于什么状态，主体放句首
3 挑细节        只留和上下文有关的：新闻稿写人物与事件，服装页写颜色版型，教程截图写要点的那个按钮
4 压缩与自检    删掉「图片显示」「这是一张……的照片」——读屏软件本来就会报出这是图像；alt 不超过 125 字符
```
字数与重复自查（中英文都按字符计；存成 altcheck.py 用 `python3 altcheck.py` 运行，或在 IDLE 里按 F5）：

```python
alts = [
    "小王在白板前给团队讲解调整后的项目排期",  # 一组图就逐条往下加
]
for i, alt in enumerate(alts, 1):
    note = "超长，挪进正文" if len(alt) > 125 else "OK"
    if alt in alts[:i - 1]:
        note += "；和前面某条重复"
    print(i, len(alt), note, alt)
```
125 是业内常用的经验上限，WCAG 本身不规定字数。超了说明你在写长描述：alt 留一句，其余挪进正文、图注或表格。

## 四种用途：模板与反例

| 用途 | 一句话模板 | 要点 |
|---|---|---|
| 无障碍 alt | [主体] + [动作或状态] + [与上下文相关的一个细节] | 不堆关键词，不写「图片显示」 |
| 电商商品图 | alt：[品类] + [看得见的区分点] + [视角或场景]；详情描述补图上看不出的 | 成分、尺码从商品资料取，不从图里猜；同款多色每张写颜色 |
| 社媒配文 | 图里看不到的背景 → 一句感受或观点 → 需要时一个互动问题 → 2–4 个话题标签 | 配文代替不了 alt，平台有替代文字栏就另写一句 |
| 数据图表 | [图表类型]：[主题]，[时间范围与单位]。[一句总体趋势]。[2–3 个关键数字]。完整数据见下表。 | 不替数据加因果；复杂图另写长描述：总述、读法、走势、数据表 |

每种用途的正例与反例、复杂图表长描述的写法、写进 HTML 的格式，见 [references/templates-by-use.md](references/templates-by-use.md)。

## 信息不全或出错时

| 情况 | 怎么处理 | 对用户说的话 |
|---|---|---|
| 没给图，也没描述（只说「帮我写个 alt」） | 请用户上传图片或用一两句话描述画面，同时问放在哪 | 「请把图发我，或者用一句话说说画面里有什么；这张图放在哪一页？」 |
| 描述太模糊（「一张开会的图」），或图看不清、链接打不开 | 按能确认的部分写，其余标 [待确认]，注明「未见原图」或「图片无法打开」；只追问最关键的一个细节 | 「我只能确认是会议场景；谁在讲、讲什么，你补一句，不然 alt 只能写得很泛。」 |
| 判断不出类型（装饰还是信息） | 用「删掉它，这一页少了什么」检验；仍拿不准，两种写法都给，请用户按页面选 | 「删掉这张图，这一页会少什么？什么都不少就是装饰图，alt 留空。」 |
| 要求和图的作用矛盾（装饰图却要一段长描述；图标按钮要写外观） | 指出矛盾，给两种理解让用户选 | 「这是页眉装饰，alt 应该留空；如果你想让读者知道图里的内容，那它就是信息图，我按信息图写。」 |
| 超出范围（认出图里是谁、推断年龄种族健康；解读医学影像；整站 WCAG 评估） | 不做；身份从图注或用户资料取；影像找医生；合规评估找专业测评人员 | 「我不从长相判断身份。如果你知道他是谁，告诉我，我写进去。」 |
| 时间紧，只要最小可用版 | 最小版 = 类型判断一句 + 一条 alt（带字符数）；备选和长描述之后补 | 「先给一条能直接用的 alt，备选和图下说明稍后补。」 |
| 用户坚持越界（写图上看不出的成分、功效，把合成图写成「实拍」，从外貌判断身份） | 守住边界，给能做的替代 | 「图上看不出是纯羊毛：商品资料写明了，我就照资料写；没写就不能写。」 |
| 用户说写得不对 | 先问是哪一步不对（类型判断、主体还是细节），只改那一步，其余不动 | 「是类型判断不对，还是主体或细节选得不对？我只改那一部分。」 |

## 输出契约

交付物按这个顺序，用不上的部分写「不适用」，缺的写 [待补]：

1. **依据**：已见原图 / 未见原图，按文字描述 / 图片无法打开，按文字描述。
2. **类型判断**：装饰、功能、信息、图中有字、复杂图中的哪一类，附一句理由。
3. **主推 alt**：一条，标出字符数；装饰图写 `alt=""` 并说明理由。
4. **备选 alt**：一条，标出字符数；装饰图写「不适用」。
5. **按用途的正文**：商品详情描述、社媒配文、图表长描述与数据表，各按模板给完整一段。
6. **待确认清单**：正文里所有 [待确认]、[待补]。

占位符：[待确认] = 图上看不清或无法确认的内容（看不清的字、人物身份与属性、要对原始数据的数字），一律标出、不猜；[待补] = 需要用户提供的资料（商品成分、尺码表、原始数据、人物姓名）。

交付前自检（逐条答是或否）：

- [ ] alt 没有「图片显示」「这是一张……的照片」这类开头？
- [ ] 每条 alt 都不超过 125 字符，而且是用上面的片段数的（装饰图 `alt=""` 除外）？
- [ ] 功能图写的是动作或去向，不是外观？
- [ ] 没写图上看不出来的东西（身份、成分、功效、因果）？
- [ ] 图表里的每个数字都对得上原始数据，或标了 [待确认]？
- [ ] 同一组图的 alt 没有重复？

## 示例

**示例**（人物与场景为虚构）

用户：「帮我写个 alt，这张是小王在白板前给团队讲排期的照片。」

助手：「这张图放在哪一页，旁边写的是什么？」

用户：「项目周报里『本周进展』那一节，旁边写的是排期调整。」

交付：

> **依据**：未见原图，按文字描述写。
>
> **类型判断**：信息图——它说明本周开过排期会；删掉它，这一节就少了一个现场信息。
>
> **主推 alt**（19 字符）：小王在白板前给团队讲解调整后的项目排期
>
> **备选 alt**（15 字符）：项目排期会上，小王在白板前讲解
>
> **按用途的正文**：不适用（周报只需要 alt）。
>
> **待确认清单**：白板上如果写着具体日期或里程碑，把最关键的一项加进 alt [待确认]；在场有几人、在做什么，看图后再补 [待补]。

商品主图（含详情描述）和数据图表（含长描述与数据表）的完整示例见 [examples/product-and-chart.md](examples/product-and-chart.md)。

## 常见问题（FAQ）

**Q：这张图该用哪个模板？**
A：先按「先判断」一节定类型，再看上面「四种用途」表里的一句话模板；正反例都在 [references/templates-by-use.md](references/templates-by-use.md)。

**Q：为什么不能写「图片显示」「这是一张照片」？**
A：读屏软件本来就会报出这是图像，再写一遍只是浪费读屏时间。

**Q：alt 超过 125 字符怎么办？**
A：alt 留一句最重要的，其余挪进正文、图注或图下表格。125 是经验上限，WCAG 本身不规定字数。

**Q：装饰图真的什么都不写吗？**
A：写 `alt=""`：属性要保留、内容留空，读屏软件才会跳过；整个属性省掉的话，有的读屏会念文件名。

**Q：能帮我认出图里是谁吗？**
A：不从长相判断身份。你知道是谁就告诉我，或者从图注里取，我写进去。

**Q：社媒配文能代替 alt 吗？**
A：不能。配文写给看得见图的人，alt 写给看不见的人；平台有替代文字栏就另写一句。

**Q：英文页面也能写吗？**
A：能，规则一样；字数同样按字符数。

## 常见错误（反模式）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 装饰图写了 alt，信息图 alt 却为空 | 前者浪费读屏时间，后者让人错过信息 | 先用「删掉它少了什么」判断类型，装饰图 `alt=""`，信息图写那一件事 |
| 拿文件名当 alt：`IMG_2031.jpg`、`banner-final-v3` | 会被原样念出来 | 写画面要传达的内容 |
| 图标按钮写外观（「齿轮」） | 读屏用户要知道的是它能做什么 | 写功能（「设置」） |
| 同一页相邻几张图用同一句 alt | 读屏用户分不清这几张图的区别 | 第一张写总述，其余只写不同之处；用自查片段查重复 |
| 猜看不出来的东西：人物身份、年龄、民族、健康、情绪的原因 | 容易写错，还可能冒犯人 | 只写看得见的（「一位戴眼镜、穿灰色外套的讲者」）；身份从图注或用户资料取 |
| 图表 alt 把每个数据点念一遍 | 那是表格的活，读屏用户记不住 | alt 只写类型、趋势和 2–3 个关键数字，完整数据放表格 |
| 堆关键词、写营销词（「绝美显瘦 百搭 ins 风」） | 读屏念出来是一串词，仍不知道图长什么样 | 按「品类 + 看得见的区分点 + 视角」写 |
| 替数据加因果（「由于 3 月促销，销售额大涨」） | 图里没有原因 | 只写方向和数字，原因交给正文里有依据的分析 |

## 边界与不做什么

- 不做人脸识别，不从长相推断身份、年龄、种族、健康状况等敏感属性。
- 不替商品编造功效、成分、认证；宣传用语是否合规（广告法、平台规则）请找法务或平台客服确认。
- 医学影像、化验单、伤情照片只描述画面，不做任何诊断解读，请找医生。
- 不写误导性描述：合成或修过的图不写成「实拍」，截图不编造上下文。
- 本技能写单张或一组图片的描述；整站无障碍合规评估（逐条对照 WCAG）请找专业无障碍测评人员。
