# 地址清洗规则（脚本 `clean` / `geocode` 共用）

目标：**让每条地址「从省市开始、到门牌或地标为止」，去掉一切不是地址的东西。** 清洗做得越好，请求次数越少、低可信越少。

## 规则与例子

| 顺序 | 规则 | 例子（清洗前 → 清洗后） |
|---|---|---|
| 1 | 全角转半角（数字、字母、括号、标点） | `福华三路１００号` → `福华三路100号`；`（…）` → `(…)` |
| 2 | 去掉「地址：」「收货地址:」等前缀 | `地址：上海市浦东新区…` → `上海市浦东新区…` |
| 3 | 括号里是备注就删 | `科苑路15号（近地铁站，放门口）` → `科苑路15号`；`【仓库收】` 删掉 |
| 4 | 括号里是地标就去括号保留文字 | `新安街道（宝安中心）` → `新安街道宝安中心`；`(金茂大厦)` → `金茂大厦` |
| 5 | 删手机号和带区号的座机 | `…100号 13800001234` → `…100号` |
| 6 | 去多余空格（中文前后的空格全部去掉） | `科苑路 15 号` → `科苑路15号` |
| 7 | 缺省市就补：优先用该行的城市列，其次用 `--region` | `南山区科技园…` + 城市列「深圳市」→ `深圳市南山区科技园…` |
| 8 | 地址里已有省或市就不补；和城市列矛盾时**不改写**，只在说明里标出 | `杭州市西湖区…` + 城市列「深圳市」→ 原样请求，并标「城市不一致」 |
| 9 | 清洗后为空的行不请求，状态记「未请求」 | 空单元格、只有电话的单元格 |

判断「备注还是地标」：括号内容以「近、靠近、旁、对面、附近、电话、联系、收件、放、送、请、备注、门口、快递、代收」开头，或含电话号码，按备注删；以「大厦、广场、中心、小区、花园、园区、公寓、大楼、商场、学校、医院、酒店、市场、写字楼、家园、苑」结尾，按地标保留；两者都不像，按备注删。

每一行做了什么，都写在输出的 `geo_clean_note` 列里，可逐条追溯。

## 已知局限（预演时重点看这几类）

- **只写城市简称、不带「市」**（如「广州南沙区」）且没有城市列：脚本认不出城市，会补上 `--region` 的城市。有城市列时不受影响。
- **县级市**（如某地级市下辖的县级市）：地址写县级市、城市列写地级市，会被标「城市不一致」，核对后可忽略。
- **同名道路**：很多城市都有「中山路」「解放路」。只要补全了城市就不会跑偏；城市列为空又没给 `--region` 的，说明里会标 [待确认]。
- **地址里混着姓名**：脚本不删姓名（容易误删地名）。姓名、电话请放在单独的列，别混进地址列。
- **楼栋、单元、房号**：保留原样。地理编码一般只精确到楼栋或门牌，房号不会让结果更准，但也不必手工删。

## 人工修正低可信行的办法

| 低可信原因（geo_note） | 常见根源 | 修正动作 |
|---|---|---|
| 可信度低于阈值 | 地址只到区县、街道，或有错别字 | 补门牌号或小区名，再单独跑这几行 |
| N 个不同地址落在同一点 | 这些地址都太笼统，被解析到区县或城市中心 | 回到原始订单补全详细地址 |
| 结果城市与城市列不一致 | 城市列填错，或同名道路解析到别的城市 | 确认真实城市后，改城市列或在地址前补城市 |
| 坐标不在中国大致范围内 | 地址是境外，或解析异常 | 人工核对，境外地址不适用本流程 |

修正后只需把这些行另存一个 CSV 再跑一次，带上同一个 `--cache`，已成功的地址不会重复请求。
