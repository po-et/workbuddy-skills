# 两份 Excel → 一页经营报告

这个完全离线的合成案例，将 excel-processing v0.1.1 和 report-making v0.1.1 的现有脚本串成一项可交付任务。输入、业务名称、异常和缺失均由演示生成；不是客户案例，也没有调用腾讯平台接口。已验证的是本地 Python 链路，WorkBuddy 客户端内的自动运行尚待单独验证。

~~~mermaid
flowchart LR
    A["两份 XLSX<br/>表头顺序不同"] --> B["按列名合并<br/>保留原件与来源行"]
    B --> C["Decimal 汇总<br/>缺失保留未知"]
    C --> D["CSV 体检<br/>固定规则筛查"]
    D --> E["一页报告<br/>结果、待查事项、校验"]
~~~

在仓库根目录运行；以下 /tmp 路径适用于 macOS/Linux，其他系统换成自己的新目录：

~~~bash
python3 examples/office-report/run_demo.py --out-dir /tmp/office-report-demo-001
~~~

随后打开输出目录的 report.md。--out-dir 必须尚不存在，即使现有目录为空也拒绝覆盖。重复运行换成 office-report-demo-002；失败时保留已生成的文件，以新目录重跑。

依赖是已有的 Python 3.8+ 和 openpyxl。脚本不联网、不安装依赖。实跑环境为 Python 3.12.12 / openpyxl 3.1.5；报告技能的两个脚本只用标准库。已有环境缺库时会明确失败，不会擅自修改环境。

WorkBuddy 中可复制这段任务说明，让它操作自己打开的本地仓库：

> 运行 examples/office-report/run_demo.py，给 --out-dir 一个新的本地目录，不要安装依赖或覆盖现有目录。成功后打开 report.md，并用 verification.json 核对原件哈希、来源行和汇总。明确说明它是合成演示；缺失指标保持“待取数”，原因写“待查”。

## 输入与预设现象

两份 XLSX 的“明细”表各有 36 行，分别为华东、华西；西部表的列顺序与东部表不同。每行是一个月/区域/渠道/批次的指标明细，包含订单数、退款订单数和销售额；不是逐笔订单账本。9 个月 × 2 区域 × 2 渠道 × 2 批次，共 72 行。

- 1–8 月保持平稳，为固定规则提供 8 期基线。
- 9 月华东/线上两批次销售额由 2,000.02 降至 800.02，约 -60%；原因待查。
- 9 月华西/线上批次 B 的销售额与退款数缺失。整组以及全月相关指标标为未知；不会拿已知部分冒充全量，也不会把缺失当成零触发下跌。

rules.json 在生成输入前就写出：环比变化绝对值 >20% 且金额变化 ≥500；或超出前 8 期均值 ±2 倍样本标准差且变化 ≥500。阈值不按结果调参。合成平稳基线只用于展示，不能据此推断真实经营的波动分布。

## 算法与验收

金额以两位小数文本存入 XLSX，解析为 Decimal 后汇总；输出既有全量值，也有单独注明的已知小计和缺失行数。只要组内有一条金额缺失，组销售额就为未知。退款率使用总退款订单数 ÷ 总订单数；退款数缺失或分母为零时为未知。空维度、重复业务键、非法/非有限金额、负数/小数计数以及退款数超过订单数都会被拒绝。

手工可核对的结果：

| 检查 | 预期 |
|---|---|
| 原件/合并/来源逐行匹配 | 72 / 72 / 72 |
| 区域×渠道×月份汇总 | 共 36 行；每月 4 组 |
| 已知金额原件、合并、分组、月份四路合计 | 312,050.89 |
| 8 月总退款率 | 12 ÷ 400 = 3.00%，不是四个渠道百分比的简单平均 5.875% |
| 9 月订单数 | 390 |
| 9 月全量销售额/退款率 | 待取数；销售额已知部分 32,050.09 |
| 异常标注 | 仅华东/线上 2026-09，环比约 -60% |
| 缺失组 | 华西/线上 2026-09 跳过金额计算，不标成下跌 |
| 原件 SHA256 | 运行前后相同 |

每个合并单元格的业务值均与来源文件/工作表/行号对应的原件比较。汇总校验失败或原件哈希改变就停止，不能输出成功结论。CSV 体检完成的退出码为 0，只代表体检已运行；本案例故意保留缺失，体检报告会列出需要处理的事项。

输出目录包含：

| 文件 | 用途 |
|---|---|
| inputs/east.xlsx、inputs/west.xlsx | 两份合成原件，附“说明”工作表 |
| merged.xlsx、details.csv | 对齐表头的明细与完整来源列 |
| summary.json、grouped.csv | 严格汇总、已知小计、缺失行数与规则输入 |
| rules.json | 事先固定的规则 |
| profile.txt、anomaly.txt、anomalies.csv | 原技能实际运行的体检与异常结果 |
| report.md | 从实际汇总推导期间、结论和行数的一页报告 |
| verification.json | 原件 SHA256、来源/汇总校验、步骤退出码、脚本 SHA256、环境与输出文件哈希 |

测试命令：

~~~bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_office_report_example.py -v
~~~

这套演示只生成自己的固定合成输入，不是企业数据导入系统。销售额是示例金额字段的合计，未处理税费、退款金额或跨月财务确认；退款数假定对应同月订单。缺失需人工补数，异常原因需人工调查。不同运行的 XLSX 文件时间元数据可能不同，哈希用于证明一次运行中原件不变，业务结果则可复现。
