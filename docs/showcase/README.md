# Captain 成果页

可直接静态部署的 `index.html`，无构建、无外部字体、无第三方脚本。唯一配套图片为公开的合成视频联系表，使用相对路径 `assets/video-contact-sheet.jpg`；部署时将此目录作为网站根目录。页面不收集输入、不联网运行技能，也不上传文件。

## 设计计划与复核

应用 `frontend-design` 的「计划→对照 brief→实现→自评」过程。

目标用户是第一次接触这些技能的 WorkBuddy 用户。主要任务是选一项具体交付，复制正确的安装命令与任务，再按公开样本核对结果。

颜色采用六个用途明确的 token：白纸 `#FFFFFF`（正文与工作区）、浅蓝台面 `#EEF5FB`（页面背景）、深蓝墨迹 `#12304A`（标题）、蓝 `#1763CF`（主操作）、青 `#067C7D`（通过与核对）、砖红 `#B74335`（真实差异）。红、青同时配文字与符号，不仅依赖颜色。

字体使用本机中文字体：PingFang SC / Microsoft YaHei / Noto Sans CJK SC；标题以较重字重和短行构成辨识度，正文适度加大行高。等宽字体仅用于命令、JSON 与字段名，避免把技术视觉散落到普通操作文案。

布局候选：

```text
A：三张并列技能介绍卡
   [接口] [Excel] [视频] → 用户需自行拼装安装、任务与验收

B：一个任务工作台（采用）
   [品牌与主张]            [旧响应 / 回归 / 修正对照]
   [任务选择竖栏]          [输入 → 交付 → 验收]
                            [复制安装] [复制任务]
                            [折叠样本与完整案例]
   [验收记录与当前证据边界] [具体反馈入口]
```

内容左对齐，桌面保留明确的任务选择栏，移动端改为一列的选择按钮与交付区。复制操作、错误回退、反馈入口保持同一组动词。

复核 brief 后舍弃方案 A：重复营销卡会把代表作再次变成目录。方案 B 以接口的字段对照为唯一主视觉，其他区域保持安静；选择任务后直接切换完整交付，避免额外弹窗与虚构在线执行。

## 可用性与检查

- 任务选择支持点击及方向键 / Home / End；每项完整内容独立标注。
- 命令自动换行，页面不要求横向滚动；样本表在自己的容器内滚动。
- 复制优先使用剪贴板 API，失败后尝试旧式复制；仍失败时显示可手动选择的文本与明确操作。
- 明显的键盘焦点、跳过导航、减少动态效果；图片有描述与尺寸。
- 普通导航仅链接 GitHub 主分支、完整 SkillHub namespace 和官方指引。所有技能动作都发生在用户的本机。
