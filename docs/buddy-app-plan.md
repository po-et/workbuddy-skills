# Buddy 应用：调研与建设方案（2026-09-16）

## 一句话结论

Buddy 应用是**配置出来的品牌工作台**，不是代码；个人开发者当前**不能创建**（后台弹窗原文见下）。
解锁路径是企业认证，个体工商户很可能走得通（待确认）。在解锁之前，把首个应用「研发效能 Buddy」的
全部配置内容做好（已完成，见 `buddy-apps/devops-buddy/`），认证一过就提交；第二阶段再用全栈能力
加一个自有后端连接器，把"配置"变成"产品"。

## 1. Buddy 应用到底是什么

来源：[开放平台文档《Buddy应用》](https://open.workbuddy.cn/docs/buddy-app)、
[客户端文档《Buddy 应用》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Buddy-App)、
官方设计规范包 `buddy-app.zip`。

- **形态**：终端用户在客户端首页左上角「应用入口」选择应用，进入一个独立的品牌工作台：自己的标题/slogan、
  2–4 个**工作模式**（每个模式一份 system prompt + 绑定的技能/专家/连接器，决定会话角色与工具组合）、
  一排**场景胶囊**（预置任务，点一下自动召唤绑定的专家并填入指令卡）、自己的**市场页**（精选场景卡片 + 专家/技能/连接器）。
- **制作方式**：后台网页表单，五个模块——应用身份（名称/头像/描述/OAuth 与可信来源）、首页配置、市场配置、
  其他（绑定鉴权、占位文案、模型选择与排序）、预览调试（导出配置 JSON、指定客户端版本预览）。
  官方原话：合作伙伴不是在做产品，是在做配置。
- **审核**：两段——创建审核 → 配置审核。
- **设计规范**：头像 256×256；工作模式图标 16×16、线宽 1.2px、有断口；精选场景底图 1000×910
  （底图 670px + 两层灰蒙层 + 全局蒙层，日 #F2F2F2/#FFFFFF、夜 #242424）。

## 2. 门槛：实测

2026-09-16 用个人认证账号在 `/buddy-app/all` 点「创建」，弹窗：

> 个人开发者无法创建Buddy应用，如需创建，请进行企业认证，成为企业开发者

按钮「去创建」通向企业认证（身份流程，未替用户点）。旁证：[官方 Q&A Q11] 与
[《手把手教你接入 WorkBuddy 开放平台》](https://news.qq.com/rain/a/20260902A0DOKE00)："个人认证的话，Buddy 应用和硬件无法使用"。

### 解锁路径（推荐：个体工商户）

| 步骤 | 内容 | 依据 / 状态 |
|---|---|---|
| ① 注册个体工商户 | 各地政务平台线上办，需经营者身份证、经营场所（多地允许住宅或集群注册） | 据公开信息推测，费用与时限以当地市场监管局为准 |
| ② 腾讯云企业实名 | 机构类型可选「个体工商户」，营业执照 + 经营者人脸/银行卡 | 腾讯云公开文档（2026-09-16 检索） |
| ③ WorkBuddy 企业认证 | 三条快速路径之一：腾讯云账号 / 微信公众号 / 企业法人实名 | [入驻指南](https://zhuanlan.zhihu.com/p/2078592838682648887)；**个体工商户主体是否被接受，待确认** |

一个账号可同时持有个人认证与企业认证（同上指南），已提交的 9 个资产不受影响。
备选：注册公司（成本高）、借用他人企业主体（资产归属风险，不建议）。
**需确认**：与雇主的兼职/竞业约定是否允许以个体户名义发布。

## 3. 现在平台上有什么应用（能复刻什么）

- **没有公开榜单**。后台「Buddy应用」列表只显示自己的应用；客户端应用入口在内测（欢迎页只是微信扫码加入名单）。
- **合作伙伴（首批 30+，公开点名 9 家）**：通达信、广发证券、北大法宝、帆软、北森、美图、腾讯健康、腾讯 SSV、微盟，
  覆盖金融/SaaS/法律/医疗/教育/公益/设计 20+ 领域（[网易](https://www.163.com/dy/article/L62UCLVL05319LDA.html)、
  [网易 2](https://www.163.com/dy/article/L5R4RE7L0550WHYR.html)、[腾讯新闻](https://news.qq.com/rain/a/20260903A06A9H00)）。
- **唯一可用的用量信号**：帆软 9 个专家上线一周调用过万；**平台调用量前三全是数据分析类**（同上报道）。
- **共同结构**：自有数据/服务（连接器）+ 领域专家 + 场景胶囊 —— 微盟公开的就是"模块 + 专家 + 场景"。

结论：伙伴应用的护城河是**数据**（行情、法规库、报表引擎），个人复刻不了数据，只能复刻**结构**。
所以"复刻热门应用"的正确姿势是：把已验证的结构套在我们有资产的领域上，而不是照抄某个应用。

## 4. 全栈工程师的真正优势在哪

配置谁都会做；表单里的 **OAuth 列表 / 回调地址 / 可信来源 / 绑定鉴权** 就是给"有自有后端的伙伴"用的。
全栈工程师能做而配置型开发者做不了的，是**一个自己运营的服务，通过 OAuth 连接器接进应用**——这才是从
"资产合集"到"产品"的分界线。三档难度：

| 档 | 做什么 | 工程量 | 护城河 |
|---|---|---|---|
| A 配置 | 把现有技能/专家/连接器组装成应用 | 0 代码 | 低，但是我们 9 个资产的分发渠道 |
| B 无状态连接器 | 调公开 API 的 MCP/CLI 连接器（OSV 漏洞库、GitHub Trending、HN） | 1–3 天/个 | 中 |
| C 自有服务 | 自己部署的后端 + OAuth + MCP server，有持久数据与跨仓库视角 | 2–4 周 | 高 |

## 5. 候选应用与排序

| 候选 | 复用现有资产 | 需求证据 | 新增工作 | 护城河 | 结论 |
|---|---|---|---|---|---|
| **研发效能 Buddy**（周报/上线/排查/方案画图） | 9/9 全部复用 | 周报与汇报类在各智能体平台长期是高频类目（据公开信息推测，无量化数据） | 0 代码，配置已做完 | 低→中（第二阶段接自有服务） | **首发** |
| 研发效能看板服务（DORA 四指标 + 团队趋势）作为 OAuth 连接器 | 加进上面的应用 | LinearB / Swarmia / Jellyfish 等商业化验证 | 2–4 周，Node 或 FastAPI + Postgres + MCP | 高 | **第二阶段** |
| 数据分析 Buddy（本地 CSV/SQLite/MySQL 分析 + 图表） | 只复用画图连接器 | 平台调用前三都是数据分析（帆软报道） | 1 个数据源连接器 + 2 个专家 | 低（官方内置数据分析 + 帆软在） | 观察；需要第二个应用时再做 |
| 开学季·计算机学生 Buddy（作业讲解/算法题/毕设/简历项目） | 部分复用 | 平台正在推学生（开学季积分活动） | 配置 + 2 个专家，1 天 | 低 | 机会型，认证后顺手做 |
| 开源维护者 Buddy（issue 分诊、PR 评审清单、release notes） | 复用 QA 专家 | GitHub 生态需求明确 | 1 个 GitHub 连接器 | 中 | 合并为首发应用的第 5 个模式，不单独做 |

## 6. 首发应用「研发效能 Buddy」设计

完整粘贴稿与机器可读配置在 `buddy-apps/devops-buddy/`（`app.md`、`config.json`、`assets/`），
校验：`python3 tools/check_buddy_app.py buddy-apps/devops-buddy`。要点：

- Slogan「代码之外的活，我来干」——延续「CodeBuddy 写代码，WorkBuddy 干剩下的」定位，但不在应用文案里提他人品牌。
- 4 个工作模式：迭代汇报 / 上线守门 / 线上排查 / 方案与画图，各自绑定对应技能与专家；system prompt 与专家包共用
  同一套输出契约（每条结论附来源、不下最终结论、红线段落）。
- 8 个场景胶囊，覆盖每个模式最常见的两个入口。
- 市场：3 张精选场景卡片（迭代与汇报 / 发布与质量 / 故障与稳定性），全部 9 个资产。
- 资源：头像、4 个模式图标、3 组日/夜底图均按官方规范自绘生成（无第三方素材）。

## 7. 第二阶段：研发效能看板（让应用有"数据"）

- **数据流**：GitHub/GitLab OAuth → 拉取 PR/Issue/CI/部署事件 → 计算 DORA 四指标（部署频率、变更前置时间、
  变更失败率、恢复时间）与评审时延 → 按团队/仓库/周持久化 → MCP server 暴露 `metrics.query`、`trend.compare`、
  `report.weekly` → 以连接器接入应用的「迭代汇报」模式。
- **技术栈建议**：TypeScript（Hono/Fastify）或 Python（FastAPI）+ Postgres；部署在腾讯云轻量或 EdgeOne（同一生态，
  也符合挑战赛口径）。凭证只走 OAuth token，绝不落用户代码。
- **商业化钩子**：免费 1 个仓库 / 付费多仓库与历史趋势——等平台分成规则落地前先靠这个自己收钱。
- 公开版永远只对接 GitHub/GitLab/Jira 等公开平台，不含任何公司内部系统。

## 8. 行动清单

**用户侧（我做不了）**
1. 决定是否注册个体工商户（步骤①）；同时确认雇主的兼职/竞业约定。
2. 完成腾讯云企业实名（步骤②）→ 在开放平台「去创建」走企业认证（步骤③）。
3. 认证结果回来告诉我，特别是"个体工商户是否被接受"。

**我方侧（已就绪）**
- 配置包完成并校验通过；企业认证通过当天可提交创建审核。
- 9 个资产过审后才能绑定进市场与模式（据文档推测，待实测）。
- 拿到官方导出 JSON 后，给 `config.json` 加官方字段映射，让 `check_buddy_app.py` 直接对导出文件校验。
- 认证等待期启动第二阶段的看板服务原型（不依赖认证）。

## 9. 诚实的边界

- "热门应用"没有公开数据，本文所有"高频/长青"判断都是据公开信息推测；唯一硬数据是帆软的调用量与"数据分析前三"。
- 个体工商户能否通过 WorkBuddy 企业认证、市场是否只能绑定已过审资产、表单字段长度限制、预览所需客户端版本——
  全部待实测，配置包按保守值准备。
- 配置型应用护城河低，别人可以照抄；真正的壁垒在第二阶段的自有服务。
