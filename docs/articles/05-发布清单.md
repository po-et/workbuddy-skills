**脚本 B（图2）** —— `updated_at` 的 2×2 对照，这是全文最关键的一张图：

```bash
cd /Users/limit/AI/My-Research/workbuddy-skills
python3 - <<'EOF'
import csv
from pathlib import Path
B = Path("docs/metrics")
snap = lambda d: {r["slug"]: r for r in csv.DictReader(open(B / f"skillhub-{d}.csv", encoding="utf-8"))}
tot_c = tot_s = 0
for a, b in (("2026-09-18", "2026-09-19"), ("2026-09-19", "2026-09-20")):
    A, Bs = snap(a), snap(b)
    chg, same = [], []
    for k, nb in Bs.items():
        na = A.get(k)
        if not na or na["found"] != "True" or nb["found"] != "True":
            continue
        d = int(nb["downloads"] or 0) - int(na["downloads"] or 0)
        (chg if na["updated_at"] != nb["updated_at"] else same).append(d)
    print(f"{a} -> {b}   配对 {len(chg)+len(same)} 组")
    print(f"  updated_at 变了   n={len(chg):>3}   增量 {sorted(set(chg))}   其中为 0 的：{chg.count(0)}")
    print(f"  updated_at 没变   n={len(same):>3}   增量 {sorted(set(same))}   其中非 0 的：{len(same)-same.count(0)}")
    tot_c += len(chg); tot_s += len(same)
print(f"\n合计 {tot_c+tot_s} 组配对：{tot_c} 组变动全部增长，{tot_s} 组未变全部零增长，0 例外。")
EOF
```

## 五、发布后 24 小时做什么

这篇文章的 KPI 不是阅读量，是**有多少人去 star 仓库、有多少人回来给你数据**。所以发完不是结束。

### 前 2 小时

- **两边都发完后各自留一条自己的评论**，内容就是文章里那三条验证邀请的精简版（"如果你在 SkillHub 上也有技能，帮我看一眼你的 `updated_at`……"）。置顶它。这条评论的作用是把"读者"变成"参与者"，比正文里的邀请更容易被看到。
- 检查**代码块有没有被平台转义搞坏**（知乎尤其容易把 `<你的slug>` 里的尖括号吃掉）。有问题立刻改。
- 检查图片是否加载正常、GitHub 链接是否可点。

### 前 24 小时

- **每条评论都回**，哪怕只是"谢谢"。前 24 小时的互动率直接影响两个平台的推荐权重。
- **三类评论要认真回，回复本身就是内容**：
  1. **质疑 `updated_at` 是同义反复的**——这是最可能被质疑的点，正文第四节已经承认了。回复时不要辩护，直接说"你说得对，这正是我列的第一条证伪路径，我还没做，你要是能做请告诉我结果"。**这类评论是这篇文章最值钱的部分，遇到了要顶上去。**
  2. **贴出自己技能数据的**——立刻要具体数字（slug 可以不给，给两天的 downloads 和 `updatedAt` 就行）。这是你唯一可能拿到的外部样本。
  3. **问"那到底怎么才能涨"的**——如实说不知道，指向第五节"仍然没解开的谜"。**不要为了讨好读者编一个答案**，这篇文章的全部可信度建立在"不知道就说不知道"上。
- **不要回**：纯情绪的平台吐槽、拉踩其它平台的引战、要你评价腾讯的。这篇不是平台评价文。

### 24 小时后

- 记一下两边的：阅读 / 点赞 / 收藏 / 评论数、GitHub 仓库的 star 增量、以及**有没有人真的跑了那三条验证命令**。最后一项才是这篇文章成功与否的唯一标准。
- 如果有人给了反例（`updated_at` 没动但下载涨了），**那是一篇新文章的开头**，别让它沉在评论区。

## 六、不要做的事

- **不要把这篇投到 SkillHub 的评论区或技能页去导流。** 平台反馈（`docs/feedback/`）和这篇文章是两件事，混在一起会让反馈显得像是为了推广。
- **不要在文章里承诺"后续会有第四篇"**——实验还没出结果，承诺了就欠了。
- **不要为了数据好看改任何数字。** 1872 和 0 收藏是这篇文章可信度的地基；一旦有人去仓库对 CSV 发现对不上，方法论那几节的全部说服力都会一起塌。
