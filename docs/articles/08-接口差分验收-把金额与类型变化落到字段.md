# 接口差分验收：把金额与类型变化落到字段

维护一个接口差分工具时，我用同一份公开订单样本启动两台本地 HTTP 服务，发送相同 GET，再逐字段比较。这个合成样本不是客户生产数据；本文记录的是本机 Python 工具的开发与验收，还没有对应的 WorkBuddy 客户端会话实测。

## 一个具体问题

订单回归响应里有四处变化：实付金额从 19900 分变成 18900 分、商品数量从 2 变成 3、`can_refund` 从 `true` 变成数字 `1`、`note` 从显式 `null` 变成缺失。同时 `id`、`request_id`、`updated_at` 每次变化，是这个样本约定要忽略的响应噪音。

旧版真实请求后只报出了数量和缺失字段两处。金额被 `id` 的子串正则误忽略：`paid_amount` 也含 `id`；布尔类型变化因 Python 的 `True == 1` 被当作一致。两者都会削弱上线前差分结论。

| 核对位置 | 旧响应 → 回归响应 | 0.1.0 实跑 | 0.1.1 实跑 |
|---|---|---|---|
| `$.paid_amount` | 19900 → 18900 | 漏报 | 数值差异 |
| `$.items[0].quantity` | 2 → 3 | 检出 | 数值差异 |
| `$.can_refund` | boolean → number | 漏报 | 类型差异 |
| `$.note` | null → 缺失 | 检出 | 仅 A 存在 |

这里仍然由业务契约判断哪些变化是缺陷。工具负责把变化准确留给验收者，不替整套系统签署迁移结论。

## 怎样修正并复验

0.1.1 按完整字段名匹配忽略规则，逐条写出实际忽略路径；比较 JSON 类型后再比较值，响应小数用 Decimal；双方同为 500、解析失败或请求失败都退出非零。文本比较完整字节的 SHA256，不截取前 4000 字符来判断是否一致。

默认只访问回环地址、只发 GET/HEAD、不跟随重定向；外部地址和写方法需要显式开关与实际授权。金额和数量的常见命名，以及含这些字段的父对象，不能被忽略。保护名单是命名规则，不能识别所有自定义业务语义，因此仍应人工复核自己的响应契约。

```mermaid
flowchart LR
    A[公开合成订单与用例] --> B[两台本地 HTTP 服务]
    B --> C[第一次 GET 检出四处差异]
    C --> D[修正新服务响应]
    D --> E[同一用例重新 GET]
    E --> F[一致报告与输入 SHA256 核对]
```

完整样本、服务启动和验收逻辑均在技能里，不需要外部账号：

```bash
# 在仓库根目录，使用新的输出目录
python3 skills/api-diff/examples/local_order_demo.py --out /tmp/captain-order-demo
```

它先输出 `regressed.json` / `regressed.md`：CLI 退出 1、四处差异可见。然后切换到修正后的响应重新请求，输出 `repaired.json` / `repaired.md`：CLI 退出 0。三个噪音字段仍然变化且忽略路径可见。`verification.json` 保存两轮结果、实际请求、脚本和输入 SHA256；全部条件符合预期时演示脚本才退出 0。

旧版复跑时排除了本机系统代理的影响，确认两端真正收到本地 GET；初次受代理影响的结果没有拿来证明业务差分。这个环境因素也说明，报告中的 HTTP 错误不能草率当作接口业务变化。

## 在 WorkBuddy 中使用

本机已有 SkillHub CLI 时，安装到明确的客户端目录：

```bash
skillhub install api-diff-test --namespace indiv-captain --dir "$HOME/.workbuddy/skills"
```

目录与重启要求见 [SkillHub 官方安装说明](https://skillhub.cn/install/skillhub.md)。重启客户端后，可以要求 WorkBuddy 先读技能，再复跑上述合成示例，检查两轮 JSON、差异路径、忽略字段和原件 SHA256。本轮 CLI 的命名空间安装目录是 `@indiv-captain/api-diff-test`，仓库源目录是 `api-diff`；安装包也附带同一个演示脚本与样本。

这是可复制的操作任务，不代表本篇已经完成了客户端调用。实际运行后应保留使用版本、调用方式、过程与结果；不能用下载数替代任务完成。
