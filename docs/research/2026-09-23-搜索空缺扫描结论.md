# 搜索空缺扫描结论（2026-09-23）

## 扫描一：222 个短名词（`search-gap-scan-2026-09-23.json`）

空缺 15、薄弱 25、已有 182。平台在常见名词上已基本饱和；空缺集中在长尾生活/办公场景（检讨书、KPI、长文总结、图片描述、UI 文案、购物清单、养狗、生日策划、买车、SQL 生成、Python 脚本、自动化办公、会议录音整理、报表制作、数学题）。
按空缺/薄弱词命名建了 30 个新技能（wave1a–2c），**上线当天全部目标查询第一**（读数见 `docs/metrics/2026-09-23-改名实验读数.md`）。

## 扫描二：137 个动词短语（`search-gap-scan-longtail-2026-09-23.json`）

91 条的第一名是热榜兜底（0.050），即**完全无匹配**。直接对照：

| 查询 | 第一名 | 分数 |
|---|---|---|
| 请假条 | 请假条（我们） | 0.079 |
| 写请假条 | 编程专家.Skill（兜底） | 0.050 |
| 年终总结 | 年终总结 | 0.094 |
| 写年终总结 / 帮我写年终总结 | 兜底 | 0.050 |

**结论：搜索引擎对展示名做的是子串匹配，不分词。** 带动词前缀的查询在全平台都只能得到兜底结果，不是「没人做这件事」。

**决定：不建「写X」类重名技能。** 同一内容取两个名字去接两种写法，是利用引擎缺陷占位，不是满足需求；这条与「触发面必须有对应方法」是同一条伦理线。正确做法是把「不分词」作为平台反馈提交（已加入 docs/feedback 待办），并继续只在名词空缺上建技能。

## 对「用户从哪来」的含义

技能商店搜索框大概率收的是名词；用户对 Agent 说的动词句子走的是另一套选择机制（描述/模型判断），不经过这个接口。所以名字解决「商店里被搜到」，描述解决「对话里被选中」——两者分开优化，不互相替代。
