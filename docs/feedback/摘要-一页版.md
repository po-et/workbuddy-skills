# SkillHub 平台反馈 · 一页摘要（2026-09-21）

个人账号 `@indiv-captain`，113 个上架技能、4 天快照。下列 5 条均于 2026-09-21 复现；完整版 9 条见 `docs/feedback/SkillHub-平台反馈-2026-09-21.md`

---

**1. 路径里带 `dockerfile` 的请求被边缘安全策略拦掉，返回 HTTP 566（最高优先级）**
`/api/v1/skills/dockerfile-check` 及其 `/evaluation` 均 566，`server: TencentEdgeOne`，返回 HTML 拦截页；不存在的 `/skills/dockerfile-nonexistent-xyz123` 同样 566，而 `docker-compose-check`、`my-dockerfile-helper`、`dockerfileabc` 正常——**凡路径段以 `dockerfile` 开头且跟词边界即被拦，大小写不敏感**，已连续 4 天。
→ 建议：slug 路径段排除文件名类规则，566 至少返回 JSON。任何人发 `dockerfile-lint` 都会踩同一个坑。

**2. 作者看不到自己技能的下载量与收藏数**
详情接口有 `stats: {downloads, installs, stars, comments, versions}`，搜索接口原始响应亦有，但 CLI 打印前过滤掉；15 个子命令均无「我的技能」列表。`skill rankings` 会打印计数，但只覆盖榜单（319 个里本账号 0 个）；`search?namespace=` 被忽略，`/namespaces/{h}/skills` 返回 405。
→ 建议：`skill reports` 直接打印已有的 `stats`，零新接口、零鉴权改动。

**3. 发布限频没有文档、没有配额字段、不告知何时可重试**
CLI 的 429 分支**已会渲染** `retryAfter` 与 `rule`（源码 `_format_publish_error()`），是服务端没下发；响应体查不到 quota/limit/remain 字段。
→ 建议：429 补 `retryAfter`，CLI 零改动即生效；文档写明配额口径与失败请求是否计数。
（限流报文本轮未复现，触发需真实发布；配额约「滚动 24 小时 100 次」为推测，需确认。）

**4. frontmatter 解析器不是 YAML，标准写法的列表被静默丢弃**
`parse_skill_md_frontmatter()` 逐行 `partition(":")`，不含冒号的行跳过。跑真实技能包：`tags -> ''`、`examples_zh -> ''`（源文件是块状列表）。publish 仅在 `isinstance(tags, list)` 时上送，**块状写法的标签一个不送，无警告**。旁证：我们 113 个技能 `tags` 全为 `[]`，榜单 319 个里 22 个非空。
→ 建议：换真正的 YAML 解析，或至少对「值为空且下一行以 `- ` 开头」告警。标签是搜索命中字段，静默丢弃等于白做可发现性。

**5. `downloads` 与 `installs` 没有口径定义，两者差 2–4 个数量级**
更正旧记录：`installs` 并非未启用：`tencent-docs` 是 8,107，榜单 319 个里 82 个（25.7%）大于 0。但 `dev-expert`（123 万下载）、`parenting-expert`（67 万）恰好为 0，下载超 10 万而 installs 为 0 的有 33 个，比值 0.00%–14%。我们 113 个技能连续三天 installs/stars/comments 全 0，downloads 从 1084 涨到 1872，09-19→09-20 有 65 个恰好 +5。
→ 建议：文档补一句两个计数各在什么动作下 +1、是否去重、是否含平台流水线。口径不明时，1872 次下载可能是 1872 个用户，也可能一个都没有。
