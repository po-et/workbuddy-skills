# WorkBuddy 下一阶段：让技能成为可反复用的资产

当前优先推进的链路是：**取得一个任务包 → 在自己的环境完成任务 → 换成自己的输入 → 在另一个任务中实际复用。** 技能数量和文章数量是辅助记录，不能替代这条链路的结果。下文区分本轮已交付与后续选择；它不是自动化安排。

## 先把三个现有任务交付完整

2026-10-21 已将接口差分、两份报价、PPT 字号检查发布为[三个独立任务包 0.1.0](task-kits.md)。每包包含技能、脚本、样例、开始说明与来源清单；读者先拿到一个可运行的最小交付，不必先了解整个技能目录。

三个正式候选包均已在含空格的新目录解压运行，核对原件保护、输出、退出码和文件来源；13 项自动测试通过。公开 ZIP 已匿名取回，与正式候选 SHA256 及包内清单一致，详见[发布记录](releases/task-kits-2026-10-21.md)。这些是维护者验收，尚未确认独立用户完成或复用。

下一项要取得的证据是一份可核对的外部自愿任务反馈，再验证是否用于另一个任务。先处理第一份实际使用反馈暴露的阻碍：是没有跑起来、结果难读、缺了输入类型，还是换到自己的任务后失效。只有能说明问题的样例和复现，才决定下一次修改；不为提高自动评分而加入无关功能。

## 用实际完成和复用判断方向

[10 月 21 日 14:50 的已核验快照](metrics/2026-10-21-readout.md)是累计下载 **20,212**、收藏 **3**。三个收藏仍是此前的报价、视频抽帧和接口差分，没有新增收藏证据。收藏者身份、独立任务完成和重复使用均未知；下载数不能换算用户数，API installs 为 0 也不能推导无人使用。

因此后续分别记录：

| 要知道什么 | 可接受的证据 | 不能替代它的信号 |
|---|---|---|
| 是否取得资产 | 对应版本的下载/安装结果 | 总榜排名、阅读量 |
| 是否完成自己的任务 | 自愿说明目标、产物或失败步骤；有脱敏结果可进一步核对 | 维护者演示、AI 评分 |
| 是否实际复用 | 已在另一个任务使用，并说明那次结果 | “有兴趣”“计划再用” |

反馈保持简短、自愿，不给任务添加遥测，不要求交出业务原件。维护者、代理、CI 和验包下载另列。没有反馈时保留“尚未确认”，不虚构用户、转化率或节省时间。

## 下一项资产怎么选

先从三个任务的实际失败、复用障碍和用户自愿提出的需求中选择；已有下载分布只作为弱信号。候选需同时回答：谁要交付什么、当前哪里失败、用哪个公开或脱敏输入能复现、修正后怎样验收、如何再用于下一次任务。

再核查来源和许可。独立实现时保留需求来源与设计说明；借用上游代码或材料时检查实际许可证并保留署名、版权和必要声明。不复制第三方技能正文后换名发布，也不带入内部资料、个人信息或凭据。没有真实任务理由的同质技能先不扩张。

文章用于解释已交付的资产、具体问题和复跑方法；先有可用内容，再决定是否需要文章。外部发文、消息与推荐送审仍按各自授权执行，本计划不自动触发任何发送或持续任务。
