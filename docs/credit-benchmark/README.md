# WorkBuddy 额度实测协议

这份协议的产出物是一篇文章的原始数据：**《同一个任务，模式选错额度差几倍：WorkBuddy 省钱实测》**。

技术人群只认可复现的数据。所以这里定义的是一个**可被别人重跑并验证的实验**，不是经验之谈。

---

## 0. 为什么值得做

社区普遍说法是"额度烧得快"，但几乎没有人给出**受控对比数据**。已知的定性结论是：额度主要由「上下文长度 × 模型档位 × 模式选择」决定，而非输出量；做对可省 50-80%（来源：腾讯云开发者社区重度用户实测文，为定性结论，无公开数据表）。

**这个数据缺口就是你的位置。** 谁先发出第一份受控数据，谁就是这个话题的引用源。

---

## 1. 变量设计

| 类型 | 变量 | 取值 |
|---|---|---|
| 自变量 1 | 执行模式 | Ask / Plan / Craft |
| 自变量 2 | 上下文状态 | `fresh`（每次 `/clear`）/ `accumulated`（连续 5 轮不清） |
| 自变量 3（Phase B） | 模型档位 | 轻量档 / 标准档 / 推理档（记录实际模型名） |
| 因变量 | 额度消耗 | Credits（任务前后差值） |
| 因变量 | 墙钟耗时 | 秒 |
| 因变量 | 是否完成 | 完成 / 中断 / 结果不可用 |
| 因变量 | 输出质量 | 1-5 分，按第 3 节 rubric |

### 必须固定的控制变量

1. **同一组任务**，同样的输入文件，同样的提示词逐字不变（存进 `tasks/`）
2. **同一个 WorkBuddy 版本** —— 官方两三天一版，跨版本数据不可比。每次记录版本号
3. **同一时段** —— 客户端会显示夜间折扣，**跨时段数据不可比**。全部实验放在同一时段内跑，并单独用 Phase C 验证折扣幅度
4. **同一网络环境**，同一台机器
5. 每个格子**跑 3 次取中位数**，不是跑 1 次。单次结果噪声太大

## 2. 任务集

任务要覆盖复杂度梯度，且必须是**研发场景**（呼应你的垂直定位，数据能复用到别的文章）。

| ID | 任务 | 复杂度 | 说明 |
|---|---|---|---|
| T1 | 把一段 500 字需求描述整理成结构化条目 | 低 | 纯文本推理，不碰文件 |
| T2 | 读 3 个 .md 文件，汇总成一份对比表格 | 中 | 读文件 + 结构化输出 |
| T3 | 读一个 git log 导出，生成迭代周报 | 中高 | 多步推理 + 长输入 |
| T4 | 扫描一个目录的依赖文件，输出升级影响面清单 | 高 | 多文件遍历 + 判断 |
| T5 | 给定一组日志片段，定位可疑变更并出排查简报 | 高 | 长上下文 + 因果推理 |

提示词逐字存进 `tasks/T1.md` ~ `tasks/T5.md`。**任何一个字的改动都会让数据不可比。**

---

## 3. 输出质量 rubric

不评分就无法说明"省下的额度有没有牺牲质量"，这是整篇文章最容易被质疑的地方。

| 分 | 标准 |
|---|---|
| 5 | 结构完整、事实准确、可直接交付，无需修改 |
| 4 | 可用，需少量措辞修改 |
| 3 | 骨架对但有遗漏或需补充，需实质修改 |
| 2 | 有明显事实错误或结构缺失，修改成本接近重做 |
| 1 | 不可用 |
| 0 | 未完成 / 中断 |

**盲评**：评分时不要看是哪个模式跑出来的。把输出存成文件、打乱文件名再评。

## 4. 执行阶段

### Phase A — 核心矩阵（必做，18 次运行 × 3 重复 = 54 次）

`T1, T3, T5` × `Ask, Plan, Craft` × `fresh, accumulated`

这一组单独就能支撑文章的核心结论。先把它跑完再考虑扩展。

### Phase B — 模型档位（加分，12 次 × 3）

在 `T3, T5` 上跑 `轻量 / 标准 / 推理` 三档 × `Ask, Craft`。

### Phase C — 夜间折扣验证（加分，6 次）

取 `T3` 在 `Craft + fresh` 下，白天与夜间各跑 3 次，验证折扣幅度是否与客户端显示一致。

**这一项如果做出来，很可能是全网第一份。**

---

## 5. 记录方法

每次运行后立刻填一行 `runs.csv`（模板见同目录）。**不要事后回忆补录。**

关键操作顺序：

```
1. /clear（fresh 组）或 跑满前置 5 轮（accumulated 组）
2. 记录 credits_before（客户端额度面板）
3. 开始计时 → 粘贴任务提示词 → 提交
4. 任务结束 → 停止计时
5. 记录 credits_after、是否完成
6. 输出另存为 outputs/<run_id>.md（供后续盲评）
```

## 6. 分析

```bash
python3 analyze.py --input runs.csv --out report/
```

产出：
- `by_mode.md` —— 模式 × 上下文 的额度中位数矩阵（文章主表）
- `cost_quality.md` —— 额度 vs 质量分，回答"省钱是否牺牲质量"
- `summary.md` —— 倍数结论，可直接引用的句子
