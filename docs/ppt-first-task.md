# 下次交付 PPT 前，用自己的文件查一次小字

如果你正在准备周会汇报、培训或技术分享，可以先用这份工具检查现有 `.pptx`：找出检查范围内的小字号、定位其来源，列出字号未知和需要人工复核的地方。它只读原件，不替你修改 PPT，也不把“未发现问题”当成整份演示合格。

这是电脑上的本地工具，不是在手机网页中检查 PPT。需要 **Python 3.9+**；不需要安装演示软件、第三方 Python 依赖、SkillHub 或克隆仓库。也可交给能访问本地文件、运行命令的 WorkBuddy 等 AI 助手。

## 1. 下载并解压

[下载 PPT 任务包 0.1.1](https://github.com/po-et/workbuddy-skills/releases/download/task-kits-v0.1.1/pptx-making-task-kit-0.1.1.zip)，内含 PPT 技能 **0.1.3**、检查脚本和两份合成样例。[发布页与校验和](https://github.com/po-et/workbuddy-skills/releases/tag/task-kits-v0.1.1)可核对来源。

解压后打开包目录，把你有权处理的 PPT 放在该目录中。以下以 `my-deck.pptx` 为例；也可在命令中填写文件的绝对路径。下载、运行无需 GitHub 登录。

## 2. 检查自己的 PPT

在解压目录打开终端，运行：

```sh
python3 start.py --input "./my-deck.pptx" --out-dir "./my-result"
```

Windows 若没有 `python3` 命令，可替换为 `py -3`。`my-result` 必须是**不存在的新目录**；再次运行请改用 `my-result-2`，已有空目录也会被拒绝。输入文件和旧结果不会被覆盖。

如果希望先熟悉输出，可选跑一次包内合成样例：

```sh
python3 start.py --demo --out-dir "./demo-result"
```

样例中的两处 8 磅文字和一处字号未知是预设数据。跑通样例不代表已经检查了你的文件。

## 3. 打开报告，完成人工复核

先读 `my-result/input.txt`，再按需查看 `input.json` 中的页码、文字与字号来源。`verification.json` 记录真实退出码和输入哈希。默认小字号底线为 18 磅，是本工具的检查规则，不是适用于所有演示场景的标准。

| 命令退出码 | 如何处理 |
|---|---|
| `0` | 检查范围内未发现问题；仍需核对未知项，并在演示软件中逐页预览。 |
| `3` | 已发现问题，先按报告定位；这通常是检查结果，不是程序崩溃。 |
| `2` | 文件无法读取或输入无效，按实际错误检查路径与文件。 |

**未知字号不等于合格。** 工具读取页内文字的片段、段落和列表样式，不解析母版、版式、主题继承；不检查图片或独立图表部件内的文字，也不判断实际字体替换、重叠、裁切或投影可读性。自动缩小提示也需要结合实际渲染核对。

你可以据报告在演示软件中修改自己的文件，再用新输出目录复查；本工具本身不修复 PPT。下次交付另一份 PPT 时，同一个命令可替换输入再次使用。

## 也可以交给本地 AI 助手执行

在 AI 助手中打开解压目录，提供你允许它处理的 PPT 路径，然后粘贴：

> 请阅读本目录 START-HERE.md 和 skill/SKILL.md，检查我指定的 PPTX。实际运行 start.py 的 --input 模式，将 --out-dir 指向一个不存在的新目录；保留原件，不安装依赖。读取真实 input.txt、input.json 和 verification.json，说明小字号位置、未知项与检查范围，退出码 3 要解释为发现问题，不要改写成执行失败。不能运行时报告实际错误，不手写检查结果。不要上传 PPT 或业务原文，不把未知项写成通过；最后告诉我哪些地方仍需要在演示软件中预览。

直接用 Python 执行检查脚本无需联网，不会上传 PPT。使用云端 AI 助手时，提示词、读取的文本或命令输出可能发送给其服务方；这不同于纯本地脚本。请按你所在组织及服务方的数据规则使用，不要把“脚本离线”理解为“AI 对话完全离线”。
