# CONTEXT.md 格式

## 结构

```md
# {上下文名}

{一两句话：这个上下文是什么、为什么存在。}

## 语言

**订单（Order）**：
{一两句话描述这个术语}
_避免_：购买、交易

**发票（Invoice）**：
交付后发给客户的付款请求。
_避免_：账单、付款请求

**客户（Customer）**：
下订单的个人或组织。
_避免_：客户端、买家、账户
```

## 规则

- **要有主见。** 同一概念有多个词时，选最好的那个，其余列在 `_避免_` 下。
- **定义要紧。** 最多一两句。定义它**是什么**，不是它做什么。
- **只收本项目特有的术语。** 通用编程概念（超时、错误类型、工具模式）不属于这里，哪怕项目大量使用。加术语前先问：这是本上下文独有的概念，还是通用编程概念？只有前者才收。
- **自然成簇时用子标题分组。** 所有术语属于同一块紧凑领域时，平铺列表即可。

## 单上下文与多上下文仓库

**单上下文（多数仓库）：** 仓库根目录一个 `CONTEXT.md`。

**多上下文：** 根目录放 `CONTEXT-MAP.md`，列出各上下文、位置和相互关系：

```md
# 上下文地图

## 上下文

- [订单（Ordering）](./src/ordering/CONTEXT.md)：接收并跟踪客户订单
- [账单（Billing）](./src/billing/CONTEXT.md)：生成发票并处理付款
- [履约（Fulfillment）](./src/fulfillment/CONTEXT.md)：管理仓库拣货与发货

## 关系

- **订单 → 履约**：订单发出 `OrderPlaced` 事件；履约消费它开始拣货
- **履约 → 账单**：履约发出 `ShipmentDispatched` 事件；账单消费它生成发票
- **订单 ↔ 账单**：共享 `CustomerId` 与 `Money` 类型
```

技能自行推断适用哪种结构：
- 存在 `CONTEXT-MAP.md`：读它找到各上下文
- 只有根目录 `CONTEXT.md`：单上下文
- 都没有：第一个术语落定时在根目录惰性创建 `CONTEXT.md`

多上下文时，推断当前话题属于哪个上下文；不清楚就问。
