# 上下文组件：技术参考

## 系统提示词工程

### 分段结构

```
<BACKGROUND_INFORMATION>  领域背景、用户偏好、项目细节
<INSTRUCTIONS>            核心行为准则与任务指令
<TOOL_GUIDANCE>           何时、如何使用各工具
<OUTPUT_DESCRIPTION>      期望的输出格式与质量标准
```

清晰的段让 Agent 快速定位，也为高级实现的选择性加载留出可能。

### 指令高度校准

**太低（易碎）：** 「用户问价格就查 docs/pricing.md；如果是 USD 就按 config/exchange_rates.json 换算成 EUR；用户在欧盟就按 config/vat_rates.json 加增值税；格式带货币符号、两位小数、附增值税说明。」

**太高（空泛）：** 「帮助用户解决价格问题。要有帮助、要准确。」

**合适（启发式驱动）：**
```
价格咨询：
1. 从 docs/pricing.md 取当前费率
2. 按用户所在地调整（见 config/location_defaults.json）
3. 用合适的货币与税务口径格式化

优先给精确数字而不是估算。费率不可得时明说，不要推算。
```

## 工具定义规范

每个工具定义：name、description（做什么 + 何时用 + 产出什么）、parameters（每个参数的类型、说明、默认值、required）、returns（返回什么、结构如何）。

**弱描述：** 「在数据库里搜索客户信息。」

**强描述：**
```
按 ID 或邮箱取回客户信息。
何时用：用户询问某个具体客户的详情、历史或状态；用户给出客户标识符并需要相关信息。
返回：客户对象——基本信息（姓名、邮箱、账户状态）、订单历史摘要、工单数。
客户不存在返回 null；数据库不可达返回错误。
```

## 检索文档管理

**标识符设计。** 弱：`data/file1.json`、`ref/ref.md`、`2024/q3/report`。强：`customer_pricing_rates.json`、`engineering_onboarding_checklist.md`、`2024_q3_revenue_report.pdf`。强标识符让 Agent 没有搜索工具也能定位文件。

**语义切块。** 在章节标题、段落、逻辑断点处切；块大小在最小/最大阈值之间；避免按固定字符数在句子或概念中间切开。

## 消息历史管理

**轮次表示。** 每条消息保留 role、content、可选的 reasoning、tool_calls / tool_output，以及对话过长时的 summary。

**摘要注入模式。** 每隔 N 轮（如 20）为最近的 N 轮生成一段摘要，以 system 角色插入并标记 is_summary，保留上下文的同时限制增长。

## 工具输出优化

**响应格式选项。** 提供 `format: concise | detailed`：concise 只返回关键字段，detailed 返回完整对象。

**观察遮蔽。** 超过阈值（如 500 字符）的输出存入外部引用，在上下文中替换为「[前一观察已省略，全文见引用 {id}]」，保留可达性同时减少 token。

## 上下文预算估算

**粗略换算：** 英文约 4 字符/token；1000 词 ≈ 7500 字符 ≈ 1800–2000 token。只用于规划，实际以模型分词器为准。

**预算分配参考：**

| 组件 | 典型范围 | 说明 |
|---|---|---|
| 系统提示词 | 500–2000 token | 会话内稳定 |
| 工具定义 | 每个 100–500 token | 随工具数增长 |
| 检索文档 | 可变 | 常是最大消耗者 |
| 消息历史 | 可变 | 随对话增长 |
| 工具输出 | 可变 | 可能主导上下文 |

开发期间监控真实用量，建立基线。

## 渐进式披露实现

**技能激活模式。** 启动时只加载全部技能的元数据（名称 + 描述）；任务描述匹配某技能触发条件时，才加载其完整内容注入上下文；同时激活的技能数设上限。

**引用加载模式。** 引用文件只在显式需要时读取，读过一次后在会话内缓存，避免重复加载。
