# 限定范围复审提示词模板

一轮修复之后派发复审时用这份模板。复审人核实那些发现是否已被解决，并检查
修复 diff 有没有引入新的破坏。**它不是一次全新评审** —— 完整评审已经做过了。

**目的：** 逐条核实上一次评审的发现是否被解决，以及修复本身有没有弄坏东西。

```
子代理（通用型）：
  描述："复审任务 N 修复第 R 轮"
  模型：[必填 —— 按 SKILL.md「选模型」挑；小的修复 diff 用中低档]
  提示词：|
    你在复审一个任务的一轮修复。上一次评审产出了一些发现，实现者尝试修复了
    它们。**你的工作是逐条给发现下判定、并检查修复 diff —— 仅此而已。**

    ## 任务

    读任务简报：[BRIEF_FILE]

    ## 待核实的发现

    [FINDINGS]

    ## 修复

    读实现者的报告（修复报告追加在文件末尾）：[REPORT_FILE]

    **Fix base：** [FIX_BASE_SHA]（上一次评审看到的 head）
    **Head：** [HEAD_SHA]
    **Diff 文件：** [DIFF_FILE]

    把 diff 文件读一次 —— 它包含修复提交、变更统计、以及带上下文的修复 diff。
    不要重跑 git 命令。若 diff 文件缺失，自己取：
    `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]` 与 `git diff [FIX_BASE_SHA]..[HEAD_SHA]`。

    **你的评审对这个检出是只读的。** 不要以任何方式改动工作树、索引、HEAD
    或分支状态。

    ## 你不得派发子代理

    这次复审全部由你自己完成。绝不生成子代理去看 diff 的一部分，也绝不生成
    另一个评审人求第二意见。你生成的评审人是按全价重复一个已有席位，它的
    判定不算数。若 diff 大到一遍看不完，你自己分几遍看，并在报告里说明。

    ## 范围

    **你的范围就是那份发现清单和修复 diff。** 逐条给发现下判定。检查修复
    diff 有没有引入新问题。**不要**去复审修复没碰过的代码：如果你注意到一个
    完全在修复 diff 之外的问题，把它放进「范围外观察」—— 它**不阻塞**这个
    任务，也**不延长**循环。覆盖整个分支的评审会在全部任务完成后进行。

    ## 测试

    实现者已经重跑了覆盖被改代码的测试，并把结果追加进报告文件。**把报告当作
    未经证实的声明**：确认修复报告点名了覆盖测试并给出了它们的输出，并拿 diff
    核实这些声明。不要为了确认他们的报告而重跑套件。只有当读代码引出一个现有
    运行回答不了的具体疑问时才跑测试 —— 而且是聚焦测试，绝不是整包套件。

    ## 输出格式

    **你的最终消息就是报告本身**：直接从第一条发现的判定开始。每一行要么是
    判定、要么是带 `文件:行` 的发现、要么是你跑过的检查 —— 没有开场白，没有
    流程旁白。

    ### 发现判定

    按「待核实的发现」里的顺序，逐条给出：
    - **[发现一句话]** —— 已解决 | 未解决，附 `文件:行` 证据。
      **「尝试过」不算已解决**：那个具体缺陷必须不再存在。

    ### 修复 diff 中的新破坏

    修复本身弄坏或引入的东西，带严重度（Critical/Important/Minor）与 `文件:行`。
    干净就写「无」。

    ### 范围外观察

    你注意到的、完全在修复 diff 之外的问题。不阻塞；协调者会把它们记进账本
    交给终审。没有就写「无」。

    ### 判定

    **本轮修复：** [全部发现已解决，且无新的 Critical/Important 破坏 | 仍有
    发现未解决] —— 列出未解决的那些。
```

**占位符：**

- `[MODEL]` —— 必填；小的修复 diff 用中低档
- `[BRIEF_FILE]` —— 任务简报文件（与实现者用的是同一份）
- `[FINDINGS]` —— 上一次评审的 Critical/Important 发现与 spec 缺口，逐字照抄，一条一个要点
- `[REPORT_FILE]` —— 实现者的报告文件（修复报告追加在末尾）
- `[FIX_BASE_SHA]` —— 上一次评审看到的 head
- `[HEAD_SHA]` —— 当前提交
- `[DIFF_FILE]` —— `scripts/review-package.sh PLAN_FILE FIX_BASE HEAD` 打印的路径

**复审人返回：** 逐条发现判定（已解决 / 未解决）、修复 diff 中的新破坏、范围外观察、本轮判定。
