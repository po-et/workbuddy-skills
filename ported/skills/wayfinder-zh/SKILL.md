# 导航图

一个松散的想法来了，大到一次会话装不下，笼罩在迷雾里：从这里到**目的地**的路还看不见。导航不是冲向目的地，是把路找出来：在工单系统上画一张**共享地图**，然后一次解决一张**决策工单**（答案是一个决定，而不是要执行的一片工作），直到路线清晰。

## 先规划，不执行
默认这是**规划**：每张工单解决一个决策，地图完成的标志是"路已清晰，动手前没有要决定的事了"。想直接去干活的冲动通常说明你到了地图边缘，该交接了。工作可以在「备注」里声明把执行也纳入地图，否则产出决策不产出交付物。

## 用名字引用
每张地图和工单都是一个 issue，有**名字**（标题）。给人看的一切（叙述、已定决策索引）都用名字，不用光秃秃的编号或 slug——一墙的 `#42, #43, #44` 没法读，名字一眼懂。链接可以包在名字里，但绝不替代名字。

## 地图
一个 issue，标签 `wayfinder:map`，是规范产物；工单是它的子 issue。地图是**索引**不是仓库：列出已做的决策并指向持有细节的工单；一个决策只活在一处（它的工单），地图只做一句概述加链接。
**默认用本地 Markdown 工单系统**：`docs/wayfinder/<地图名>/MAP.md` + `tickets/NN-<slug>.md`，阻塞关系写在工单正文的「阻塞于」；项目有 GitHub/Jira/Linear 时用其原生的父子与阻塞关系（前沿能在工单系统 UI 里可视化）。
地图正文（每次会话加载一次的低分辨率视图；开放工单不列，靠查询）：
```
## 目的地      到达终点是什么样：这次要找到的 spec / 决策 / 变更，一两行；每次会话先对准它再选工单
## 备注        领域；每次会话都该参考的技能；本项工作的固定偏好
## 已定决策    索引：每张已关闭工单一行 - [工单名](链接)：答案一句话
## 尚未明确    迷雾：范围内但还说不清的问题，随前沿推进逐步"毕业"为工单
## 范围外      被判定超出目的地的工作；关闭，永不毕业
```
工单正文只有一个问题（`## 问题`：这张工单要解决的决策或调查），大小以一次约 100K token 的会话为限；带 `wayfinder:<类型>` 标签。会话在开工**之前**先**认领**（把工单指派给自己），并发会话就会跳过它；未指派的开放工单就是未认领。**未阻塞** = 阻塞它的工单全部关闭；**前沿** = 开放、未阻塞、未认领的子工单，已知世界的边缘。答案不写在正文里，解决时记录；产出的资产从工单链接，不粘贴。

## 工单类型
每张工单要么**有人在环**（HITL，和能为自己发言的人一起做，代理绝不替人回答——自问自答的盘问就破了规矩），要么**无人值守**（AFK）。
- **研究**（AFK）：读文档、第三方 API、知识库，找出某个决策等着的事实。用「一手来源研究」技能解决。
- **原型**（HITL）：做个便宜粗糙的具体物让讨论提高保真度（大纲、草案、桩、UI/逻辑代码），链接为资产。适用于"该长什么样/该怎么表现"是关键问题时。
- **盘问**（HITL）：对话，默认类型。用「需求盘问官」+「领域建模」。
- **任务**（HITL 或 AFK）：决策之前必须发生的手工工作——没什么可决定、原型、研究，但不做讨论就被卡住：注册服务以便评估其 API、开通权限、搬数据以便看清形状。唯一"做"而不是"决定"的类型，靠解封决策挣位置，不靠交付目的地。代理能做的自己做（AFK），否则给人一份精确清单（HITL）。答案记录做了什么与后续工单依赖的事实（凭证位置、新 URL、行数）。

## 迷雾
地图**刻意**不完整：看不见的不要画。活工单之外是**迷雾**：能感到要来但还钉不住的决策与调查，因为它们悬在仍开放的问题上。解决一张工单就清掉它前方的迷雾，把现在能说清的"毕业"为新工单，一次一张，直到路清、工单为零。
「尚未明确」写下这个模糊视野：疑似的问题、要回头看的区域；它是**朝向**目的地的未发现前沿，都在范围内，只是还不够锋利到能做工单。写多松都行，也是协作者看方向的路标。
**迷雾还是工单？** 标准是**现在能否精确地陈述问题**，而不是能否回答：问题已锋利（哪怕被阻塞）→ 工单；还说不到那么锋利 → 尚未明确，别预先把迷雾切成工单大小——它比工单粗，一片可能毕业成几张，也可能一张都没有。

## 范围外
迷雾只朝目的地聚集。超出目的地的工作不是迷雾，进「范围外」：你有意识地排除在**这次**工作之外的事。范围外永不毕业（前沿止于目的地），只有目的地重画时才回来，而且是新的一次工作。发现某张已有工单其实在目的地之外（画图时误入或被某个解决暴露）→ **关闭它**（关闭的工单明确不在前沿），在范围外留一行：概述 + 为什么 + 链接。不进「已定决策」，那记录的是实际走过的路线。

## 调用
两种模式；无论哪种，**一次会话只解决一张工单**（研究类例外）。
**画地图**（用户带来松散想法）：1 命名目的地——用「需求盘问官」+「领域建模」钉住这张图要到达的 spec / 决策 / 变更，目的地定范围所以先定。2 探前沿——再盘问，这次**广度优先**：横扫整个空间而不是深挖一条线，找出开放决策与现在就能走的第一步。**如果没有迷雾**（路已清晰、整件事一次会话能做完）就不需要地图，停下来问用户想怎么进行。3 建地图（目的地与备注填好，已定决策空，迷雾写进尚未明确）。4 建现在能说清的工单，然后**第二遍**接阻塞关系（工单有了编号才能互相引用），接完自然分出前沿与被阻塞；说不清的留在迷雾。5 派研究——每张研究工单起一个后台任务并行解决，发现记到一次性分支或 `research/` 目录并在工单留指针。6 停——画图是一次会话的工作，不手解任何工单。
**推进地图**（用户带来地图，工单可选；没指定就由你而不是用户选下一个决策）：1 加载地图的低分辨率视图，不加载每张工单正文。2 选工单：用户点名就用它，否则取前沿第一张；**认领**。3 解决：按需**放大**（按需取相关或已关闭工单的全文；调用备注里点名的技能；拿不准就盘问 + 领域建模）。4 记录：答案作为**解决评论**，**关闭**工单，在地图已定决策**追加**一行指针。5 加新工单（建再接）；把答案让它变清晰的迷雾毕业出来，并从尚未明确里清掉；答案显示某张工单超出目的地就判为范围外而不是在路线上解决；决策让地图其他部分失效就更新或删除那些工单。
用户可能并行跑多个未阻塞工单，预期其他会话在同时编辑。
