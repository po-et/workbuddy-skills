# 需求访谈（一次一问）

人们**要的**和**说出来的**不是一回事。说"要个仪表盘"是因为大家都这么说，不是因为仪表盘解决了问题；说"要更快"却没有数字。发现这个缺口最便宜的时刻是**任何计划、spec、代码存在之前**——开工之后切换成本真实存在，用户会把错的东西合理化成"够用"。

本技能在其他"定义阶段"技能之前：「需求盘问官」按设计树发散追问，「需求→Spec」把已明确的写下来，「质疑驱动」在方案之后对抗复审；这个在最前面，一次一问，附上猜测，直到你能预测对方下一句话。

## 什么时候用 / 不用

用：需求缺少 谁用 / 为什么 / 成功是什么 / 硬约束 之一；请求是套话而非具体（"做个 X""快一点"）；你想带着没说出口的假设开工；两个合理目标冲突（简单 vs 灵活、成本 vs 速度）却没说优先谁；用户明确要求。
不用：需求无歧义且自包含；用户明确要速度不要确认；纯信息问答；机械操作；你已有 ≥95% 把握（先看下面的停止条件再下结论）。
**需要在线的人**：CI、定时任务、自主循环里不要用；需求不清就标记为阻塞交给人。

## 流程

### 第 1 步：一句话假设 + 置信度
问任何问题之前先写：
```
假设：你想在站会上回答"我们做得怎么样"，"仪表盘"只是顺口的惯例。
置信度：约 30% —— 缺：给谁用、"指标"指什么、成功长什么样
```
数字逼你诚实：写了高分却预测不了接下来三个问题的反应，就是虚高。低于 ~70% 时同一行附上"还缺什么"。

### 第 2 步：一次一问，附上猜测
```
问：你说"我们做得怎么样"，是谁在问——你自己、站会上的团队、还是向上汇报？
猜：站会上的团队，因为"我们"通常这么指；如果是给高管看，指标和框架都会变。
```
等对方回应再问下一个。**为什么不批量问**：对方无法对藏在列表里的假设做反应；批量导致略读；第三个问题常取决于第一个的答案。**为什么附猜测**：对错误猜测做反应比从零生成答案快；它把你的假设暴露出来——这正是访谈要做的事。风险是礼貌的人会顺着你的猜测点头：要显得随时愿意被推翻，偶尔故意往你预期会被反驳的方向猜。

### 第 3 步：听出"该要"而不是"想要"
危险的答案是听起来像深思熟虑的话：套用最佳实践术语（"要可扩展""干净架构"）却无具体；诉诸惯例（"大多数应用都这样"）；"我应该……""按道理……"；把"现代""健壮"当目标。
听到这些就问：**"如果不需要向任何人交代，你其实想要什么？"** 这一句常常顶前面五句。

### 第 4 步：用对方的话复述（5–8 行）
```
我现在理解你要的是：
- 结果：…　- 用户：…　- 为何现在：…　- 成功：…　- 约束：…　- 范围外：…
对 / 不对 / 要改？
```
「范围外」必须有：一半的错位来自对"不做什么"的沉默分歧。

### 第 5 步：明确的"是"
不算"是"的：「你看着办」（在委托，说明对方也没有 95%——给两个具体选项让他选）；「听起来不错」（问：有要改的吗？沉默不是确认）；「行，开始吧」（常是礼貌退出）；沉默后的「那开始吧」（对方放弃了访谈而不是达成了共识——停下来问是否漏了什么）。有纠正就吸收后再复述，循环到明确的"是"。

### 95% 停止条件
**我能预测对方对接下来三个问题的反应吗？** 能 → 停，输出复述。不能 → 继续问。它也有下限：问了好几轮还是预测不了，说明缺的是根本性的东西——停下来告诉对方"问了 X 个问题还预测不了你的反应，要不要退一步？"

## 产出
经确认的**意图陈述**（第 4 步的复述 + 明确的是）。spec、计划、任务都在它下游。多会话项目可存到 `docs/intent/<主题>.md`——用户确认后才保存。

## 例子（压缩版）
"给我做个指标仪表盘" → 假设 30%：站会用的团队看板 → 问：谁在问？猜团队 → 答："其实是我自己，我老记不住哪些实验在跑、早期信号如何" → 更新：不是团队看板，是个人实验追踪，60% → 问：缺的是"不知道有哪些实验"还是"看不到结果"？猜后者 → 答："前者，我连清单都没有" → 两个问题后发现要的不是仪表盘，是**一张清单**。仪表盘会是错的。

## 合理化借口对照

| 借口 | 现实 |
|---|---|
| "需求够清楚了" | 现在写不出一句话的目标，就不清楚；先做第 1 步 |
| "问太多浪费时间" | 4–6 个问题几分钟；做错东西几周，成本还是对方的 |
| "边做边搞清" | 代码存在后切换成本是现在的 10 倍 |
| "他说你看着办，那我定" | 那是委托不是决定；给两个具体选项 |
| "给几个选项让他挑" | 选项适合已知目标的权衡；他还不知道要什么，选项只会扩大搜索 |
| "附猜测是在引导" | 引导就是目的；反应比生成快；风险是顺从，用可被推翻的姿态化解 |
| "聊够了我懂了" | 测一下：能预测接下来三个问题吗？ |

## 红灯
一条消息里三个以上问题（那是问卷）；问题没附猜测（那是调查）；把"你看着办"当终点；未确认复述就产出 spec/计划；问"最佳实践是什么"而不是"你想要什么"；对方给了"可扩展/干净/现代"这类信号词你就接受了；三轮后置信度没涨（换问法）；置信度 <70% 却没写缺什么；未确认就保存意图文档；复述里没有范围外。

## 验收
- [ ] 第一轮就给出假设与置信度　- [ ] <70% 的置信度附了原因　- [ ] 一次一问、每问附猜测
- [ ] 对套话答案至少追问过一次"如果不用交代你想要什么"　- [ ] 给出了六行复述　- [ ] 拿到明确的是
- [ ] 停止时能预测接下来三问的反应　- [ ] 下游交接基于确认后的意图而非原始请求
