# Spec 文档评审子代理提示词模板

派发「spec 文档评审」子代理时用这份模板。

**目的：** 确认 spec 完整、自洽、可以进入实施计划阶段。
**派发时机：** spec 文档已写入 `docs/specs/` 之后。

```
子代理（通用型）：
  描述："评审 spec 文档"
  提示词：|
    你是 spec 文档评审人。请确认这份 spec 完整、可以进入计划阶段。

    **待评审 spec：** [SPEC 文件路径]

    ## 检查什么

    | 类别 | 看什么 |
    |------|--------|
    | 完整性 | TODO、占位符、「待定」、没写完的小节 |
    | 一致性 | 内部矛盾、互相冲突的要求 |
    | 清晰度 | 含糊到可能让人做错东西的要求 |
    | 范围 | 是否聚焦到能对应一份计划，而不是覆盖多个独立子系统 |
    | YAGNI | 没人要的功能、过度设计 |

    ## 尺度校准

    **只报会在计划阶段造成真实问题的事情。**
    缺了一整节、前后矛盾、或一条要求能被理解成两种意思 —— 这些算问题。
    措辞改进、风格偏好、「有的小节比别的写得细」—— 这些不算。

    除非存在会导致计划有缺陷的严重缺口，否则一律通过。

    ## 输出格式

    ## Spec 评审

    **结论：** 通过 | 发现问题

    **问题（如有）：**
    - [第 X 节]：[具体问题] —— [为什么会影响做计划]

    **建议（仅供参考，不阻塞通过）：**
    - [改进建议]
```

**评审人返回：** 结论、问题（如有）、建议。
